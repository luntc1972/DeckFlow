|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Information disclosure | ScryfallTaggerService manual Cookie replay | mitigate | Auto-cookie-management via CookieContainer keeps the session-cookie scope to the handler instance; deletes the manual `AddHeader("Cookie", session.CookieHeader)` path that previously serialized the cookie into a service-managed string. | T-05-01-02 | Tampering | Stale CSRF token replay | mitigate | Existing 270s `TaggerSessionCache` TTL + AsyncLocal-guarded 403 retry path (`RefreshSessionAndRetryAsync`) preserved unchanged. New `Tagger.RefreshAndRetry` log template surfaces this. |
| T-05-01-03 | Denial of service | Tagger upstream returning 5xx repeatedly | accept | Existing Polly `tagger`/`tagger-post` pipelines + `ScryfallThrottle` rate-limit gate already mitigate. Returning empty tag list is graceful degradation per service contract; severity low. |
| T-05-01-04 | Repudiation | Silent Tagger failure (the Phase 4 abandonment cause) | mitigate | Five structured log templates with `{StatusCode}` + `{ElapsedMs}` + step name distinguish Resolve/SessionFetch/GraphQlPost/Parse/RefreshAndRetry — closes the diagnostic gap that hid the BUG-01 root cause for ~5 days. |
