<objective>
Lay the two Core foundations both later plans build on, with zero coupling between them so they land in one wave:

1. **SYNC-14 git seam** — add `FetchAsync` + `GetBehindCountAsync` to `IGitRepository` (throwing default-interface-methods) and implement them for real in `GitRepository` via the existing `BuildStartInfo`/`RunAndCaptureAsync` shell-out plumbing. This is the missing capability to know a local checkout is *behind its remote* (today's `GetSubjectsAheadOfRemoteAsync` only reads local-ahead and never fetches). `FetchAsync` must use an EXPLICIT refspec so the remote-tracking ref actually advances (HIGH-1 — a bare branch fetch updates only FETCH_HEAD and leaves the tracking ref stale, so the behind-count would read stale and falsely report "Fresh").

Purpose: both are pure-Core, side-effect-free additions with exact in-repo analogs; keeping them in one wave-1 plan unblocks the merged coordinator+page hardening (92-02) immediately.
Output: extended `IGitRepository`/`GitRepository`, extended `SyncDiffEntry`/classifier, extended `FakeGitRepository`, new classifier test.
