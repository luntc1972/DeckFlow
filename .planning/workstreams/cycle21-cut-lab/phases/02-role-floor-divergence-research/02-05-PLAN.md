# Phase 2 Plan 05 — Make criterion 7 structural, and put the verdict on P25

## Release Posture

**This phase ships NO user-visible change and is NOT a release.** `DeckFlow.Core/Research/` and
`DeckFlow.CLI` are not referenced by any controller, view or web service. No CalVer bump, no tag.

## Why This Plan Exists

Two ROADMAP criteria are still open, and both fail the same way if handled by convention.

### Criterion 7 — "never presented as a percentile" must be structural, not a promise

> 7. Floors are reported as **25th percentiles** over real per-deck distributions (D-B). Any cell
>    backed only by an EDHREC point estimate is labelled as such and is never presented as a
>    percentile.

The obvious implementation is a `Source` string on a shared stat class plus a rule in the emitter
that says "if source == edhrec, print `n/a` in the P25 column". That is a convention. Conventions
survive exactly until the next person adds a table.

The structural fact that makes a stronger guarantee possible: **one EDHREC cell is one synthesized
average deck.** Verified live 2026-07-27 — `deck` is a single 92-entry list summing to 100 cards, and
`bracket_counts` reports how many real decks were averaged to produce it, but the individual decks
are not exposed. There is no sample, so there is no percentile, no SD, no z, and no Cohen's d. Not
"we chose not to compute one" — **there is nothing to compute one from.**

So the type carrying a percentile must not exist for EDHREC-sourced data. If
`EdhrecRolePointEstimate` has no `P25` property, no emitter can print one, no future contributor can
add a column by accident, and the guarantee is checked by the compiler on every build.

### Criterion 7 second half — the verdict is still mean-driven

Plan `02-03` added `ClearsFloorBar`, but deliberately did not switch the call site, because
`RoleFloorResearchCommandRunner.cs` belonged to a different wave. The harness still calls
`ClearsBar` at `:242-250`, so P25 remains a cosmetic column. This plan switches it and deletes the
old method in the same commit, so the dead mean-driven bar never survives a wave boundary.

### Criterion 8 — "distinguishable in the output"

> 8. Both corpora are used and distinguishable in the output (D-A): every reported figure states which
>    source it came from, and coverage is reported per source — commanders reached, cells qualifying,
>    decks deduped.

Coverage differs in kind between the two corpora. Postgres coverage is *commanders reached and decks
deduped*; EDHREC coverage is *cells fetched and cells qualifying at the ≥400 floor*. Reporting them
in one table would force one of the two into the wrong units. They get separate blocks.

## Design Decisions

### D-01 — two closed types, not one type with a nullable percentile

Options considered:

| Option | Verdict |
|---|---|
| One `RoleStat` with `Source` and `double? P25` | **Rejected.** Nothing stops an emitter printing `P25.GetValueOrDefault()`, and nothing stops a future contributor setting `P25` on an EDHREC row. The guarantee is a comment. |
| One type with `Source` plus a runtime guard throwing when EDHREC + P25 | **Rejected.** Moves a compile-time property to a runtime exception discovered during a multi-hour run. |
| A C#-style discriminated pair: `PostgresRoleDistribution` (has `P25`, `Mean`, `StdDev`, `ZScore`, `CohensD`, `ClearsBar`) and `EdhrecRolePointEstimate` (has `Count`, `DeckCount`, `Bracket` — **and no percentile, SD, z, or d property at all**) | **Chosen.** |

Both are `sealed record`s in `DeckFlow.Core/Research/RoleFloorFigure.cs`, matching the project's
"sealed record for immutable DTOs with `required` / `init` properties" convention. Both carry a
`required RoleFloorSource Source` property. `RoleFloorSource` is an `enum { Postgres, Edhrec }` — no
default value, so a figure cannot be constructed without declaring its origin.

**Forward note (added 2026-07-27):** plan `02-09`, in wave 6, adds a THIRD member `EdhrecBulk = 3` for
the EDHREC bulk card-counts arm, together with its own record type and its own column list. That plan
carries the narrow authorization to change this plan's enum member-count assertion from `2` to `3`,
and nothing else in `RoleFloorFigureTests`. Write the assertion so its intent is clear — it exists to
prevent a zero-valued default source, not to freeze the enum — and do not treat the number as a
permanent invariant. `IRoleFloorFigure`'s three-member assertion IS permanent, and the reflection
assertion proving `EdhrecRolePointEstimate` carries no distribution property IS permanent; `02-09`
adds an equivalent assertion for its own type rather than relaxing either.

**`{ get; init; }` is mandatory, never `{ get; }`.** The project CLAUDE.md records this as a
bug-driven carve-out: System.Text.Json silently skips get-only properties in .NET 9+, which has
already broken `EdhTop16Client` deserialization once. These records are serialized into
`RESEARCH-FINDINGS.json`.

### D-02 — the shared abstraction is deliberately thin

A common base tempts a shared emitter, which reintroduces the shared column set the whole design
exists to prevent. The two records share only `Source`, `Role`, and `CommanderName`, expressed as an
interface `IRoleFloorFigure` with exactly those three members. Any code needing a percentile must
narrow to `PostgresRoleDistribution` explicitly, and that narrowing is visible in review.

### D-03 — the constant lives at the call site with the others

Plan `02-03` made `absoluteFloorGap` a parameter rather than a literal, precisely so the whole written
bar is visible in one place. Add `private const double AbsoluteFloorGap = 2.0;` beside the existing
`RatioLow` / `RatioHigh` / `ZThreshold` at `RoleFloorResearchCommandRunner.cs:27-29`, and pass it
explicitly. RFLR-02 requires the bar be "defined in writing and applied uniformly to every role" —
one constant block plus one `ClearsFloorBar` call satisfies both halves.

### D-04 — delete `ClearsBar` in the same commit as the switch

Leaving both methods alive would give a future reader two bars and no way to know which one produced
the committed findings. Plan `02-03` kept `ClearsBar` only so wave 1 would build. Its purpose ends
the moment the call site moves.

After deletion, `RoleFloorDivergenceStats` must have exactly one bar method. If any test in
`RoleFloorDivergenceStatsTests` still exercises `ClearsBar` — plan `02-03` added a guard assertion
that does — **delete that specific test member** and say so in the SUMMARY. This is the one and only
authorized test deletion in this phase, and it is authorized because the test's subject no longer
exists. It is not an expectation edited to make a failure pass.

### D-05 — EDHREC figures are not fed into the go/no-go

`BuildGoNoGo` (`:567-613`) keys off `ClearsBar` per commander. `ClearsFloorBar` requires a
`corpusStdDev` and an `n`, neither of which an EDHREC cell has. **EDHREC cells therefore never enter
the go/no-go computation.** They are reported as context — the bracket dimension Postgres cannot
supply — and the lands calibration control in plan `02-07` reads them.

State this explicitly in the emitted methodology text. A reader must not assume a go was influenced
by a bracket that never touched the verdict.

### D-06 — the markdown's source attribution is declared in a testable schema, not carried by headings

The JSON side of criterion 8 is machine-checkable by construction: each Postgres role object carries
`"source": "postgres"` as a field, so a missing tag is a missing field. **The markdown side, as
originally planned, was not.** It relied on the *table heading* ("### Postgres — within-commander
distribution") to attribute every number underneath it. That is a convention with a specific hole: a
future contributor can add a numeric column to a figure table, or add a whole new figure table, with
no per-row source, and pass every grep this plan listed. Criterion 8 says *every reported figure
states which source it came from* — a heading three rows up is not a statement attached to the figure.

Fix, in three parts:

1. **A `Source` column on every figure table.** Both the Postgres table and the EDHREC table gain a
   leading `Source` column whose per-row value is the row's own `RoleFloorSource` rendered as its
   string name. Redundant with the heading by design — redundancy is what survives the next edit.
2. **The column list is declared once, in `DeckFlow.Core`, where a test can see it.** Add a
   `public static class RoleFloorFigureTable` to `RoleFloorFigure.cs` exposing
   `PostgresColumns` and `EdhrecColumns` as `IReadOnlyList<string>`, plus
   `public static bool HasSourceColumn(IReadOnlyList<string> columns)`. The emitter builds its header
   row and its column order FROM these lists — it never writes a header literal.
3. **A `DeckFlow.Core.Tests` assertion over the declarations.** Every public
   `IReadOnlyList<string>` column declaration on `RoleFloorFigureTable`, discovered by REFLECTION so
   a newly-added table is covered automatically, must satisfy `HasSourceColumn`. A contributor who
   adds `PhaseThreeColumns` without a `Source` entry fails the test gate.

This keeps the guarantee where the compiler and the test runner can enforce it, matching D-01's
reasoning about the percentile: the reason `EdhrecRolePointEstimate` has no `P25` property is that
conventions do not survive the next table, and neither do heading-based source tags.

Plan `02-08` adds the matching runtime check over the artifact the run actually produces — a gate
over the generated `RESEARCH-FINDINGS.md` asserting no figure table lacks per-row source attribution.
Declaration-time and output-time are both covered; neither alone is sufficient.
