## Summary

Phase 19 is a pure persistence + contract foundation phase — no outbound HTTP, no runtime behavior. It creates 8 SQLite tables across 4 aggregate stores, lays down `DeckFlow.Core` distillation record models, specifies the AI-prompt artifact file format, and defines the slim site-index schema contract that is the only shape destined for Render Postgres. The phase also enables `PRAGMA foreign_keys=ON` globally in `RelationalDatabaseConnection.CreateConnection` and proves via an xUnit test that `ON DELETE CASCADE` actually fires on SQLite.

The most critical finding from codebase inspection is the **FK blast-radius audit**: every existing SQLite store (`FeedbackStore`, `CategoryKnowledgeRepository`, `HarvestRunStore`, `HarvestScheduleStore`, `AdminBruteForceTrackerStore`) uses NO declared foreign keys in its DDL. All parent-child integrity is maintained in application code (explicit `DELETE` + `INSERT` sequences inside transactions). Enabling `PRAGMA foreign_keys=ON` globally is therefore **safe** — there are no existing FK constraints that would suddenly be enforced, and no insert-order dependencies that would break. The pragma only begins to matter for the new `content_*` tables that actively declare `REFERENCES` clauses.

The `HarvestRunStore` dual-DDL-constant + `SemaphoreSlim` schema-gate pattern is the exact template to copy for each of the 4 new stores. The `IRelationalDialect.SurrogateIdColumnType` property already provides the correct dialect-specific PK declaration string (`BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` for Postgres, `INTEGER PRIMARY KEY AUTOINCREMENT` for SQLite). The test fixture convention is one unique temp-file SQLite DB per test class, with `IDisposable` cleanup — confirmed across `FeedbackStoreTests` and `CategoryKnowledgeRepositoryTests`.

**Primary recommendation:** Copy `HarvestRunStore`'s class skeleton verbatim for each new store; add `PRAGMA foreign_keys=ON` as a single two-line addition in `RelationalDatabaseConnection.CreateConnection()` immediately after `new SqliteConnection(ConnectionString)`; use a separate SQLite `:memory:` or per-test temp file for the CASCADE proof test with an explicit `PRAGMA foreign_keys=ON` issued on the test connection.

### Pattern 1: HarvestRunStore Dual-DDL + Schema-Gate (the exact template)

[VERIFIED: DeckFlow.Web/Services/Harvest/HarvestRunStore.cs lines 18-96, 436-471]

Every new store MUST copy this structure verbatim:

```csharp
public sealed class ContentSourceStore : IContentSourceStore
{
    private readonly RelationalDatabaseConnection _connectionInfo;
    private readonly SemaphoreSlim _schemaGate = new(1, 1);
    private volatile bool _schemaReady;

    // SQLite test-seam ctor (mirrors HarvestRunStore line 32-33)
    public ContentSourceStore(string databasePath)
        : this(RelationalDatabaseConnection.FromSqlitePath(databasePath)) { }

    // RelationalDatabaseConnection ctor (mirrors HarvestRunStore line 42-55)
    public ContentSourceStore(RelationalDatabaseConnection connectionInfo)
    {
        ArgumentNullException.ThrowIfNull(connectionInfo);
        _connectionInfo = connectionInfo;
        if (_connectionInfo.IsSqlite)
        {
            var directory = Path.GetDirectoryName(_connectionInfo.ExtractSqlitePath());
            if (!string.IsNullOrEmpty(directory))
                Directory.CreateDirectory(directory);
        }
    }

    // DI ctor (mirrors HarvestRunStore line 65-66; uses DeckFlowDatabaseConnectionFactory)
    public ContentSourceStore(IWebHostEnvironment environment)
        : this(DeckFlowDatabaseConnectionFactory.CreateContentKbConnection(environment)) { }

    public async Task EnsureSchemaAsync(CancellationToken cancellationToken = default)
    {
        if (_schemaReady) return;
        await _schemaGate.WaitAsync(cancellationToken).ConfigureAwait(false);
        try
        {
            if (_schemaReady) return;
            await using var connection = await OpenConnectionAsync(cancellationToken).ConfigureAwait(false);
            await using var create = connection.CreateCommand();
            create.CommandText = _connectionInfo.IsPostgres
                ? PostgresCreateTableSql
                : SqliteCreateTableSql;
            await create.ExecuteNonQueryAsync(cancellationToken).ConfigureAwait(false);
            _schemaReady = true;
        }
        finally
        {
            _schemaGate.Release();
        }
    }

    private async Task<DbConnection> OpenConnectionAsync(CancellationToken ct)
    {
        var connection = _connectionInfo.CreateConnection();
        await connection.OpenAsync(ct).ConfigureAwait(false);
        return connection;
    }

    // DDL constants — see Pattern below for exact type mapping
    private const string PostgresCreateTableSql = """
        CREATE TABLE IF NOT EXISTS content_sources (
          ...
        );
        """;

    private const string SqliteCreateTableSql = """
        CREATE TABLE IF NOT EXISTS content_sources (
          ...
        );
        """;
}
```

**Key invariant:** `_schemaReady` is `volatile bool`; double-checked lock pattern around `_schemaGate.WaitAsync`. This is load-bearing — do not simplify.

### Pattern 2: Type Mapping Table (Postgres → SQLite)

[VERIFIED: DeckFlow.Web/Services/Harvest/HarvestRunStore.cs lines 436-471, HarvestScheduleStore.cs lines 165-181, FeatureFlagStore.cs lines 156-170, AdminBruteForceTrackerStore.cs lines 162-176]

| Postgres Type | SQLite Equivalent | Notes |
|---------------|-------------------|-------|
| `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | `INTEGER PRIMARY KEY AUTOINCREMENT` | From `IRelationalDialect.SurrogateIdColumnType` — use the dialect property, not a literal |
| `TIMESTAMPTZ NOT NULL DEFAULT now()` | `TEXT NOT NULL DEFAULT (datetime('now'))` | Parens required in SQLite |
| `TIMESTAMPTZ NULL` | `TEXT NULL` | Read back via `DateTimeOffset.Parse(..., RoundtripKind)` |
| `BOOLEAN NOT NULL DEFAULT TRUE` | `INTEGER NOT NULL DEFAULT 1` | Read via `ReadBool()` switch expression (see FeatureFlagStore) |
| `BOOLEAN NOT NULL DEFAULT FALSE` | `INTEGER NOT NULL DEFAULT 0` | Same pattern |
| `TEXT NOT NULL CHECK (x IN ('a','b'))` | `TEXT NOT NULL CHECK (x IN ('a','b'))` | CHECK syntax identical |
| `BIGINT REFERENCES parent(id) ON DELETE CASCADE` | `INTEGER NOT NULL REFERENCES parent(id) ON DELETE CASCADE` | CASCADE only fires on SQLite with `PRAGMA foreign_keys=ON` |
| `now()` (in UPDATE/INSERT) | `datetime('now')` | |
| `INTERVAL '15 minutes'` | No equivalent — compute in app code | AdminBruteForceTrackerStore uses C# TimeSpan |

**Critical:** The `SurrogateIdColumnType` dialect property already exists at `DeckFlow.Core/Storage/IRelationalDialect.cs:11`, implemented as:
- SQLite: `"INTEGER PRIMARY KEY AUTOINCREMENT"` (`SqliteRelationalDialect.cs:14`)
- Postgres: `"BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY"` (`PostgresRelationalDialect.cs:14`)

New store DDL that needs integer surrogate PKs MUST use `_connectionInfo.Dialect.SurrogateIdColumnType` in the DDL string interpolation, exactly as `CategoryKnowledgeRepository.cs:64` does — OR use separate Postgres/SQLite const strings like `HarvestRunStore` does. Either approach is acceptable; the separate-const approach (HarvestRunStore style) is slightly more readable for multi-table DDL.

### Pattern 3: FK Cascade Enforcement — Where to Add the Pragma

[VERIFIED: DeckFlow.Core/Storage/RelationalDatabaseConnection.cs lines 29-35]

The `CreateConnection()` method currently reads:

```csharp
public DbConnection CreateConnection()
    => Provider switch
    {
        RelationalDatabaseProvider.Sqlite => new SqliteConnection(ConnectionString),
        RelationalDatabaseProvider.Postgres => new NpgsqlConnection(ConnectionString),
        _ => throw new NotSupportedException($"Unsupported database provider '{Provider}'.")
    };
```

D-03 requires applying `PRAGMA foreign_keys=ON` when a SQLite connection is opened. The correct insertion point is **not** in `CreateConnection()` itself (which only constructs the connection object without opening it), but in the pattern used by every store: they call `CreateConnection()` then `OpenAsync()`.

**Two valid approaches:**

**Option A — Modify `CreateConnection()` to use `SqliteConnectionStringBuilder` with FK on:**

Not viable: `SqliteConnection` does not honor `PRAGMA` via the connection string. The pragma must be issued after the connection is open.

**Option B — Add a new helper method to `RelationalDatabaseConnection`:**

```csharp
// In RelationalDatabaseConnection.cs — add below CreateConnection()
public async Task<DbConnection> OpenConnectionAsync(CancellationToken cancellationToken = default)
{
    var connection = CreateConnection();
    await connection.OpenAsync(cancellationToken).ConfigureAwait(false);
    if (IsSqlite)
    {
        // Why: SQLite enforces FK ON DELETE CASCADE only with this pragma
        // per connection. Without it, CASCADE silently no-ops (D-03).
        await using var pragma = connection.CreateCommand();
        pragma.CommandText = "PRAGMA foreign_keys=ON;";
        await pragma.ExecuteNonQueryAsync(cancellationToken).ConfigureAwait(false);
    }
    return connection;
}
```

Each new content store then replaces its local `OpenConnectionAsync` helper with a call to `_connectionInfo.OpenConnectionAsync(ct)`. Existing stores keep their own local `OpenConnectionAsync` (which simply calls `CreateConnection()` + `OpenAsync()`) and are **not affected** — the pragma is only applied when the new shared helper is used.

**Option C — Add `PRAGMA foreign_keys=ON` in each new store's `OpenConnectionAsync`:**

Simpler blast radius: each content store applies the pragma in its own `OpenConnectionAsync`, leaving `RelationalDatabaseConnection` unchanged. This is safer but more repetitive.

**Recommendation:** Option B (add `OpenConnectionAsync` to `RelationalDatabaseConnection`) is preferred because it centralizes the behavior for all future FK-using stores, matches D-03's "central" intent, and requires no change to existing stores' methods (they keep their own local helper). The new content stores call `_connectionInfo.OpenConnectionAsync(ct)` instead of their local helper.

### Pattern 5: CASCADE Proof Test Mechanism

[VERIFIED: CategoryKnowledgeRepositoryTests.cs fixture pattern; HarvestRunStore test-seam ctor]

The cascade proof test must:
1. Use a unique per-test temp file (not `:memory:`) — `:memory:` creates a new DB per connection in SQLite by default, which breaks multi-connection tests. Use `Path.Combine(Path.GetTempPath(), $"content-test-{Guid.NewGuid():N}.db")`.
2. Apply `PRAGMA foreign_keys=ON` on the test connection. This is guaranteed if the store's `OpenConnectionAsync` calls `_connectionInfo.OpenConnectionAsync(ct)` (Option B above). If not, the test must issue the pragma explicitly.
3. Insert a parent row (video), insert child rows (transcript/summary/clip/tag), delete the parent, assert children are gone.

```csharp
// Source: verified pattern from CategoryKnowledgeRepositoryTests.cs + FeedbackStoreTests.cs
[Fact]
public async Task DeleteVideo_CascadesToTranscripts_WhenForeignKeysEnabled()
{
    // Arrange — own SQLite file per test (F-PROD-CONTRACT 999.6 lesson)
    var dbPath = Path.Combine(
        Path.GetTempPath(), $"content-cascade-test-{Guid.NewGuid():N}.db");
    try
    {
        var store = new ContentVideoStore(dbPath);
        await store.EnsureSchemaAsync();

        var sourceId = await store.InsertSourceAsync(...);
        var videoId = await store.InsertVideoAsync(sourceId, ...);
        await store.InsertTranscriptAsync(videoId, ...);

        // Act
        await store.DeleteVideoAsync(videoId);

        // Assert — transcript row must be gone
        var transcript = await store.GetTranscriptAsync(videoId);
        Assert.Null(transcript);
    }
    finally
    {
        if (File.Exists(dbPath)) File.Delete(dbPath);
    }
}
```

**Warning:** The test proves CASCADE fires at the SQLite layer, not just that DDL declares it. If the pragma is missing on the connection, the DELETE will succeed but child rows will remain — the test will catch this as a failure.

### Anti-Patterns to Avoid

- **Not applying `PRAGMA foreign_keys=ON`:** CASCADE silently no-ops on SQLite. The entire FK design of the content tables becomes a documentation lie. The Phase 19 cascade proof test will catch this.
- **Sharing `HarvestRunStore`'s table or extending its `kind` CHECK:** `content_harvest_runs` MUST be a separate table with `content_` prefix. Sharing creates schema coupling between Archidekt harvest and content harvest lifecycles (Pitfall 12).
- **Using `:memory:` SQLite for multi-connection tests:** `:memory:` creates a new empty DB for each `SqliteConnection`, so two connections to `"Data Source=:memory:"` see different databases. Use unique temp files per test class.
- **Putting `content_site_index` DDL in `ContentVideoStore`:** The slim-index store is the only Phase 22 shape destined for Render Postgres. It belongs in its own store (`ContentSiteIndexStore`) so it can be independently registered and schema-checked against Render.
- **get-only properties on record models:** `{ get; }` instead of `{ get; init; }` causes System.Text.Json to silently skip the property during deserialization. Has broken `EdhTop16Client` before.
- **Re-indenting raw-string DDL constants:** changes the literal value. CLAUDE.md explicitly forbids this.

## Common Pitfalls

### Pitfall 1: SQLite CASCADE silently no-ops without pragma
**What goes wrong:** `ON DELETE CASCADE` clause in DDL has zero effect unless `PRAGMA foreign_keys=ON` was issued on the same connection after it opened. A DELETE of a video row leaves orphan transcripts, summaries, clips, tags in the DB. No error surfaces.
**Why it happens:** SQLite's FK enforcement is opt-in per-connection, defaulting OFF for backward compatibility.
**How to avoid:** Add `PRAGMA foreign_keys=ON` in `RelationalDatabaseConnection.OpenConnectionAsync` (Option B in Pattern 3). The Phase 19 cascade proof test (Pattern 5) will catch any regression.
**Warning signs:** After deleting a video, `SELECT COUNT(*) FROM content_transcripts WHERE video_id = @id` returns > 0.

### Pitfall 2: `:memory:` SQLite breaks multi-connection tests
**What goes wrong:** Test uses `"Data Source=:memory:"` connection string. `EnsureSchemaAsync` opens connection 1 (creates tables), closes it. Test code opens connection 2 — sees an empty database. Schema initialization appears to silently fail.
**Why it happens:** In-memory SQLite databases are private per connection by default; sharing requires `"Data Source=:memory:?mode=memory&cache=shared"` and a kept-open root connection.
**How to avoid:** Use `Path.GetTempPath() + Guid.NewGuid()` temp file path. All existing DeckFlow store tests use this pattern (verified: `FeedbackStoreTests`, `CategoryKnowledgeRepositoryTests`). Clean up in `Dispose()`.

### Pitfall 3: `{ get; }` instead of `{ get; init; }` on record models
**What goes wrong:** System.Text.Json silently skips get-only properties when deserializing. Records appear to deserialize successfully but all skipped properties are `default`. Has broken `EdhTop16Client` deserialization in production before.
**How to avoid:** All new record types in `DeckFlow.Core/Knowledge/` MUST use `{ get; init; }` (or `required` + `{ get; init; }`). Plan-checker grep: `grep -n '{ get; }' DeckFlow.Core/Knowledge/*.cs` must return empty for new records.

### Pitfall 4: Slim-index `artifact_path` as absolute path
**What goes wrong:** `artifact_path` stored as `/data/content-kb/command-zone/abc123.md`. On a different machine or after a re-mount, the path breaks. Phase 22 can't resolve the file.
**How to avoid:** D-12 specifies relative path (e.g., `content-kb/{slug}/{id}.md`). The store inserts only the relative path. Phase 22 prepends `MTG_DATA_DIR` at read time.

### Pitfall 5: DeckFlow.Core gaining a Web dependency
**What goes wrong:** A record model in `DeckFlow.Core/Knowledge/` imports `Microsoft.AspNetCore.*` (e.g., `IWebHostEnvironment` for a factory method). `DeckFlow.CLI` can no longer reference `DeckFlow.Core` without pulling in the Web stack.
**Why it happens:** Copy-paste from a `DeckFlow.Web` service.
**How to avoid:** `DeckFlow.Core.csproj` has ZERO `ProjectReference` entries (verified by grep: no output). It must stay that way. The DI-ctor that takes `IWebHostEnvironment` belongs only in the `DeckFlow.Web/Services/Content/` store classes, never in Core.

### Pitfall 6: `content_harvest_runs` colliding with `harvest_runs`
**What goes wrong:** Developer names the new table `harvest_runs` or extends `HarvestRunStore`. `CREATE TABLE IF NOT EXISTS` silently no-ops on the existing table; v1.1 columns are absent from the new store's DDL.
**How to avoid:** All new tables use `content_` prefix. `ContentHarvestRunStore` is a separate class in `DeckFlow.Web/Services/Content/` — never subclass or share with `HarvestRunStore`. Pitfall 12 in PITFALLS.md is the canonical reference.

```csharp
// Source: DeckFlow.Web/Services/Harvest/HarvestRunStore.cs:69-96
public async Task EnsureSchemaAsync(CancellationToken cancellationToken = default)
{
    if (_schemaReady) return;                        // fast-path: volatile read
    await _schemaGate.WaitAsync(cancellationToken).ConfigureAwait(false);
    try
    {
        if (_schemaReady) return;                    // double-checked under lock
        await using var connection = await OpenConnectionAsync(cancellationToken).ConfigureAwait(false);
        await using (var create = connection.CreateCommand())
        {
            create.CommandText = _connectionInfo.IsPostgres
                ? PostgresCreateTableSql
                : SqliteCreateTableSql;
            await create.ExecuteNonQueryAsync(cancellationToken).ConfigureAwait(false);
        }
        _schemaReady = true;
    }
    finally
    {
        _schemaGate.Release();
    }
}
```
