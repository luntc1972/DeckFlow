<objective>
Inject the curated Expert Context block into all three analysis prompt variants and wire the relevance service into the packet pipeline (service call -> prompt -> zip -> result), including the re-upload replay path so the panel survives a zip round-trip.

Purpose: KBI-02 (Expert Context block in the prompt artifact) + KBI-03 (block-quote pull-quotes with attribution). The three variants are intentionally decoupled (ADR 0001 / a1fa5ad lesson) — the Expert Context prose is hand-edited in each, never extracted.
Output: Prompt artifacts that include `## Expert Context` when clips match, absent when not, with the clips persisted into the packet zip and result, and restored on re-upload.

**HIGH-1 (no divergence by construction):** The clip set is ALREADY budget-trimmed by plan 02's `GetRelevantClipsAsync` (it fits the tightest variant cap). This packet service passes that single set to ALL THREE variants and persists THAT SAME set into the zip + result. The three variants therefore inject the identical set, and the panel shows exactly that set — prompt == zip == panel by construction. The Gemini variant keeps a defensive paste-cap guard, but with up-front trimming it is a belt-and-suspenders no-op in the normal path; it MUST NOT silently drop clips that were persisted (if it ever trips, that is a calibration bug in plan 02's maxRenderedChars, not a per-variant divergence the panel should hide).

**HIGH-2 (re-upload replay):** On the `/deck-analysis/upload` path, `LoadFromZip` (plan 02) populates `request.ExpertContextJson`. `BuildAsync` MUST prefer those persisted clips (deserialize request.ExpertContextJson) over a fresh relevance fetch, so the re-uploaded packet shows exactly the clips the original prompt contained — even if the live corpus has since changed. `DeckController.DeckAnalysisUpload` must map `result.ExpertContextClips` into its view model (it currently omits it).
</objective>
