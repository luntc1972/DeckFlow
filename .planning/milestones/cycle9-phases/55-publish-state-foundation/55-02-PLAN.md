<critical_context>
PLACEMENT (CLAUDE.md hard rule): PublishStateDeriver MUST live in DeckFlow.Core (pure, unit-testable), NOT DeckFlow.Web or DeckFlow.Studio. Mirror VideoStatusResolver's placement and shape (DeckFlow.Core/Content/), but UNLIKE VideoStatusResolver it takes NO store dependencies — it is a pure function over three scalar inputs. Callers in Phase 56/57 read the row from a store and pass the three values in. Do NOT inject IContentSiteIndexStore here.

THE FOUR STATES (exact strings for display; these are the locked vocabulary):
  - "Never published"  — pushed_to_prod_utc IS NULL.
  - "Pushed-hidden"    — pushed_to_prod_utc set, but entry is not visible (is_visible == false).
  - "Published"        — pushed_to_prod_utc set, visible, and the local content is not newer than the push.
  - "Local-newer"      — pushed_to_prod_utc set, visible, and local index/distill time is strictly AFTER pushed_to_prod_utc (local changes not yet re-pushed).

LOCAL-NEWER COMPARISON (CLAUDE.md UTC pitfall + F-51-PG-01): compare two `DateTimeOffset` values using `.UtcDateTime` / `.ToUniversalTime()` so a stored `+00:00` and a local-offset stamp compare on the same instant — never compare raw local clock or `.DateTime` without normalizing. Boundary semantics (locked): equal timestamps => Published (NOT Local-newer); only a STRICTLY-LATER local time is Local-newer. The "local index/distill time" input is the row's IndexedUtc (the latest local index/distill instant).

PRECEDENCE ORDER (evaluate in this order, first match wins):
  1. pushedToProdUtc is null            -> NeverPublished
  2. !isVisible                          -> PushedHidden
  3. localIndexedUtc (UTC) > pushedToProdUtc (UTC)  -> LocalNewer
  4. otherwise                           -> Published
</critical_context>
