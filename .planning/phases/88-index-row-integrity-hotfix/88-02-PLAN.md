<objective>
Close the C4-collision bug at its source: sync diff classification must key rows by the `(natural_key_type, natural_key_value)` composite drawn from the stored vocabulary, not by a bare `PinId` value that lets a YouTube id collide with a podcast RSS guid (SYNC-05). Extract one shared natural-key helper in `DeckFlow.Core` so the classifier and DirectPush (Plan 88-03) can never diverge on keying again, migrate `SyncDiffEntry.NaturalKeyType` to the stored `youtube_channel`/`podcast_rss` vocabulary, and replace the silent missing-key skip with a structured warning.

Purpose: This is the Core half of the composite-key fix. Plan 88-03 consumes the helper this plan creates and simplifies the Studio consumers to the vocabulary this plan emits.
Output: New `ContentNaturalKey` helper, a rewired `ContentSyncDiffClassifier`, corrected `SyncDiffEntry` xmldoc, and a collision + missing-key regression test.
</objective>

  - string? YoutubeVideoId { get; init; }

Proven composite-key join to reuse verbatim (DirectPushCoordinator.cs:119-136): the C# interpolation is written literally as $"{keyType}\u0000{keyValue}" — the separator is the U+0000 NULL character escape \u0000, NOT a space. It is a shipped Codex MED anti-collision fix: NULL cannot appear in either key component, so a type/value boundary can never be forged. Both diff paths MUST use this exact \u0000 NULL-separator format so they key identically; substituting a space (or any printable character) would silently revert the hardening.

Structured-log style to mirror (PullFromProdCoordinator.cs:209): `_logger.LogWarning("... {KeyType}:{KeyValue}", ...)`.
