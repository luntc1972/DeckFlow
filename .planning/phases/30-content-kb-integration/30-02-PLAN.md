<objective>
Build the relevance-scoring core: the `ContentKbExcerpt` record, the `## Key Clips` parser, the D-07 archetype deriver (category-knowledge distribution -> archetype tags), the `ContentKbRelevanceService` (flag-gated scoring + selection + up-front budget trim), and the zip persistence + re-upload destination (D-03 / HIGH-2). This is the engine plan 03 (prompt injection) and plan 04 (panel + admin preview) both consume.

Purpose: KBI-02 relevance selection + KBI-05 flag-gated empty path. The scoring thresholds/weights are set from `30-TAG-AUDIT.md` produced in plan 01 — they are calibration constants, NOT research-time guesses.
Output: A working, tested `IContentKbRelevanceService` whose selected set is already budget-trimmed (so prompt, zip, and panel can never diverge), a serializable `ContentKbExcerpt`, a category-knowledge-driven archetype signal, a `32-expert-context.json` zip round-trip, and the `DeckAnalysisRequest.ExpertContextJson` re-upload destination.

**Binding D-07 note (orchestrator constraint, NOT relaxed by review):** Research found `ICategoryKnowledgeStore` is NOT currently in the relevance path. D-07 locks archetype derivation to category-knowledge distribution + commander free-text hit. This plan DOES the DI wiring (`ICategoryKnowledgeStore` into `ContentKbArchetypeDeriver`) — it does NOT downgrade to commander-name keyword inference or commander+bracket only. The research's "commander-name keyword fallback" is used ONLY as a last resort when the commander has no category-knowledge rows. Codex flagged this as a MEDIUM scope increase; the user decision D-07 is binding and overrules that concern — match-quality risk is mitigated by the admin preview (D-08, plan 04) and audit-calibrated thresholds.

**HIGH-1 design (budget-before-persistence):** A deck-analysis packet produces THREE per-variant prompts but ONE zip + ONE panel. To make "the panel shows exactly what the prompt contained" mechanically true — including the Gemini paste-cap case — clip-set budget enforcement moves OUT of the prompt variants and INTO this relevance service, BEFORE persistence. `GetRelevantClipsAsync` trims the selected clip set so its rendered size fits the tightest variant budget (Gemini's ~50,000-char paste cap, the binding minimum). The returned set is therefore final and identical for all three variants; plan 03's variants render whatever they are handed without ever skipping. The single trimmed set is what plan 03 persists into the zip and surfaces on the result, so prompt == zip == panel by construction. (Plan 03 keeps a defensive Gemini guard, but with up-front trimming it is a belt-and-suspenders no-op in the normal path.)
</objective>
