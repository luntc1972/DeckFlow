## Deliberate Design Trade-offs

### D-14 fix already shipped — no production source edit in P03

Grep against `CategorySuggestionService.cs` and `CommanderCategoryService.cs` confirms `IArchidektCacheJobService.GetActiveJob() is not null` guards are in place on both code paths. The original H1 hypothesis (`.planning/debug/harvest-killed-by-suggestion.md`) was parked because the root-cause investigation was gating, not parallel-shippable. The fix landed 2026-05-03 (commit history available in `.planning/debug/harvest-killed-by-suggestion-rootcause.md`). P03 closes the loose ends — archive the docs, prune the STATE row, lock the contract with regression facts.

### D-15 uses `git mv`, not `cp + rm`

Preserves the per-file git history so future readers can `git log .planning/debug/archive/harvest-killed-by-suggestion.md` and see the H1 hypothesis evolution. `cp + rm` would break the rename detection threshold (git's `--follow` heuristic still tracks across renames but `git mv` makes the intent explicit and avoids the threshold edge case).

### D-17 splits across two test files (not a shared `[Theory]`)

`SuggestAsync` and `LookupAsync` are on different services with different collaborator constellations. A shared `[Theory]` would force a common test harness — over-engineered for two facts. Each fact lives in its own test file, in the canonical TESTING.md `<TypeUnderTest>Tests.cs` location. The harness wiring is local to each file.

### Creating `CommanderCategoryServiceTests.cs` from scratch is in scope

D-17 binding says "mirror `LookupAsync_SkipsCacheSweep_WhenHarvestActive` to `CommanderCategoryServiceTests.cs`" but the file does not yet exist. The binding implicitly requires creating it. Scope is intentionally minimal: the new file contains the one regression fact + the smallest harness wiring needed (mirror what `CategorySuggestionServiceTests.cs` does for `SuggestAsync`, adapted to `CommanderCategoryService`'s constructor dependencies). Other facts (happy-path lookup, error handling, etc.) are OUT OF SCOPE — backlog candidates for a future test-coverage phase, not 999.5.

### Two commits, not one — commit 1 is doc-only, commit 2 is test-only

Splitting per D-19 (`P03 = 2 commits`) keeps the blame surface narrow: a doc-move audit can `git log -- .planning/debug/` cleanly without test-code noise; a test-addition audit can `git log DeckFlow.Web.Tests/CategorySuggestionServiceTests.cs DeckFlow.Web.Tests/CommanderCategoryServiceTests.cs` cleanly without doc noise. Commit 1 also touches `STATE.md` (D-16 row removal) — STATE is a planning artifact, so it groups naturally with the doc-archive commit.
</design_notes>
