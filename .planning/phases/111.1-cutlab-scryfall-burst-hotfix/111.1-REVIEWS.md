## 0. LIVE SCRYFALL PROBE EVIDENCE (orchestrator-run, 2026-07-31)

Five deliberate calls, spaced, `User-Agent: DeckFlow/1.0 (+https://www.deckflow.gg)`. **This
resolves RESEARCH.md assumption A1, which the plans could not resolve.** These are measured
results, not inferences.

| Input name | `POST /cards/collection` | `GET /cards/search` `!"…"` |
|---|---|---|
| `Smugglers Copter` (no apostrophe) | ✓ resolves → `Smuggler's Copter` | ✓ resolves → `Smuggler's Copter` |
| `Fire / Ice` (Archidekt single-slash) | ✗ `not_found` | ✓ resolves → `Fire // Ice` |
| `Fire // Ice` (canonical) | ✗ `not_found` | ✓ resolves (Copilot probe) |
| `Sol Ring★` | ✗ `not_found` | ✗ 404 (Copilot probe) |

**A1 ANSWER:** `/cards/collection`'s `name` identifier is **punctuation-tolerant** but does **NOT**
accept combined multiface names in either slash form. `/cards/search` with the `!"…"` exact
operator is **more forgiving than `/cards/collection`** for slash forms.

### Consequences — these change the phase's substance

**C-1. The SC-1 delegate swap is SAFE. Proven, no longer assumed.** On every class tested, the
removed `cards/collection` POST inside `ResolveSingleAsync` rescues nothing that
`SearchFallbackCardAsync` does not also resolve. For DFCs, search is *strictly better* than the
removed path. Fable's inference from the prod log — that the strictly-alternating POST/GET pattern
meant the redundant POST resolved nothing — is confirmed empirically. **SC-1 no longer needs the A1
probe to gate wave 1.**

**C-2. The phantom-miss generator is PUNCTUATION, not DFC separators.** `"Smugglers Copter"` is
resolved by the batch `cards/collection` call, but the batch matcher's raw
`string.Equals(name, card.Name, OrdinalIgnoreCase)` (`ScryfallReferenceResolver.cs:136`) compares it
to the returned `"Smuggler's Copter"` and fails → phantom miss → a full extra round-trip for a card
the batch **already had in hand**. This is the burst, and it is pure waste. DFCs are a different and
smaller case: `collection` genuinely cannot resolve them, so their fallback is legitimate work.

**C-3. SC-4 is upgraded from speculative to the highest-leverage fix in the phase.** A **normalized
second-pass match over the already-received batch response**, applied only to names unmatched by the
existing raw pass, eliminates the fallback entirely for the punctuation class at **zero extra network
cost**. It is ADDITIVE — it does not alter the raw-match semantics that
`ScryfallReferenceResolver.cs:52-61` documents or that the "H2 lock" test
(`ScryfallReferenceResolverTests.cs:27-52`) pins, because that test's single-slash case still lands
in `not_found` at the API and therefore still falls through to fallback exactly as asserted.
**Verify that claim against the H2 test before implementing — do not assume it.**

## 1. BLOCKERS — must be fixed before execution

### B-1 [Fable HIGH] 429 fail-open poisons the pool cache for 30 minutes
**Plan 01 Task 3 / SC-2.** Verified chain: names in a swallowed-429 chunk land in neither
`resolvedByName` nor `knownMissingNamesSet`, but `ResolveCardsAsync` still calls
`_resolvedCardCache.Set(poolKey, resolvedCards, knownMissingNamesSet)`, caching the **partial** pool
under a 30-minute TTL (`CutLabResolvedCardCache.cs:16`, verified). The next import hits
`TryGetCachedResolvedCards` and never re-resolves (`CutLabPageService.cs:~493-501`). `ProcessAsync`
then primes every `entry.Card is null` name — including 429 casualties — as `unresolvedCardNames`
(`CutLabPageService.cs:275-282`), so `EnumerateMissingPoolCards` excludes them from later attempts too.

Pre-fix, the fail-closed throw happened **before** the cache write, so partials were never cached.
**Plan 01 introduces this.** The banner said "Try again shortly" and retrying WORKED; post-fix,
retrying within 30 minutes silently returns the same degraded pool.

**Fix:** distinguish "attempted, Scryfall says missing" from "not attempted, transient failure."
Skip the cache `Set` when any chunk was swallowed as transient, or carry a separate
transient-failure set excluded from both the `Set` and the `PrimeResolvedCardsCache` call.

### B-2 [Fable HIGH] Plan 02's 429 tests cannot pass — fixture violates the pool-size floor
`CutLabPoolValidator.MinPoolCards = 101` (verified), enforced in `ProcessAsync` **after**
`ResolveEntriesAsync`. Plan 02's ~10-name fixture means resolution succeeds (429 correctly
swallowed), then `ValidateCardCount` throws and `ErrorMessage` is populated anyway. The asserts
("ErrorMessage null or empty") fail even against a perfect fix, and the plan instructs the executor
to STOP and report — a guaranteed false alarm.
**Fix:** fixture must be 101–150 non-basic names. (The 503 inverse test passes at 10 cards only by
accident, because resolution throws before validation.)

### B-3 [Fable HIGH] Plan 02's 503 test asserts a string the code never produces
A 503 on the batch collection call raises `ScryfallReferenceCollectionException` whose message
contains `"cards/collection"`, which routes `UpstreamErrorMessageBuilder` down
`BuildDetailedScryfallMessage` → **"Scryfall card reference lookup failed while building the
analysis packet with HTTP 503. Try again shortly."** The plan asserts the substring
`"Scryfall returned HTTP 503"`, which only arises from the *fallback-search* exception path.
Plan 02's interfaces block carries the same overclaim for the 429 literal.
**Fix:** assert the detailed-message shape for the batch path, or drive the test through the
fallback exception where the literal applies.

### B-4 [plan-checker BLOCKER] `111.1-VALIDATION.md` does not exist
19 sibling phases carry `<N>-VALIDATION.md`, including the decimal-phase precedent
`110.1-VALIDATION.md` (verified). RESEARCH.md has a `## Validation Architecture` section, which
triggers the convention. Mechanical promotion, not new analysis.

## 2. WARNINGS — fix or explicitly accept

- **W-1 [Fable MED]** Degradation is invisible to the user. Swallowed-429 cards flow in with
  `TypeLine = ""`, `Card = null`: commander eligibility can fail, lands go uncounted, roles/combos
  unassigned — silently wrong cut recommendations, signalled only by a server-side `LogWarning`.
  The same method already adds a user-visible warning for banlist failure
  (`CutLabPageService.cs:259-263`). Use that existing mechanism.
- **W-2 [Fable MED]** Wave-2 plans have mutually incompatible git-diff gates in a shared worktree:
  plan 04 fails if any non-`.planning` file is in the diff, but plan 03 edits production files; plan
  02 requires the diff to be exactly its two files. **Fix:** scope every git-diff assertion with
  `-- <files>`, or serialize.
- **W-3 [Fable MED]** A stronger test seam exists and was overlooked. `ScryfallCardResolver`'s
  internal ctor accepts `executeCollectionAsyncOverride`/`executeSearchAsyncOverride`; constructing
  the REAL resolver with counting delegates makes "collection once, search once per miss" directly
  assertable end-to-end — observing what `CountingResolver` cannot. Both the planner and the
  plan-checker wrongly accepted "impossible to observe." Use it, or decline with a stated reason.
- **W-4 [Fable MED]** Plan 04's `(calls−1) × 300ms` is a worst-case bound mislabeled as "a
  measurement, not an estimate" — it assumes zero service time, while the prod anchor shows
  200–300ms real per-call latency. **Fix:** `(calls−1) × max(0, 500 − measured per-call time)`, with
  ×300 stated as the upper bound. Also add client-side `AbortController` budgets to the STEP 5
  timeout census.
- **W-5 [plan-checker]** Plan 05 reads plan 03's ADR output but omits `111.1-03` from `depends_on`.
- **W-6 [plan-checker]** RESEARCH.md `## Open Questions` lack resolution markers. Both are now
  discharged — Q1 by plan 04's checkpoint, **Q2 (A1) by the probe evidence in §0 above**.
- **W-7 [Fable LOW]** Plan 01 Task 1's documented RED output is self-inconsistent: the extended
  `CountingResolver` still delegates to `SearchFallbackCardAsync`, so pre-fix shows
  `SearchFallbackCalls == 3`, not the stated `0`. Test is still RED, but on a different assertion.
- **W-8 [Fable LOW]** After swallowing a 429, the chunk loop continues POSTing to an upstream that
  is actively rate-limiting. Bounded but counterproductive. Consider breaking out.
- **W-9 [Fable LOW]** Citation drift: `DeckAnalysisPacketService` lives at `Services/`, not
  `Services/Packets/`; its `ResolveBatchAsync` call is `:1893`, delegate `:1895`. Substance correct.
