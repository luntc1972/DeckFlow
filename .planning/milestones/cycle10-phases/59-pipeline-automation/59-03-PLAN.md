<objective>
Add the one-click harvest→auto-distill→auto-approve flow (AUTO-01) to the Harvest page, applying
the persisted auto-approve settings (AUTO-02) and surfacing a per-video outcome summary.

Purpose: Deliver the phase's headline — one operator action turns selected videos into review-ready
(often already-approved) entries (SC1). One-click inline distill runs SUBSCRIPTION ($0) PROVIDERS
ONLY; on a metered provider the action does NOT distill (Core refuses metered live distill at
ContentKbOrchestrator.cs:244) — it surfaces a clear "live distill requires a subscription provider"
message and points the operator to the existing manual Distill section, whose dry-run preview stays
available (D-08 AMENDED 2026-06-20, SC4). Auto-approve flips approval_status to 'approved' for
distills with clip count >= the persisted cutoff when the toggle is ON (SC2); OFF leaves everything
in the queue (SC3). Continue-on-failure with a per-video summary whose counts come from canonical
result fields so nothing is silently lost (D-10, D-11). The existing manual Distill section stays
untouched as a fallback (D-12).
Output: a new "Harvest + Auto-distill" action + outcome card in Harvest.razor, README update, bUnit.

D-08/D-09 AMENDMENT NOTE (read 59-CONTEXT.md "Spend gate interaction" — AMENDED 2026-06-20 after
Codex plan-review HIGH #1, verified against ContentKbOrchestrator.cs:244): Core HARD-REFUSES any
`!dryRun && !isSubscriptionProvider` distill (returns Success=false, AbortedReason). Metered live
distill is therefore unsupported by Core today. One-click + auto-approve are scoped SUBSCRIPTION-ONLY
this phase. The auto-approve step is still authored as a SHARED post-distill method so that IF Core
ever legalizes metered live distill (out of scope now), the same step applies without rework —
metered live distill auto-approve is explicitly DEFERRED, not delivered.
