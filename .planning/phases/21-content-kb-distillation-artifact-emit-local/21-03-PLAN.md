<objective>
Build the artifact file writer, a durable per-video distill-status table, the source-scoped distill query, and the additive store methods the distill orchestrator (Plan 04) needs. 1. `ContentArtifactWriter` (Knowledge) — pure `ToText` + `WriteFile` pair (DeltaExporter pattern) emitting the LOCKED `ContentArtifactSpec` format (D-07); null timestamp → omit `[mm:ss]`, rendered from the in-memory nullable clip result, NEVER reconstructed from a DB `timestamp_s=0` sentinel (D-08/Q1 + MEDIUM-3).

NEW `content_distill_status` table + `ContentVideoStore` methods `GetDistillStatusAsync`/`SetDistillStatusAsync` (HIGH-3) — durable per-video status (`distilled`|`skipped_over_cap`|`failed`) that SUPERSEDES the CONTEXT D-09/D-10 derived-state idempotency (this is the review-driven refinement; see note below).
3. `ContentVideoStore` additive query/transcript/clear methods — **`ListVideosPendingDistillAsync(long sourceId, ...)` is SOURCE-SCOPED** (HIGH-2), plus `GetLatestTranscriptAsync`, `ClearDistillOutputAsync` (+ interface + test-fake updates).

5. `.gitignore` entry for `content-kb/` (D-06) — gated behind a blocking human-action checkpoint because `.gitignore` is on CLAUDE.md's Do-Not-Modify list.

> **Supersession note (review-driven):** CONTEXT D-09/D-10 said idempotency would be DERIVED from artifact-file + slim-index-row presence. The new `content_distill_status` table is that mechanism and supersedes the derived-state approach. A NEW IF-NOT-EXISTS table is schema-safe on the existing UAT db (no ALTER).
