<objective>
The vertical slice: compose Plans 01-03 + the existing Phase 19/20 stores into the `distill` CLI verb that turns each harvested, un-distilled transcript into an AI-prompt artifact file + a slim-index row + persisted summary/clip/tag rows, recording a `content_harvest_runs` summary. Iterate the ENABLED sources and query each source's videos SOURCE-SCOPED so every video is distilled under its OWN source slug and disabled-source videos are never processed (HIGH-2). Per-video distill completion is tracked durably in `content_distill_status` (HIGH-3): a re-run skips `distilled` videos, (re-)attempts `skipped_over_cap`/`failed`/no-row videos. Over-cap videos are durably marked `skipped_over_cap`; failures are durably marked `failed`. A `--dry-run` projects spend and processes nothing (SC5). Also add the `content-source-set-enabled` verb (KB-01/D-13). `distill` is a SIBLING of `RunHarvestAsync` — do NOT edit harvest (D-09; the marker at `CommandRunners.cs:532` means "do it elsewhere").

After this plan, the headline user story is verifiable end-to-end: run `distill` locally over the source list → pasteable prompt artifacts + an index ready for the site.

Purpose: the single persistence owner (Phase 20 D-11) that wires pure services + stores into the end-to-end run, enforcing the guardrails (strict-schema failure classification, tag allowlist, conservative spend cap, durable per-video failure marking, status-based idempotent skip, dry-run).
Output: `RunDistillAsync` (public + internal, with `dryRun`) + `RunContentSourceSetEnabledAsync` + `ResolveContentKbArtifactRoot` helper + two registered CLI verbs (`distill` with `--dry-run`) + `RunDistillAsyncTests` (E2 / status-skip / failure-marking / cap-boundary / dry-run / per-source-slug via injected fakes).
