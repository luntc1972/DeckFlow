<objective>
Build `DeckFlow.Studio/Pages/Publish.razor` — the commit-publish path (PUB-03) — and register the
Plan 02 `IGitRepository` in Studio DI. The operator exports the approved-only seed (LF, D-13) **into
the repo tree**, the page **copies the approved markdown artifacts from the Studio data root into the
repo working tree** (D-03 — so the committed seed never references files absent from the repo), sees a
diff (Added/Updated/Removed counts + raw `git diff`, D-11/D-12), then — only after checking "I have
reviewed the diff above" (D-04) — commits the seed + artifacts onto the **current branch** (D-02/D-03).
**Studio never pushes** (D-01); a post-commit reminder shows the manual push command.

**Resolution of CONTEXT "Claude's Discretion: repo-root / git working-dir resolution + dirty-tree
handling":** repoRoot is resolved via `git rev-parse --show-toplevel` (Plan 02 `ResolveRepoRootAsync`)
and surfaced in the UI; the seed and copied artifacts are written under that repoRoot; the commit is
pathspec-scoped to exactly those paths so unrelated working-tree/staged state is never swept in. The
key correctness fix this plan carries: Studio writes artifacts under `ArtifactRoot =
{studioData}/content-kb`, which is NOT the repo tree — so the publish flow must COPY each approved
artifact (and write the seed) into `repoRoot/content-kb/...` before staging, or the commit ships a
seed pointing at markdown files that do not exist in the repo.

Purpose: This is the primary publish path. The two-stage gate + commit-only design is the strongest
accidental-deploy safeguard: Render auto-deploys only on push to `main`, and Studio physically cannot
push (the git service has no push verb).

**SC4 reinterpretation (record this):** ROADMAP SC4 literally says "Stage 1 git commit / Stage 2 git
push are separate UI actions." Per CONTEXT D-04 this phase reframes the two stages as **Stage 1 =
export + artifact copy + diff preview, Stage 2 = commit (gated behind the reviewed-diff checkbox)**;
the `git push` is the deliberate out-of-app third step the operator runs from a terminal. SC4's intent
— force a deliberate, diff-reviewed action and prevent accidental auto-deploy — is honored more
strongly because Studio never pushes at all.

Output: One Blazor page implementing the full UI-SPEC Publish contract + the git-service DI line.

**This plan does NOT touch NavMenu** (Plan 03 added both nav entries) — keeping Wave 2 free of file
overlap.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator (browser) → Blazor circuit → IGitRepository → git CLI | Export/commit clicks drive git subprocesses against the working tree |
| Publish page → Core (seed write + artifact copy) | Writes the repo seed; copies artifacts data-root → repo tree |
| Studio data root → repo working tree (artifact copy) | Approved markdown copied from {studioData}/content-kb into repoRoot/content-kb |
| Pre-existing staged index → publish commit | Anything pre-staged must NOT enter the publish commit |
| git working tree → (out of app) push to main → Render deploy | Push is deliberately NOT reachable from Studio |
