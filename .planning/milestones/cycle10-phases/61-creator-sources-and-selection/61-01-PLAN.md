## Trust Boundaries
Operator-entered `channel_ref` / `youtube_video_id` are untrusted strings that reach SQL and (later)
YouTube browse. ALL SQL parameterized via Dapper; no string concatenation. Normalize/trim before
store. Stores hold no secrets.

## STRIDE Threat Register
- **Tampering (T-61-01):** local FS edit of content-kb.db — same trust model as blocked_videos;
  no new exposure. Mitigation: parameterized SQL, schema guards.
- **Information disclosure (T-61-02):** stores must never persist secrets — only creator display
  names / channel refs / video ids. Mitigation: column set is non-sensitive by construction.
- **Integrity (T-61-03, HSEL-02 invariant):** SkippedVideoStore must not write blocked_videos or
  delete artifacts. Mitigation: store scope is its own table only; covered by a test asserting
  blocked_videos is untouched after a skip.
