<objective>
Add a read surface to the LLM spend ledger so the Harvest page can display "monthly cap"
and "remaining" (HARV-05 / D-02), prove that a resolver-supplied cap override actually
changes `WouldExceedCapAsync` behavior (the foundation for the Studio session override, D-03),
and add a `redistill` force flag to the distill orchestrator so the Harvest UI's double-confirm
re-distill flow (Wave 4) can actually re-process already-distilled videos (HIGH-4 fix).

This is a Core-only enabler wave. No Studio code, no UI. It unblocks the spend-gate UI in
Wave 4 (cap getter + redistill flag) without re-implementing any logic in the page.

Purpose: Expose the configured monthly cap through `ILlmSpendLedger`, and add the orchestrator
force-redistill path, without breaking the existing `WouldExceedCapAsync` /
`GetMonthlyTotalAsync` contract, the resolver mechanism, or any existing DistillAsync caller.
Output: One new interface member on the ledger; one promoted method + one new public method on
the ledger base class; one new `redistill` parameter on `IDistillOrchestrator.DistillAsync` and
`ContentKbOrchestrator.DistillAsync` (defaulted so callers compile unchanged); and new xUnit
tests in the existing `LlmSpendLedgerTests` fixture plus a new orchestrator distill test fixture.
