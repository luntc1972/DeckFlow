    Create a cross-platform bash script (WSL + Windows Git-Bash) taking one arg: `staged` or `ci`.
    Step A — changed-line ranges: in `staged` mode run `git diff --cached --unified=0 -- '*.cs'`; in `ci` mode resolve the base ref (pull_request event -> `origin/${GITHUB_BASE_REF}`; push event -> `git merge-base origin/main HEAD`) then `git diff --unified=0 "$BASE"...HEAD -- '*.cs'` (THREE dots). Parse `@@ -old +newStart[,newCount] @@` hunk headers with awk into a per-file set of changed line numbers; skip hunks with newCount==0 (pure deletions). Use the awk extractor pattern from RESEARCH Code Examples.
    Step B — early exit: if no changed `.cs` files, print "no changed C# files" and exit 0.
    Step C — run the formatter non-mutating: `dotnet format DeckFlow.sln --include <space-separated changed .cs paths> --verify-no-changes --report "$REPORT" --no-restore` where `REPORT=./artifacts/format-report.json` (repo-local — Pitfall 1; mkdir -p artifacts first). Use FULL `dotnet format` if 50-01-SUMMARY lists any gate-enforceable (dotnet_*/csharp_*) ADOPT-RS style key (Pitfall 6); otherwise whitespace mode is acceptable — document the choice in a comment citing the SUMMARY.
    Step D — intersect: parse the report's `FileChanges[].LineNumber` per file using grep/sed/awk (NOT jq — Pitfall 4). For each reported violation line, test membership in that file's changed-line set. Collect intersections as `file:line`.
    Step E — verdict: if any intersection exists, print each offending `file:line` plus a one-line "run `dotnet format <file>` and re-stage only the changed lines" hint, then exit 1. Otherwise exit 0.
    Security: quote every `"$file"` expansion; pass changed files to `--include` as separate quoted args, never a joined eval'd string; never `eval` diff/report content (filenames are untrusted — Tampering/EoP mitigation). Use `set -euo pipefail`.
    Filter scope: only ever `*.cs` in the diff and `--include`; never run a global `git add` or any EOL normalization (Pitfall 5 — protects `.ps1/.bat/.cmd` CRLF carve-out files).
    Make the script executable (`chmod +x`). The report lives at `./artifacts/format-report.json`, and `artifacts/` is ALREADY gitignored (verified line 4) — make NO `.gitignore` change. ONLY if you deliberately choose a report path OUTSIDE `artifacts/` (do not) would a new `.gitignore` entry be warranted; keep the report under `artifacts/` to avoid touching `.gitignore` (minimal-diff discipline).
