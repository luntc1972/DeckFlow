# Phase 103 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Mode:** AUTO — no user questions were asked. All decisions below trace to 103-CONTEXT.md's 16 locked decisions (D-01..D-16), 103-RESEARCH.md's engine/latency findings, or the shipped Phase 101/102 Cut Lab page (cited by file:line). Genuinely open product choices are marked **FLAG** and logged in **Assumptions Log (Auto Mode)**.
>
> **Scope:** Phase 103 adds three new sections to the existing (dark-default, flag-gated) `/cut-lab` page, appended **after** the Phase 102 "Role floors" section: a **Cut rounds** workspace (sticky progress bar + round banner + one-at-a-time proposal card + tradeoff deltas + accept/reject/defer), a **Cuts made** restore list, and a **Compare to baseline** collapsible panel (SIM-02). The Phase 101/102 intake, lock, slot-competition, findings, and floor sections are inherited unchanged.

## Spacing Scale

Inherited verbatim from 101/102-UI-SPEC (15px root, rem-based organic scale):

| Token | Value | ~px (at 15px root) | Usage |
|-------|-------|---------------------|-------|
| xs | 0.25rem | ~4px | Gaps inside delta-line icons/values, evidence chip padding |
| sm | 0.5rem | ~8px | Gap between decision buttons, chip-to-chip gaps |
| md | 1rem | ~15px | Default rhythm — proposal card sections, cuts-made rows |
| lg | 1.5rem | ~23px | Section padding inside proposal card and compare panel |
| xl | 2rem | ~30px | Gap between Cut rounds / Cuts made / Compare-to-baseline sections |
| 2xl | 3rem | ~45px | Major section breaks (matches page-shell rhythm) |
| 3xl | not used | — | Omit, no DeckFlow page spaces beyond 3rem |

Exceptions:
- **44×44px minimum touch target** (binding, D-14): sticky bar itself, every decision button (Accept/Reject/Defer), every "Restore" button in the Cuts-made list, the delta-table expander `<summary>`, and the Compare-to-baseline `<summary>`.
- **Sticky bar height: exactly 44px** content box (D-14's literal wording), `position: sticky; top: 0;`, matching the `.prompt-sticky-download` precedent (`site-common.css:1920-1948`) but height-constrained rather than flex-wrapping — the bar must never grow taller than 44px on any viewport, so its three fields (round name, count, accepted count) truncate/stack via `text-overflow: ellipsis` on narrow widths rather than wrapping to a second line.
- **Inline spinner: 16px** diameter, reusing `@keyframes busy-spin` at a smaller scale than the full-page `.busy-indicator__spinner` (which stays reserved for the pool-import full-page overlay only — see Component Contract 4).

## Typography

Inherited verbatim from 101/102-UI-SPEC — Phase 103 introduces **zero new sizes or weights**:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 0.95rem (`--fs-base`) | 400 | 1.5 |
| Label | 0.85rem (`--fs-sm`) | 600 | 1.3 |
| Heading | 1.05rem (`--fs-lg`) | 600 | 1.2 |
| Display | 1.5rem (`--fs-xl`) | 700 (inherited hero chrome only — zero new instances) | 1.15 |

- **Heading** — new `h2` section titles: "Cut rounds", "Cuts made", "Compare to baseline". Round-banner text and proposal card-name render at Label size/weight (0.85rem/600), matching `.cutlab-finding__heading`.
- **Body** — delta line text, evidence chip labels, empty/error state copy.
- Sticky bar text renders at Label size/weight throughout (it is a status readout, not prose) — no Body-size text inside the 44px bar.
- Delta numeric values (the colored `▲2.1%`/`▼2.1%` token) render at Body size, same weight as surrounding text — direction is carried by color + glyph, never by making the number bigger or bolder (bold is reserved for headings/labels, not for implying "this matters more").

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` | Page background — unchanged |
| Secondary (30%) | `var(--panel)` | Cut rounds panel, proposal card, cuts-made list container, compare-to-baseline panel. Never `--theme-surface`. |
| Accent (10%) | `var(--accent)` | Reserved for (unchanged 101/102 list, plus): (1) the **Accept cut** button fill (the phase's primary forward action), (2) sticky bar's round-name label, (3) the accepted-cut-count number inside the sticky bar, (4) focus rings. |
| Directional — decrease | `var(--danger)` | **NEW reservation, scoped narrowly (D-06):** the small `▼{value}` token inside a delta line when a metric moves down after a proposed cut. **Not** a destructive/error color in this context — see the binding rule below. Never applied to the card name, the proposal heading, or any full-line background. |
| Directional — increase | `var(--success)` | The small `▲{value}` token inside a delta line when a metric moves up after a proposed cut. Same scoping rule as above. |
| No-change | `var(--muted)` | The "no meaningful change" line and any metric whose delta falls below the noise floor. |
| Warning (semantic, existing) | `var(--gold-warning, var(--warning, #c8a040))` | Reserved for: floor-break warnings on a proposed cut (inherits Phase 102's FLOOR-02 handoff verbatim), and the round-banner accent when auto-advancing (a informational, non-alert callout — never `--danger`). |
| Destructive | `var(--danger)` | **Outside delta lines**, unchanged 101/102 reservations only (intake rejection, commander-unlock block). Phase 103 introduces **zero new destructive UI** — Accept/Reject/Defer are all reversible (D-16: any accepted cut is individually restorable), so none of the three decision buttons use `--danger` as a button color, even Reject. |

**Binding rule distinguishing directional red from destructive red (resolves the apparent conflict with `--danger`'s prior "destructive only" scoping in 101/102):** `--danger` in a delta line is a **magnitude/direction indicator on a number**, always paired with neutral, non-judgmental sentence copy per D-06 ("cutting this lowers keepable-hand 2.1%" — never "this makes your deck worse"). It never colors a button, a card name, a full row background, or a heading. This keeps the existing "destructive = red button/banner" idiom intact while satisfying D-06's explicit directional-color requirement. If the checker or auditor flags this as a `--danger` misuse, the rebuttal is D-06 (locked CONTEXT decision) plus this scoping rule.

Accent reserved for: Accept cut button, Recalculate/primary CTAs (unchanged), sticky bar round name + accepted count, focus rings, locked-package/adjusted-floor left borders (unchanged 102). **Never** on Reject/Defer buttons, delta values (those use directional/no-change colors above), or card names.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Accept cut"** — the forward-driving action of the round loop. Accent-filled button, same visual family as "Import pool"/"Recalculate analysis". |
| Decision action trio (extends primary CTA) | **"Accept cut"** (accent fill) · **"Reject cut"** (neutral bordered, same family as "Start over") · **"Defer decision"** (neutral bordered). All three sit in one row under the proposal card, 44px each, `aria-live` region announces the outcome. |
| Restore action (D-16) | **"Restore"** — per row in the Cuts-made list. No verb variation; consistent across every restorable decision. |
| Round-advance CTA | None — rounds **auto-advance** (D-03); there is no "Next round" button. The round banner itself is the only signal. |
| Empty state heading | Section renders only once the pool is ≤150 cards over target (i.e., cuts are needed); if the locked/floor-adjusted pool is already ≤100, the Cut rounds section shows: **"Nothing to cut"**. |
| Empty state body | *"Every remaining card is either locked or your working list is already at 100 cards. Review your locks and packages above, or adjust a role floor if you want to reconsider."* |
| All-rounds-complete state | Heading **"You're at 100 cards"** — body: *"Review the cuts you made below, or reopen a card from the Cuts made list if you want to reconsider."* Rendered in the same panel, replacing the proposal card once the count reaches zero-remaining. |
| Error state (async decision failure) | Body-size `--muted` line replacing the button row temporarily: *"Couldn't recalculate this cut — nothing changed. Try again."* Never names a subsystem, never blames the card. If the 3s hard cap (D-11) is hit: *"This is taking longer than expected. Try again in a moment."* Both states re-enable the three decision buttons so the user can retry immediately; no page reload required (D-09's async pattern). |
| Destructive confirmation | **None.** Accept/Reject/Defer are all reversible via the Cuts-made restore list (D-16) — no `window.confirm()`, no modal. This is a deliberate contract: the phase's entire UX promise is "nothing is final until export" (Phase 105), so confirmation friction is actively wrong here. |
| Floor-break warning (inherits FLOOR-02, Phase 102 Component Contract 3, reused verbatim) | *"Cutting {card} drops {role} to {newCount}, below your floor of {floor}."* Gold-warning inline block inside the proposal card, above the decision buttons. **Non-blocking** — Accept remains clickable; the warning is the acknowledgment FLOOR-02 requires, not a gate. |

Example: *"Round 1 · Obvious cuts — 12 to cut · 3 cut so far."* On narrow viewports the three fields truncate independently (never wrap) — see Component Contract 1. |

## Component Contract 5: Async Decision Busy State (D-09, D-11)

| Element | Contract |
|---------|----------|
| Trigger | Any click on Accept/Reject/Defer (Component Contract 2) or Restore (Component Contract 3). |
| Visual treatment | **Inline, not full-page.** The full-page `.busy-indicator` overlay (`site.css:644-680`) stays reserved for the pool-import flow only (per its existing `data-busy-title="Importing pool"` contract on `CutLab.cshtml:25-27`) — reusing it here would block the whole page for a ~1s action, which is disproportionate. Instead: on click, disable all three decision buttons on the current proposal card (`disabled` attribute, `aria-busy="true"` on `.cutlab-proposal`), and show a **16px inline spinner** (`.cutlab-busy-spinner`, reusing `@keyframes busy-spin` from `site.css:1121` at reduced scale) next to the clicked button's label, replacing the button text momentarily (e.g. "Accept cut" → spinner + "Recalculating…"). |
| Latency budget (D-11) | ~1s target: spinner is the only feedback, no additional messaging. If the request exceeds ~1.5s elapsed (a UI-side soft threshold, not the 3s hard cap), no copy change — the spinner alone communicates "still working" and avoids anxious re-messaging for what is still within budget. At the 3s hard cap, if no response has arrived, buttons re-enable and the "taking longer than expected" error copy (Copywriting Contract) renders. |
| Success | Spinner removed, button row re-enabled, proposal card / sticky bar / delta values patch in place (D-09) — the round banner may simultaneously swap if the round queue exhausted (D-03 auto-advance), all within the same response cycle. |
| Failure | Spinner removed, button row re-enabled, error line renders per Copywriting Contract, nothing about the working list or cuts-made list changes (fail-safe: an error never leaves the state ambiguous — either the decision fully applied or it didn't). |
| No-JS fallback | Full-page form-POST remains available per D-09 — same `data-busy-title`/`data-busy-message` pattern already on the Cut Lab form covers this path; the inline spinner contract above applies only to the JS-hydrated fetch path. |
