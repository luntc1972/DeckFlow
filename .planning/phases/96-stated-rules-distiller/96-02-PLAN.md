content_type heuristic (LOCKED partition — evaluate in this order so all four buckets are reachable, D-05a):
  1. gameplay  — if the count of DISTINCT gameplay keywords matched across clip excerpts >= GameplayKeywordThreshold (2). MEDIUM-2: matched keywords accumulate into a case-insensitive `HashSet<string>` of the DISTINCT keyword literals hit; a single keyword repeated N times counts as ONE, so one repeated word never classifies as gameplay. Keyword set (case-insensitive, deterministic string scan over already-extracted clip text, NOT a new LLM call): "on turn", "my opponent", "i cast", "combat", "attack", "block", "priority", "mulligan to", "keep this hand", "line of play".
  2. meta-commentary — else if CardCategoryTags.Count == 0.
  3. deck-tech — else if ArchetypeTags.Count >= 1.
  4. deckbuilding-theory — else (CardCategoryTags.Count >= 1 AND ArchetypeTags.Count == 0).
  Do NOT read ClassificationResult.Verdict past the keep/drop gate (RESEARCH Pitfall 5 — only "keep" videos reach here, so verdict carries zero signal).

TranscriptChunker:
  public static IReadOnlyList<string> Chunk(string transcript)
  - Split on the transcript's [mm:ss] markers into natural speech segments.
  - Accumulate segments into chunks targeting ~3000 words (TargetWordsPerChunk const), never exceeding a hard MaxCharsPerChunk cap.
  - Carry a small overlap (last 1-2 sentences of chunk N as leading context of N+1) so a boundary rule is not truncated.
  - A transcript at/below one chunk returns a single-element list (no forced splitting).
  - Bound the chunk count (MaxChunks const, e.g. derived from MaxTranscriptInputTokens); assert/clamp rather than emit unbounded chunks.
