<doc_comment_rules>
Locked decisions from 02-CONTEXT.md. Apply verbatim; do NOT re-derive.

- D-01: Interface/impl pairs — the INTERFACE type carries the full prose summary
  (+ param/returns per D-02); the implementing class AND its public members use inheritdoc.
  THIS PLAN has four such pairs:
    IEdhTop16Client / EdhTop16Client (EdhTop16Client.cs),
    ICategoryKnowledgeStore / CategoryKnowledgeStore (split across two files),
    IFeedbackStore / FeedbackStore (split across two files),
    IScryfallSetService / ScryfallSetService (ScryfallSetService.cs).
  Write the prose on the interface; put a type-level inheritdoc on the impl class.
  Several impl classes already have per-method summary/inheritdoc on individual members — leave
  those byte-identical; this plan only adds the missing TYPE-level comment.
- D-01a: Standalone classes/records with no interface get a full summary written directly.
- D-02: Add param/returns on an interface method ONLY when it has >=2 real params (a trailing
  CancellationToken cancellationToken = default does NOT count) OR when the return's meaning is
  non-obvious from the method name. Single-arg self-evident methods get summary only.
- D-03: Hybrid sourcing — seed summary text from CLAUDE.md's Component-Responsibilities table
  where listed (FeedbackStore "Persistence over RelationalDatabaseConnection"; EdhTop16Client
  "EDH metagame data"; CategoryKnowledgeStore "Persistence over RelationalDatabaseConnection");
  VERIFY against current code; write fresh for the rest (ScryfallCardFace, FeedbackRequestContext,
  IScryfallSetService). Inline comments explain WHY.
- D-04: Records get a type-level summary; add param on positional fields ONLY where a field's
  meaning is not self-evident. ScryfallCardFace fields (Name, ManaCost, TypeLine, OracleText,
  Power, Toughness) ARE self-evident -> type-level summary only, NO param. FeedbackRequestContext:
  type-level summary; add param only on positional fields whose meaning is not obvious from the
  name (judge per the field names present in the file).

FORMATTING (CLAUDE.md R-6 — binding): touch ONLY the doc-comment lines you add. NO Format
Document. NEVER convert get-init to get-only (System.Text.Json silently skips get-only props —
this exact bug already broke EdhTop16Client deserialization once; see CLAUDE.md). NEVER inline a
JsonPropertyName attribute or any attribute onto the property/type line. NEVER re-indent C#
raw-string literals. Preserve LF line endings. Each file's git diff MUST contain only added
doc-comment lines.

DO NOT touch DeckFlow.Web/DeckFlow.Web.csproj — NoWarn strip is Phase 8's job (Pitfall 8).
</doc_comment_rules>
