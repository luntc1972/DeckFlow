    Add `.cutlab-anchor-nav` styling in site-common.css (layout CSS belongs here, never site.css),
    reusing `.manabase-anchor-nav` values for the static desktop treatment. Inside a
    `@media (max-width: 640px)` block make the nav `position: sticky; top: 0; z-index: 15;` with an
    opaque background `var(--panel-soft-bg, var(--panel))` and `box-shadow: 0 2px 6px rgba(0,0,0,0.18)`
    (matching .cutlab-sticky-bar) so scrolling content does not show through — including dark forks
    where a flat border can vanish. When stuck, render as a single horizontally scrollable pill row:
    `.cutlab-anchor-nav-list { display:flex; flex-wrap:nowrap; overflow-x:auto; white-space:nowrap; }`.
    Keep total stuck height <= 4rem so the global `scroll-margin-top: 4rem` still lands correctly (D-05)
    — do NOT override that rule and do NOT measure height in JS. Resolve the sticky-bar collision by
    LAYOUT, not paint order (LOW): the real invariant is that on mobile the `.cutlab-sticky-bar` top
    offset must be `>=` the anchor nav's fixed height budget so the two stuck bars occupy disjoint
    vertical bands. Declare a custom property `--cutlab-anchor-nav-stuck-height: 4rem` (the nav's fixed
    budget) and, within the same mobile breakpoint, set
    `.cutlab-sticky-bar { top: var(--cutlab-anchor-nav-stuck-height, 4rem); }` (it is `top:0` today,
    site-common.css:4507-4520) so the bar sticks BELOW the nav's band rather than at the same `top:0`.
    z-index is NOT the collision fix — it only decides paint order if a transient overlap occurs during
    scroll; the disjoint top offsets are what prevent the overlap. Keep the nav at a z-index below the
    bar's existing 20 (e.g. 15) purely so any momentary paint order is sane. Use COMPOUND selectors
    (e.g. `nav.cutlab-anchor-nav`, `.cutlab-anchor-nav .cutlab-anchor-nav-list a`) so the 11 theme forks
    loaded after site-common.css cannot beat these rules on equal-specificity source order. LF endings;
    append/scope changed lines only, do not reflow the file.
  </action>
