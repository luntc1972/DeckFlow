<objective>
Add an LLM quality classifier as a gate inside the distill flow (REBUILD-02): each video is
classified keep (deck-advice / deckbuilding-philosophy) vs drop (trivia / news / meta-only /
intro-only). Dropped videos are marked `filtered`, have any prior distill output cleared, have any
existing site-index row deleted, and never reach the published site. Keep videos distill normally.
Adds the `"filtered"` distill status with an idempotent CHECK-constraint migration for both SQLite
and Postgres.

Purpose: The hybrid quality gate — LLM removes obvious junk, operator publishes survivors.
Without it the re-harvest re-ingests the same generic/intro-only junk the value gate condemned.
Output: ClassifyAsync on the LLM service (subscription-only, fail-closed for OpenAI), a classifier
gate in DistillVideoAsync that also cleans up a re-classified video's stale rows, the `filtered`
status + migration, and Wave-0 tests for keep/drop routing and stale-row cleanup.

REVIEW-FIX NOTE (Codex peer review — this plan owns 2 of the 4 HIGH):
- FINDING 3 (HIGH): the drop early-return only skipped a NEW UpsertRowAsync. For a video that was
  PREVIOUSLY distilled, stale summaries/clips/tags AND an existing `content_site_index` row stayed
  published. Task 5 makes the drop branch ALSO call ClearDistillOutputAsync AND delete any existing
  site-index row (via GetByNaturalKeyAsync → DeleteByIdAsync), so a re-classified junk video
  disappears. A test covers the preexisting-index-row → drop → row-removed case.
- FINDING 4 (HIGH): OpenAI is the DEFAULT provider when `DECKFLOW_LLM_PROVIDER` is unset
  (LlmDistillationProviderFactory:35). `isSubscriptionProvider` (RunDistillAsync:491-492) is false
  for unset/OpenAI, and projected spend hardcodes `DistillationCallCount = 3` (CommandRunners:1938).
  A 4th unmetered classifier call would undercount the OpenAI spend cap. DECISION: the classifier is
  SUBSCRIPTION-CLI-ONLY and FAILS CLOSED — RunDistillAsync errors out (no distill) when
  `!isSubscriptionProvider`, so the classifier never runs on a metered provider. The live snail run
  uses the claude CLI ($0) backend (CONTEXT.md / Phase 21.2), so this is the simpler, correct choice
  and never silently undercounts. (We do NOT carry TokenUsage on ClassificationResult or bump the
  call count, because the metered path is now forbidden rather than under-metered.)
</objective>

RESOLVED — Open Question 4 (CHECK-constraint migration for `'filtered'`):
content_distill_status.status CHECK (status IN ('distilled','skipped_over_cap','failed')) is set
at CREATE TABLE time (ContentVideoStore.cs Postgres line 633, SQLite line 687). `CREATE TABLE IF
NOT EXISTS` will NOT update an existing constraint, so a DDL-string edit alone is insufficient on a
pre-existing DB. SQLite cannot ALTER a CHECK constraint in place.

CONCRETE STRATEGY (specified, not left open): content_distill_status is a CHILD of content_videos
(`video_id ... ON DELETE CASCADE`) and this phase resets the corpus to empty BEFORE distilling, so
the table holds no rows the operator needs. Use an idempotent table-rebuild migration inside
ContentVideoStore.EnsureSchemaAsync, guarded so it runs at most once:
  - Detect whether the current content_distill_status CHECK already allows 'filtered'. SQLite:
    query `SELECT sql FROM sqlite_master WHERE type='table' AND name='content_distill_status'` and
    test the sql text for the literal `'filtered'`. Postgres: query the check-constraint definition
    via `information_schema`/`pg_constraint` (or the check_constraints view) and test for `'filtered'`.
  - If absent: SQLite → `DROP TABLE content_distill_status;` then recreate with the new CHECK
    (data loss is acceptable — corpus is reset). Postgres → `ALTER TABLE content_distill_status
    DROP CONSTRAINT <name>; ALTER TABLE ... ADD CONSTRAINT ... CHECK (status IN
    ('distilled','skipped_over_cap','failed','filtered'));` (look up the constraint name from
    pg_constraint at runtime — do not hard-code a name). Also update both inline CREATE-TABLE DDL
    strings so fresh DBs include 'filtered' from the start.
This mirrors the idempotent, double-checked EnsureSchemaAsync migration shape used in
ContentSiteIndexStore (PATTERNS.md lines 426-454).

RESOLVED — FINDING 4 (classifier spend metering). The classifier is SUBSCRIPTION-CLI-ONLY. The
distill provider is OpenAI by default (`LlmDistillationProviderFactory.Resolve` defaults to OpenAI
when `DECKFLOW_LLM_PROVIDER` is unset; CliLlmDistillationServiceTests/RESEARCH). `isSubscriptionProvider`
is computed in RunDistillAsync (CommandRunners.cs:491-492) as true only when the provider env var is
set AND not "openai". On a metered (OpenAI) provider the existing projected spend uses
`DistillationCallCount = 3` (CommandRunners.cs:1938) and would NOT account for a 4th classifier call,
undercounting the cap. Rather than re-plumb spend accounting for an unwanted code path, the classifier
FAILS CLOSED: RunDistillAsync returns an error (no distill performed) when `!isSubscriptionProvider`,
with a message like "classifier requires the subscription LLM CLI (set DECKFLOW_LLM_PROVIDER to a
subscription provider); refusing to run an unmetered classifier on a metered provider." The live snail
run uses the claude CLI subscription backend ($0), so this is satisfied.

RESOLVED — FINDING 3 (stale rows on drop). The drop branch must additionally clear prior distill
output and delete any existing site-index row so a re-classified video disappears. Verified store
methods exist: `IContentVideoStore.ClearDistillOutputAsync(long videoId, ...)`
(IContentVideoStore.cs:154), `IContentSiteIndexStore.GetByNaturalKeyAsync(string naturalKeyType,
string naturalKeyValue, ...)` (IContentSiteIndexStore.cs:37), and
`IContentSiteIndexStore.DeleteByIdAsync(long id, ...)` (IContentSiteIndexStore.cs:79). The natural-key
type/value are derived from the video the same way CommandRunners already does in GetNaturalKey(row)
(CommandRunners.cs:1894-1901): `ContentSourceType.Youtube`/video.YoutubeVideoId or
`ContentSourceType.Podcast`/video.RssGuid. DistillVideoAsync already receives `indexStore`
(IContentSiteIndexStore) as a parameter, so no new dependency is needed.

Cost: the classifier call is $0 with the claude CLI subscription backend (no spend-ledger record
needed). On a metered provider it never runs (fail-closed above).
