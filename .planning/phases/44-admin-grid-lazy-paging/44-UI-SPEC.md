## Component Inventory

### 1. Commander Grid Section Shell (existing, modified)

**Selector:** `#harvested-commanders` with class `admin-harvest__panel`

On initial page load, this section renders as an empty placeholder. The grid and pagination
are absent from the server-rendered HTML. The section contains only:

```html
<section id="harvested-commanders" class="admin-harvest__panel">
  <h2>Harvested Commanders</h2>
  <div id="commanders-grid-container"
       aria-live="polite"
       aria-busy="true"
       aria-label="Harvested commanders grid">
    <p class="admin-harvest__grid-loading">Loading commanders…</p>
  </div>
</section>
```

- `aria-busy="true"` is set on initial render; the TypeScript sets it to `false` once the
  partial arrives (success) or once an error is displayed (failure).
- `aria-live="polite"` ensures screen readers announce when content appears without interrupting
  the user.
- `id="commanders-grid-container"` is the stable swap target for innerHTML replacement.

### 2. Loading State (new CSS, in `admin-common.css`)

While the first `fetch('/Admin/Harvest/commanders?page=1')` is in flight:

- The `#commanders-grid-container` shows a single paragraph with class
  `admin-harvest__grid-loading`.
- Copy: `Loading commanders…` (exact copy — see Copywriting section)
- Styling: `color: var(--muted); font-style: italic; margin-top: 12px; padding: 8px 0;`
  (12px here is the inherited table padding value — see Inherited Exceptions above)
- Minimum height of the container: `min-height: 48px` so there is no layout jump when
  the real grid arrives.
- No animation or spinner. The admin shell has no spinner defined in `admin-common.css`
  (the public site's `.busy-indicator__spinner` is site.css–only and uses public guild tokens
  not available in the admin context). A static text label is sufficient for an admin tool
  where the operator will see the grid appear in under 1 second once the index is in place.

CSS to add to `admin-common.css` under `.admin-shell` scope:

```css
/* Phase 44 — commander grid lazy load states */
.admin-shell .admin-harvest__grid-loading {
  color: var(--muted);
  font-style: italic;
  margin-top: 12px;
  padding: 8px 0;
}

#commanders-grid-container {
  min-height: 48px;
}

.admin-shell .admin-harvest__grid-error {
  color: var(--danger);
  margin-top: 12px;
  padding: 8px 0;
}

.admin-shell .admin-harvest__grid-error a {
  color: var(--accent);
}
```

### 3. Partial Grid Content (new Razor partial)

File: `Views/AdminHarvest/_CommandersGrid.cshtml`

The partial renders the full grid section interior when the AJAX call returns. It contains:

a. **Page count line:** `<p class="admin-harvest__grid-meta">…</p>` — copy format below.
b. **Scroll wrapper + table:** identical classes to the existing grid in `Index.cshtml:228-254`
   (`admin-table-scroll` + `admin-table`). No new classes.
c. **Numbered pagination control** (new): replaces the existing prev/next-only nav.

### 4. Numbered Pagination Control (new, inside partial)

**Selector:** `<nav class="admin-feedback-pagination admin-harvest__grid-pager">`

Reuse the existing `.admin-feedback-pagination` class (already styled in `admin-common.css:357`
and covered by the 44px touch-target rule at line 402). The added class
`admin-harvest__grid-pager` is used only if scoping is needed; it carries no new CSS.

Structure (rendered by Razor inside the partial, not by TypeScript):

```html
<nav class="admin-feedback-pagination admin-harvest__grid-pager"
     aria-label="Commander grid pagination">
  <!-- Prev link — hidden on page 1 -->
  <a href="#" data-page="N-1">Prev</a>

  <!-- Windowed page numbers: show current ±2, ellipsis for gaps -->
  <a href="#" data-page="1">1</a>
  <span aria-hidden="true">…</span>
  <a href="#" data-page="N-1">N-1</a>
  <strong aria-current="page">N</strong>   <!-- current page: bold, accent color -->
  <a href="#" data-page="N+1">N+1</a>
  <span aria-hidden="true">…</span>
  <a href="#" data-page="last">last</a>

  <!-- Next link — hidden on last page -->
  <a href="#" data-page="N+1">Next</a>
</nav>
```

- `data-page` attributes carry the target page number; TypeScript uses event delegation on
  `#commanders-grid-container` to intercept clicks, call the AJAX endpoint, and swap innerHTML.
- The current page `<strong>` element: `font-weight: 600; color: var(--text);` — NOT accent,
  to differentiate "I am here" from "click me". Add to `admin-common.css` under:
  ```css
  .admin-shell .admin-harvest__grid-pager strong[aria-current="page"] {
    font-weight: 600;
    color: var(--text);
    padding: 0 4px;
  }
  ```
- Window size: show up to 5 page numbers centered around the current page, with `…` ellipsis
  when the range does not reach the first or last page. For ≤7 total pages, show all.
- When only 1 total page exists, the pagination `<nav>` is omitted entirely from the partial.

### 5. Error State (in TypeScript, innerHTML swap)

When the fetch fails (network error, non-2xx response, or timeout):

```html
<p class="admin-harvest__grid-error">
  Could not load commanders. <a href="#" id="commanders-retry">Retry</a>
</p>
```

- TypeScript attaches a click handler to `#commanders-retry` (re-fires the page-1 fetch).
- `aria-busy` is set to `false` on the container when this state is shown.

### 6. Empty State (rendered by Razor partial when 0 rows)

```html
<p class="admin-empty">No harvested commanders yet.</p>
```

Reuse the existing `.admin-empty` class (`admin-common.css:335-338`:
`color: var(--muted); font-style: italic; margin-top: 12px`). No new CSS.

## Interaction Contract

### Auto-load sequence

1. `DOMContentLoaded` fires in `admin-harvest.ts`.
2. TypeScript immediately calls `fetch('/Admin/Harvest/commanders?page=1', { credentials: 'same-origin' })`.
3. While in flight: `#commanders-grid-container` shows `.admin-harvest__grid-loading` copy;
   `aria-busy="true"` is already set from server render — no TypeScript change needed yet.
4. On success (2xx): replace `#commanders-grid-container`'s innerHTML with response text;
   set `aria-busy="false"` on the container; attach event delegation for pagination clicks.
5. On failure (non-2xx or network error): replace innerHTML with the error state markup;
   set `aria-busy="false"`; attach retry click handler.

### Pagination click sequence

Event delegation is attached to `#commanders-grid-container` on the stable parent (survives
innerHTML swaps). On click of any element with a `data-page` attribute:

1. Prevent default (`e.preventDefault()`).
2. Set `aria-busy="true"` on `#commanders-grid-container`.
3. Replace innerHTML of `#commanders-grid-container` with the loading state markup
   (same `.admin-harvest__grid-loading` paragraph).
4. Fetch `/Admin/Harvest/commanders?page={n}` with `credentials: 'same-origin'`.
5. On success: swap innerHTML, set `aria-busy="false"`, re-use the same event delegation
   (attached to the stable parent — no re-bind needed).
6. On failure: swap innerHTML with error state, set `aria-busy="false"`, attach retry handler
   targeting page `n` (not page 1).
7. Scroll `#harvested-commanders` into view after a successful swap:
   `document.getElementById('harvested-commanders')?.scrollIntoView({ behavior: 'smooth', block: 'start' })`.
   Honor `prefers-reduced-motion`: use `behavior: 'instant'` when the media query matches.

### 403 on direct navigation

Direct browser GET to `/Admin/Harvest/commanders` (no same-origin headers) returns a plain-text
403 — no HTML page. The partial endpoint is internal-only. No special UI needed for this case
since it is not a user-reachable path.

## Accessibility Contract

- `role="region"` + `aria-label` on the `admin-table-scroll` div: already present in
  `Index.cshtml:228`. Preserve verbatim in the partial.
- `<caption class="sr-only">` on the table: already present in `Index.cshtml:230`.
  Preserve verbatim in the partial — exact copy:
  `Harvested commanders with deck count and last processed timestamp`
- `aria-live="polite"` + `aria-busy` on `#commanders-grid-container`: both attributes
  are required. Do not remove either during the lifecycle.
- All pagination links must satisfy the 44px touch-target floor already enforced by the
  `.admin-feedback-pagination a` rule in `admin-common.css:402-417`. No extra CSS needed
  if the pagination uses that class (as specified above).
- Focus: after a pagination swap, do NOT steal focus — let the user tab naturally. The
  `scrollIntoView` call positions the viewport but does not move keyboard focus.
- `prefers-reduced-motion`: the `scrollIntoView` smooth behavior must be guarded:
  ```ts
  const prefersReduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
  el.scrollIntoView({ behavior: prefersReduced ? 'instant' : 'smooth', block: 'start' });
  ```
