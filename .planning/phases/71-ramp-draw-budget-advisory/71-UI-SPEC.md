# Phase 71 — UI Design Contract

> Visual and interaction contract for the plain-language layer added to `/manabase`:
> (A) inline metric glosses, (B) the "Reading your deck" verdict block, (C) the
> Casual-only ramp/draw budget block. All three sit below/around the existing
> two-lens result band and render only when flag-gated ON. Generated by
> gsd-ui-researcher; verified by gsd-ui-checker.

This is a **contract (decisions)**, not exploration. All `71-CONTEXT.md` locked
decisions are treated as fixed.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-written CSS, no component library, no Tailwind) |
| Preset | not applicable |
| Component library | none — server-rendered Razor + CSS custom-property theme tokens |
| Icon library | none (inline Unicode glyphs already in use: ✓, ⚠, ★, ·) |
| Font | inherited from layout (no new font); theme `:root` owns family |
| Theming | 24 guild theme CSS forks + light/dark, all driven by `--` tokens |

**Hard rule (project):** all new layout CSS goes in `site-common.css`. New
color/spacing values must use the **existing** theme tokens via `var(--token, fallback)`
exactly as the neighboring `.manabase-*` rules do. No hard-coded colors (causes
dark-on-dark "light islands"). **No new tokens are required for this phase.**

## Spacing Scale

DeckFlow uses a **rem-based rhythm**, not an 8-point px scale. Reuse the existing
`.manabase-*` values verbatim so the new blocks read native. (Approx px shown for
reference only; do not introduce px.)

| Token (rem) | ~px | Usage in this phase |
|-------------|-----|---------------------|
| 0.15rem | ~2px | inline glyph/badge gaps |
| 0.3–0.35rem | ~5px | list item spacing, tight stack |
| 0.45–0.55rem | ~8px | gloss top-margin under a lens note |
| 0.85rem | ~14px | panel inner padding (vertical), grid gap |
| 1rem | ~16px | panel inner padding (horizontal) |
| 0.75–1rem | ~12–16px | block-to-block vertical margin between result sections |

Panel geometry (reuse from `.manabase-lens`): `border-radius: 12px`,
`padding: 0.85rem 1rem`, `border: 1px solid var(--line, …)`.

Exceptions: none — every value above already exists in `site-common.css`.

## Typography

Reuse the established manabase type roles. No new sizes.

| Role | Size | Weight | Notes |
|------|------|--------|-------|
| Block label / verdict heading | 0.72rem | 600 | UPPERCASE, `letter-spacing: 0.06em`, `--muted` — matches `.manabase-lens-label` |
| Verdict issue lines / fine paragraph | inherit (~1rem) | 400 (600 on key spans) | base body; bold the actionable verb/quantity span only |
| Metric gloss | 0.8rem | 400 | matches `.manabase-lens-note`, `--muted` |
| Budget line | 0.85rem | 400 | matches `.manabase-help`; the count figures may be 600 |
| Budget disclaimer/proxy note | 0.8rem | 400 | `--muted`, de-emphasized |

Weights in use across the project: **400 / 600 / 700** (700 is reserved for the
existing big-number lens; this phase does not add a new 700 element). Body
line-height inherits the layout default (~1.5); the uppercase labels inherit
their compact line-height from the existing lens-label rule.

## Color

Theme-tokenized; there is **no fixed hex palette** — the 60/30/10 split is
expressed in tokens so all 24 themes + dark mode resolve automatically.

| Role | Token | Usage |
|------|-------|-------|
| Dominant surface (60%) | `--bg` (page) | page behind the result panel |
| Secondary surface (30%) | `--panel-soft-bg, var(--surface, transparent)` | verdict + ramp/draw block panel backgrounds, bordered with `--line` |
| Accent (10%) | `--accent-strong, var(--accent, inherit)` | verdict headline emphasis + budget count figures only |
| Issue — moderate | `--gold-warning, var(--warning, #c8a040))` | issue verdict left-accent + "short" emphasis (matches `.manabase-lens-short`) |
| Issue — severe | `--danger, var(--error, #c53030))` | severe-shortfall issue accent (matches `.manabase-row--weakest` left border) |
| OK / fine | `--success, #2f855a` | no-issue verdict accent + check tone (matches `.manabase-lens-met`) |
| Muted text | `--muted, #5a6472` | glosses, disclaimers, proxy note |

Accent reserved for: the verdict **headline** word emphasis and the ramp/draw
**count figures** only. Severity color is reserved for the verdict block's
**left-border accent + a single emphasis span**, never a full filled background.

**Cross-theme / light-dark safety:**
- Tinted panel backgrounds for state MUST use `color-mix(in srgb, var(--token) 14–18%, transparent)` (the same technique as `.manabase-chip--low/ok/good`) so the tint sits on light AND dark panels without becoming a "light island."
- State is never conveyed by color alone — pair the left-border accent with the headline text and the issue list wording (issue vs fine is readable in grayscale).
- Do NOT copy the `.manabase-health--*` fixed-hex pattern here; those are deliberate status badges. The verdict/budget blocks must stay fully token-driven.

## Placement (layout contract)

Order inside `<section class="result-panel">`, relative to existing markup:

```
.manabase-twolens              (existing two-lens band, ~L169)
  ├─ left lens  (Karsten)      + .manabase-lens-gloss ×2  (Karsten gloss, then weakest-color gloss)   [both modes]
  └─ right lens (cast rate)    + .manabase-lens-gloss     (cast-rate gloss)                            [Casual only]
.manabase-context              (existing mode/commander line)
Lands / Health line            (existing ~L213) + demanding gloss appended in the demanding span       [issue states]
► .manabase-verdict            (NEW — the headline read)                                               [Casual; verdict != null]
► .manabase-rampdraw           (NEW — budget advisory)                                                 [Casual; budget != null]
.manabase-ramp <details>       (existing actual-ramp card list, ~L235)
… rest of result unchanged …
```

Placement rules:
- **Glosses (A)** live *inside* their lens, appended after that lens's `.manabase-lens-note`. Cast-rate gloss MUST be inside the `@if (showRightLens)` block so it never renders in cEDH. Weakest-color + Karsten glosses live in the left (mode-independent) lens, so the Karsten gloss is the one guaranteed in cEDH. Demanding-cards gloss renders ONLY alongside the existing conditional demanding span.
- **Verdict (B)** is the synthesized headline → place it directly after the Lands/Health line, before the ramp/draw block and the existing ramp `<details>`, so the human read sits together above the raw per-color table.
- **Budget (C)** immediately follows the verdict (it is one of the verdict's inputs). Casual-only by construction (the view-model field is null in cEDH).
- Flag OFF (`!ShowPlainLanguage && PlainLanguageVerdict == null && RampDrawBudget == null`): none of these elements render — the view is byte-identical to today.

## Class Names (BEM-ish, `manabase-` prefixed)

The four classes named in 71-04-PLAN are the required minimum; the sub-element /
state-modifier classes below are the fuller contract the view + `site-common.css`
will use.

| Class | Element | Tokens used |
|-------|---------|-------------|
| `.manabase-lens-gloss` | metric gloss paragraph inside a lens | `--muted` text; inherits lens padding; 0.8rem |
| `.manabase-verdict` | verdict block container (panel) | `--panel-soft-bg`/`--surface` bg, `--line` border, `border-radius:12px`, `padding:0.85rem 1rem` |
| `.manabase-verdict--issues` | state modifier (issue path) | left-accent + `color-mix` tint BOTH built from `--gold-warning` as the base (NEVER `--warning` directly — it is a variable surface token; matches `.manabase-lens-short`); use `--danger` base if severe |
| `.manabase-verdict--fine` | state modifier (no-issue path) | left-accent `--success` + `color-mix` tint |
| `.manabase-verdict-heading` | the `Headline` ("Reading your deck") | uppercase label style, `--muted`; emphasis word may use `--accent-strong` |
| `.manabase-verdict-list` | `<ul>` of prioritized issue lines | `padding-left:1.2rem`; matches `.manabase-ramp ul` |
| `.manabase-verdict-fine` | no-issue "why-it's-fine" paragraph | base body; success tone via parent modifier |
| `.manabase-rampdraw` | budget block container (panel) | same panel tokens as `.manabase-verdict` |
| `.manabase-rampdraw-line` | the main budget sentence | base/0.85rem; count figures 600, `--accent-strong` |
| `.manabase-rampdraw-note` | heuristic + proxy disclaimer | `--muted`, 0.8rem; matches `.manabase-help` |

Notes:
- Reuse `.manabase-help` / `.manabase-lens-note` styling rather than re-declaring muted-text rules where a paragraph is purely informational.
- `.manabase-lens-gloss` differs from `.manabase-lens-note` only enough to read as the *plain-language* layer (e.g. a hair more top-margin or a subtle left tick); keep it visually subordinate to the note so it doesn't compete with the metric.

## Copywriting Contract

Tone: plain, friendly, non-expert, terse. **Plain hyphens only — no em/en dashes**
in the rendered copy (per plan task 1C). All copy is deterministic templated prose
(no LLM call). Glosses are **UI-only** (never mirrored into the prompt artifact).

### Glosses (A) — `ManabaseDisplay.*Gloss`

| Slot | Copy template |
|------|---------------|
| Karsten source check | "Enough lands/rocks of each color to reliably have that color when you need it. 'need -3' means about 3 sources short." |
| Simulated cast rate | "Across simulated games, how often your spells are castable on or before their ideal turn. Higher is smoother." |
| Weakest color | "Your thinnest color - the one most likely to leave you unable to cast a spell on time." |
| Demanding cards | "Cards with heavy or early color needs that strain the manabase the most." |

### Verdict (B) — `ManabaseVerdict`

| Element | Copy |
|---------|------|
| Heading (`Headline`) | "Reading your deck" |
| Issue line template | "{plain instruction} - {rough quantity}; {example lever}." |
| Issue line example | "You're ~3 white sources short - add about 3 white-producing lands or rocks; you could cut a colorless utility land for one." |
| Ordering | land/color shortfall → ramp → draw (Liebig minimum); cap at top ~3 lines |
| No-issue (`NoIssueReason`) | specific, drawn from the actual numbers - name the colors that cleared + the cast rate + why it's acceptable for the mode. NOT a generic "looks good." |
| No-issue example | "Both colors clear their Karsten targets and your 87% average on-curve cast rate is healthy for Casual - no changes needed." |

### Budget (C) — `ManabaseRampDrawBudget` (Casual only)

| Element | Copy template |
|---------|---------------|
| Budget line | "You run ~{RampCount} ramp / ~{DrawCount} draw. For a ~MV{Threshold} deck a common split is {TargetRamp} / {TargetDraw}." |
| Overlap suffix | " ({OverlapCount} do both)" — appended only when OverlapCount > 0 |
| Heuristic label | "Community heuristic, not Karsten math." |
| Proxy disclosure | "Threshold proxied from {commander MV | curve 75th-percentile MV}." — must state the proxy explicitly |
| Balanced read | when `IsBalanced` (within the ±2-slot deadband), phrase as "your ramp/draw split looks balanced" rather than a nudge |

Number formatting matches the surrounding view (`F1` for half-counts like 8.5,
plain integers for targets). Demanding-cards / cast-rate figures use the existing
helpers (`AvgOnCurve`, `CastPercent`).

### Standard states (this phase adds no forms/CTAs/destructive actions)

| Element | Copy |
|---------|------|
| Primary CTA | none added (existing "Download analysis (.txt)" / "Copy this prompt" unchanged) |
| Empty state | not applicable — the plain-language layer renders only when a result + flag exist; with no result, nothing renders |
| Error state | not applicable — synthesis reads already-computed report data; no new failure path |
| Destructive confirmation | none — no destructive actions in this phase |

## Responsive Behavior

Breakpoint: reuse the existing `@media (max-width: 640px)` rule (two-lens grid
collapses `grid-template-columns: 1fr 1fr` → `1fr`). Verify at 390px (plan).

- **Glosses** are block paragraphs inside the lens — they wrap naturally and stack with the lens when it goes single-column. No new media query needed; just ensure `overflow-wrap`/normal wrapping (no `white-space: nowrap`).
- **Verdict + budget blocks** are full-width single-column already, so they reflow without change. Confirm the issue `<ul>` keeps its `padding-left` and does not overflow at 390px.
- Do not alter `.manabase-twolens` grid declarations — the new elements live inside or after it and must not change its column behavior.

## Theme / Token Cost

**New tokens required: ZERO.** Every color and spacing value reuses an existing
`--` token already referenced by neighboring `.manabase-*` rules, each with the

`site.css` changes. All new CSS lands in `site-common.css`.

(If a future iteration wanted a dedicated verdict accent token, that would cost a
`:root` addition in all 24 theme files + light/dark — explicitly **avoided** here.)
