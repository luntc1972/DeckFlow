  guild themes (admin pages never load site-common.css), so live bleed risk is low — but
  AMOB-04 still requires the scoping as a spec-compliance / future-proofing guard. Treat it as
  mandatory. Acceptance criteria grep for the scoping.

- DECISION D-CACHE (resolves Codex MEDIUM @import cache-busting): switch `_AdminLayout.cshtml`
  from one `<link href="~/css/admin.css">` to TWO tags —
  `<link rel="stylesheet" href="~/css/admin-common.css" asp-append-version="true" />` then
  `<link rel="stylesheet" href="~/css/admin-mobile.css" asp-append-version="true" />` (common
  first so the mobile @media overrides win the cascade). This gives BOTH files independent
  ASP.NET fingerprint query strings, eliminating the stale-import cache risk. The two-`<link>`
  pattern mirrors `_Layout.cshtml` lines 44-47 (site-common.css + site-mobile.css each
  fingerprinted). `admin.css` is STILL reduced to the `@import` shim (Task 3) and retained as a
  documented fallback entry point, but it is no longer referenced by the layout.

- DECISION D-A11Y-HEADER (resolves Codex HIGH #4 card-stack SR behavior): the card-stack
  contract MUST NOT use `thead { display: none; }` because that strips column-header semantics
  from the accessibility tree. Instead, visually hide the header row with the established
  `.sr-only` clip pattern (`position:absolute; width:1px; height:1px; overflow:hidden;
  clip:rect(0 0 0 0); white-space:nowrap;`) applied to `.admin-shell .admin-table--card thead`
  so the `<th scope="col">` cells remain in the a11y tree for screen-reader users. The CSS
  `content: attr(data-label)` per-cell label stays as a VISUAL-ONLY affordance for sighted
  users (it is decorative; SR users get the real `<th>` semantics). Document this in the
  card-stack block comment.

- WCAG WORDING (resolves Codex LOW): the 44px floor is DeckFlow's stricter PRODUCT floor
  aligned with WCAG 2.5.5 Target Size (Enhanced) = Level AAA (44×44 CSS px). It is NOT the AA
  bar — WCAG 2.5.8 Target Size (Minimum) = Level AA is only 24×24 px. State "44px product floor
  (WCAG 2.5.5 AAA)" in any comment referencing the target-size standard; do NOT label 44px as
  the AA minimum.
