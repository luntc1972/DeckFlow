<objective>
Add the read-only `content-kb-check` CLI command that joins `content_site_index` rows to local
`.md` artifact files and reports orphans, exiting 1 when any PUBLISHED orphan exists. Extract the
orphan-detection as a pure, unit-testable helper `ContentKbOrphanScanner` in `DeckFlow.Core` so
the CLI handler stays thin and the classification logic is covered by xUnit (per
65-VALIDATION.md Wave 0). This is the SC3 repeatable check.

Purpose: SC3 ("a post-reconcile check confirms every remaining prod row's artifact expectation
matches reality") needs a repeatable, deterministic tool. The pure scanner makes the severity
gate (published vs hidden orphans) testable without prod or console glue.

Output: `ContentKbOrphanScanner.cs` (+ tests) in Core, `RunContentKbCheckAsync` in the CLI runner,
and the `content-kb-check` command in `Program.cs`.

This plan is independent of the Plan 01 probe results — it can land in Wave 1 in parallel with 65-01.
</objective>
