    Refactor `DeckFlow.Web/wwwroot/ts/df-typeahead.ts` to implement the ARIA combobox pattern per WAI-ARIA 1.2 "combobox with list autocomplete". Make the following additions; do not remove existing public API surface (consumer views in 5 pages call into the existing module entry points — preserve them).

    On the input element (set once at attach-time):
    - `role="combobox"`
    - `aria-autocomplete="list"`
    - `aria-expanded` — initially `"false"`; flip to `"true"` whenever the suggestion panel becomes visible and back to `"false"` whenever it hides
    - `aria-controls` — set to the id of the suggestion panel element. If the panel does not currently have an id, generate one (e.g., `df-typeahead-panel-<unique-counter>`); use the same id on `aria-controls` and on the panel element itself
    - `aria-activedescendant` — initially absent; set to the id of the currently highlighted option element while keyboard navigation is active; remove (or set empty) when no option is highlighted

    On each suggestion element rendered into the panel:
    - `role="option"`
    - A stable, unique id (e.g., `df-typeahead-option-<panel-counter>-<index>`) used by `aria-activedescendant`
    - `aria-selected="true"` on the currently-highlighted option (per CONTEXT.md Claude's Discretion — the ARIA label / aria-selected wiring may use whatever idiomatic combobox pattern fits)

    Keyboard handlers on the input (`keydown` listener):
    - `ArrowDown` — if panel is closed and there are pending suggestions, open it; otherwise move highlight to the next option (wrapping at end is Claude's discretion — pick "no-wrap" to match common combobox UX). Update `aria-activedescendant` on the input and `aria-selected` on the affected options. `event.preventDefault()` to stop caret movement.
    - `ArrowUp` — symmetric to ArrowDown; move highlight to previous option. `event.preventDefault()`.
    - `Enter` — if a suggestion is highlighted, invoke the existing selection callback (do not break the existing public callback API). `event.preventDefault()` to stop form submission. If no suggestion highlighted, allow native form behavior.
    - `Escape` — close the panel, clear `aria-activedescendant`, set `aria-expanded="false"`. If the panel was already closed, allow native Escape behavior. `event.preventDefault()` only when something was actually dismissed.

    Mouse behavior (existing) must remain unchanged: hovering an option highlights it (mirror that to keyboard highlight state for consistency); clicking selects.

    Constraints:
    - Compile clean under `strict: true` (no implicit any, all DOM lookups null-checked, prefer `instanceof HTMLElement` guards over non-null assertions).
    - Do NOT break the existing module API consumed by the 5 typeahead pages — `attachTypeahead` / `createTypeaheadPanel` signatures must remain backwards-compatible. Add new behavior behind the existing entry points; do not require consumer view changes in this sweep.
    - Do NOT add new external dependencies. Pure DOM + TypeScript.
    - Do NOT modify any consumer view (`.cshtml`) — markup-level changes are out of scope for this sweep; the ARIA attributes are applied programmatically by df-typeahead.ts at attach time. If consumer markup is missing a hook the module relies on (e.g., the input has no id), generate one in TS rather than editing Razor.
    - Per CONTEXT.md Claude's Discretion: pick context-appropriate ARIA label text and id naming. No specific copy is mandated.
