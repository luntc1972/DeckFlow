# 70-05 — MQ-05: Color-aware London-mulligan keep heuristic

**Finding:** Audit #5 (Med). Verified in code (`CastabilitySimulator.cs` `LondonMulligan` keeps on
land-COUNT bands only; color access ignored).
**Risk:** Med. **Blast radius:** absolute cast% on multi-color decks (a hand with enough lands but
all of one color is currently kept; it should mulligan). Cast%-affecting → gated + baseline-diffed,
same discipline as MQ-02/MQ-03.

## Problem
`LondonMulligan` (`CastabilitySimulator.cs:918`) accepts/mulligans purely on `CountLands` band
(`lo..hi`) per depth. A 3-color deck that draws 3 lands all producing only White is "kept" exactly
like a 3-land hand that covers WUB. This biases absolute cast% upward and weakens the
"mulligan-aware" framing behind `SimRequiredSources`. Mono-color decks are unaffected by colors.

## Locked decisions
- **Color check is ADDITIVE to the existing land-count band, never replaces it.** A hand is keepable
  iff (land count in band) **AND** (lands' combined colors cover the required threshold). The count
  band, schedule, free-mull, and bottoming logic are untouched.
- **Required color count `C`** = distinct colors that appear in the deck's spell pip demand
  (union over `deck.Spells[*].Pips`, excluding Colorless), capped at 5. Derived once per `Simulate`
  call (cheap), threaded into `LondonMulligan`. (Pip-demand, not color identity, so a splash the deck
  never actually casts off doesn't inflate the keep bar.)
- **Coverage source = LANDS in the opening 7 only** (mirrors the land-count band; ramp must be cast
  first so it is not a turn-1 color source). Union `LibraryCard.ColorMask` over active lands in the
  7-card look. (Ramp-as-color-source is a deliberate later extension, not v1 — keeps the heuristic
  defensible and the diff bounded.)
- **Keep rule (single unambiguous expression — Codex HIGH).** The color gate is one early-out, NOT a
  `min(C,…)` that can leave mono decks at K=1:
  ```
  if (!colorAwareMulligan || forcedKeep || C <= 1) -> NO color gate (count-band only)
  else                                             -> keep iff CountColors(openingLandMask) >= min(C, landsKept, KCap)
  ```
  `KCap = 2` (LOCKED, user 2026-06-23): want ≥2 colors when the deck is 2+ colors; never demand all
  colors of a 3-5c deck in the opener (real play keeps WU in a WUBRG deck). The explicit `C <= 1`
  early-out is what makes mono decks **byte-identical even flag-ON** — do NOT rely on `min(1,…)=1`,
  which would wrongly fail a colorless-land mono opener.
- **Forced-keep depth drops the color gate** (you keep your final hand regardless — matches real
  London: at hand size 5 you take what fixes you have).
- **Cast%-affecting → ship behind a flag, default OFF**, decided after baseline diff. New flag
  `manabase.color-aware-mulligan` (seed FALSE, SQLite + Postgres). Flag-OFF path runs the CURRENT
  count-only `LondonMulligan` verbatim → byte-identical cast% across the suite.
- **MQ-05 does NOT touch color counts / verdict math** (`EffectiveSources`, `SimRequiredSources`,
  `Deficit`, `Health`). It only changes which opening hands the sim keeps → absolute cast% only.

## Side-Effects Report
- **Files (direct):**
  - `DeckFlow.Core/Manabase/CastabilitySimulator.cs` — `LondonMulligan` takes a new
    `int requiredColorCount` + `int colorCapK` (or a single `colorAwareMulligan` bool + derived `C`);
    add `CoversColors(...)` helper unioning land `ColorMask` over the 7-look; gate keep on it when on.
    `Simulate` derives `C` from `deck.Spells` pips and threads a `bool colorAwareMulligan` param
    (default false → off path).
  - `DeckFlow.Core/Manabase/ManabaseAnalyzer.cs` — thread `bool colorAwareMulligan = false` through
    `Analyze` → `BuildCastability` → `Simulate` (same pattern as `useManaQuantity`).
  - `DeckFlow.Web/Services/Manabase/ManabaseAnalysisService.cs` — read `manabase.color-aware-mulligan`
    via `IsFlagOn` (fail-safe OFF), pass into `ManabaseAnalyzer.Analyze`.
  - `DeckFlow.Web/Services/FeatureFlags/FeatureFlagStore.cs` — seed `manabase.color-aware-mulligan`
    FALSE (Postgres + SQLite).
- **No Core model change** (no new field; `ColorMask` already on `LibraryCard`, `Pips` already on
  `SpellRequirement`).
- **Other callers:** `Analyze`/`Simulate` overloads keep `colorAwareMulligan = false` default →
  CLI / tests / probe path byte-identical.
- **Shared state / external:** none. **Contract:** report shape unchanged; only cast% values move,
  flag-on only. **Interaction with MQ-02/03:** independent flags, all read in the service; orthogonal
  (MQ-02 affordability, MQ-03 land target, MQ-05 mulligan keep) — test combinations don't interfere.
- **Backward-compat:** flag-OFF must reproduce today's cast% exactly; mono-color decks identical even
  flag-ON.

## Steps
1. **Color-coverage helper.** `CountColors(mask)` (popcount over the 5 color bits) +
   `OpeningLandColorMask(library, active, shuffled, top=7)` unioning `ColorMask` of active lands.
2. **Color-aware keep gate in `LondonMulligan`.** Apply the single keep rule from "Locked decisions":
   gate only when `colorAwareMulligan && !forcedKeep && C > 1`; then keep iff `(lands in band)` AND
   `CountColors(openingLandMask) >= min(C, lands, KCap)`. Off path / forced-keep / `C<=1` skip the
   gate (byte-identical). NOTE: `SimRequiredSources`' direct probe call at `ManabaseAnalyzer.cs:613`
   passes `Simulate(..., colorAwareMulligan: false)` by default — leave it on the default so the
   verdict probe path is never color-gated (Codex MED).
3. **Derive `C` + thread params.** `Simulate` computes `C` from `deck.Spells` pips once; thread
   `colorAwareMulligan` through `Analyze`/`BuildCastability`/`Simulate` (default false).
4. **Wire the flag** in the service (read once via `IsFlagOn`, fail-safe off); seed
   `manabase.color-aware-mulligan` FALSE in both DB dialects.
5. **Baseline diff** (extend the harness): a 3-color deck, a 5-color deck, a 2-color deck, and a
   mono deck — cast% + verdict OFF vs ON. Confirm mono unchanged. Decide flag default.

- `MonoColorDeck_Identical_EvenWhenOn` — `C<=1` ⇒ flag-on equals flag-off.

## Resolved decision
**`KCap = 2`** (user, 2026-06-23). Opener lands must show ≥2 distinct colors when the deck is 2+
colors (threshold also clamped by lands held and deck color count `C`); rejected the strict `KCap=C`
(over-mulligans high-color decks) and the weak `KCap=1` (near no-op).
