<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| YouTube transcript → distill LLM | Untrusted third-party transcript text is sent to the LLM; a prompt-injected transcript could try to make the model echo local files or off-topic content |
| Operator → production | DirectPush writes to the Render Postgres + `/data` over SSH; only the operator holds prod secrets |
| AI → production | Hard invariant: the AI never writes to prod and only runs SELECT-only local reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58-03 | Tampering | prompt-injection via untrusted transcript | mitigate | Distill runs the Phase-57 prompt unchanged (no provider/tool swap); the distill slice has no file/tool access for the transcript to exploit, and the operator inspects every distilled entry (SC1) before approving — an injected/off-topic result fails the quality verdict and is not published. |
| T-58-04 | Denial of service | uncapped real-money LLM spend | mitigate | `llm_spend_ledger` enforces `DECKFLOW_LLM_MONTHLY_CAP_USD` (default $15); Task 1 confirms the cap before spending and records cap-vs-actual; the run is a single video. |
| T-58-05 | Elevation / Tampering | AI writing to production | mitigate | All publish/prod-write steps are operator-only `checkpoint:human-action`; the AI may run ONLY SELECT-only reads against the LOCAL Studio DB, never a prod-write connection (project rule). |
| T-58-06 | Information disclosure | prod secrets (Studio:ProdConnectionString, SCP key) | mitigate | DirectPush secrets stay operator-side (user-secrets / env); the evidence doc records only status strings/SHAs/spend numbers, never connection strings or keys. |
</threat_model>
