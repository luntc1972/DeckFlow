<objective>
Make DirectPush re-export `index-seed.json` through the SAME shared factory Publish uses (SYNC-08 / D-08), and, when `sync.directpush-gitbody` is ON, drop the `[skip render]` phrase from the DirectPush durability commit so Render actually redeploys the body to `/app` (D-09) — the deploy the Plan 90-05 confirm step verifies. Add a minimal read-only Studio accessor (D-04) so DirectPush can read the authoritative web-DB flag from the prod feature_flags table.

Purpose: Today DirectPush's commit stages bodies ONLY (never the seed) and always carries `[skip render]` — so a reseed reverts DirectPush'd rows (C3) and no redeploy ever happens. This plan closes the seed gap via the shared `ContentIndexExportRow.From()` path (no forked writer) and enables a real deploy under the flag, without changing flag-OFF behavior.
Output: `ReadFlagAsync` on the existing read-only prod reader, DirectPush seed re-export + staging, flag-gated skip-render drop, and coordinator/reader unit tests.
</objective>
