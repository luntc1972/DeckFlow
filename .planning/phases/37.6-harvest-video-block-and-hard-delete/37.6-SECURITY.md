## T-376-01 — SQL parameter binding (mitigate)

Every SQL statement in the new/changed code binds via `AddParameter`; no operator input is interpolated:

- `BlockedVideoStore.cs` — Add `@youtubeVideoId`/`@reason` (`:72-73`), Remove `@youtubeVideoId` (`:90`), IsBlocked `@youtubeVideoId` (`:108`); INSERT uses `ON CONFLICT DO NOTHING` (PG) / `INSERT OR IGNORE` (SQLite) raw-string constants (`:165-202`). List has no params and no input.
- `ContentVideoStore.DeleteVideoByYoutubeIdAsync` — `DELETE ... WHERE youtube_video_id = @youtubeVideoId` with `AddParameter` (`:303-316`).
- `ContentSiteIndexStore.DeleteByIdAsync` — `DELETE ... WHERE id = @id` with `AddParameter` (`:310-323`).
- `CommandRunners.cs` block/unblock/list runners — no inline SQL; all DB access via store methods.

Input validation (`ArgumentException.ThrowIfNullOrWhiteSpace`) present at every store + runner entry point:
- Store: `BlockedVideoStore.cs:65, 80, 97`; `ContentVideoStore.cs:305`.
- Runner: `CommandRunners.cs:616` (block), `:647` (unblock).

Sole interpolation in the touched file — `ContentSiteIndexStore.cs:396` `$"PRAGMA table_info({tableName})"` — is NOT a finding: `tableName` is a hard-coded internal literal (`"content_site_index"`, `:56`), no operator input reaches it, and it pre-dates this phase (lives in `GetTableColumnsAsync`, not the new `DeleteByIdAsync`). PG branch of the same method parameterizes `@tableName` (`:417`).

## T-376-02 — Irreversible hard-delete (accept-with-mitigation)

Mitigation present and ordered correctly in `CommandRunners.RunBlockVideoAsync` (`:607-639`):
1. `AddBlockAsync` (block row) — `:624`, with `// Why:` note (`:622-623`) — FIRST.
2. `DeleteVideoByYoutubeIdAsync` (content-kb, all-source, FK-cascade) — `:625`.
3. `GetByNaturalKeyAsync` + `DeleteByIdAsync` (site-index) — `:626-630`.

A partial failure after step 1 leaves the video blocked-but-present (never deleted-but-reharvestable). Unblock (`RunUnblockVideoAsync`, `:641-660`) calls only `RemoveBlockAsync` — no `DeleteVideoByYoutubeIdAsync`, no site-index delete, no restore (D2 confirmed). Operator-only local invocation; explicit id required.

**Accepted residual risk:** content_videos child rows (transcripts/summaries/clips/tags/distill_status via FK cascade) and the site-index row are permanently destroyed; `unblock-video` does not resurrect them. Re-harvest must re-ingest. Accepted per plan disposition (operator-only local CLI op).

## T-376-03 — reason free-text (accept)

**Accepted risk (logged):** the operator-supplied `reason` free-text is stored verbatim in the local `blocked_videos.reason` column (`BlockedVideoStore.cs:73`). It is bound as a parameter only and never emitted to any external sink (no log line, console, telemetry, or upload path includes the block `reason` — the only `reason=` log at `CommandRunners.cs:1507` is the unrelated distill-abort reason). The local content-kb.db is never uploaded to Render. No secrets expected in operator notes. Accepted.
