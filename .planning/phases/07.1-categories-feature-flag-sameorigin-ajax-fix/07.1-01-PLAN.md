<objective>
Add a default-on `feature.categories.enabled` flag (CATFLAG-01), gate the two visible surfaces — `_DeckToolTabs.cshtml` Categories dropdown entry and `Home.cshtml` Categories hub-card (CATFLAG-02) — and the page route itself via the existing Phase 6 `[FeatureFlagGate]` attribute (CATFLAG-03). All three surfaces consult the SAME flag key. Toggling OFF in `/Admin/Flags` simultaneously hides the nav and landing entries AND makes `GET /suggest-categories` return 503 + maintenance copy.

Purpose: The Categories AJAX flow is currently broken (separate plan 02 fixes the regression). Until the fix lands and is verified live, prod operators need a one-click way to hide the entire Categories surface from users. This plan ships the kill-switch using the canonical Phase 6 pattern — zero new infrastructure, just one seed-row addition, two view conditionals, and one attribute on the controller action. Per FLAG-01 / Phase 6 plan 02 lesson: the seed lives at the schema layer (`ON CONFLICT (key) DO NOTHING`) so the flag survives both fresh DB bootstrap AND re-bootstrap of an already-toggled prod DB.

Output: Operator visits `/Admin/Flags`, clicks **Disable** on the `feature.categories.enabled` row. Within ~30s (or one round-trip via D-10 sync ReloadAsync from the admin write path), the AI Category Suggestions entry disappears from the Categories dropdown on every page that renders `_DeckToolTabs`, the Categories hub-card on `/` no longer renders the AI Category Suggestions tile, and a direct GET to `/suggest-categories` returns 503 + maintenance page. Re-enabling restores all three surfaces on the next IFeatureFlagCache snapshot.
</objective>
