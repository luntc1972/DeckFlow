## Implementation Decisions

### P01-a FeedbackStoreTests SQLite file-lock race

- **D-01:** Fix root cause via `SqliteConnection.ClearAllPools(); GC.Collect(); GC.WaitForPendingFinalizers();` before `File.Delete(_dbPath)` in `FeedbackStoreTests.Dispose()`. Rationale: Microsoft.Data.Sqlite enables connection pooling by default; the per-test `await using` disposal releases the connection logically but the pool retains the OS file handle. The canonical .NET pattern is `ClearAllPools`. 3-line change, no `[Collection]` serialization overhead, no Polly retry on `File.Delete`, no leaked `%TEMP%` files.
- **D-02:** Test name stays `Dispose`; no method rename. Only the body changes.
- **D-03:** Apply identically to `CategoryKnowledgeStoreTests` and any other test class with the same `IDisposable` + `File.Delete` SQLite pattern. Sweep with `grep -rn "File.Delete(_dbPath)" DeckFlow.Web.Tests/` before commit.

### P01-b ScryfallThrottleTests 429-no-Retry-After

- **D-04:** Test is stale, not production behavior. `ScryfallThrottle.cs:117-122` deliberately retries 429-without-Retry-After using `FallbackRetryDelay` for Cloudflare BIC/burst recovery (intentional, comment-documented). Production retry-loop runs `MaxRetryAttempts` (= 2) → total calls 3.
- **D-05:** Rename both test methods (`ExecuteAsync_NonGeneric_DoesNotRetryFor429WithoutRetryAfter` and `ExecuteAsync_Generic_DoesNotRetryFor429WithoutRetryAfter`) to `ExecuteAsync_<NonGeneric|Generic>_RetriesFor429WithFallbackDelay_WhenRetryAfterMissing`. Update assertions to `Assert.Equal(MaxRetryAttempts + 1, calls)` (= 3). Other 429 facts (`AboveRetryAfterCap`, `WithZeroRetryAfter`, `Returns200ResponseAsIs`) stay byte-identical — their contracts are still valid.
- **D-06:** Use the literal `ScryfallThrottle.MaxRetryAttempts` constant reference if visible to tests via `[InternalsVisibleTo]`, otherwise hardcode `3` and add a one-line comment cross-referencing `ScryfallThrottle.cs:30`.

### P01-d DeckComparisonServiceTests:286 CRLF assertion
