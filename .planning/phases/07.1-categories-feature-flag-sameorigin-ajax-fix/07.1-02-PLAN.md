<objective>
Diagnose and fix the regression where the Categories AJAX endpoint (`POST /api/suggestions/card`) returns "This endpoint only accepts same-origin browser requests." for a legitimate same-origin browser request from `https://www.deckflow.gg/suggest-categories`. Root cause is unknown at planning time — leading hypotheses (per STATE.md line 97):

1. **Scheme mismatch behind Render reverse proxy** — `request.Scheme` may be `http` if forwarded headers don't fully populate, while the browser's Origin header is `https://www.deckflow.gg`. `UriMatchesRequestOrigin` (validator line 75) compares schemes case-insensitively but exactly — `https != http` → reject.
2. **Host header mismatch** — `www.deckflow.gg` vs `deckflow.gg` (one redirects to the other; Origin header may carry the canonical, request.Host the post-redirect).
3. **Port mismatch** — IsDefaultPort calculation discrepancy if forwarded `X-Forwarded-Port` differs.
4. **Origin truly absent + Referer absent** — should pass (line 32 fallthrough), so this is unlikely to be the cause given the failure message text.
5. **Browser sends Origin: null** — happens for opaque origins (sandboxed iframe, file://); `Uri.TryCreate("null", UriKind.Absolute, ...)` returns false, validator falls through to Referer; if both Referer and Origin are bad strings, falls through to true. So this would NOT cause the failure either.
6. **Some new middleware or proxy hop in Render's stack changed Host:Port composition** — must be confirmed by logged values, not assumed.

Purpose: **The diagnostic phase is part of this plan, not a prerequisite.** This plan ships in two atomic tasks:
- **Task 1 (diagnostic + checkpoint):** Add temporary structured logging at SameOriginRequestValidator.IsValid → ship to deploy → operator triggers a real failing /api/suggestions/card request from the live site → operator captures logged Origin / Referer / X-Forwarded-Proto / X-Forwarded-Host / X-Forwarded-Port / request.Scheme / request.Host values → returns to plan with the captured evidence.
- **Task 2 (fix):** Based on the operator-confirmed root cause, modify the validator's matching logic (not middleware ordering) to accept the legitimate same-origin pattern observed in production. Remove the diagnostic logging. Verify cross-origin requests still fail.

Output: Operator clicks "Suggest categories" on `/suggest-categories` (with the flag from Plan 01 ON), the AJAX request completes normally (200 response or a domain-level 4xx like 400/408 for bad input), the SameOrigin 403 message is gone. Cross-origin attempts (manually crafted with `Origin: https://evil.example.com`) still return 403. CAT-FIX-01 closed.
</objective>

From DeckFlow.Web/Security/SameOriginRequestValidator.cs (current state, full file):
```csharp
public static class SameOriginRequestValidator
{
    private const string ForbiddenMessage = "This endpoint only accepts same-origin browser requests.";

    public static bool IsValid(HttpRequest request)
    {
        ArgumentNullException.ThrowIfNull(request);

        if (TryParseOrigin(request.Headers.Origin, out var origin))
        {
            return UriMatchesRequestOrigin(origin, request);
        }

        if (TryParseOrigin(request.Headers.Referer, out var referer))
        {
            return UriMatchesRequestOrigin(referer, request);
        }

        // Allow non-browser callers and same-origin requests where the browser omitted both headers.
        return true;
    }

    public static string GetForbiddenMessage() => ForbiddenMessage;

    private static bool TryParseOrigin(string? headerValue, out Uri uri) { ... }
    private static bool UriMatchesRequestOrigin(Uri origin, HttpRequest request)
    {
        var requestHost = request.Host.Host ?? string.Empty;
        var requestPort = request.Host.Port
            ?? (string.Equals(request.Scheme, "https", StringComparison.OrdinalIgnoreCase) ? 443 : 80);
        var originPort = origin.IsDefaultPort
            ? (string.Equals(origin.Scheme, "https", StringComparison.OrdinalIgnoreCase) ? 443 : 80)
            : origin.Port;

        return string.Equals(origin.Scheme, request.Scheme, StringComparison.OrdinalIgnoreCase)
            && string.Equals(origin.Host, requestHost, StringComparison.OrdinalIgnoreCase)
            && originPort == requestPort;
    }
}
```
