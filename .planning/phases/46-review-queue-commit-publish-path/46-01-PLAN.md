<objective>
Add the only new Core data surface this phase needs: an approval-status mutation method on
`IContentSiteIndexStore` — a single-row overload and a batch overload, both keyed by **natural key**
(`(naturalKeyType, naturalKeyValue)`), constrained to `pending` / `approved` / `rejected`. This is
the write side that the Review queue UI (Plan 03) calls on every approve/reject click (D-05, D-06).

and the grandfather backfill. The queue cannot mutate approval state today — no setter exists. This
plan closes that gap and nothing more.

Output: Two interface declarations, two implementations mirroring `SetVisibilityAsync`/`SetEvergreenAsync`
(the batch overload wrapped in a single atomic transaction per D-06), and real-SQLite tests proving
single, atomic batch, validation, and admin-field preservation.
