<design_notes>
## Deliberate Design Trade-offs

### D-11 reuses existing wrong-shape strings — NO new `internal const`

`DeckComparisonService` already throws `"The submitted AI response did not contain a valid deck_comparison payload."` on wrong-shape inputs (line 942). The new semantic-empty branch ORs into the same `if (result is null)` guard and reuses the same message. Same shape for `MetaGapService` (`"...valid meta_gap payload."` at line 970).

Rationale: 999.4 introduced `internal const string TruncatedResponseMessage` because the truncation copy was new and shared across 4 parse sites. The semantic-empty copy is NOT new — the existing wrong-shape message correctly describes both failures from the user's perspective ("the payload was valid JSON but the parser could not recognize it as a usable response"). Promoting to a const for 2 sites is over-engineering. If a third or fourth service ever needs the same guard, promote then and refactor 999.5's 2 services onto the const.

### D-12 fact scope is 1 sync fact per service, NOT a theory

Two single-message facts (one per service) keep the test surface minimal and read parallel to 999.4 D-04's `TruncatedInput_ThrowsLockedMessage` style. A `[Theory]` with multiple semantic-empty fixtures would test the helper's coverage of every field in the OR-chain — that is field-by-field unit-testing the helper, not the guard. The guard contract is "semantically-empty input throws" — one canonical fixture (the 999.4 D-07 example) is sufficient.

### D-09/D-10 inline helper OR helper-method — Claude's Discretion

CONTEXT.md §Claude's Discretion allows: "Whether to extract a shared `HasMeaningfulMetaGapData` private helper or inline the OR-chain (judgment call based on resulting line count and readability — match the surrounding-file style)."

Default recommendation: extract a `private static bool HasMeaningful*Content(...)` helper at the bottom of the file, matching the `ResponseParsers.cs:124-136` pattern. The OR-chain is 12+ clauses; inlining inside the guard would be unreadable. The helper costs one method header but reads identical to the canonical pattern, which is the whole point of the mirror.

### Cross-class const reference NOT introduced

Unlike 999.4 (where `ResponseParsers.TruncatedResponseMessage` was cross-referenced from `DeckComparisonService` and `MetaGapService`), this plan introduces zero cross-class references. Each service's helper lives in the service's own file; each service reuses ITS OWN existing wrong-shape thrown string. This keeps the diff per file minimal and avoids namespace coupling.
</design_notes>
