**Architectural pivot from iter 1 (Codex reviews H1-H4):** The iter-1 design used a `public static string ComputeCacheKey(request, normalizedDeckSource, commander)` helper that required the CONTROLLER to supply pre-normalized deck text and pre-extracted commander name. Codex review correctly identified this CANNOT WORK for DeckAnalysisRequest (no `CommanderName` property exists) and DOES NOT enforce parity in the general case (D-02 normalization depends on which importer ran).

The iter-2 fix moved cache-key composition to a per-service async instance helper. Codex pass-2 then identified a remaining parity gap (H1 UNRESOLVED): the iter-2 plan's helper logic did not exactly match `DeckAnalysisPacketService.BuildAsync` — BuildAsync uses `Take(2)` partner inference + third-entry alphabetical guard at lines 226-253, may call `ValidateCommanderAsync` (Scryfall round-trip at line 283), and may oracle-normalize the commander at line 435. The iter-2 helper used `Take(1)` and tolerated the divergence.

The pass-3 fix introduced a shared `BuildDeckAnalysisCacheInputs` field-bag helper called from BOTH read and write paths, with a "capture pre-Scryfall commander into a local around line 271" technique. Codex pass-3 rejected this fix: while the field-bag composer was shared, the inline inference block in `TryComputeCacheKeyAsync` only assigned `commanderName` and did NOT perform the reflag mutation at lines 257-267 (the block that sets `Board='commander'` on inferred commander entries in BOTH `entries` AND `deckEntries`). Because `BuildCanonicalDeckSourceText` sorts by Board first, the same logical Moxfield deck without an explicit commander section produced different canonical text bytes (different SHA-256) in the read vs write paths — silent cache miss for inferred-commander decks.

**Pass-4 fix (this revision):** Extract the ENTIRE pre-Scryfall commander resolution + reflag block at `DeckAnalysisPacketService.cs:226-271` into ONE NEW shared private static helper `ResolvePreScryfallCommanderState(List<DeckEntry> entries)` returning a 4-tuple `(List<DeckEntry> Entries, List<DeckEntry> DeckEntries, string? CommanderName, bool InferredCommanderFromMoxfieldOrdering)`. This helper mirrors BuildAsync EXACTLY, including the reflag mutation that sets `Board='commander'` on inferred commander entries in BOTH the `entries` collection AND the `deckEntries` collection. Both `BuildAsync` (write) AND `TryComputeCacheKeyAsync` (read) call this helper FIRST, before any subsequent processing, so the reflag mutation is applied identically in both paths BEFORE `BuildCanonicalDeckSourceText` (called by `BuildDeckAnalysisCacheInputs`) sees the entries. Same logical input → same Board values → same sort order → same SHA-256 → cache HIT.

**Two-helper design (signature reconciliation per Codex pass-3 LOW):**
- `ResolvePreScryfallCommanderState(entries) → (Entries, DeckEntries, CommanderName, InferredCommanderFromMoxfieldOrdering)` — 4-tuple-returning, owns the inference + reflag logic.
- `BuildDeckAnalysisCacheInputs(request, entries, commanderName) → DeckAnalysisCacheInputs` — field-bag composer (unchanged from pass-3).

Two helpers, distinct responsibilities. Both write and read paths call `ResolvePreScryfallCommanderState` FIRST, then call `BuildDeckAnalysisCacheInputs` SECOND with the helper's returned `Entries` and `CommanderName`. The must-have section and task instructions now agree on both signatures.

This is the explicit single-stage decision: **cache key uses commander as extracted from the parsed deck entries BEFORE ValidateCommanderAsync / oracle-normalization, WITH the inferred-commander reflag mutation applied to both `entries` and `deckEntries`.** Both read and write paths call the same `ResolvePreScryfallCommanderState` helper followed by the same `BuildDeckAnalysisCacheInputs` helper. Key parity is enforced by code locality — there is only ONE place the pre-Scryfall commander state is computed and ONE place the field bag is composed.
