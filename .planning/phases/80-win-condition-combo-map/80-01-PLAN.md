<objective>
Add the pure-Core win-condition / combo map that Phase 80 surfaces: enumerate a deck's Commander
Spellbook combos (ranked, banded) and one-card-away near-combos (strictly separate), count assembly
paths, distinguish "combo data unavailable" from "ran, found none", and list non-combo closing-power
cards so a combo-less deck still gets a win-condition read. All of this is a pure CPU transform over
already-fetched combo data + already-resolved card text, so it lives in `DeckFlow.Core` where it is
unit- and golden-testable without the web host.

Purpose: WINCON-01 needs the enumerated combo + near-combo map and an assembly-path count; WINCON-02
needs the coarse assembly band (from `ManaValueNeeded`) AND the low-MV/high-popularity ranking; WINCON-03
needs the data-unavailable sentinel + the closing-power card list. Commander Spellbook types are a
`DeckFlow.Web` concern — Core takes plain input DTOs and the Web layer (Plan 80-02) maps
`CommanderSpellbookResult` onto them, so Core stays free of any Web reference.
Output: one model file (records + `WinConBand` enum + input DTOs), one aggregator, and Core golden tests
(all GREEN on CI).
</objective>
