*decline* — not necessarily a code change.

The asymmetry: `ScryfallReferenceResolver.ResolveBatchAsync` matches collection hits by comparing the
ORIGINAL request name to the RETURNED `card.Name` with raw `OrdinalIgnoreCase`
(`ScryfallReferenceResolver.cs:136`), while `ScryfallCardResolver.ResolveSingleAsync` matches with
`CardNormalizer.Normalize` on both sides (`ScryfallCardResolver.cs:117-118`). The batch matcher is
strictly stricter, so it manufactures phantom misses that the fallback then successfully resolves —
which is why fallback volume was high AND why the fallbacks mostly succeeded. That behavior is
marked LOAD-BEARING / "do not fix" at `ScryfallReferenceResolver.cs:52-61` and is shared by five
services, with a deliberately-locked regression test (`ScryfallReferenceResolverTests.cs:27-52`).

Purpose: this is exactly the kind of decision that must be written down rather than made silently by
whoever next reads the code. It is also the one place where the phase can legitimately conclude
"we deliberately did not fix this."

Output: one logged live-API probe, one ADR, one corrected xmldoc.

```csharp

var matchingName = chunk.FirstOrDefault(name => string.Equals(name, card.Name, StringComparison.OrdinalIgnoreCase));
```

The "do not fix" guard, `ScryfallReferenceResolver.cs:52-61` (excerpt):
> LOAD-BEARING behaviors preserved from the three current implementations (do not "fix"): ...
> Collection hits are matched back by comparing the ORIGINAL request name to the RETURNED card's
> `Name` (Ordinal-IgnoreCase). When `normalizeForScryfall`-equivalent normalization is ON, it affects
> ONLY the submitted identifier -- never the match key -- so a single-slash Archidekt name (`"A / B"`)
> that normalizes to `"A // B"` on submission and gets returned as `"A // B"` will NOT match its
> original `"A / B"` request and falls through to the fallback strategy, exactly as today.

The contradicting xmldoc, `ScryfallCardResolver.cs:222-228`:
```csharp
/// <summary>
/// Normalizes a card name for use in Scryfall API payloads.
/// Converts the single-slash DFC separator used by Archidekt exports (" / ")
/// to the double-slash form Scryfall expects (" // ") so DFC cards resolve on
/// the first /cards/collection attempt instead of cascading into per-card fallbacks.
/// DeckEntry.Name is NOT modified — normalization happens only at the call site.
/// </summary>
public static string NormalizeForScryfall(string cardName)
```
The clause "so DFC cards resolve on the first /cards/collection attempt instead of cascading into
per-card fallbacks" is the false half: for the `ResolveBatchAsync` path, normalization changes what
is SUBMITTED but never the match key, so the phantom miss survives and the card still cascades to
the fallback. `ResolveBatchAsync`'s own param doc ("Never affects the match key") is the accurate one.

The already-deserialized escape hatch nobody in these two classes reads
(`ScryfallDtos.cs:32-34`):
```csharp
ScryfallCollectionResponse(List<ScryfallCard> Data, [property: JsonPropertyName("not_found")] List<ScryfallCollectionIdentifier>? NotFound)
```
In-repo precedent for consuming it, `CardLookupService.cs:139-145`:
```csharp
foreach (var identifier in response.Data.NotFound ?? [])
{
    if (!string.IsNullOrWhiteSpace(identifier.Name)) { missingNames.Add(NormalizeName(identifier.Name)); }
}
```

The competing option's hidden cost, `DeckFlow.Core/Normalization/CardNormalizer.cs:24-28`:
`CardNormalizer.Normalize` DROPS the DFC back face. Two different DFCs sharing a front face would
collide under a Normalize-based match key. This is a real argument against option (c) below.

The locked test that any adopted change would have to rewrite,
`ScryfallReferenceResolverTests.cs:27-52`:
`ResolveBatchAsync_SingleSlashNameWithNormalizeOn_FallsThroughToFallbackKeyedByOriginalName` — its
fixture supplies `NotFound: []` and returns a card named `"A // B"` for request `"A / B"`. A
not_found-driven matcher would treat that as a HIT, not a fallback, so this test asserts the opposite
of option (b) and would need its fixture changed to actually populate `NotFound`.

The five services sharing `ResolveBatchAsync`: `DeckComparisonService.cs:378`, `MetaGapService.cs:564`,
`DeckAnalysisPacketService.cs:1895`, `DeckHistoryPageService.cs:271`, and (post-plan-01)
`CutLabAnalysisContextBuilder.cs:410`.
