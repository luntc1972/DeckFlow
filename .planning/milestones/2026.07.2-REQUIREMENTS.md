### THEME — `--accent-strong` Semantic-Token Migration

`--accent-strong` (143 refs across 27 theme files) is overloaded across link, brand, focus, error, and CTA roles; semantic tokens (`--link`/`--danger`/`--focus`/`--cta-border`) exist but the migration was never finished. Error text reads as a link in red guild themes.

- [x] **THEME-01**: Every `--accent-strong` usage is reclassified onto the correct semantic token (`--link` / `--danger` / `--focus` / `--cta-border`) by role across all 27 theme files; token additions live in each theme's `:root` and layout stays in `site-common.css`.
- [x] **THEME-02**: Error/danger text no longer resolves to the link color in red guild themes; the fix is visually verified across affected themes at desktop and mobile viewports.
- [x] **THEME-03**: No unintended visual regression on non-error surfaces — the theme render diff is limited to the intended semantic corrections.

### CREATOR — Creator-Source Model Hardening

The Studio content-KB tracks a creator in two unlinked local-DB tables: `creator_sources` (operator-curated list, no slug) and `content_sources` (KB source with slug/url/enabled, minted lazily at harvest). They can drift — a `/creators` add produces no KB source and no slug, remove orphans the KB row and on-disk artifacts, and the slug is invisible until harvest. Studio-local `content-kb.db` only — no prod DB, no web UI, so paste artifacts and theme render are untouched (cross-cutting gate trivially held). Plan v3 converged through 4 Codex plan-review rounds ("no HIGH — proceed").

- [x] **CREATOR-01**: Adding a creator and harvesting it links `creator_sources`↔`content_sources` by a persisted `content_source_id`, set via a single idempotent update keyed by the creator row id; creator provenance is carried on the browsed videos and stamped only when the browse target still matches the selected creator (edit-after-select cannot mislink one creator to another channel).
- [x] **CREATOR-02**: An existing-but-disabled same-URL content source is correctly detected and re-enabled on BOTH the `AddSourceAsync` unique-violation path and `EnsureYoutubeSourceAsync` (enabled-agnostic lookup), returning the persisted canonical slug rather than the display-derived one.
- [x] **CREATOR-03**: The `/creators` page surfaces each creator's slug and an existence-aware link status; removing a creator disables its linked content source (never deletes KB data, guarded against disabling a source a sibling alias still uses) and notes any remaining on-disk artifacts.
- [x] **CREATOR-04**: `creator_sources` migrates additively and idempotently (`source_slug` + `content_source_id`); an existing `content-kb.db` upgrades cleanly; `DeckFlow.Core.Tests` + `DeckFlow.Studio.Tests` (including the four provenance/dedupe failure-mode cases) pass and the build stays clean.
