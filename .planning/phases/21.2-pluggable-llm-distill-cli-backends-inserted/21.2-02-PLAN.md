## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env (`DECKFLOW_LLM_PROVIDER`, `DECKFLOW_LLM_CLI_COMMAND`) → CLI runner | Operator-controlled provider selection + command override |
| transcript text → CLI subprocess (via stdin) | Untrusted YouTube/podcast transcript content fed to the LLM CLI |
| CLI output → ledger/run record | Subscription backend reports no per-token cost; run record must not be poisoned with bogus spend |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21.2-05 | Tampering | `DECKFLOW_LLM_CLI_COMMAND` → process FileName/Arguments | mitigate | Command/args come ONLY from the operator's own env or per-provider const defaults (set in Plan 01's `ResolveCommand`); transcript content is never concatenated into the command. `UseShellExecute=false` — no shell interpolation. The override is a trusted local operator boundary, documented in the ops doc with a safe-construction note. |
| T-21.2-06 | Repudiation / Integrity | spend ledger + run record under subscription | mitigate | Ledger cap-gate bypassed only when provider != openai; `RecordCallAsync` still writes a row (cost 0) so the run is auditable (whisper_calls = LLM call-count, spend_usd = 0 in `content_harvest_runs`). openai path is unchanged → no integrity regression for the metered backend. |
| T-21.2-07 | Denial of Service | hung/slow CLI subprocess during a real run | mitigate | The distill run threads a CancellationToken; the per-call CLI process (Plan 01) uses stdin-close + concurrent stdout/stderr reads to avoid pipe-buffer deadlock; a persistent failure marks the video `failed` (non-terminal) rather than hanging the run. |
