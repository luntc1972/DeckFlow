## Reuse justification — why a new script rather than `edhrec-download`

The project's standing rule is to explore the architecture for reuse before building. The candidates
were examined and rejected for a stated reason, so the choice is on the record rather than implicit:

| Existing tool | What it does | Why it does not fit |
|---|---|---|
| `DeckFlow.CLI/EdhrecDataDownloadCommandRunner.cs` (`edhrec-download`) | Downloads and unpacks EDHREC's **bulk tarball archives** (`data.tgz`, `averages.tgz`) into `artifacts/edhrec/`. | Different job entirely. It fetches **two** large archive files over HTTP and untars them. This fetcher pages **1,525 individual per-cell JSON documents** off `json.edhrec.com/pages/average-decks/<slug>/<bracket>.json`, with per-cell resumability, slug resolution and throttling. There is no shared mechanism to extend — a tarball downloader and a paginated per-cell crawler have nothing in common but the hostname. |
| `DeckFlow.CLI/EdhrecAveragesCommandRunner.cs` + `DeckFlow.Core/Manabase/EdhrecAveragesConverter.cs` | Converts `averages.csv` into a `ManabaseBaselineSnapshot`. | Consumes the bulk archive, does not fetch anything. It IS reused here, but as an **input dependency**: this fetcher reads the same `averages.csv` to select commanders. |
| `DeckFlow.Core/Integration/EdhrecCardLookup.cs` | Card-level EDHREC lookup. | Card scope, not commander x bracket scope. |
| `scripts/cedh-baseline/fetch.py` | The stdlib-only, resumable, `--outdir`-taking precedent this script's SHAPE was copied from. | Reused as the pattern, exactly as intended. Its EDHTop16-specific logic is not applicable. |

So: `averages.csv` and its converter are reused; the crawl itself is new because no existing tool
crawls. The bulk archives it depends on are documented in the next section.

## Design Decisions

### D-01 — stdlib-only Python, mirroring `scripts/cedh-baseline/fetch.py`

Held as shipped. `urllib.request`, `json`, `time`, `argparse`, `pathlib`, `re`, `csv` and `sys` cover
everything needed. No `requests`, no `requirements.txt`, no virtualenv. CLAUDE.md forbids new
dependencies without explicit approval.

### D-02 — one file per cell, plus a manifest

Held as shipped, and vindicated: `cells/<slug>__<bracket>.json` per cell plus `manifest.json`. A cell
already on disk is skipped, so an interrupted run resumes for free. The recorded run needed no resume
(`cells_skipped_existing: 0`) but the property is what makes a re-run safe — which is not a licence
to perform one.

### D-03 — record the yield, do not filter the corpus

**Changed from the original plan, and the change matters.** The original design had the fetcher write
a `qualifies` boolean per cell against a `--min-decks 400` cell floor. The shipped fetcher does not:
it records each cell's real `n_decks` and makes no judgement.

That is the better split, and it is now the contract: **the fetcher reports, the ingestion judges.**
Every cell — including the 720 that fall below 400 — is on disk with its real deck count, so
qualification can be recomputed at any threshold without re-fetching, and coverage stays reportable
as *fetched versus qualifying* (ROADMAP criterion 8). Plan `02-06` derives `Qualifies` from
`n_decks >= 400`.

### D-04 — the decklist is stored raw; parsing moves to C#

**Changed from the original plan.** The original had Python emit pre-parsed `{quantity, name}`
objects. The shipped fetcher stores EDHREC's `deck` array verbatim as `"<qty> <Card Name>"` strings.

Consequence, binding on plan `02-06`: the quantity-prefix parse happens in `EdhrecCellReader`, not in
Python. Plan `02-06`'s scope and tests must cover it, including a malformed-entry path. This is
recorded here rather than left for `02-06` to discover.

### D-05 — the commander list is derived, not curated

**Changed from the original plan.** The original had a committed `commanders.txt`. The shipped
fetcher instead selects every solo commander in `averages.csv` whose `number_decks` clears
`--min-decks` (8,000), which at the recorded run yielded 305 commanders and resolved every slug with
zero failures.

This is strictly better: the sweep is reproducible from a licensed input file rather than from a
hand-maintained list that would drift, and re-scoping is a flag change (`--min-decks 12000`) rather
than a file edit. **`commanders.txt` does not exist and must not be created.**

### D-06 — EDHREC's own land aggregate is retained as a self-check

Held as shipped. Each cell carries EDHREC's `land`, `basic` and `nonbasic`. Plan `02-06` compares
`land` against the harness's own `lands` role count for the same decklist — a free correctness check
on the one role where an independent ground truth exists.
