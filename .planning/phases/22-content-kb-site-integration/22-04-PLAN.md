<locked_decisions>
## D-22D — last-loaded timestamp source (LOCKED; resolves MED last-loaded)
"Last loaded" in the status panel = **max(indexed_utc) across all index rows** (the seed-load sets IndexedUtc; a reload refreshes content rows so the max advances). NO new table/column/status row is added. The controller computes it from `GetAllRowsAsync()` (`rows.Count == 0 ? null : rows.Max(r => r.IndexedUtc)`), displayed as a UTC string or "Never" when there are no rows. This is an approximation of seed-load time (indexed_utc is the index-generation timestamp, refreshed on curation-preserving upsert), which is the best available signal without new schema — documented rationale per the review's MED disposition.

## D-22E — CSRF on the reused flag toggle (LOCKED; resolves HIGH-4)
The KB admin page reuses `AdminFlagsController.Toggle` for the global flag. That action has `[ValidateAntiForgeryToken]` but NOT `SameOriginRequestValidator` (verified at AdminFlagsController.cs:70-93). The locked SC4/P11 criterion requires BOTH on every mutating admin POST. Task 1 adds the same-origin guard to Toggle (first line of the method body, mirroring the AdminContentKb actions). The CSRF grep gate counts ALL FOUR mutating actions across the two controllers (3 in AdminContentKb + 1 in AdminFlags) and asserts each has both guards.
</locked_decisions>
