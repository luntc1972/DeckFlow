<objective>
Implement the service-layer plumbing that turns the singular `commanderName` into a full command-zone
picture and surfaces the companion — all behind `analysis.command-zone-awareness`, byte-identical when
OFF. This is the plumbing the three variants (Plan 03) will render. No variant body changes here.

Two existing gaps are closed (research §RQ1/§RQ3): `DeckAnalysisPacketService.BuildAsync` discards
`loaded.DetectedCompanionName` (line 404-406) and uses only the FIRST commander entry. When the flag
is ON we collect ALL `Board == "commander"` names, oracle-resolve each individually, then join with
" & "; and we resolve the companion (designator wins over detected, trimmed + collapsed to a single
line + 200-char capped).

**Awareness-only invariant (Codex HIGH-1):** the companion is surfaced as SIDE METADATA only — we do
NOT touch, filter, or move the deck text. For Archidekt the companion stays classified `mainboard`
(`ArchidektApiDeckImporter.cs`) so it legitimately keeps appearing in the decklist; that is fine and
required to preserve flag-OFF byte-identity. There is no display-only decklist mutation in this phase.

**Injection hardening (Codex HIGH-2):** `request.CompanionName` is free-form user input. `BoundCompanionName`
MUST collapse it to a single line (strip CR/LF), matching how `NormalizeSingleLine`/`CollapseWhitespace`
already normalize `Format`/`DeckName`, so a crafted newline cannot break prompt structure. (Claude
additionally XML-escapes the value in its `<companion>` tag — that is Plan 03.)

Purpose: variants receive an enriched `commanderName` and an explicit `companionName` without any
shared helper (ADR 0001) and without changing the cache key or any flag-OFF byte.
Output: flag-gated enrichment in `BuildAsync` + new unit tests (3-platform flag-OFF byte-identity,
partner pair, single-commander) + the existing manabase/leak guards still green.
</objective>
