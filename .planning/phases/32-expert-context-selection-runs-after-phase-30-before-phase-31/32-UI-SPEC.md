## Spacing Scale

All spacing is in rem units mapped to the project's 15px html base. Values are multiples of 4px effective at 15px/rem.

| Token | Rem | Effective px | Usage in this phase |
|-------|-----|-------------|---------------------|
| xs | 0.25rem | ~4px | Icon-to-label gaps inside chip; glyph padding |
| sm | 0.5rem | ~8px | Pin/Follow button internal padding (compact); chip gap |
| md | 1rem | ~15px | Card inner gap between action row and existing content; tray padding |
| lg | 1.5rem | ~23px | Section spacing between filter bar and card grid |
| xl | 2rem | ~30px | Major section breaks |

**Exceptions:**
- Touch targets: Pin button, Follow button, chip remove (×) buttons — minimum 44px height, per existing `.kb-filter-bar input` (min-height: 44px) and CLAUDE.md WIG constraint. Apply `min-height: 44px; min-width: 44px` via `.kb-card-actions button` scoped rule in `site-common.css`.
- Chip pill padding: 0.1rem 0.45rem vertical/horizontal (mirrors existing `.kb-tag` geometry exactly, since chips reuse that class shell).

## Component Inventory

### C-01: Pin Button (on hub-card, /content-kb browse)

**HTML structure:**
```html
<button type="button"
        class="kb-pin-btn"
        aria-label="Pin '@entry.Title' for next analysis"
        aria-pressed="false"
        data-kb-pin
        data-video-id="@entry.VideoId"
        data-video-title="@entry.Title">
    📌 Pin
</button>
```

**States:**
- Default: border `var(--line)`, background `var(--panel-soft-bg)`, color `var(--ink)`
- Pressed/pinned (`aria-pressed="true"`): border `var(--accent)`, color `var(--accent-strong)`, label changes to "Pinned" (TS toggles)
- Disabled (pin cap of 3 reached, this video not pinned): `opacity: 0.45; cursor: not-allowed` — mirrors existing `.run-button:disabled` pattern
- Focus-visible: `outline: 2px solid var(--focus, var(--accent)); outline-offset: 2px`

**Placement:** Inside each `.hub-card article`, in a new `<div class="kb-card-actions">` row appended after the existing tag `<div aria-hidden="true">`. Source tag (`.kb-tag`) row comes first; actions row below it. No layout restructure of `.hub-grid`.

**CSS class:** `.kb-pin-btn` — new rule in `site-common.css`.

**Touch target:** `min-height: 44px` enforced via `.kb-card-actions button` rule.

```html
        data-kb-follow
```

### C-04: Expert Context Chip Area (/deck-analysis form)

An editable chip area placed immediately below the AI selector and above the decklist textarea in Step 1 of the analysis form. Rendered server-side from replayed `PinnedVideoIds`/`FollowedCreators`; TS hydrates from localStorage on `DOMContentLoaded` and merges with server-rendered state.

**HTML structure (server-rendered shell):**
```html
<section class="kb-chip-area" aria-labelledby="kb-chip-heading">
    <h3 id="kb-chip-heading" class="kb-chip-area__heading">
        Expert Context
        <details class="info-tooltip">
            <summary>i</summary>
            <p>Pinned videos and followed creators whose clips are guaranteed a place in your analysis prompt. Cleared after each run (videos) or sticky (creators).</p>
        </details>
    </h3>

    <div class="kb-chip-area__chips" data-kb-chips aria-label="Selected expert context items">
        @* Server-renders one chip per replayed PinnedVideoId / FollowedCreator *@
        @foreach (var id in Model.Request.PinnedVideoIds)
        {
            <span class="kb-chip kb-chip--pinned" data-chip-id="@id" data-chip-type="video">
                📌 <span class="kb-chip__label">@(Model.ResolvedPinTitles.GetValueOrDefault(id, id))</span>
                <button type="button" class="kb-chip__remove" aria-label="Remove pinned video">×</button>
            </span>
        }
        @foreach (var creator in Model.Request.FollowedCreators)
        {
            <span class="kb-chip kb-chip--followed" data-chip-creator="@creator" data-chip-type="creator">
                ★ <span class="kb-chip__label">@creator</span>
                <button type="button" class="kb-chip__remove" aria-label="Remove followed creator @creator">×</button>
            </span>
        }
    </div>

    @* Hidden fields — submitted even without JS; TS injects additional ones from localStorage *@
    @foreach (var id in Model.Request.PinnedVideoIds)
    {
        <input type="hidden" name="PinnedVideoIds" value="@id" />
    }
    @foreach (var creator in Model.Request.FollowedCreators)
    {
        <input type="hidden" name="FollowedCreators" value="@creator" />
    }

    @* Typeahead to add more *@
    <div class="autocomplete-anchor kb-chip-area__typeahead" data-kb-chip-typeahead>
        <input type="text"
               class="kb-chip-area__search"
               placeholder="Add pinned video or followed creator…"
               aria-label="Add expert context item"
               autocomplete="off"
               data-kb-typeahead-input />
        <div class="autocomplete-panel" hidden data-kb-typeahead-panel role="listbox" aria-label="Suggestions"></div>
    </div>

    @if (Model.Request.PinnedVideoIds.Count == 0 && Model.Request.FollowedCreators.Count == 0)
    {
        <p class="kb-chip-area__empty-hint">No expert context selected. Clips will be chosen automatically.</p>
    }
</section>
```

**Chip CSS classes:**
- `.kb-chip` — base pill: `display: inline-flex; align-items: center; gap: 0.25rem; padding: 0.1rem 0.45rem; border: 1px solid var(--line); border-radius: 999px; font-size: var(--fs-xs); font-weight: 600; background: var(--panel-soft-bg); white-space: nowrap` (same geometry as existing `.kb-tag`; new class for interactivity)
- `.kb-chip--pinned` — additionally: `border-color: var(--accent); color: var(--accent-strong)`
- `.kb-chip--followed` — same accent border as pinned
- `.kb-chip__remove` — `background: transparent; border: none; cursor: pointer; padding: 0 0.15rem; font-size: var(--fs-sm); color: var(--muted); line-height: 1; min-height: 44px; min-width: 44px; display: inline-flex; align-items: center; justify-content: center`
- `.kb-chip__remove:hover` — `color: var(--danger)`

**Typeahead API endpoints (new, added to `SuggestionsApiController`):**
- `GET /api/content-kb/entries?q={query}` — returns `[{id, title}]` for visible KB entries
- `GET /api/content-kb/creators?q={query}` — returns `[string]` for distinct source names

Both use `window.DeckFlow.attachTypeahead` from `df-typeahead.ts`. Result items show source type in a secondary label: "[video]" or "[creator]".

**Progressive enhancement contract:** When JS is absent, the form submits with only the server-rendered hidden fields. The chip area still displays (CSS only), but no live add/remove occurs. Selection is exactly what was replayed from the zip. This satisfies the no-JS path per S-04/CONTEXT.md.

**Placement in DeckAnalysis.cshtml:** After the AI selector section (`.ai-selector`) and before the Step 1 form fields group. No existing form fields move.

**CSS classes:** `.kb-chip-area` and children — new rules in `site-common.css`.

## Interaction Contracts

### IC-01: Pin state lifecycle

1. User clicks Pin button on browse card → `kb-selection.ts` writes to `localStorage["deckflow.kb.pinned"]` (JSON array `[{id, title}]`, max 3 entries).
2. Button transitions to `aria-pressed="true"`, label "📌 Pinned".
3. Tray updates (if tray visible): new item appears; count updates.
4. All other cards' Pin buttons re-evaluate disabled state (cap at 3).
5. User navigates to /deck-analysis → `kb-selection.ts` reads localStorage on `DOMContentLoaded`, injects hidden `<input type="hidden" name="PinnedVideoIds" value="…">` for each pin.
6. Analysis runs → server one-shots the pin (does not persist it beyond the request).
7. Post-analysis: `kb-selection.ts` clears `localStorage["deckflow.kb.pinned"]` on successful form submit. Creator follows remain.

**Pin cap enforcement:** When `pins.length >= 3`, all un-pinned Pin buttons get `disabled` attribute and `aria-disabled="true"`. Title shows "Pin cap reached (3 max). Remove a pin to add another." via `title` attribute.

### IC-02: Follow state lifecycle

1. User clicks Follow button → `kb-selection.ts` writes to `localStorage["deckflow.kb.followed"]` (JSON array `[{source: string}]`).
2. Button transitions to `aria-pressed="true"`, label "★ Following".
3. Tray updates.
4. On /deck-analysis: TS injects `<input type="hidden" name="FollowedCreators" value="…">` per follow.
5. Analysis runs → follows are sticky; NOT cleared after submit.
6. Multiple cards from same creator: ALL their Follow buttons reflect the same `aria-pressed` state (keyed by creator name string).

### IC-03: Typeahead (chip area on /deck-analysis)

1. User types 2+ chars in the typeahead input → debounced fetch to `/api/content-kb/entries?q=…` (videos) and `/api/content-kb/creators?q=…` (creators).
2. Results shown in `.autocomplete-panel` (reuses existing `.autocomplete-option` CSS from `site-common.css`).
3. Video results prefixed with "📌" label, creator results with "★" label in the option text.
4. Selecting a video option: adds `.kb-chip--pinned` chip + hidden `PinnedVideoIds` field; updates localStorage.
5. Selecting a creator option: adds `.kb-chip--followed` chip + hidden `FollowedCreators` field; updates localStorage.
6. Keyboard: Arrow up/down navigate options; Enter selects; Escape closes panel. (Reuse `window.DeckFlow.attachTypeahead` from `df-typeahead.ts`.)

### IC-04: Zip replay restores selection chips

1. User uploads zip → `LoadFromZip` deserializes `33-expert-selection.json` → populates `request.PinnedVideoIds` + `request.FollowedCreators`.
2. Server renders chip area with those values as hidden fields AND as visible chip elements.
3. `kb-selection.ts` reads the server-rendered chip data on `DOMContentLoaded` and writes it back to localStorage (re-hydration). This means the pins appear both in the chip area and in localStorage so further form edits work correctly.

### IC-05: Evergreen admin toggle

1. Admin clicks "Evergreen: Off" → form POSTs to `SetEvergreen` → server sets `is_evergreen = true` → redirect with `TempData[BannerKey] = "Evergreen status updated."` → banner renders as `.admin-banner.admin-banner--success`.
2. Same flow for toggling back to Off.
3. No JS required; standard form POST.
4. `SameOriginRequestValidator.IsValid(Request)` + `[ValidateAntiForgeryToken]` double-guard (mirrors SetVisibility exactly).

```typescript
    };
};
```

**localStorage keys:**
- `"deckflow.kb.pinned"` — serialized as `JSON.stringify([{id: string, title: string}])`, max 3 entries
- `"deckflow.kb.followed"` — serialized as `JSON.stringify([{source: string}])`

**Initialization entry point:**
```typescript
document.addEventListener('DOMContentLoaded', initKbSelection);
```

**Progressive enhancement contract:** All DOM manipulations are guarded by `if (element === null) return;`. If the pin/follow buttons or chip area are absent from the DOM (e.g., page without them), the module initializes without error.
