## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server HTML → browser innerHTML | Partial HTML from the same-origin endpoint is injected via innerHTML |
| browser → AJAX endpoint | Client fetch carries the same-origin Origin header that the server guard checks |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-xss-client | Information Disclosure (XSS) | innerHTML swap in loadCommandersGrid | accept | The swapped HTML is the server's own Razor-rendered partial fetched same-origin; all row fields are Razor-HTML-encoded server-side. The error/loading HTML strings are static literals with no user input. No untrusted data is concatenated into innerHTML on the client. |
| T-44-csrf-client | Spoofing | client fetch to /Admin/Harvest/commanders | mitigate | Client uses `credentials: 'same-origin'`; the browser attaches the same-origin Origin header so the server-side `SameOriginRequestValidator` (Plan 02) passes for legitimate use and rejects cross-origin callers (403). Per the resolved 403 contract, a bare no-header direct-nav is allowed by the validator but is still gated by admin BasicAuth. Client-side has no separate guard — the server is authoritative. |
| T-44-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs; RESEARCH.md Package Legitimacy Audit = N/A (zero new packages). No new npm dependency for TypeScript. |
</threat_model>
