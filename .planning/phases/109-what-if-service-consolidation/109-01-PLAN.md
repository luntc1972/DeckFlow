# Plan 109-01 — Rename to ICutLabWhatifService and Add Shared CommitSwapAsync

<objective>
Consolidate Cut Lab what-if logic behind a single interface. Rename the existing preview-only `ICutLabWhatifPreviewService` to `ICutLabWhatifService` (CLUP-04 names this interface exactly), rename `ComputeSwapPreviewAsync` to `PreviewSwapAsync` for symmetry, and add a new non-throwing `CommitSwapAsync` that extracts the swap-commit rules currently duplicated across both controllers. Prove the shared rules (commander-lock, quantity legality, floor-state preservation, swap eligibility, atomicity) with service-level tests. This plan is purely additive/mechanical for behavior: after it lands the solution builds clean, all tests pass, and both transports behave exactly as before — the controllers still use their own duplicated commit blocks. Plan 109-02 flips them onto `CommitSwapAsync`.

Purpose: CLUP-04/CLUP-05 — establish the one shared service surface and lock its rules with shared tests before the controllers adopt it.
Output: Renamed interface/class, new `CommitSwapAsync` + `CutLabWhatifCommitResult`, updated DI + all name references, and shared service tests.
</objective>

<execution_context>
Delegation: per project rules Codex writes the implementation; this plan is executor-agnostic but implementation-ready. </execution_context>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-01 | Tampering | `CommitSwapAsync` swap-pair validation | mitigate | Re-validate server-side: reject when the card-out pool card is missing, `IsLocked`, or `IsCommander`, and when the card-in is not an accepted (cut-pile) card. Adopt the stricter explicit `!IsCommander` check (the no-JS path's variant), not the API path's `IsLocked`-only check, so the commander-lock invariant is provable even if the deserialize-time re-assertion is ever weakened. |
| T-109-02 | Tampering | Atomicity / quantity legality of the restore-then-accept swap | mitigate | Keep the existing decision-count overshoot guard inside `CommitSwapAsync`: if `afterSwap.Decisions.Count == afterRestore.Decisions.Count`, return the original `state` unchanged with `Applied=false` — never surface `afterRestore` as a half-applied partial (regression guard, prior atomicity fix commit `7cb68348`). |
| T-109-03 | Tampering / EoP | Validation drift between the two transports | mitigate | Route both commit paths (in 109-02) through this one method so locked/commander/quantity/cut-pile rules cannot diverge; this plan makes the single implementation exist and tests it. |

No package-manager installs occur in this phase (pure internal C# refactor, no new dependency) — no supply-chain (`T-109-SC`) checkpoint required.
</threat_model>

<behavior>
- Preview is non-destructive: PreviewSwapAsync does not mutate the input state's Pool/Decisions.
- Valid pair commits atomically: restore card-in then accept card-out, tagged with the what-if round key; result Applied=true, State reflects both decisions.
- Locked card-out rejected: Applied=false, ErrorMessage=NoChangeMessage, State equals input unchanged.
- Commander card-out rejected: Applied=false (explicit IsCommander guard), State unchanged.
- Card-in not in the cut pile rejected: Applied=false, State unchanged.
- Overshoot replacement cut rejected atomically: when the accept would exceed the 100-card budget, decision count is unchanged, Applied=false, and NO half-applied state is returned (State equals the original input, not afterRestore).
- Floor state preserved on commit: the committed state retains its RoleFloors so downstream floor-warning computation is unaffected.
- Invalid pair uses the try-pattern: CommitSwapAsync returns a result and does NOT throw for any expected-invalid pair.
</behavior>
