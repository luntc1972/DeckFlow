# Phase 45 — UI Design Contract: Harvest + Distill UI

> Visual and interaction contract for the Harvest + Distill UI page in DeckFlow.Studio.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

This contract covers the **DeckFlow.Studio** Blazor Server application only. It is a standalone
local operator tool — not the public deckflow.gg site. The guild-theme CSS, `site-common.css`,
and multi-theme token files of DeckFlow.Web do NOT apply here.

**Audience:** single operator running Studio locally. Clarity and cost-safety affordances take
priority over marketing polish.

---

## Spacing Scale

Declared values (multiples of 4). Expressed as Bootstrap utilities where possible; raw CSS
values for component-level scoped CSS.

| Token | Value | Bootstrap Utility | Usage |
|-------|-------|-------------------|-------|
| xs | 4px | `gap-1`, `p-1`, `m-1` | Icon gaps, badge inner padding |
| sm | 8px | `gap-2`, `p-2`, `m-2` | Compact row spacing, inline element gaps |
| md | 16px | `gap-3`, `p-3`, `m-3` | Default card/section padding |
| lg | 24px | `gap-4`, `p-4`, `m-4` | Section padding within the page |
| xl | 32px | `gap-5`, `p-5`, `m-5` | Major section separation |
| 2xl | 48px | custom `mt-6` in scoped CSS | Above-the-fold section breaks |
| 3xl | 64px | not used in this phase | Page-level only — not needed in Studio |

Exceptions: progress log area uses 12px line-height gap between lines (not on the 8-point scale
— justified: monospace log output, not layout).

## Typography

All sizes are rem-derived, converted to px at 16px base.

| Role | Size | Weight | Line Height | CSS |
|------|------|--------|-------------|-----|
| Body | 16px (1rem) | 400 (regular) | 1.5 | Default Bootstrap body |
| Label | 14px (0.875rem) | 600 (semibold) | 1.4 | `.fw-semibold .small` |
| Section heading | 20px (1.25rem) | 600 (semibold) | 1.2 | `<h2 class="h5 fw-semibold">` |
| Page heading | 24px (1.5rem) | 600 (semibold) | 1.2 | `<h1 class="h4 fw-semibold">` |

Maximum 4 sizes, 2 weights (400 regular + 600 semibold). Do not introduce a third weight.

Progress log text: 13px monospace (`font-family: monospace; font-size: 0.8125rem`) inside
the scrollable log pane. This is the only monospace context.

## Color

Bootstrap 5 semantic color variables. No custom hex values needed — all colors resolve to
Bootstrap's default theme. This keeps the Studio visually neutral and legible without a
separate design pass.

| Role | Bootstrap Var / Class | Hex Reference | Usage |
|------|----------------------|---------------|-------|
| Dominant (60%) | `--bs-body-bg` | #ffffff (light) | Page background, content area |
| Secondary (30%) | `--bs-gray-100` / `bg-light` | #f8f9fa | Cards, sidebar, table-striped rows |
| Accent (10%) | `--bs-primary` / `btn-primary` | #1b6ec2 | Trigger buttons, active badge borders, progress spinner |
| Warning | `--bs-warning` / `text-warning` `bg-warning` | #ffc107 / #fff3cd | Re-distill warning banner, Re-distill badge background |
| Destructive | `--bs-danger` / `text-danger` `btn-danger` | #dc3545 | Blocked-video badge, destructive confirm dialogs |
| Success | `--bs-success` / `text-success` | #198754 | Distilled badge, harvest-complete flash message |
| Muted | `--bs-secondary` / `text-muted` | #6c757d | Not-harvested badge, placeholder copy |

Accent (`--bs-primary`) is reserved for:
- "Harvest Selected" primary CTA button
- "Run Distill (dry-run)" primary CTA button
- "Confirm Distill" primary CTA button after dry-run confirmation
- Active/checked state outline on video selection checkboxes
- Progress spinner (`spinner-border text-primary`)

The Re-distill warning uses `--bs-warning` (amber) — distinct from the destructive red — because
re-distilling is costly but not irreversible.

## Status Badge Vocabulary

These are the exhaustive badge states for the per-video status indicator. Every video in the
list MUST display exactly one badge at all times.

| State | Label | Bootstrap Class | When Applied |
|-------|-------|----------------|--------------|
| `not-harvested` | Not harvested | `badge bg-secondary` | Video found in channel/queue; no transcript in DB |
| `harvested` | Harvested | `badge bg-info text-dark` | Transcript exists in DB; no distill output |
| `distilled` | Distilled | `badge bg-success` | `content_site_index` row exists for this video |
| `blocked` | Blocked | `badge bg-danger` | Video is in `blocked_videos` table |
| `duplicate` | Already in DB | `badge bg-warning text-dark` | Video ID already in `content_videos` — shown on paste queue before harvest |

**Implementation note:** badge state is resolved at list-render time by cross-referencing
`IContentVideoStore` and `IBlockedVideoStore`. The `duplicate` state is a pre-harvest warning,
not a post-harvest status; it appears only in the URL/ID paste queue section.

## Interaction Contracts

### Section 1 — Channel Browse (HARV-01)

**Input:** Single text field labeled "YouTube channel URL, handle, or ID". Placeholder:
`e.g. @SomeCreator or https://youtube.com/@SomeCreator`

**Trigger:** "Browse Channel" button (`btn-outline-primary`). Disabled while a channel fetch
is in flight.

**Loading state:** Spinner + "Fetching channel videos..." text replaces the Browse button label.
The input is disabled during fetch. The lister runs serialized (SemaphoreSlim(1) — Pitfall 6).

**Results:** A table with columns: Checkbox | Thumbnail (40×30px) | Title | Published | Status badge.
Already-harvested rows (`harvested` or `distilled` badge) display with `table-secondary`
row tinting to visually pre-distinguish them before selection.

**Empty result:** "No videos found for this channel. Check the handle or URL and try again."

**Error:** "Could not fetch channel — {reason}. Check the URL format and try again."

**Concurrency guard:** The Browse button is disabled while harvest or distill is in flight.
Show a note: "Harvest or distill in progress — channel browse unavailable."

---

### Section 2 — URL/ID Paste Queue (HARV-02)

**Input:** Multi-line textarea labeled "Paste video URLs or IDs (one per line)".

**Trigger:** "Add to Queue" button (`btn-outline-secondary`). Parses each line, resolves video
ID, cross-references DB, and appends to the queue list below.

**Queue list:** Same columns as channel browse table. `duplicate` badge shown for videos already
in DB. Operator can remove individual rows via a `btn-close` / `oi oi-x` icon per row.

**Duplicate handling:** Duplicates are flagged visually but NOT blocked from harvest. The
operator explicitly selects which videos to harvest; duplicates are pre-warned, not auto-excluded.

---

### Section 3 — Harvest Trigger (HARV-03, HARV-04)

**Pre-conditions visible before trigger:**
- Checkbox row count summary: "{N} videos selected ({M} already harvested)"
- Already-harvested selection shows inline warning: `text-warning` icon + "X selected video(s)
  already harvested — these will be skipped by the harvester."

**Primary CTA:** "Harvest Selected" (`btn-primary`). Disabled if 0 checkboxes selected or
harvest/distill already in flight.

**Progress pane** (shown after trigger, hidden before):
- Header: "Harvesting..." with `spinner-border text-primary` (16px)
- Scrollable log box: `<pre class="bg-light border rounded p-2" style="height:200px; overflow-y:auto; font-size:0.8125rem; font-family:monospace">` — messages appended via `IOrchestratorProgress.Report()` bridged to `InvokeAsync(StateHasChanged)`
- Cancel button: "Cancel Harvest" (`btn-outline-danger btn-sm`) — sets CancellationTokenSource. Cancellation token is also wired to `IDisposable.Dispose()` to stop in-flight ops when tab closes (Pitfall 7).

**Completion state:**
- Spinner replaced by `oi oi-check` (`text-success`)
- Summary: "Harvest complete — {Captions} transcripts from captions, {Whisper} via Whisper, {SkippedNoCaptions} skipped (no captions)."
- Badge states on the video list update to reflect new DB state.
- "Harvest Selected" button re-enables.

**Failure state:**
- `oi oi-warning` (`text-danger`)
- Message: "Harvest stopped — {HarvestResult.Message}. Check the log above for details."

---

### Section 4 — Distill Spend Gate (HARV-05)

This section appears below the harvest results (or independently if operator selects
already-harvested videos). It has two stages: dry-run projection, then confirm-and-execute.

#### Stage A — Dry-Run Projection

**Pre-conditions visible:**
- "Videos ready to distill: {N}" — counts harvested-but-not-distilled videos from selection
- Already-distilled videos in selection show: amber banner `alert alert-warning`:
  "Warning: {K} selected video(s) have already been distilled. To re-distill, check 'Re-distill
  already-distilled videos' below. This will incur additional LLM spend."
- Re-distill checkbox: `<input type="checkbox" id="redisitll">` labeled "Re-distill
  already-distilled videos (additional spend)" — unchecked by default. Requires a second
  explicit check to enable. When checked, a secondary confirm text appears inline:
  "You are about to re-distill {K} video(s) that already have summaries. This will overwrite
  existing distill output. Are you sure?" with a "Yes, I understand" checkbox that must also
  be checked before the dry-run button activates. (Two-checkbox secondary confirmation for
  Re-distill — Pitfall 5.)

**CTA:** "Estimate Spend (dry run)" (`btn-outline-primary`). Disabled until the Re-distill
double-confirmation is resolved (if applicable). Runs `DistillAsync(dryRun: true)`.

**Spinner + progress pane:** Same pattern as harvest — `spinner-border text-primary` +
scrollable log box.

**Dry-run result card** (`card border-primary`):
```
Dry-run complete
Videos that would distill: {WouldRun}
Projected spend:           ${ProjectedSpendUsd:F4} USD
Monthly cap remaining:     (from spend ledger)
```
If `ProjectedSpendUsd` would exceed monthly cap: `alert alert-danger`:
"Projected spend (${X}) exceeds your monthly cap (${Y}). Reduce selection or raise the cap."
Distill CTA is disabled until cap clears.

#### Stage B — Confirm and Execute

After a successful dry-run result card:

**Confirmation checkbox** (required): `<input type="checkbox" id="distillConfirm">` labeled
"I have reviewed the estimated spend above and want to proceed with actual distillation." Must be
checked to enable the execute button.

**Primary CTA:** "Run Distill" (`btn-primary`). Disabled until confirmation checkbox is checked.
Clicking it runs `DistillAsync(dryRun: false)`.

**Progress pane:** Same pattern. Cancel button: "Cancel Distill" (`btn-outline-danger btn-sm`).

**Completion result card** (`card border-success`):
```
Distill complete
Videos distilled:   {VideosDistilled}
LLM calls:         {LlmCalls}
Actual spend:      ${LlmSpendUsd:F4} USD
Videos filtered:   {VideosFiltered}
Failed:            {DistillFailed}
```
If `DistillFailed > 0`: `alert alert-warning` with failed video IDs listed.

**Post-distill badge refresh:** Video list badges update to `distilled` for successfully
processed videos.

## Page Layout

The Harvest page uses the existing Studio two-column layout (250px dark sidebar + main content).
Within `<article class="content px-4">`:

```
[Section 1: Channel Browse]         ← card with card-body
[Section 2: URL/ID Paste Queue]     ← card with card-body, mt-4
[Divider: <hr>]
[Section 3: Harvest Trigger]        ← card with card-body, mt-4
  [Progress pane — shown in-place when active]
[Section 4: Distill Spend Gate]     ← card with card-body, mt-4
  [Stage A: dry-run]
  [Stage B: confirm + execute — only visible after dry-run success]
```

Sections 1 and 2 are independent input areas; Sections 3 and 4 are operation areas. Each section
is a Bootstrap `card` with a `card-header` title and `card-body` content. `mt-4` (24px) between
cards.

| Action | Risk | Confirmation |

No hard-delete actions exist in Phase 45. Blocking/unblocking videos is out of scope for this
phase (that is a Phase 46+ maintenance action).

## State Machine Summary

The Harvest page has one shared operation lock: `_operationInFlight` (bool). Only one of
{harvest, dry-run distill, execute distill} can be in progress at a time.

```
Idle
  → [Browse Channel] → FetchingChannel → Idle (results rendered)
  → [Add to Queue]   → QueueUpdated   → Idle
  → [Harvest Selected] → Harvesting → HarvestComplete | HarvestFailed | HarvestCancelled
  → [Estimate Spend] → DryRunning   → DryRunComplete (shows result card + Stage B)
  → [Run Distill]    → Distilling   → DistillComplete | DistillFailed | DistillCancelled
```

All transitions call `await InvokeAsync(StateHasChanged)` from the background `Task.Run`
wrapping the orchestrator call (Pitfall 7 mitigation). The `CancellationTokenSource` is
newed on each operation start and disposed on `IDisposable.Dispose()`.

## Accessibility Notes

- All form inputs have explicit `<label for="...">` associations.
- Progress log `<pre>` has `role="log" aria-live="polite"` so screen readers announce new lines.
- Spinner has `aria-label="Operation in progress"` + `role="status"`.
- Disabled buttons retain their label text (do not clear to blank when disabled).
- Badge color is never the sole differentiator — label text always accompanies color.
