## Implementation Decisions

### Wrapper strategy for Claude

- **D-01:** **Drop `<result>` wrapper instruction from all 5 Claude prompt variants.** Remove BOTH the `JsonTextFormatterService.ResultWrapInstruction` AppendLine call AND the immediate follow-on `"Wrap your final structured output in <result>...</result> tags. … Do not put JSON outside <result>."` line. Replace in-place with the verbatim ChatGPT counterpart's fenced-block directive (D-04 below).

  Rationale: Claude empirically ignores the "Do not put JSON outside `<result>`" directive (user observation 2026-05-17 during Phase 13 UAT T4) and emits both the wrapper AND a duplicate fenced ```json block. Tightening the directive would be brittle (model already disobeys an explicit ALL-CAPS-tier directive). Inverting parser primacy would force rewriting all 15 wrap-instruction call sites and contradict Phase 10 design. Per-Claude-prompt divergence is the smallest, most reversible change that lands a clean user-visible chat output.

  Rejected alternatives:
  - Tighten Claude prompt; keep wrapper — brittle, Claude already non-compliant on the directive.
  - Invert parser primacy: fenced-first, `<result>` fallback — touches `JsonTextFormatterService.ExtractJsonPayload`, forces rewording all 15 wrap-instruction call sites, rewrites Phase 10 design rationale, breaks legacy-zip parse path.
  - Hybrid drop + extra anti-`<result>` directive — adds a "do not emit `<result>`" instruction on top of the fenced-block ask. Negative-instruction language can backfire on instruction-tuned models; redundant when wrapper instruction is already removed.

### Scope — which Claude families

- **D-02:** **All 5 Claude prompt-variant families.** Edit every file matching `DeckFlow.Web/Services/PromptBuilders/*/Claude*PromptVariant.cs`. Same defect site in all 5 (same `ResultWrapInstruction` AppendLine + same follow-on line). Symmetric scope; cleanest git-blame; matches Phase 15 D-04 file-per-type symmetry. Deferring 4 of the 5 families would invite the same bug report on Comparison/MetaGap/FollowUp/SetUpgrade workflows in a few weeks.

### Follow-on line ("Do not put JSON outside `<result>`") fate

- **D-03:** **Remove entirely.** The line currently appended right after `ResultWrapInstruction` in each Claude variant says: `"Wrap your final structured output in <result>...</result> tags. Inside <result>, return a single JSON object matching <output_schema>. Place the readable answer prose BEFORE the <result> tag (outside it). Do not put prose inside <result>; do not put JSON outside <result>."` Once D-01 drops the wrapper instruction, the follow-on is dead weight. Delete both lines as one mechanical change per variant.

### JSON delivery shape after the change

- **D-04:** **Fenced ```json code block.** Each Claude variant emits the verbatim ChatGPT counterpart's directive: `builder.AppendLine("You MUST return the JSON inside a fenced ```json code block (triple-backtick json). Do not return raw JSON outside a code block.");` (the text Claude variants gain is the same string as `ChatGptAnalysisPromptVariant.cs:198` and analogous sites in the other 4 ChatGPT family files).

  Rationale: Claude's natural inclination is to emit fenced code blocks; this directive aligns prompt with that inclination. Identical wording across platforms maximises parser-consistency proof (same emitted directive → same expected output → fewer model-divergence variables to debug if a future bug surfaces). Parser brace-scan (`ExtractJsonPayload` lines 68-81) already handles fenced-only output without code change.

  Rejected alternatives:
  - Bare JSON — Claude tends to wrap code blocks autonomously; bare-JSON ask is fighting the model.
  - New XML tag (`<json>`) — would need a new parser branch; contradicts D-01 "parser unchanged" lock.
  - "You decide during planning" — directive is uniform across 5 variants; locking it now eliminates inconsistent rewordings between commits.

### Directive wording — exact-copy from ChatGPT variant counterpart

- **D-05:** **Verbatim copy from each Claude variant's ChatGPT counterpart in the same family.** E.g., `ClaudeAnalysisPromptVariant.cs` plugs in the line found at `ChatGptAnalysisPromptVariant.cs:198`. `ClaudeComparisonPromptVariant.cs` plugs in the line found at `ChatGptComparisonPromptVariant.cs:84` (or the closest equivalent fenced-block directive in that file). Plan author confirms exact source line during execution.

  Rejected:
  - Reword for Claude's instructional voice (XML-tagged `<task>`/`<output_schema>` style) — per-variant judgment work; identical wording across platforms is a strictly stronger invariant.
  - Add a new shared const (`FencedJsonInstruction`) and migrate 10 non-Claude variants too — touches 10 files for no behavior gain.

### Placement of the new directive within each Claude variant

- **D-06:** **Same position as the removed wrapper lines.** Both deleted lines (`ResultWrapInstruction` AppendLine + the "do not put JSON outside" AppendLine) sat immediately before the `builder.AppendLine("</" + "task>");` close. The new fenced-block directive lands in that exact same position. Preserves prompt flow; the diff per file is a 2-line-delete + 1-line-insert at one location. Plan author makes no judgment calls about repositioning.

  Rejected:
  - End-of-prompt mirroring `GeminiJsonMandate`'s last-instruction-wins pattern — breaks the existing prompt's `<task>`-closed XML structure in Claude variants; not necessary because Claude is not the AI ignoring the JSON ask (Gemini is).

### Sub-object fenced-block directives stay intact

- **D-07:** **Leave existing per-version `deck_profile` fenced-block instructions alone.** Examples to NOT touch: `ClaudeAnalysisPromptVariant.cs:200` ("Return it in a ```json fenced code block labeled with the version name (e.g. ```json deck_profile — Budget Efficiency)") and similar sub-object emit-site directives in other Claude variants. Those describe nested JSON objects emitted by the user's deck-analysis workflow, not the main JSON envelope this phase addresses.

### Code locality — per-variant edits, not platform-level switch

- **D-08:** **Per-Claude-variant edits, 5 files.** No new `AiPlatform.UseResultWrapper` record property. No new `IResultWrapPolicy` strategy interface. No helper method on `JsonTextFormatterService`.

  Rationale: Adding `UseResultWrapper` to the `AiPlatform` record would violate Phase 15 D-01 invariant ("AiPlatform is a data-only sealed record with three string properties — no Enabled property, no ResponseExtractor delegate, no Strategy interface"). Adding `IResultWrapPolicy` as a new strategy family is over-engineered for a binary divergence on one platform — would land 4 new files (interface + 3 platform impls + registry) for a behavior that 5 lines of variant edits cover. The prompt variants ARE the per-platform strategy surface (Phase 15 D-01: "the registry pattern at the prompt-builder layer is the 'strategy' surface SC1 names"); 999.2 exercises that exact extensibility by diverging Claude prompts from ChatGPT/Gemini.
