<objective>
Render the goals editor and per-goal results (GOAL-01 UI). Each of the three turn goals gets an editable turn-number input seeded from `state.Goals`, plus a display of the current probability and its trend versus the original-pool baseline, reusing the existing metrics/compare rendering. Two submit paths keep progressive enhancement intact: with JS the edited turns ride through `CutLabStateJson` (like role floors); without JS, named form fields POST to a dedicated `/cut-lab/goals` action that binds and clamps them into `state.Goals`.

Purpose: Turn the backend goal wiring (104-01) into something a builder can see, steer, AND submit with or without JavaScript. Goals are a core requirement, not the sanctioned JS-only exception (only GOAL-02 scenarios are).
Output: `GoalRows` on the view model, a Goals `<section>` in CutLab.cshtml, cut-lab.ts snapshot support, and the no-JS `Goals` controller action.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server -> browser | Goal labels/values rendered into HTML |
| browser -> server | Goal turn ints posted inside CutLabStateJson (JS) or as named form fields (no-JS) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-03 | Tampering | Goal turn inputs (CutLabStateJson or named fields) | mitigate | Server-side clamp is authoritative on BOTH paths: `CutLabGoalRules.ClampGoals` runs in the serializer (JS/CutLabStateJson path) and again in the `Goals` action (no-JS named-field path); client `Math.trunc`/min-max are convenience only. |
| T-104-15 | Spoofing / CSRF | New `/cut-lab/goals` POST | mitigate | `[ValidateAntiForgeryToken]` + `[FeatureFlagGate]` + `[RequestSizeLimit]`, identical to the Decide action; the goals form emits the antiforgery token field. |
| T-104-04 | Information Disclosure / XSS | Dynamic goal Label rendered in Razor | mitigate | Labels are server-composed from ints via interpolation and emitted through Razor's default HTML encoding; no user free-text enters the label. |
| T-104-SC | Tampering | package installs | accept | No package installs in this plan; legitimacy gate N/A. |
</threat_model>
