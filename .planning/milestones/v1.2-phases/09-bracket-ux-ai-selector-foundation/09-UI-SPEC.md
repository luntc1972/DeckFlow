## New Components — Visual Spec

### 1. Bracket Required-Field Callout (BRKT-01)

**Where:** ChatGptPackets.cshtml, Step 2 — immediately wrapping the existing `<label class="field">` for `TargetCommanderBracket`.

**Treatment:** Replace the bare `<label class="field">` with a callout wrapper.

```
.bracket-callout {
  border: 1px solid var(--line);
  border-left: 4px solid var(--accent-strong);
  border-radius: 8px;
  background: var(--panel-soft-bg);
  padding: 16px;
  margin-bottom: 16px;
}

.bracket-callout__label {
  font-size: var(--fs-sm);
  font-weight: 600;
  color: var(--accent-strong);
  text-transform: uppercase;
  letter-spacing: 0.05em;
  margin-bottom: 8px;
}
```

**Visual anatomy (top to bottom):**
1. Eyebrow label: "Required before generating" — `--fs-sm`, weight 600, `--accent-strong`, uppercase + letter-spacing
2. The existing df-select control (no change to the select itself)
3. The existing `<small class="sync-column__hint">` hint text below the select — no change

**Mode-note:** Do NOT add a `.mode-note` below the callout. The existing `<small class="sync-column__hint">` already explains the field. The callout's visual prominence (left border + label) is the sole added treatment.

**Interaction:** No new interaction. The callout is purely visual. The df-select retains all existing ARIA 1.2 combobox behavior.

### 2. AI Target Selector (AISEL-01)

**Where:** All three analysis pages:
- `ChatGptPackets.cshtml` — insert at the top of Step 2 panel, before the bracket callout
- `ChatGptDeckComparison.cshtml` — insert at the top of the Step 2 panel (before deck inputs)
- `ChatGptCedhMetaGap.cshtml` — insert at the top of the Step 2 panel (before reference deck selection)

**Rationale for Step 2 placement:** The AI selector must be visible "at the top of the analysis step" (AISEL-01). Step 2 is the first action step on all three pages. Placing it in Step 1 would require it to persist across navigation — Step 2 top is the correct and consistent anchor.

**Component class:** `.ai-selector`

**Visual spec:**

```

  margin-bottom: 16px;

.ai-selector__options {
  display: flex;

  gap: 8px;
}

.ai-selector__option {
  /* hidden native radio */
}

.ai-selector__option-label {
  display: inline-flex;
  align-items: center;
  gap: 4px;
  padding: 8px 16px;
  border: 2px solid var(--line);
  border-radius: 6px;
  background: var(--panel);
  color: var(--ink);
  font-size: var(--fs-base);
  font-weight: 400;
  cursor: pointer;
  min-height: 44px;       /* touch target */

}

.ai-selector__option:checked + .ai-selector__option-label {
  border-color: var(--accent-strong);
  background: var(--panel-soft-bg);
  font-weight: 600;
  color: var(--accent-strong);

  font-size: var(--fs-sm);
  color: var(--muted);
  margin: 8px 0 0 0;

```

**HTML structure pattern (Razor partial `_AiSelector.cshtml`):**

```html
<div class="ai-selector">
  <p class="ai-selector__heading">Analyze with</p>
  <div class="ai-selector__options" role="radiogroup" aria-label="AI analysis target">
    <input type="radio" name="TargetAiPlatform" id="ai-chatgpt" value="ChatGPT"
           class="sr-only ai-selector__option" checked />
    <label for="ai-chatgpt" class="ai-selector__option-label">ChatGPT</label>

    <input type="radio" name="TargetAiPlatform" id="ai-claude" value="Claude"
           class="sr-only ai-selector__option" />
    <label for="ai-claude" class="ai-selector__option-label">Claude</label>

    <input type="radio" name="TargetAiPlatform" id="ai-gemini" value="Gemini"
           class="sr-only ai-selector__option" />
    <label for="ai-gemini" class="ai-selector__option-label">Gemini</label>
  </div>
  <p class="ai-selector__hint">ChatGPT format used for all targets in this phase. Claude and Gemini optimizations arrive in Phase 10.</p>
</div>
```

**Default:** `ChatGPT` radio is `checked` by default — rendered server-side via `Model.Request.TargetAiPlatform == "ChatGPT"`.

**Round-trip (AISEL-04):** The `TargetAiPlatform` value is written to `01-request-context.txt` in the zip and restored on upload via `ChatGptRequestContextParser` / `ChatGptPacketArtifactStore.LoadFromZip`. If the field is absent in a legacy zip, default to `"ChatGPT"`.

**Keyboard behavior:** Native radio group keyboard nav (arrow keys cycle options). No custom JS required for this phase.

**Focus:** Uses existing `var(--focus)` / `focus-visible` rule in `site.css` — no new focus CSS.

## Interaction Contracts

### Bracket callout visibility

- The callout is always visible in Step 2, not conditionally shown.
- If the user submits Step 2 with no bracket selected, the existing `required` / `aria-required="true"` on the `<select>` fires native browser validation. The callout border does not change color on error — the browser's native invalid state on the `<select>` is sufficient.

### AI selector persistence

- The selected value is a standard form field (`name="TargetAiPlatform"`). It round-trips via normal form submission — no JS hydration needed.
- On zip resume: server reads `TargetAiPlatform` from `01-request-context.txt` and pre-selects the matching radio via Razor `checked` binding. If absent, defaults to `ChatGPT`.
- The selection does NOT affect any visible output in Phase 9 (artifact content is ChatGPT-format for all targets). The Phase 10 content branch is gated server-side.

### Shared partial

Both components should be implemented as shared Razor partials consumed by all three pages:
- `Views/Shared/_BracketCallout.cshtml` — wraps the bracket df-select with the callout treatment (Packets page only; Comparison and Meta Gap do not have a bracket field)
- `Views/Shared/_AiSelector.cshtml` — the AI target radio group (all three pages)

The AI selector partial accepts a `string selectedValue` parameter defaulting to `"ChatGPT"`.
