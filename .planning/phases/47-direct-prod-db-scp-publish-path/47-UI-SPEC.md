# Phase 47 — UI Design Contract

> Visual and interaction contract for the new **Direct Prod-DB + SCP Publish** page in the
> standalone local `DeckFlow.Studio` Blazor Server app. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>
> **This is NOT the public deckflow.gg site.** It is an internal, single-operator local tool.
> The visual design system is **already locked** by the existing Studio pages (Bootstrap 5 +
> open-iconic). This contract's primary job is to lock the **interaction + state machine** for
> a PROD-write flow — the two-stage gate, the diff preview, the explicit PROD confirmation, and
> the per-item reconcile list — far more than to invent new visual tokens. All tokens below are
> pulled verbatim from `Publish.razor`, `Review.razor`, `Harvest.razor`, `site.css`, and
> `MainLayout.razor.css`. **Do NOT introduce new visual tokens, fonts, or a component library.**

## Spacing Scale

The Studio uses Bootstrap's spacing utilities exclusively. Bootstrap's `1rem` base on a
16px root **is** the 8-point scale. Use only Bootstrap spacing utilities (`mt-3`, `mb-2`,
`py-2`, `px-4`, `g-2`, `gap-2`, `ms-1`, `p-3`) — never inline pixel margins/padding.

| Token | Value | Bootstrap class | Usage (as already used in Studio) |
|-------|-------|-----------------|-----------------------------------|
| xs | 4px | `*-1`, `gap-1` | Inline badge gaps, `ms-1` after a badge |
| sm | 8px | `*-2`, `g-2`, `gap-2`, `py-2` | Compact stacks; alert vertical padding `py-2`; flex `gap-2` |
| md | 16px | `*-3`, `px-4` content gutter | Default element spacing; card top margin `mt-3`; table top `mt-3` |
| lg | 24px | `*-4` | Section break between major cards (`mt-4` as on Harvest) |
| xl | 32px | `*-5` | Reserved — rarely needed at this density |

Exceptions (carried verbatim from existing pages — keep, do not invent new ones):
- Scrollable code/preview panes use inline `style="max-height:300px;overflow-y:auto;font-size:0.875rem;font-family:monospace"` (matches `Publish.razor` diff `<pre>` and `Review.razor` content preview).
- Fixed narrow table columns use inline `style="width:40px"` / `style="width:50px"` for checkbox/chevron cells (matches `Review.razor`).
- Truncated title cells use inline `style="max-width:300px"` + `class="text-truncate"` (matches `Review.razor`).

## Typography

Studio uses Bootstrap heading/utility classes — no custom type scale. Mirror `Publish.razor`
exactly: page `h1.h4.fw-semibold`, card titles `h2.h5.fw-semibold.mb-0`, sub-card titles
`h3.h6.fw-semibold`. Two weights only: regular (400, default) and semibold (`fw-semibold`).

| Role | Size | Weight | Line Height | Class (existing) |
|------|------|--------|-------------|------------------|
| Page heading | 1.5rem (`h4`) | semibold | Bootstrap default (~1.2) | `h1 class="h4 fw-semibold"` |
| Card heading (stage) | 1.25rem (`h5`) | semibold | ~1.2 | `h2 class="h5 fw-semibold mb-0"` |
| Sub-card heading | 1rem (`h6`) | semibold | ~1.2 | `h3 class="h6 fw-semibold"` |
| Body / lead | 1rem | regular | 1.5 (Bootstrap default) | `p.text-muted` lead; default `<p>` |

| Small / hint | 0.875rem (`small`) | regular | 1.5 | `span class="text-muted small"`, `form-text` |
| Monospace (code/diff/path) | 0.875rem | regular | 1.5 | `<code>`, `<pre style="font-family:monospace">` |

No new font sizes. No third weight.

## Color

The Studio palette is Bootstrap 5 semantic theme colors plus two app-specific overrides in
`site.css` (`a/.btn-link` `#0071c1`, `.btn-primary` `#1b6ec2`) and the sidebar gradient in
`MainLayout.razor.css`. Reuse these — do not add hexes inline.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / `#fff` (body, card bodies, `bg-white`) | Page + card backgrounds |
| Secondary (30%) | `#f7f7f7` top-row, `table-light` headers, `bg-light` (`#f8f9fa`) panels, sidebar gradient `rgb(5,39,103)→#3a0647` | Nav sidebar, card headers, table heads, code panes |
| Accent (10%) | primary blue `#1b6ec2` / link `#0071c1` (`btn-primary`, `text-primary`, `border-primary`) | See reserved list below |
| Destructive | Bootstrap `danger` red (`btn-*-danger`, `alert-danger`, `bg-danger`, `border-danger`, `table-danger`) | The PROD-write affordance + errors — see below |

**Accent (primary blue) reserved for:**
- The Stage-1 trigger button (`btn-outline-primary`) — "Compute Prod Diff" (matches `Publish.razor` Export button).
- Active state on any nav-tab / filter control (`nav-link active`), if used.
- Spinner color (`text-primary`) on in-flight buttons.
- The diff-preview sub-card border + heading (`border-primary`, `text-primary`) — matches `Publish.razor` Diff Preview card.
- NOT used for the actual PROD-write step buttons — see PROD-danger affordance below.

**PROD-danger affordance (phase-specific, the most important color rule here):**
Because both write steps target **production**, the two write-step buttons and the target
banner MUST use the **danger** treatment, not primary — this is the one place the Studio
deviates from `Publish.razor` (which writes only to the local git tree and uses primary).

| Element | Treatment |
|---------|-----------|
| "TARGET: PRODUCTION" banner (always visible above the diff) | `alert alert-danger py-2` with bold "PRODUCTION" text + `oi oi-warning` icon |
| Stage-2 button "Upload Artifacts to Prod /data (SCP)" | `btn-danger` |
| Stage-3 button "Write Approved Rows to Prod DB" | `btn-danger` |
| Per-item success badge | `badge bg-success` ("Uploaded" / "Written") |
| Per-item failure badge | `badge bg-danger` ("Failed") |
| Skipped/blocked badge | `badge bg-secondary` |
| "Prod connection: not configured" / "SCP: not configured" disabled banner | `alert alert-warning py-2` (`text-dark`) |
| Errors | `alert alert-danger py-2` (matches every existing page) |
| Success summary | `alert alert-success py-2` |

Configured/not-configured status pills (SC5 — presence only, never the value):
`badge bg-success` "configured" / `badge bg-secondary` "not configured".

## Interaction & State Contract (the core of this phase)

This is the load-bearing section. The visual tokens above are inherited; the planner/executor
must implement this state machine exactly. It mirrors the `Publish.razor` two-stage pattern
but adds a third stage and a per-item reconcile list, and swaps primary→danger on write steps.

### Page skeleton (mirror `Publish.razor`)
```
<h1 class="h4 fw-semibold">Publish to Production (Direct)</h1>
<p class="text-muted">…lead…</p>
<article class="content px-4">
  [config gate]  → if not configured: render warning banner, stop.
  [status header] → "N entries approved and ready" + prod/SCP "configured" pills.
  [TARGET: PRODUCTION danger banner]   (always visible once configured)
  Card: Stage 1 — Compute Prod Diff
  Card: Stage 2 — Upload Artifacts (SCP)   (shown after diff ready)
  Card: Stage 3 — Write Rows to Prod DB    (shown after diff ready; button gated on Stage 2)
  [post-run success summary]               (outside the stage cards, like Publish.razor)
</article>
```

### State machine
| State | Condition | Visible UI |
|-------|-----------|------------|
| **Loading** | `OnInitializedAsync` in flight | spinner + "Resolving configuration…" (matches `Publish.razor` init spinner) |
| **Not configured** | `!IsProdConfigured` OR `!IsScpConfigured` | `alert alert-warning`; show which is missing; all action buttons absent/disabled. No diff, no write. |
| **Ready (no approved rows)** | configured, `approvedCount == 0` | empty-state copy; Stage-1 button disabled. |
| **Idle** | configured, `approvedCount > 0`, no diff yet | TARGET banner + Stage-1 button enabled (`btn-outline-primary`). |
| **Diff computing** | Stage-1 in flight | Stage-1 spinner; button disabled; `_operationInFlight=true`. |
| **Diff ready** | diff computed OK | Diff Preview sub-card (New/Updated counts + per-row + per-file lists); confirmation checkbox; Stage-2 + Stage-3 cards appear. Stage-2 button enabled only when checkbox checked. Stage-3 button **disabled** (hint shown). |
| **SCP running** | Stage-2 in flight | Stage-2 spinner; per-file list streams success/fail badges; both stage buttons disabled. |
| **SCP complete (all OK)** | every file uploaded | Stage-2 success summary; Stage-3 button **enabled** (still `btn-danger`). |
| **SCP partial failure** | ≥1 file failed | per-file list shows failed rows w/ reason; Stage-3 stays **locked**; overall SCP-failed error copy; re-run-upload allowed. |
| **DB running** | Stage-3 in flight | Stage-3 spinner; per-row list streams success/fail; buttons disabled. |
| **DB complete (all OK)** | every row written | DB success summary (notes is_visible/is_evergreen preserved). |
| **DB partial failure** | ≥1 row failed | per-row list shows failed rows w/ reason; DB-failed error copy; reconcile-the-subset guidance. |

### Gating rules (locked — D-06, D-09)
1. **Confirmation gate:** the "I have reviewed…" checkbox (`form-check-input` + `form-check-label`, identical markup to `Publish.razor` `#diffReviewed`) MUST be checked before the Stage-2 SCP button enables.
2. **Artifact-first gate:** the Stage-3 (DB) button is `disabled` until Stage-2 reports **full** success (every file uploaded). A single failed file keeps Stage-3 locked. (Pitfall 2 / SC2.)
3. **Single in-flight guard:** reuse the `_operationInFlight` boolean pattern from `Publish.razor`/`Review.razor` — only one stage runs at a time; all other buttons disable while any stage runs.
4. **Disabled-not-hidden when unconfigured:** when prod/SCP config is absent, render the warning banner and keep the page reachable but inert (D-09).

### Diff preview presentation (D-04 / D-05 / SC1)
- Reuse the `Publish.razor` Diff Preview sub-card shell: `card border-primary` → `card-body` → `h3.h6.fw-semibold.text-primary` "Diff Preview".
- Count badges row (matches `Publish.razor`): `badge bg-success` "New: N", `badge bg-primary` "Updated: N". (No "Removed" — direct push only writes; it never deletes prod rows.)
- A `dl.row` showing target = **PRODUCTION** (in danger text) and the artifact target path described **by label only** ("Remote artifact path: configured") — never the literal path (D-07).
- **Per-row list** (New + Updated rows): a `table table-sm table-hover align-middle` (mirror `Review.razor`) with columns: Title, Natural key (type/value), New-vs-Updated badge, Artifact file name. This is the row set that Stage 3 will upsert.
- **Per-file list** for Stage 2: the resolved artifact file set to SCP (one row per file), columns: Artifact path (relative, repo-style — safe to show; it is not a secret), and a status cell that starts blank and fills with success/fail badge during the run.

### Reconcile list presentation (D-05 / SC4) — the key partial-failure surface
Both write steps render a **per-item status table** detailed enough to reconcile the failed
subset manually without re-running the whole set:
- **SCP (Stage 2): per-file.** Columns: File (relative path), Status badge (`bg-success` Uploaded / `bg-danger` Failed / `bg-secondary` Pending), Reason (failure message text, shown only on failure; never include host/key/remote-path — surface SSH.NET's structured error message with secrets redacted).
- **DB (Stage 3): per-row.** Columns: Title, Natural key, Status badge (`bg-success` Written / `bg-danger` Failed / `bg-secondary` Pending), Reason (on failure).
- Counts-only is explicitly rejected (D-05). The operator must be able to read exactly which file/row failed and why.
- Lists persist after the run so the operator can act on them; a failed SCP run leaves Stage 3 locked and the per-file list on screen.

### Async / disposal pattern (carried — Pitfall 7, D-09)
Mirror `Publish.razor`/`Review.razor` verbatim: `@implements IDisposable`; `Task.Run` for the
store/SCP/network work off the Blazor sync context; `InvokeAsync(StateHasChanged)` with
`try/catch (ObjectDisposedException)/(InvalidOperationException)`; a component-scoped
`CancellationTokenSource` cancelled+disposed in `Dispose()`. Per-item progress streams via
the existing `ActionOrchestratorProgress` sink pattern so the lists fill live.

### Nav entry (mirror `NavMenu.razor`)
Add one `nav-item px-3` with a `NavLink class="nav-link" href="direct-push"` and
`<span class="oi oi-data-transfer-upload" aria-hidden="true"></span> Direct Push`, placed
directly below the existing "Publish" entry. Same markup shape as the four existing entries.

### Accessibility (carried from existing pages)
- Every spinner: `role="status"` + `aria-label="Operation in progress"` + `<span class="visually-hidden">Loading...</span>` (verbatim from existing pages).
- Streaming lists / live regions: `aria-live="polite"` on the per-item status containers (matches the `Publish.razor` diff `<pre role="log" aria-live="polite">`).
- Disabled write buttons keep an `aria-label` describing why they are disabled (matches `Review.razor` approve-disabled pattern).
- Checkbox uses `<label for>`/`id` association (matches `Publish.razor` `#diffReviewed`).
