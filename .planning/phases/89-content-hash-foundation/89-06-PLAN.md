<objective>
Add the one-time deterministic backfill (D-08) as a host-agnostic `DeckFlow.Core` service and wire it on BOTH hosts: the web app startup (after `EnsureSchemaAsync()` + `LoadIfPresentAsync()`, covering prod + local-web) AND the Studio local `content-kb.db` store startup (after its store registration at `DeckFlow.Studio/Program.cs:81`). The service computes `body_sha256` for every row whose stored hash is null, resolving each `ArtifactPath` through an injected artifact-body resolver (Web adapts `ContentKbArtifactPathResolver`; Studio adapts its artifact root) and hashing via the shared `ComputeBodySha256` helper, persisting through the null-only setter (89-02). Idempotent, DDL-free, skips missing files with a warning.

Purpose: D-08 explicitly requires the backfill on BOTH "the web app startup/seed path for prod AND the Studio/publish path for local." Studio registers its own `new ContentSiteIndexStore(contentKbDatabasePath)` (Program.cs:81), so a web-only backfill would leave legacy local rows with `BodySha256 == null` while web rows get hashed — producing false divergence during DirectPush/Pull compares under the unified signature (89-01/89-03). Hosting the service in Core (it needs only `IContentSiteIndexStore` + a resolver seam + `ComputeBodySha256`) lets both hosts consume it. Depends on 89-01 (helper) and 89-02 (`GetAllRowsAsync` + `SetBodySha256IfNullAsync`).
Output: Core backfill service + resolver seam + Web adapter/wiring + Studio adapter/wiring; Core.Tests logic coverage + Studio.Tests local-path coverage.
</objective>

| T-89-13 | DoS | startup cost over many rows | accept | One-time single pass over existing rows (hundreds, per the prod audit); one resolver read + SHA per null row. Bounded, runs once at boot on each host. No new dependency (T-89-SC: SHA256 BCL). |
