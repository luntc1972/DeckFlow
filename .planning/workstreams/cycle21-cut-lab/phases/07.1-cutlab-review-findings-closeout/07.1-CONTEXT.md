## Locked constraints (violating these is how these defects were made)

1. **Line endings.** Preserve each touched file's existing endings exactly; detect per file.
   Verify `git diff --stat` against `git diff --ignore-all-space --stat` — they must agree.
2. **Guild themes are standalone CSS forks.** A theme fix requires a census across all 24
   (`site.css` + 23 `site-*.css`, excluding `site-common.css`, `site-mobile.css`,
   `site-theme-overrides.css`, `admin-*.css`). Fixing three by hand is the exact failure F-6
   records. Layout CSS goes in `site-common.css`, never `site.css`; token values go in each
   theme's `:root`.
3. **`aria-disabled`, never native `disabled`.** `_WorkflowStepTabs.cshtml:24-32` documents
   why; the `type`/`form` binding must stay unconditional (making it conditional previously
   left the Export tab looking enabled while submitting nothing — `cut-lab-export.spec.ts:141`).
4. **The partial is shared by five tools.** `_WorkflowStepTabs.cshtml` and `site.ts` reach
   CedhMetaGap, DeckPrimer, DeckComparison, DeckAnalysis and CutLab. Prefer changes scoped to
   `cut-lab.ts` / `CutLab.cshtml`; if a shared file must change, census all five consumers first.
   `UseMobileLabeledTabs` is Cut Lab-only — verified, only `CutLab.cshtml:18` passes `true`.
5. **Every new or changed test needs a named killing mutation, run and shown to fail.**
   A green test is not evidence on this branch.
6. **Changed C# lines must satisfy the changed-lines format gate**; the five `.editorconfig`
   carve-outs apply — notably never convert `{ get; init; }` to `{ get; }`.

## Decisions left deliberately open — planning must state these, not default into them

**D-1 — F-5 hiding mechanism.** Hide non-current panels client-side on init, server-side in
`CutLab.cshtml`, or both; and what happens with JavaScript off. Server-rendered `hidden` strands
the other steps for a JS-off user; client-only leaves five panels in the first paint. Genuine
fork — pick one and record the reasoning.

**D-2 — F-5 collapse side effect.** `activateStepTab` calls
`if (readCollapsedSectionIds() === null) applyDefaultSectionCollapseState(step)`
(`cut-lab.ts:506-508`), which force-opens the step's primary `<details>` and closes the rest.
Reaching panel-hiding *through* `activateStepTab` on load would run that on every page load for
a user with no stored state, changing which sections are open on arrival. Nothing is persisted
(`applyDefaultSectionCollapseState` does not write `localStorage`), but the visual default moves.
Decide explicitly whether init should hide panels **without** the collapse side effect.

**D-3 — F-7 direction.** The review's phrasing points at declaring `nextProposal` nullable on
both sides, since `null` is what the builder emits. The alternative — making `BuildAdjustPatch`
always emit a non-null marker — changes the wire payload and what the client renders, so it is a
behaviour change, not a contract correction. **Prefer nullable unless the consumer census argues
otherwise**, and run the census (every builder path, every TS consumer), not a sample.

**D-4 — the no-tab-selected fallback.** `attachStepTabHandler` returns early when no tab is
`aria-selected="true"`, leaving all five panels visible (`cut-lab-step-tabs.test.ts:83`). That is
defensible progressive enhancement — content must never be stranded behind a tablist with no
selection. State the chosen behaviour explicitly rather than changing it by accident.

## Edge cases the planner must carry into tasks

- **Focus and selection must decouple.** `cut-lab-step-tabs.test.ts:70` asserts Plan *receives
  focus* on ArrowRight, and that is correct roving-tablist behaviour — its own recorded killing
  mutation is "skip aria-disabled tabs during ArrowRight traversal", i.e. the naive R2-1 fix
  breaks it. Keep focus moving; add the missing `aria-selected === 'false'` assertion.
- **Home / End and wrap-around** hit the same predicate as ArrowLeft/ArrowRight.
- **Reserved panel 3 must stay in the DOM** — `aria-controls` points at
  `cut-lab-step-panel-3`; a dangling `aria-controls` is its own a11y defect.
- **The theme census may find more than three failures.** Those are in scope — the point of
  widening `workflowComponentThemes` is that the fix and the test stop sharing a blind spot.
- **Raising `--muted` affects every element using it** (`site-common.css` alone has 49
  `var(--muted)` uses, `site.css` 14). Check each raised value against `--bg` as well as
  `--panel`, and against the named elements the existing 24-theme sweep already asserts.
- **Density precondition must bound the right population.** `twins.Count > 0` is the minimum;
  evidence-level assertions also need at least one evidence entry, or the inner loop stays
  vacuous even with a nonempty outer list.
