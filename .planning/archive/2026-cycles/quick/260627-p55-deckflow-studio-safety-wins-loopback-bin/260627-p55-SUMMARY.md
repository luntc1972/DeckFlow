# Phase 260627-p55 Plan 01: DeckFlow Studio Safety Wins Summary

Three independent, low-risk safety fixes to DeckFlow.Studio: loopback-bind guard, read-only diff path, and exception logging.

## What Was Built

### Task 1 — Loopback-bind guard at startup (H2) [TDD]

`DeckFlow.Studio/LoopbackBindGuard.cs` — `internal static class` with three pure, testable members:

- `IsLoopbackBindUrl(string)` — classifies a Kestrel bind URL as loopback-only or non-loopback. Handles bracket IPv6 (`[::1]:5271`), bare IPv6 (`::1`), numeric IPs via `IPAddress.IsLoopback`, and explicit wildcards (`0.0.0.0`, `+`, `*`, `::`, `[::]`). Fails closed: null/whitespace returns false.
- `FindNonLoopbackBindings(IEnumerable<string>)` — filter returning only offending URLs.
- `GatherConfiguredBindUrls(IConfiguration)` — assembles effective bind URLs from ASPNETCORE_URLS/`--urls`, `Kestrel:Endpoints:*:Url`, and the Studio default `http://localhost:5271`.

`DeckFlow.Studio/Program.cs` — guard wired right before `await app.RunAsync()`: if any configured URL is non-loopback, logs a Fatal message naming the offending host(s) and throws `InvalidOperationException`, so Kestrel never gets to bind.

`DeckFlow.Studio.Tests/LoopbackBindGuardTests.cs` — 15 xUnit tests covering all loopback-true cases (localhost, 127.x, [::1], ::1), all non-loopback-false cases (0.0.0.0, +, *, [::], LAN IP, DNS), `FindNonLoopbackBindings` mixed-list, and `GatherConfiguredBindUrls` (Kestrel endpoint, ASPNETCORE_URLS, and default fallback).

TDD gate sequence: RED commit `9fc1aee5` → GREEN commit `1ddccc9a`.

## Deviations from Plan

None — plan executed exactly as written. One implementation clarification:

The spec's `IsLoopbackBindUrl` algorithm for "http://::1" (bare IPv6 without brackets) extracts an empty host (`authority = "::1"`, `host = ""`) via the standard path. Rather than treating empty host as an unconditional `false`, a bare-IPv6 fallback (`authority[0] == ':' → IPAddress.TryParse(authority)`) is used, which correctly returns `true` for `::1` and `false` for `::`. This matches the behavior spec exactly and is aligned with the spec's "IPv6 in authority starts with ':'" intent.
