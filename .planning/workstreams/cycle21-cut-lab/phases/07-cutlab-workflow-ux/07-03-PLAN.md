<task type="auto">
  <name>Task 1: Re-parent the loose sections into their panels</name>

<task type="auto">
  <name>Task 2: Implement activation in cut-lab.ts</name>

  Add `attachStepTabHandler()`:

  - Read `button.dataset.cutLabStep`; ignore non-numeric.
  - Set `hidden` on every `[role="tabpanel"]` whose step is not the target;
    remove `hidden` from the target. Use the `hidden` attribute, not a CSS class
    — it degrades correctly and needs no stylesheet coordination.
  - Move `aria-selected="true"` and `tabindex="0"` to the clicked tab; the rest
    get `aria-selected="false"` and `tabindex="-1"` (roving tabindex). Toggle
    `.is-active` in the same initial and interactive activation path: active gets
    it, every other tab loses it.
  - Focus the newly-shown panel with `preventScroll: true`, then scroll it into
    view honoring `prefers-reduced-motion`. `scrollJumpTargetIntoView` and
    `focusJumpTarget` already exist at `cut-lab.ts:452-466` — reuse them, do not
    duplicate.
  - Skip entirely when the button is `disabled` (tab 4 before 100 cards).

  Add `ArrowLeft` / `ArrowRight` / `Home` / `End` keydown handling on the
  tablist, skipping disabled tabs. The ARIA tabs pattern is already claimed by
  the existing `role="tab"` markup, so this is owed, not extra.

  **Tab 5 is both a submit and a tab.** It carries
  `form="cut-lab-export-form"`. Do not `preventDefault()` — let the submit
  proceed, and activate the panel first so a failed/slow submit still leaves the
  user looking at Export.
</task>

<task type="auto">
  <name>Task 3: Initial state on load</name>

  On DOM ready, activate the step the server already chose. Do not recompute it
  in TS — read the tab that carries `aria-selected="true"`, which
  `_WorkflowStepTabs.cshtml:10-12` already renders as "first enabled incomplete
  step". One source of truth; TS follows the server.

  If no tab carries `aria-selected="true"` (defensive), leave every panel visible
  and return — degrade to today's behavior rather than hiding everything.
</task>

    project CSS rule — never in `site.css`, and never keyed on anything but the
