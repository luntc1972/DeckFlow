## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator UI -> Core maintenance orchestrator | Unblock crosses here; recovery action (re-allows harvest), non-destructive |
| Local DB (blocked_videos) -> page | Read of blocked rows for display; local-only tool, no auth surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-56-03-01 | Tampering | UnblockVideoAsync wrong-id | mitigate | Page passes the exact `BlockedVideoListItem.YoutubeVideoId` to UnblockVideoAsync; bUnit test pins that the recorded call matches the clicked row's id |
| T-56-03-02 | Denial of Service | ListBlockedAsync on Blazor sync context | mitigate | All orchestrator calls wrapped in Task.Run; UI updates via disposal-safe InvokeAsync (Pitfall 4) |
| T-56-03-03 | Information Disclosure | Exception message leaking internal paths into alert | mitigate | Error copy is "Could not load blocked videos — {message}" / "Unblock failed — {message}"; orchestrator already maps to operator-safe copy; do not echo stack traces |
| T-56-03-04 | Repudiation | Unblock re-allows previously-blocked content silently | accept | Local operator-only tool; unblock is an intentional reversible recovery action and the blocked_videos row removal is the audit record |
| T-56-03-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs; bUnit + xUnit already present |
</threat_model>
