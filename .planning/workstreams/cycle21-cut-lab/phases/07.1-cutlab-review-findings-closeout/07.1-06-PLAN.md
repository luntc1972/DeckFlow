<objective>
Close R2-2: replace the synthetic F-1 regression guard with one that asserts against production
markup, so passing it certifies that a real workflow control beneath the pinned proposal still
receives a click.

Purpose: `e2e/cut-lab-workflow-ux.spec.ts:183` creates a `position: fixed` `<button>` in
JavaScript, appends it to `.cutlab-proposal__body`, and checks it receives a click. Production
never emits such an element. The guard is not inert — making `.cutlab-proposal--pinned` intercept
pointer events can fail it — but passing it says nothing about a real control, and F-1's original
defect was precisely "tests went green against a live defect".

Output: a guard aimed at markup the page renders, with an explicit overlap precondition so it
cannot go vacuous.
</objective>

**D-8 (guard target) — locked: the delta-expander summary inside `.cutlab-proposal__body`.**
`CutLab.cshtml:975-982` renders `<details data-cut-lab-delta-expander>` with a
`<summary>Show full metric breakdown</summary>` inside the proposal body, and `cut-lab.ts:2654-2656`
renders the same element on the AJAX path. It is the only interactive control production puts
beneath the sticky pinned block, and its `open` state is a real, observable consequence of a real
click — a stronger signal than any geometry assertion alone.
Reversibility: **reversible** — test-only.

**D-9 (missing target is a failure, never a skip) — locked.**
The expander renders only when `Model.Proposal.DeltaUnavailableMessage` is empty
(`CutLabViewModel.cs:742` sets it when proposal deltas are null). If the e2e pool ever stops
producing deltas the control disappears — and the guard must then FAIL with a diagnostic naming
what was missing, not skip, not silently degrade to the geometry-only half. A guard that quietly
stops guarding is the R2-2 defect wearing different clothes.
Reversibility: **reversible**.

**Do not touch `site.ts` or `_WorkflowStepTabs.cshtml`.** Both are shared by five tools. This plan
edits one e2e spec and nothing else; `site-common.css` is mutated transiently in Task 2 and
restored byte-for-byte.
</locked_decisions>

       same way G-5 does at `:137-139`.
    2. Locate `details[data-cut-lab-delta-expander]` and its `> summary`. Assert the summary is

    4. Scroll so that the summary's centre point lies INSIDE the bounding rectangle of
       `.cutlab-proposal--pinned`. Because the pinned block is `position: sticky`, scrolling the
       page down moves body content up underneath it; scroll in a loop until the two rectangles
       overlap at the summary's centre, up to a bounded number of attempts.
    5. **Assert the overlap precondition explicitly**: the summary's centre point is within the
       pinned block's rectangle. If it is not, fail with a message reporting both rectangles. This
       is the vacuity guard — without it the test could pass by clicking a point the pinned block
       never covered, which is exactly the class of defect R2-2 records.

       of it — not `.cutlab-proposal--pinned` and not a descendant of the pinned block.
    7. Click at that exact point with a real pointer event (`page.mouse.click` at the coordinates,
       not `locator.click()`, which would auto-scroll and re-derive its own point and so bypass the
       overlap the test just established).
    8. Assert the `details` element's `open` state flipped. That is the real control observing the
       real click.

    Nothing in the test creates an element, sets an inline `position`, or appends to the DOM. The
