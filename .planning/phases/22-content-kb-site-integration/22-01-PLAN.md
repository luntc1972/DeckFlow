<objective>
Extend the existing `ContentSiteIndexStore` (Phase 19, Render-bound slim index) with the curation primitives every other Phase 22 plan depends on: an additive `is_visible` column (default hidden, both SQLite + Postgres), a visibility-preserving upsert for the commit-then-deploy seed path, published-only / all-rows / by-id reads, per-entry and per-source visibility setters, and the `content.kb.enabled` feature-flag seed row (default OFF).

Purpose: This is the data-layer foundation. The CLI export (Plan 02), public browse + seed loader (Plan 03), and admin curation grid (Plan 04) all bind to these contracts. Getting the visibility-preserving upsert exactly right is the single highest-risk item in the phase (Pitfall 1: a naive upsert re-hides everything on every deploy).

Output: Extended store + interface + row record + flag seed + a focused Core.Tests fixture proving the migration, the visibility-preserving upsert, and the new queries.
</objective>
