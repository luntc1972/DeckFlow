Build the pure, Core-testable half of the creator-style artifact engine: a deterministic rubric scorer that diffs a submitted deck's statistics against a creator's fused numeric targets, plus a pure exemplar-deck selection rule. No I/O, no DI, no HTTP, no LLM anywhere in this plan.

Purpose: Isolate all the deterministic scoring/selection logic (CS-27 + the selection half of CS-28) into pure functions that unit tests can exercise with hand-built fixtures, satisfying Success Criterion #4 ("no controller or page dependency") for the scoring core. The Web orchestrator (Plan 99-03) consumes these.
Output: `CreatorStyleRubricScorer` (Core static), `SubmittedDeckStats`/`RubricScoreResult`/`RubricMetricScore` records (Core), `CreatorDeckExemplarSelector` (Web static), and their unit tests.
</objective>

FusedTarget (DeckFlow.Core/Knowledge/CreatorStyleProfile.cs) — the creator targets to diff against:
  required string Metric; required double Value; required double Weight; required string Source;
  string? Condition; double? StatedMin; double? StatedMax; double? MeasuredValue; int? NumDecks;
  double? EffectiveSampleSize; string? Verdict; string? VerdictReason; string? Confidence; FusedConflict? Conflict.
  All properties use { get; init; } — DO NOT change to { get; } (System.Text.Json drops get-only members on .NET 10).

Metric-key join — TWO vocabularies, bridged by StatedMetricKeyMapper (NOT a single verbatim key set):
  - FusedTarget.Metric is in the STATED vocabulary. ProfileFusionEngine assigns `Metric = rule.Metric`
    (ProfileFusionEngine.cs:67-70 and every other FusedTarget construction), i.e. the bare stated keys from
    StatedRulesMetricVocabulary.Metrics (StatedRulesExtraction) — "ramp", "removal", "draw", ... (the 11
    ContentTagVocabulary.CardCategories) plus "karsten:target_lands", "karsten:land_delta", "karsten:health_score",
    "combo_density:included_per_deck", and stated-only keys ("land_count", "interaction", ...).
  - SubmittedDeckStats is keyed by the MEASURED vocabulary: "category_ratio:{category}", "karsten:target_lands",
    "karsten:land_delta", "karsten:health_score", "combo_density:included_per_deck".
  - The scorer MUST bridge the two via StatedMetricKeyMapper.TryMapToMeasuredKey(statedMetric, out measuredKey)
    (StatedMetricKeyMapper.cs:80-91): "ramp" -> "category_ratio:ramp", "removal" -> "category_ratio:removal", ...,
    and the karsten:*/combo_density:* keys map to themselves. When it does NOT map (stated-only keys like
    "land_count"/"interaction"), there is no measured counterpart -> emit "insufficient-measured".
  - DO NOT look up FusedTarget.Metric directly against SubmittedDeckStats — a bare "ramp" target will never
    match a "category_ratio:ramp" stat and would silently produce all-insufficient rows (the exact HIGH finding).

Verdict/confidence vocabulary — reuse from ProfileFusionEngine (DeckFlow.Core/Knowledge/ProfileFusion/ProfileFusionEngine.cs):
  FusedTarget.Confidence is ALREADY a banded string? ("high"/"med"/"low", or null for measured-only targets) —
  it was banded at fuse time by ProfileFusionEngine.ToConfidenceBand. The scorer copies it verbatim; it must
  NOT re-band it or replicate ToConfidenceBand (that helper takes a double and does not apply here).
  Verdict string "insufficient-measured" for a fused target that has no comparable submitted-deck value.

CreatorDeckCacheEntry (DeckFlow.Core/Content/CreatorDeckCacheEntry.cs) — the exemplar corpus row:
  required string CreatorSlug; required string DeckId; required string ContentHash; int? FolderId;
  string? FolderName; required int Size; required string ConfidenceMarker;
  required IReadOnlyList<DeckEntry> Entries; required DateTimeOffset CachedUtc.

ProfileFusionEngine pure-static shape to mirror (DeckFlow.Core/Knowledge/ProfileFusion/ProfileFusionEngine.cs:20):
  public static IReadOnlyList<FusedTarget> Fuse(IReadOnlyList<MeasuredMetric> measured, IReadOnlyList<StatedRuleCandidate> statedRules)
  — ArgumentNullException.ThrowIfNull guards at entry; deterministic OrderBy/ThenBy on output; no await, no I/O.
