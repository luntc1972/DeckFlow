Close SC-4 and SC-5.

Round-1 review upgraded SC-4 from "write a decision, probably a decline" to "this is the
highest-leverage fix in the phase, with measured evidence, at zero network cost."

The measured facts (`111.1-REVIEWS.md` §0, orchestrator-run live probes, 2026-07-31):
- `/cards/collection`'s `name` identifier IS punctuation-tolerant: it resolves `Smugglers Copter`
  and returns `Smuggler's Copter`.
- It does NOT accept combined multiface names in either slash form: both `Fire / Ice` and
  `Fire // Ice` come back in `not_found`.

Consequence (§0 C-2): the phantom-miss generator is PUNCTUATION, not DFC separators.
`ScryfallReferenceResolver.cs:136` matches the returned card back with raw
`string.Equals(name, card.Name, OrdinalIgnoreCase)`, so `Smugglers Copter` vs the returned
`Smuggler's Copter` fails, and a card the batch call ALREADY HAS IN HAND costs a full extra
round-trip. That is the burst, and it is pure waste. DFCs are a different, smaller, and legitimate
case: `collection` genuinely cannot resolve them, so their fallback is real work.

This plan adds an ADDITIVE second pass over the already-received batch response, applied only to
names the existing raw pass left unmatched. It does not remove or weaken the raw pass, and — verified
analytically below and to be re-verified by running the tests — it does not change the DFC behavior
the "H2 lock" test (`ScryfallReferenceResolverTests.cs:27-52`) pins.

Output: one ADR, one shared-collaborator change with two new tests, one corrected xmldoc.
No live Scryfall calls. Research assumption A1 is DISCHARGED by §0 and is not re-probed.

The "do not fix" guard, `ScryfallReferenceResolver.cs:52-61` (excerpt) — item 2 stays TRUE after
this change and must not be deleted:
> Collection hits are matched back by comparing the ORIGINAL request name to the RETURNED card's
> `Name` (Ordinal-IgnoreCase). When `normalizeForScryfall`-equivalent normalization is ON, it affects
> ONLY the submitted identifier -- never the match key -- so a single-slash Archidekt name (`"A / B"`)
> that normalizes to `"A // B"` on submission and gets returned as `"A // B"` will NOT match its
> original `"A / B"` request and falls through to the fallback strategy, exactly as today.

WHY `CardNormalizer.Normalize` IS THE WRONG KEY — verified against
`DeckFlow.Core/Normalization/CardNormalizer.cs:15-33`, which (a) collapses `" // "` to `" / "` and
then TRUNCATES at the first `" / "`, dropping the DFC back face, and (b) replaces punctuation with a
SPACE rather than deleting it:
- `Normalize("A / B")` = `"a"` and `Normalize("A // B")` = `"a"` -> EQUAL. Using it would turn the
  H2 lock's fixture into a direct hit and BREAK that test. Round-1 review §0 C-3 argued the H2 test
  survives because the single-slash case "lands in not_found at the API" — that argument is about the
  LIVE API and does NOT hold for the H2 test, whose fixture returns the card in `data` with
  `NotFound: []` (`ScryfallReferenceResolverTests.cs:257-262`). The argument was explicitly flagged as
  needing verification; it has now been verified and is REJECTED for `CardNormalizer`.
- `Normalize("Smuggler's Copter")` = `"smuggler s copter"` but `Normalize("Smugglers Copter")` =
  `"smugglers copter"` -> NOT equal. `CardNormalizer` does not even fix the punctuation class it
  would be adopted for.

THE KEY THIS PLAN USES INSTEAD — punctuation-deleting and slash-PRESERVING:
  1. trim, `ToLowerInvariant()`
  2. delete (do not replace with a space) every character that is not a Unicode letter, digit,
     whitespace, or `/`  — i.e. regex `[^\p{L}\p{N}\s/]` -> `string.Empty`
  3. collapse `\s+` to one space, trim
