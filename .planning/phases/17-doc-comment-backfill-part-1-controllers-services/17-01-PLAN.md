<objective>
Backfill XML `<summary>` doc-comments on the 7 undocumented public types across the 5
Controllers files in scope (Controllers root, Controllers/Admin/, Controllers/Api/).

Purpose: Reduce documentation debt on the highest-traffic Web surface so the NoWarn
suppression can be removed in Phase 23 (not this phase). DOC-01 partial coverage.
Output: 5 source files with added `///` doc-comments only — zero runtime/behavior change,
zero code-line churn.

Per-type discipline: SC1's ROADMAP-anchored grep is file-level (`grep -L '<summary>'`), which
passes any file that has at least ONE `<summary>` anywhere — even if a co-located type in that
same file is undocumented. AdminFeedbackController.cs holds 3 public types (an enum, a view model,
and the controller); documenting only one of them would silently satisfy the file-level grep while
leaving the other two undocumented. (This is the same blind spot that hid
DeckFlowDatabaseConnectionFactory in plan 17-02.) Acceptance here therefore checks EVERY public type
declaration has a `<summary>` on its own declaration line, in addition to the file-level grep.

Execution note (CLAUDE.md): Codex writes the doc-comments; Claude reviews. This plan is
written to be Codex-executable — the D-01..D-04 rules are inline in each task action.
</objective>

<doc_comment_rules>
<!-- Locked decisions from 17-CONTEXT.md. Apply verbatim; do NOT re-derive. -->
- Per **D-01**: Interface/impl pairs — the INTERFACE type carries the full prose `<summary>`
  (+ `<param>`/`<returns>` per D-02); the implementing class AND its public members use
  `<inheritdoc/>`. (No interface/impl pairs exist in THIS plan's files — all 7 types here
  are standalone controllers + one view model + one enum, so all get full summaries per D-01a.)
- Per **D-01a**: Standalone classes/records/enums with no interface get a full `<summary>` written
  directly.
- Per **D-02**: Add `<param>`/`<returns>` on a public method ONLY when it has >=2 *real* params
  (a trailing `CancellationToken cancellationToken = default` does NOT count toward the
  2-arg trigger) OR when the return's meaning is non-obvious from the method name.
  Single-arg self-evident methods get `<summary>` only. (Type-level summaries are the
  primary deliverable here; add method-level tags only where the D-02 threshold is met.)
- Per **D-03**: Hybrid sourcing — seed the `<summary>` text from CLAUDE.md's Component-Responsibilities
  table one-liner where the type is listed (CommanderController, FeedbackController,
  AdminFeedbackController, SuggestionsApiController, ArchidektCacheJobsController are all
  listed), VERIFY each against the actual current code, write fresh for types not in the
  table (AdminFeedbackListViewModel, AdminFeedbackOp). Inline comments explain WHY not what.
- Per **D-04**: Records get a type-level `<summary>`; `<param>` on positional fields only where the
  field meaning is not self-evident. (No positional records in this plan.)

FORMATTING (CLAUDE.md R-6 — binding): touch ONLY the `///` lines you add. NO Format Document.
NEVER convert `{ get; init; }` to `{ get; }`. NEVER inline `[Attribute]` onto the property/type
line. NEVER re-indent C# raw-string literals. Preserve LF line endings. The `git diff` for each
file MUST contain only added `///` lines — zero changes to any existing code line.

DO NOT touch DeckFlow.Web/DeckFlow.Web.csproj — NoWarn strip is Phase 23's job (Pitfall 8).
</doc_comment_rules>
