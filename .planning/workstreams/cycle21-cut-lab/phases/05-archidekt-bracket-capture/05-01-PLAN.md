Parse only top-level `edhBracket`, `deckFormat`, `theorycrafted`, `createdAt`, and `updatedAt`. **Switch on `JsonValueKind` first, then use only try-parse APIs**, and use **no bare numeric/boolean/date `Get*` accessor on any payload value** — no `GetInt32`, `GetDouble`, `GetBoolean`, `GetDateTime`, `GetDateTimeOffset`. A bare `GetInt32()` on `edhBracket: 3.5` or `1e999` throws `FormatException`/`OverflowException`, which the harvest catch filter `when (exception is HttpRequestException or InvalidOperationException)` (`ArchidektDeckCacheSession.cs:132`) does not catch and which would abort the whole `RunAsync` loop; the same throw would reach user-facing importers (`DeckEntryLoader.cs:129`, `:198`, `CategorySuggestionService.cs:183`). `GetString()` under a `JsonValueKind.String` guard is the one permitted `Get*`, because it cannot throw there and is how the numeric-string and boolean-string cases are reached.

The whitelist, per field — every rule below verified against this machine's ref pack (`Microsoft.NETCore.App.Ref/10.0.10/ref/net10.0/System.Text.Json.xml`) and by executing the parses on .NET 10:

- **`edhBracket`, `deckFormat` (integers).** `JsonValueKind.Number` → `TryGetInt32`; `JsonValueKind.String` → `int.TryParse(element.GetString(), ...)`; every other kind → null. **Non-integer and overflow numerics are malformed and parse to null**: `TryGetInt32` already returns `false` for both `3.5` and `1e999`, so the rule falls out of using `TryGetInt32` alone. **Do not reach for `TryGetDouble` and cast.** It returns `true` with `3.5`, and `true` with `∞` for `1e999`, so a `TryGetDouble → (int)` path persists `3` for `3.5` and garbage for `1e999`. `TryGetDouble` is therefore **not** on the whitelist and has no legitimate use in this parser.
- **`theorycrafted` (boolean).** **`JsonElement.TryGetBoolean` does not exist** — the type's entire `TryGet*` surface is Byte, BytesFromBase64, DateTime, DateTimeOffset, Decimal, Double, Guid, Int16/32/64, Property, SByte, Single, UInt16/32/64 — and the only boolean accessor, `GetBoolean()`, is banned above. So do not call an accessor at all: map the kind directly, `JsonValueKind.True` → `true`, `JsonValueKind.False` → `false`, `JsonValueKind.String` → `bool.TryParse(element.GetString(), ...)`, every other kind → null. A kind comparison cannot throw, which is the point.
- **`createdAt`, `updatedAt`.** `JsonValueKind.String` → `DateTimeOffset.TryParse`; every other kind → null.
- **Kind-guarding is mandatory, not stylistic.** `TryGetInt32` is safe only on a `Number` element — it throws `InvalidOperationException` on a `String`, `Null`, or `Object` element (verified). That exception *is* inside the harvest catch filter, but it would still escape into the user-facing importer paths above, so the kind switch is what keeps ROADMAP criterion 4 true.

Additionally wrap the entire metadata-extraction block so **no** exception can escape it: on any unexpected failure return `Metadata = null` and the entries parsed as before. Missing, null, malformed, array, or object values become null. Do not infer bracket locally per D-02; leave timestamp normalization to plan 05-02's repository binding.
