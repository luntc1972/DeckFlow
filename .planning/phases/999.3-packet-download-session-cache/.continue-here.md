| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Static-helper cache key over caller-supplied normalized strings | Iter-1 design used `public static string ComputeCacheKey(request, normalized, commander)` requiring controller to supply pre-normalized deck text + pre-extracted commander. Fails because (a) DeckAnalysisRequest has no CommanderName property, (b) controller cannot reproduce service-internal D-02 normalization. Caught by Codex pass-1 H1/H2/H3/H4. | blocking | Per-service async instance helper `TryComputeCacheKeyAsync(request, ct)` that re-runs the SAME private load path BuildAsync uses. Controller passes only typed Request DTO. |
| Helper commander extraction simpler than BuildAsync's write-path commander mutation | Pass-2 design used `Take(1)` + skipped ValidateCommanderAsync + skipped oracle-normalization while BuildAsync uses `Take(2)` partner heuristic + may call ValidateCommanderAsync + may oracle-normalize. Silent key divergence → preview→download cache miss persists. Caught by Codex pass-2 H1. | blocking | Single shared private helper `BuildDeckAnalysisCacheInputs(request, entries, commanderName)` called from BOTH BuildAsync write site AND TryComputeCacheKeyAsync. Write site captures pre-Scryfall commander into `preScryfallCommanderName`/`preScryfallEntries` locals around line 271 and reuses at line 467. Cache key uses pre-Scryfall commander; result still uses post-validation commander. |
| 0-byte placeholder on hit/evicted log lines | D-13 observability target is hit-ratio-vs-memory tuning; 0-byte hit/evicted lines defeat that. Caught by Codex pass-2 LOW. | advisory | `CachedEntry<TResult>(Result, SizeBytes)` envelope wraps stored value; TryGet unwraps to log real size; PostEvictionCallback casts `evictedValue as CachedEntry<TResult>` to recover real size. |
| UAT assertion of nonexistent log event | Workflow E asserted "no `Packet cache lookup` line" but D-13 emits only hit\|miss\|write\|evicted — `lookup` event does not exist. Caught by Codex pass-2 M4. | advisory | Assert ABSENCE of literal substring `'Packet cache '` (trailing space — D-13 template prefix) within wall-clock-bounded log window via `awk -v t1 -v t2 '$0 ~ /Packet cache / && $0 >= t1 && $0 <= t2'`. |
| Code-inspection substituted for empirical UAT proof of D-09 upload-write | Workflow D allowed "look at the code" instead of restart+upload-first+download sequence. Caught by Codex pass-2 M3 PARTIAL. | advisory | Mandatory empirical sequence: kill dev server → restart (cold cache) → upload zip FIRST → download. Log must show `miss` → `write` → `hit` with matching 8-char key prefix AND matching SizeBytes. Code inspection rejected. |

<context>
This is the THIRD iteration of the plan-review convergence loop on Phase 999.3. The phase optimizes preview→download by adding a 5-minute MemoryCache that BuildAsync writes to and the download controller reads from. The hard part is cache-KEY parity: write and read must compute the same SHA-256 from the same field bag, but the commander value flows through validation + oracle remapping inside BuildAsync, so the read path (which runs before BuildAsync) must reconstruct the SAME pre-mutation commander.

Pass-1 used static helpers + controller-supplied normalization — failed because controller can't reproduce service internals. Pass-2 pivoted to async per-service `TryComputeCacheKeyAsync` helpers that re-run the same private load path — but pass-2 helper's commander logic diverged from BuildAsync's. Pass-3 fixes this with ONE shared private `BuildDeckAnalysisCacheInputs` called by both, using pre-Scryfall commander captured into a separate local at line 271 and reused at line 467.

The cache key uses pre-Scryfall commander; the cached result uses post-validation commander. Different stages. Intentional. The user sees the validated name; the cache hits on a deterministic key.
