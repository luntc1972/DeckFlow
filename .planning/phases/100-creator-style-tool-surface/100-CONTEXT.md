# Phase 100: Creator-Style Tool Surface - Context

**Gathered:** 2026-07-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Ship the $0 paste-ready Creator-Style tool end-to-end: new page + controller where a user picks a creator, submits a deck, and receives a ChatGPT-ready critique packet built by the Phase 99 engine (`ICreatorStylePacketService.BuildAsync`). Feature flag seeded OFF on both dialects, packet-cache-bypass wiring, and the full web-change bundle (xUnit + Playwright desktop+mobile across themes, README, byte-identical prose gate on pre-existing artifacts). Requirements CS-30, CS-31. **This phase also solves D-14**: creator profiles must reach production, where `content-kb.db` never ships.

</domain>

<decisions>
## Implementation Decisions

### D-14 prod profile delivery (THE blocker decision)
- **D-100-01:** Profiles reach Render via a **git-shipped seed artifact** — no Postgres migration, no DirectPush this cycle. Deploy = update.
- **D-100-02:** Seed contains **fused profiles AND creator deck-cache rows** (exemplars/whitelist inputs) — full engine read-path parity between local and prod. Live APIs (Scryfall guard, Spellbook) and prod-crawled `category-knowledge.db` are NOT part of the seed.
- **D-100-03:** Seed format is **JSON files in repo** (diffable, no binary churn — public repo), hydrated into the prod-local store at startup, mirroring the `ContentKbSeedLoader` pattern in `Program.cs`.
- **D-100-04:** Seed generated by a **new DeckFlow.CLI export command**, run manually after crawl/fusion; user commits the output. No Studio UI work, no build-time export.

### Flag topology & cache wiring
- **D-100-05:** **Single flag `tool.creator-style.enabled`** (ToolRegistry convention) gates everything — tool visibility AND cache-bypass registration. The roadmap name `creator.style-artifact` is retired as an alias; requirements/roadmap references map to this one key. Seeded OFF on both dialects; operator flips in /Admin/Flags.
- **D-100-06:** Creator-style packet **uses `PacketSessionCache`** and registers its flag in the service's own prompt-mutating cache-bypass list, following the `DeckAnalysisPacketService.PromptMutatingAnalysisFlags` pattern (satisfies roadmap success criterion 3; saves repeat throttled Scryfall/Spellbook calls).
- **D-100-07:** OFF state = tile/nav hidden + route 404 + **SeoPaths/sitemap gated on the flag** — the sitemap must NOT advertise `/creator-style` while it 404s (fixes the deck-history quirk).
- **D-100-08:** Phase-99 review backlog: **fold the cheap user-facing correctness items** — IN-01 (epsilon verdict compare), IN-03 (degraded-notice wording branches on excludedCount), IN-04 (unavailable ≠ degraded status), IN-08 (exemplar dedup) — into Phase 100. Defer pure-hygiene items (IN-02, IN-05, IN-06, IN-07, IN-09, IN-10 unless trivially bundled with IN-03/IN-04 tests).

### Page UX & input flow
- **D-100-09:** Creator picker = **dropdown listing only creators present in the store**, each labeled with evidence depth (e.g. "34 decks · 12 videos"). Picker is the source of truth — no free-text creator entry.
- **D-100-10:** Deck input **reuses the standardized import component** (site dropdown + URL/paste toggle) used by meta-gap/comparison. Known backlog caveat: deck-input-store restore desync applies to all split-input tools — do not fix here, just inherit.
- **D-100-11:** **Single form → result** page structure (meta-gap/manabase shape). No `_WorkflowStepTabs` multi-step strip.
- **D-100-12:** Tile in **Analyze section**, craft-first copy: lead with measured build style + real exemplars ("critique your deck against a creator's measured build style"); AI mention limited to "ChatGPT-ready packet". **No creator-crawl/KB-sourcing claims in copy** (standing legal/messaging rule).

### Output & degraded states
- **D-100-13:** Result view = **copy-ready packet block + small on-page summary strip** (rubric verdict chips + exemplar deck names). Reuse existing copy-button and mobile re-download (fetch-intercept) patterns. No full rendered report.
- **D-100-14:** **ChatGPT-only arm at ship.** No Claude/Gemini prompt variants this cycle (ADR-0001 makes each arm hand-maintained; add arms after the tool proves value).
- **D-100-15:** Grounding degradation → **deliver packet + visible warning banner** above it. Notice wording branches per IN-03: cards-withheld text only when exclusions actually occurred; upstream-outage text otherwise.
- **D-100-16:** Profile-unavailable is a **distinct state, never dressed as grounding degradation** (IN-04). Empty store in prod → page shows a clear "no creator profiles loaded" state instead of the form.

</decisions>

## Existing Code Insights

### Reusable Assets
- `ICreatorStylePacketService` (Phase 99): complete engine — controller is a thin orchestrator over `BuildAsync`.
- Standardized deck-import component (site dropdown + URL/paste toggle) from the deck-import standardize work — reuse for deck input.
- Copy-button + mobile re-download (fetch-intercept) patterns from existing packet tools.
- `ContentKbSeedLoader` startup-hydration pattern — template for the profile/deck seed loader.
- DeckFlow.CLI `System.CommandLine` host — home for the new seed-export command.

### Established Patterns
- Tool pages: ToolRegistry entry + controller + Razor view + Analyze/Build nav section + home tile; flag `tool.<slug>.enabled`; OFF → hidden + 404.
- Packet caching: `PacketSessionCache` keys exclude flags (D-01); any prompt-mutating flag must join the service's bypass list with read-side snapshot + write-side latched locals.
- Web-change bundle: xUnit + Playwright (desktop+mobile, all guild themes), README update, byte-identical prose gate on pre-existing artifacts.
- Layout CSS → `site-common.css`; theme tokens in each theme file's `:root`; never `site.css`.

### Integration Points
- `Program.cs` DI: seed loader registration + (unchanged) `ICreatorStyleProfileStore`/`ICreatorDeckCacheStore` singletons now hydrated by seed in prod.
- `PacketServiceCollectionExtensions` — controller's service dependencies already registered by Phase 99.
- `/Admin/Flags` catalog — new flag row + description.
- Sitemap/SeoPaths — flag-gated route listing (new capability, D-100-07).

</code_context>
