PROD RULES (from CLAUDE.md — NON-NEGOTIABLE):
- The AI must NEVER write to prod: no INSERT / UPDATE / upsert / MERGE / DELETE / DDL / EXEC, under any circumstance. The live prod publish (SCP + content-columns-only upsert) is performed ONLY by the operator running the Studio DirectPush page.
- The AI may take READ-ONLY SELECT snapshots of prod, and ONLY via a sanctioned path: the Render MCP `query_render_postgres` tool (read-only) on render service `DeckFlow` (`srv-d7gmufkp3tds73a29m30`), OR the `prod-readonly-query` skill. If neither read path is available to the AI, the operator captures the snapshot via the Render dashboard / admin UI instead.
- No prod secret value (connection string, SSH host/key/passphrase, password) may appear in any committed file, the results artifact, chat, code, or logs. Secrets live only in .NET user-secrets (Studio) and the Render dashboard (`sync: false`). Refer to secrets by name only.

SCHEMA (content_site_index — verified ContentSiteIndexStore.cs):
- Natural key = `(natural_key_type, natural_key_value)`. `natural_key_type IN ('youtube_channel','podcast_rss')`.
- Admin-owned fields (the preservation target): `is_visible` (BOOLEAN), `is_evergreen` (BOOLEAN), `is_hidden` (BOOLEAN), `approval_status` (TEXT).
- Content columns (expected to change on publish): `title`, `video_url`, `artifact_path`, `published_utc`, `indexed_utc`, `archetype_tags`, `bracket_tags`, `card_category_tags`.
- `UpsertContentColumnsOnlyAsync` SQL: INSERT … ON CONFLICT (natural_key_type, natural_key_value) DO UPDATE SET only the content columns. `is_visible` / `is_hidden` / `is_evergreen` / `approval_status` are deliberately ABSENT from the DO UPDATE clause — so a pre-existing row keeps all four admin fields; only a brand-new row gets the INSERT defaults (`is_visible=FALSE`, `is_evergreen=FALSE`, `approval_status='pending'`). THIS is the property the before/after snapshot must prove.

PUBLISH FLOW (DirectPush.razor — operator-driven 3-stage):
- Stage 1 Compute Prod Diff (reads prod, shows New/Updated counts + per-row table; gated by "I have reviewed what will be written to PRODUCTION" checkbox).
- Stage 2 Upload Artifacts to Prod /data (SCP) — must fully succeed before Stage 3 unlocks (artifact-first ordering, Pitfall 2).
- Stage 3 Write Approved Rows to Prod DB — calls `UpsertContentColumnsOnlyAsync` ONLY (never a full-row upsert).
- Remote artifact root default `Studio:Scp:RemoteArtifactRoot` = `/data/content-kb`; artifacts land under `/data/content-kb/{...}/`.
- Studio secrets (user-secrets, presence-only at startup): `Studio:ProdConnectionString`, `Studio:Scp:{Host,Port,Username,KeyFile,KeyPassphrase,RemoteArtifactRoot}`. SCP is "configured" only when Host+Username+KeyFile+RemoteArtifactRoot are all set.
