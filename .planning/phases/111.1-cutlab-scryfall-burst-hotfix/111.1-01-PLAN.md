<objective>
Ship the user-facing production hotfix. Two independent defects in Cut Lab's Import-pool intake
path are fixed in a single file:

1. **SC-1** — `CutLabAnalysisContextBuilder.cs:410` passes `_cardResolver.ResolveSingleAsync` as
   the post-batch-miss fallback delegate. `ResolveSingleAsync` re-POSTs `cards/collection` for an
   identifier that already failed on that exact endpoint moments earlier in the 75-card batch call,
   then falls through to `cards/search` anyway. This roughly doubles live Scryfall call volume per
   miss and is what turns a ~2-call import into a ~21-request burst.

2. **SC-2** — `CutLabAnalysisContextBuilder.cs:434` rethrows *every* exception when
   `failOpenOnLookupErrors: false`, including a transient HTTP 429. That rethrow is what aborts the
   whole import and produces the banner.

Purpose: this is a live production bug on a flag-ON tool. This plan is the shippable unit —
after it lands, the banner cause is removed. The ADR work (plans 03) and the throttle pacing
change (plans 04/05) are deliberately NOT in this plan and must not gate it.

Output: one production file changed, one test file changed, four new regression tests.
</objective>

catch both the batch-call 429 and the fallback-call 429, which is the correct behavior: a 429 is
transient regardless of which call produced it.
