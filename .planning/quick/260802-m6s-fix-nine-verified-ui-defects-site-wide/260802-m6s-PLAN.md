# Quick Task 260802-m6s — Batch A: nine verified UI defects

Batch A of the 2026-08-02 site UI audit. Eleven fixes, no design decisions pending.
Every finding was re-verified against the code before planning; two prescribed fixes
were amended because the code path differs from the audit's assumption (see D6, D7).

## Task 1 — Markup and controller fixes

**D1 — Three landing tiles render "?"**
`ToolRegistry.cs:61` sets `IconKey = key`. `_ToolTileIcon.cshtml` switches on that key, but two
cases were written against `HelpSlug` and one key has no case, so all three hit `default:` (a
question-mark SVG).
- `case "ask-a-judge"` → `case "judge-questions"`
- `case "category-suggestions"` → `case "suggest-categories"`
- add `case "deck-history"` (clock/history glyph, 20x20, matching the sibling SVG contract)
- Totality check: all 16 registry keys must have a case.

**D2 — `Home.cshtml` has no `<h1>`**
First heading is the section `<h2>` at `:37`. Insert a visible `<h1>` above the lede at `:20`.

**D3 — 404s bypass the branded error page**
`Program.cs` wires only `UseExceptionHandler`. Add `UseStatusCodePagesWithReExecute("/Deck/Error",
"?code={0}")`, wrapped in `UseWhen(!path.StartsWithSegments("/api"))` so JSON clients keep getting
empty 404 bodies instead of an HTML page. `ShellController.Error` takes `[FromQuery] int? code` and
passes a new `ErrorPageModel`; `Error.cshtml` branches copy for 404 vs everything else.

**D4 — Feedback validation inert**
Drop `novalidate` from `Feedback/Index.cshtml:20`. `required`/`minlength="10"`/`type="email"` then
fire natively. `feedback.ts` only disables the submit button on the `submit` event, which does not
fire when constraint validation blocks — no interaction.

**D5 — Step tabs unnamed on mobile**
`site-mobile.css:352` hides `.prompt-step-tab__label`; `.prompt-step-tab__num` is `aria-hidden`.
Add `aria-label="@step.Label"` to the button in `_WorkflowStepTabs.cshtml`.

**D6 — Disabled tabs break roving-tabindex** *(amended)*
Removing the real `disabled` attribute is not sufficient — line 24 renders `type="submit"` whenever
`SubmitFormId` is set, so an un-disabled incomplete tab would submit the form. Therefore:
- drop `disabled`, keep `aria-disabled`
- render `type="button"` and omit `form=` when `!step.IsEnabled`
- add ONE capture-phase guard in `site.ts` that swallows clicks on
  `[role="tab"][aria-disabled="true"]` — covers all 5 pages in one place rather than patching the
  4 separate handlers in `deck-sync.ts` + `primer-selection.ts`

**D7 — `_DeckToolTabs` toggle controls itself** *(amended)*
The `hidden` attribute is NOT dead: it is the desktop hiding mechanism, since nothing in
`site-common.css` sets `display` on `.tool-nav__menu-toggle` and `site-mobile.css:147` only
overrides `[hidden]` inside the ≤600px query. So:
- wrap the groups in `<div id="deck-tool-nav-groups" class="tool-nav__groups">`, point
  `aria-controls` at it, and give the wrapper `display: contents` so neither the desktop flex row
  nor the mobile grid changes
- update `site-mobile.css:183,189` from `.tool-nav > .tool-nav__group` to
  `.tool-nav__groups > .tool-nav__group` (DOM-based selectors do not follow `display: contents`)
- remove the `hidden` attribute; add `.tool-nav__menu-toggle { display: none; }` to
  `site-common.css` and `display: inline-flex;` to the mobile block, replacing the
  `[hidden] { !important }` hack

**D8 — Primer "Start Over" discards the deck silently**
Add `data-cache-key="deck-primer"` to `DeckPrimer.cshtml:76`. This binds
`attachGenericPersistedForms` (`deck-sync.ts:965`), whose clear handler resets and navigates via
`data-clear-href` — and simultaneously gives the primer the form persistence it never had.

**D10 — `.table-wrapper` has no CSS rule**
`CedhMetaGap.cshtml:255` is the only use of the class site-wide; no stylesheet defines it. Add
`.table-wrapper { overflow-x: auto; }` to `site-common.css` and `tabindex="0" role="region"` +
`aria-label` on the div so keyboard users can scroll it.

**D11 — Zero-reference cuts print "0 reference deck(s)"**
`CedhMetaGap.cshtml:601` `>= 0` → `> 0`, matching its sibling at `:574`.
