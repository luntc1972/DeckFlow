## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| README + Help docs (server → human reader) | Pure documentation; rendered as Markdown to the in-app Help page. |
| Browser extension (browser ↔ DeckFlow web app) | The extension posts deck data to DeckFlow URLs via `fetch`; URL strings are baked into the extension manifest and JS. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-12 | Stale-doc social-engineering / phishing | README + Help page URLs | mitigate | Eliminating stale `/chatgpt-*` URLs from public-facing docs reduces the risk that a malicious actor stands up a typosquat at `chatgpt-packets.example.com` and links users to it from a copy-pasted doc snippet. Acceptance gate enforces zero stale URLs in `.md` files (D-15). |
| T-12-13 | Outdated browser-extension talking to wrong endpoint | extension JS files referencing chatgpt- URLs | mitigate | If Case B applies (extension had stale URLs), the 301 redirect block in `Program.cs` (Plan 01) provides backward compatibility — the extension keeps working even before the user pulls the version-bumped zip. Defense-in-depth: 301 is the safety net, the D-16 version bump is the proactive fix. |
| T-12-14 | Information disclosure via PR diff | git history reveals security-relevant deltas | accept | Public repo (`luntc1972/DeckFlow`); no secrets in any edited file. URL slug changes are not security-sensitive. CLAUDE.md "no secrets in commits" invariant unaffected by this plan. |
</threat_model>
