# 70-06 — Two-lens result header (Karsten source check + simulated cast rate)

**Why:** the manabase result buries the "what our number means vs a color-source counter"
distinction in help/`<details>` prose. MQ-02 makes our sim diverge further from a pure source
counter (it now models mana quantity too), so surface BOTH lenses at the top of the result:
- **Karsten source check** (left) — the validated colored-source target per color (✓ / ⚠ −N).
- **Simulated cast rate** (right) — our joint-game Monte-Carlo headline number.

Ships **with** the MQ-02 changes (same Phase 70 / `feature/manabase-accuracy` branch).

**Risk:** Low. **Blast radius:** the manabase result view only. **View-only — no Core change.**

## Design (locked from the approved mockup)
- Two-card band at the top of the `Result` section, above the existing `Lands … / Health chip` line.
- Left lens: one row per `report.ColorFindings` entry — `{Color}  {ActualSources:F0} / {RequiredSources} need  ✓|⚠ −N`. Mark ✓ when `ActualSources >= RequiredSources`, else ⚠ with the rounded deficit. Caption: "validated colored-source target (Frank Karsten's math)".
- Right lens: the deck-level cast-rate headline + caption "joint mana + color, with mulligan, tapped-land timing, and ramp". Pill: "avg across N non-land spells".
- **Cast-rate number = mean `CastPercent` across `report.Castability` rows** (those already exclude rocks/dorks; commander included). Labeled **"avg on-curve"**. N = `report.Castability.Count`. View-only aggregate — no new Core field.
- Desktop: 2-up grid; **mobile (<640px): stack vertically** (mockup verified, no overflow).
- Casual-only (castability rows only populate in Casual, matching the existing castability table gate); in cEDH the right lens shows the same once castability is present, else hide the right lens and keep the left.

## Side-Effects Report
- **Files:** `DeckFlow.Web/Views/Deck/Manabase.cshtml` (new markup block in `Result`),
  `DeckFlow.Web/wwwroot/css/site-common.css` (`.manabase-twolens` + lens classes — layout lives in
  site-common, never `site.css`, per the theme rule), `DeckFlow.Web/Services/Manabase/ManabaseDisplay.cs`
  (add `AvgOnCurve(IReadOnlyList<CardCastability>)` helper so the mean is unit-testable, not inline Razor).
- **Shared state / external / contract:** none. No Core types change.
- **Tests:** xUnit on `ManabaseDisplay.AvgOnCurve` (empty → 0/hidden; rounding; excludes nothing extra).
  Playwright: two-lens band visible on a result; left lens ✓/⚠ matches color findings; **mobile stacks**;
  no horizontal overflow across themes (reuse the existing theme-sweep harness).
- **Backward-compat:** purely additive UI; the per-color + castability tables below are unchanged.

## Steps
1. `ManabaseDisplay.AvgOnCurve(rows)` → `int` mean of `CastPercent` (0 when empty). Plus a small
   `KarstenMet(finding)` → (`bool met`, `int deficit`) helper for the ✓/⚠ marker.
2. Razor: add the `.manabase-twolens` block at the top of `Result`, left lens looping
   `report.ColorFindings`, right lens using `AvgOnCurve` + `report.Castability.Count`. Hide the right
   lens when `report.Castability` is empty.
3. CSS: `.manabase-twolens` grid (2-up; `@media (max-width:640px)` → 1 col), `.manabase-lens` card,
   `.is-met`/`.is-short` token colors (reuse `--success`/`--gold-warning`/`--danger`). Tokens only —
   no per-theme hardcoded colors.
4. xUnit + Playwright per above. Verify desktop + mobile across themes (no overflow) — DoD rule.

## Done when
- Build clean; `AvgOnCurve` unit-tested; Playwright two-lens + mobile-stack + theme-overflow green;
  band renders above lands/health on a real analysis; per-color + castability tables unchanged;
  README/`Help/manabase.md` note the two-lens framing if it changes the explanation. Codex review.
