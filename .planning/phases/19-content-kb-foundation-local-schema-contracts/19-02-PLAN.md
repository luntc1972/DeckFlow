<objective>
Add the single central FK-enforcement seam (D-03) and SPLIT the Content KB connection factory into two methods so heavy local-only stores can never be routed to Render Postgres. SQLite enforces `ON DELETE CASCADE` only when `PRAGMA foreign_keys=ON` is issued per-connection; without it the entire CASCADE design of the content tables is a no-op. RESEARCH confirmed the blast-radius audit: NO existing SQLite store declares `REFERENCES`, so enabling FK enforcement through a new shared helper is fully safe and changes no existing store.

Per the cross-AI review (REVIEW #2, HIGH): the original single `CreateContentKbConnection` would route transcripts/audio/spend to Postgres when `DECKFLOW_DATABASE_PROVIDER=Postgres`, violating D-14 ("heavy tables local-only, NEVER uploaded to Render"). The factory is therefore split: `CreateLocalContentKbConnection` (ALWAYS local SQLite, ignores the provider env) for the four heavy stores, and `CreateContentSiteIndexConnection` (provider-aware) as the ONLY content store allowed to reach Render Postgres.

Purpose: Provide the prerequisite the CASCADE proof test (Plan 03) and all content stores depend on (centralized FK pragma, D-03), plus the data-locality-safe factory split that protects D-14.
Output: 1 Core modification + 1 Web factory modification + 1 Core.Tests file.
</objective>
