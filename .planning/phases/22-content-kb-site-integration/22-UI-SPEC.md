# Phase 22 — UI Design Contract

> Visual and interaction contract for the three Phase 22 surfaces:
> (1) public Content KB browse page, (2) public artifact detail page,
> (3) admin curation grid.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — DeckFlow uses hand-authored CSS with 22 guild theme forks |
| Preset | not applicable |
| Component library | none (custom: `.hub-card`, `.admin-table`, `df-select`, native `<dialog>`) |
| Icon library | none — SVG inline + Unicode glyphs (existing pattern) |
| Font | "Segoe UI", Tahoma, Geneva, Verdana, sans-serif (from `html` in site.css / admin-common.css) |

**Design system constraint (CLAUDE.md / STATE.md cross-cutting invariant #11-12):**
Layout CSS goes in `site-common.css` (public surfaces) or `admin-common.css` (admin surfaces) — never in `site.css` or any theme fork. Color/visual tokens are already defined in each theme's `:root`; new components must consume existing tokens only. Admin CSS must be scoped under `.admin-shell` + `@layer admin { ... }` so zero bleed reaches the 22 guild themes (SC5).

shadcn gate result: not applicable — project is ASP.NET 10 + Razor, not React/Next.js/Vite. Registry safety gate: not applicable.

## Spacing Scale

Existing tokens (declared via rem in site.css / admin-common.css). All multiples of 4px at the default 15px html font-size base. Source: `site-common.css` primitives already in use.

| Token | Value | Usage in Phase 22 |
|-------|-------|--------------------|
| xs | 4px (0.25rem) | Tag chip gap, icon-to-text gap inside buttons |
| sm | 8px (0.5rem) | Filter control row gap; admin panel internal gap |
| md | 16px (1rem) | Card internal padding (`.hub-card` uses `1rem 1.1rem`); section spacing |
| lg | 24px (1.5rem) | Panel padding (`.admin-harvest__panel` uses `16px 20px`); major section breaks |
| xl | 32px (2rem) | Page-level top padding (`.page-shell` uses `2rem 1rem 3rem`) |
| 2xl | 48px (3rem) | Page-shell bottom padding |
| 3xl | 64px (4rem) | Reserved — not needed in Phase 22 surfaces |

Exceptions:
- Touch targets: all interactive controls min-height/min-width 44px per WDG-08 / WCAG 2.5.5 (already enforced in `admin-common.css` for admin surfaces; public surfaces follow the same WDG-08 contract from v1.3).
- Admin panel padding at mobile: `12px` (from `admin-mobile.css` `.admin-harvest__panel` override) — this is an existing exception, not a new one.
- Publish/unpublish toggle buttons in the admin grid: inline-flex, min-height 44px, min-width 44px (inherits from `.admin-shell .admin-action-form button` rule in `admin-common.css`).

## Typography

DeckFlow declares its type scale in `site.css` `:root` as CSS custom properties. All Phase 22 surfaces must use these tokens — never hardcoded px values.

| Role | Token | Resolved size | Weight | Line Height |
|------|-------|---------------|--------|-------------|
| Body / body copy | `var(--fs-base)` | 0.95rem ≈ 14.25px | 400 (normal) | 1.5 |
| Small / label / caption | `var(--fs-sm)` | 0.85rem ≈ 12.75px | 600 (semibold) for labels; 400 for muted meta | 1.35 |
| Sub-label / tag / eyebrow | `var(--fs-xs)` | 0.75rem ≈ 11.25px | 600, letter-spacing 0.08em, text-transform uppercase | 1.2 |
| Heading / panel title | `var(--fs-xl)` | 1.5rem ≈ 22.5px | 700 | 1.2 |

Active size count: 4 (xs, sm, base, xl). Weight count: 2 (400, 700; semibold 600 used on labels only as the existing pattern).

Token source: `site.css` `:root` lines 34–39 (confirmed from codebase read). Admin surfaces use `font-size: 15px` base with no token overrides — same effective sizes in px.

## Surface Contracts

### Surface 1: Public Browse Page (`/content-kb`)

**Shell:** site shell (`_Layout.cshtml`), `site-common.css` primitives, gated by `FeatureFlagGateAttribute(content_kb_enabled)` — route returns 404 / is absent from nav when flag is OFF.

**Layout:** Full-width `.page-shell` + `.page-frame` (max-width `var(--shell-max-width)` = 1120px, margin auto). Mirrors the Help Index layout (`.help-index` in `site-common.css`).

**Nav entry:** Conditionally rendered in `_Layout.cshtml` only when `content_kb_enabled` is ON. Link text: "Knowledge Base".

#### Filter bar

Positioned above the entry list, below the page heading. At desktop: single horizontal row. At mobile (≤600px): stacks vertically, each control full-width.

| Control | Type | Behavior |
|---------|------|----------|
| Text search | `<input type="search">` | Client-side; filters entry titles + source names as user types; debounced 200ms; clears on Escape |
| Source filter | `<select>` with `data-df-select` | Reuses existing `df-select` ARIA combobox component; lists distinct source names from published entries |
| Archetype filter | `<select>` with `data-df-select` | `ContentTagVocabulary` archetype values (~15 options + "Any") |
| Bracket filter | `<select>` with `data-df-select` | Wizards Feb 2025 5-bracket values + "Any" |
| Card category filter | `<select>` with `data-df-select` | `ContentTagVocabulary` card_category values + "Any" |

Filter state: client-side only. No server round-trip on filter change. All published rows loaded once on page load (index is small — SC1 guarantees no transcript/audio data). Filters are ANDed across dimensions.

Filter bar CSS class: `.kb-filter-bar` — new class, lives in `site-common.css`. Single-row flex container with `gap: 8px; flex-wrap: wrap; margin-bottom: 16px;`. Each control takes `flex: 1 1 160px; min-width: 120px;`. At ≤600px: `flex-direction: column; gap: 8px;`.

#### Entry list

Each published entry renders as a `.hub-card` (existing component in `site-common.css`). The full list is a `.hub-grid` (`grid-template-columns: repeat(auto-fill, minmax(16rem, 1fr)); gap: 1rem`).

Entry card contents:
- `.hub-card__title` (weight 600, `var(--fs-base)`) — entry title, rendered as `<a>` linking to `/content-kb/{key}`
- `.hub-card__description` (weight 400, `var(--fs-sm)`, `var(--muted)`) — source name + bracket tag + archetype tag in one line, separated by ` · `
- Tag chips (optional, below description) — see Tag chips section below

Entry card states:

| State | Visual |
|-------|--------|
| Default | `.hub-card` — `border: 1px solid var(--line); background: var(--panel)` |
| Hover/focus | `border-color: var(--accent-strong, var(--line)); transform: translateY(-1px); box-shadow: ...` (existing `.hub-card:hover` rule) |
| Hidden by filter | `display: none` via JS — do not remove from DOM, toggle visibility |
| No match | Empty state (see below) |

#### Tag chips

Small inline badges for archetype / bracket / card_category on each entry card. CSS class: `.kb-tag` — new class in `site-common.css`.

```
.kb-tag {
  display: inline-flex;
  align-items: center;
  padding: 0.1rem 0.45rem;
  border: 1px solid var(--line);
  border-radius: 999px;
  font-size: var(--fs-xs);
  font-weight: 600;
  color: var(--muted);
  background: var(--panel-soft-bg);
  white-space: nowrap;
}
```

Selected/matching chip (when user has filtered by this dimension): `border-color: var(--accent-strong); color: var(--accent-strong); background: var(--panel-soft-bg)`.

#### Empty state

Two distinct empty state scenarios:

**A. Flag ON, zero published entries (first-run / post-deploy before curation):**
- Heading: "No entries published yet"
- Body: "The Knowledge Base is enabled but no entries have been made public. Visit the admin curation page to publish entries."
- No CTA link to admin (public page cannot link to BasicAuth admin).
- CSS: `.kb-empty` — new class in `site-common.css`, mirrors `.admin-empty` pattern. `color: var(--muted); font-style: italic; margin-top: 2rem; text-align: center;`

**B. Entries exist but active filters return zero matches:**
- Heading: "No entries match your filters"
- Body: "Try broadening your search or clearing a filter."
- Show a "Clear filters" button — resets all filter controls to "Any" / empty text search. CSS: existing `.maintenance-page__action` link/button pattern (border + rounded, `var(--accent-strong)` text).

#### Responsive behavior (public browse)

| Breakpoint | Layout change |
|------------|--------------|
| >768px | Hub-grid auto-fill columns (≥2 columns); filter bar single row |
| ≤768px | Hub-grid narrows naturally (auto-fill minmax 16rem → 1 column below ~360px) |
| ≤600px | Filter bar stacks vertically; each df-select full-width |
| 375px | Single column card grid; filter controls full-width; touch targets ≥44px enforced by existing WDG-08 primitives |

### Surface 2: Public Artifact Detail Page (`/content-kb/{key}`)

**Shell:** site shell (`_Layout.cshtml`), gated by same `FeatureFlagGateAttribute(content_kb_enabled)`. Returns 404 if entry `is_visible = false` or flag OFF.

**Layout:** Prose-width container, mirrors `.help-prose` (max-width 72ch, `border: 1px solid var(--line); border-radius: 10px; background: var(--panel); padding: 1.5rem 1.75rem`). New CSS class: `.kb-artifact-prose` in `site-common.css`, spec identical to `.help-prose`.

**Breadcrumb:** `.help-breadcrumb` (existing class) — "Knowledge Base / {Entry Title}". Link to `/content-kb`.

#### Copy for ChatGPT button

Prominent, positioned in a sticky toolbar at the top of the artifact panel (mirrors `.chatgpt-sticky-download` pattern from `site-common.css`).

Button markup:
```html
<button type="button" class="copy-button run-button"
        data-copy-target="kb-artifact-text"
        aria-label="Copy this artifact for ChatGPT">
  Copy for ChatGPT
</button>
```

Hidden `<textarea id="kb-artifact-text" readonly hidden>` containing the clean pasteable text (summary + clips + tags, without frontmatter). Server-renders the clean text server-side — the controller strips frontmatter before passing to the view. The copy button invokes the existing `attachDynamicCopyButton` TS pattern (`data-copy-target` → `navigator.clipboard.writeText`).

Copy button state machine (reuses existing `.copy-button` states):
- **Idle:** label "Copy for ChatGPT"
- **Copied (1800ms):** label "Copied", class `is-copied` → theme colors button with `var(--accent)` background (existing `.is-copied` CSS in theme files)
- **Failed:** label "Copy failed", class `is-copy-failed`

The copy button is the primary CTA. It must be visible without scrolling on load at 375px.

#### Artifact content rendering

The artifact markdown is rendered via `HelpContentService` (Markdig) into HTML. CSS class `.kb-artifact-prose` inherits the full `.help-prose` rule set (headings, links, pre/code blocks, tables). Sections expected from the artifact spec (Phase 19):
- `## Summary` → renders as `<h2>` + paragraph
- `## Key Clips` → renders as `<h2>` + ordered list of timestamped clip items
- `## Tags` → renders as `<h2>` + definition list or inline tag chips (`.kb-tag`)

#### Entry metadata header

Above the artifact prose, below breadcrumb:
```
Source: {source_name}  ·  {published_date}  ·  {bracket}  ·  {archetype}
```
Styled with `var(--muted)`, `var(--fs-sm)`. Source name links to external URL (opens in new tab, `rel="noopener noreferrer"`).

#### Responsive behavior (detail page)

| Breakpoint | Layout change |
|------------|--------------|
| >768px | `.kb-artifact-prose` at max 72ch, centered |
| ≤768px | Full-width minus `1rem` horizontal padding from `.page-shell` |
| 375px | Full-width; copy button spans full width (`width: 100%`) at ≤600px (mirrors `admin-mobile.css` button pattern); artifact prose wraps naturally |

### Surface 3: Admin Curation Grid (`/Admin/ContentKb`)

**Shell:** `.admin-shell` (BasicAuth gated, `_AdminLayout.cshtml`). All CSS scoped to `.admin-shell` parent. New admin CSS additions go in `admin-common.css` under a new `/* === Phase 22 — Content KB Admin === */` block. Responsive overrides go in `admin-mobile.css`.

**Sidebar nav entry:** Add "Content KB" link in `_AdminLayout.cshtml` sidebar nav, using the existing `.admin-sidebar__link` class. Active state: `.admin-sidebar__link--active`.

#### Status panel

At the top of the page, an `.admin-harvest__panel` (existing class, reuse without modification):
- Row count: "N entries total (M published)"
- Distinct sources: "S sources"
- Last loaded: timestamp from seed load or "Never"
- `content_kb_enabled` flag toggle — reuses the existing `AdminFlagsController` form pattern (POST to `/Admin/Flags/Toggle?key=content_kb_enabled`): `<form method="post" class="admin-action-form">` with `@Html.AntiForgeryToken()` + submit button labeled "Enable" or "Disable"
- Reload-from-seed action button: "Reload Index from Seed" — POST to `/Admin/ContentKb/ReloadSeed`, `[ValidateAntiForgeryToken]` + `SameOriginRequestValidator`. Button uses `.admin-action-form button` styles. Confirmation: uses the existing `admin-modal` (`_AdminConfirmModal.cshtml` partial, Phase 16 primitive) — modal title "Reload index from seed?", message "This will upsert all rows from the committed seed file. Existing visibility settings are preserved for previously-curated entries."

#### Per-source bulk section

Grouped above the per-entry grid. Each source gets one row:
- Source name (bold)
- Entry count for that source
- "Publish All" button → POST `/Admin/ContentKb/BulkSetVisibility` with `source={slug}&visible=true`
- "Hide All" button → POST same endpoint with `visible=false`; button uses `.danger` class (existing `.admin-action-form button.danger` pattern)
- Both buttons require `@Html.AntiForgeryToken()` + `SameOriginRequestValidator`

CSS: `.admin-table.admin-table--card` (existing classes — card-stack at mobile). `<caption class="sr-only">` — "Content sources — bulk publish controls".

| Column | Width hint | Mobile |
|--------|-----------|--------|
| Source | auto | data-label="Source" |
| Entries | 6rem | data-label="Entries" |
| Actions | 14rem | data-label="Actions" (flex-wrap: wrap at mobile) |

#### Per-entry curation grid

Server-rendered table. Scrollable horizontally at desktop if needed (`.admin-table-scroll` wrapper with `overflow-x: auto; tabindex="0"`). Uses `.admin-table` + `.admin-table--card` (card-stack at ≤768px per `admin-mobile.css`).

`<caption class="sr-only">` — "Content KB entries — per-entry publish controls".

| Column | Content | Mobile |
|--------|---------|--------|
| Title | Entry title (truncated at 48ch with CSS `overflow: hidden; text-overflow: ellipsis; white-space: nowrap; max-width: 28rem`) | data-label="Title" |
| Source | Source name, `var(--muted)` | data-label="Source" |
| Tags | Archetype + bracket chips (`.kb-tag` — scoped within `.admin-shell .kb-tag` in admin-common.css to pick up admin token values) | data-label="Tags" |
| Status | "Published" (accent color) or "Hidden" (muted) — `<span class="kb-status kb-status--published">` / `<span class="kb-status kb-status--hidden">` | data-label="Status" |
| Action | Publish/Unpublish toggle button | data-label="Action" |

Status badge CSS (in `admin-common.css`, scoped to `.admin-shell`):
```css
.admin-shell .kb-status {
  display: inline-flex;
  align-items: center;
  padding: 0.15rem 0.5rem;
  border-radius: 4px;
  font-size: 0.85em;
  font-weight: 600;
  border: 1px solid var(--border);
}
.admin-shell .kb-status--published {
  color: var(--accent);
  border-color: var(--accent);
  background: rgba(59, 130, 246, 0.08);
}
.admin-shell .kb-status--hidden {
  color: var(--muted);
  background: transparent;
}
```

Publish/Unpublish toggle:
- Markup: `<form method="post" class="admin-action-form">` + `@Html.AntiForgeryToken()` + hidden `entryId` + hidden `visible` + `<button type="submit">Publish</button>` or `<button type="submit">Unpublish</button>`
- POST target: `/Admin/ContentKb/SetVisibility`
- Both verbs require `[ValidateAntiForgeryToken]` + `SameOriginRequestValidator.IsValid(Request)` (SC4/P11)
- No modal confirmation needed for per-entry toggle (low-risk, reversible)
- Unpublish button: plain `.admin-action-form button` styling (no `.danger` class — this is a reversible visibility toggle, not a destructive delete)

ARIA on toggle buttons: `aria-label="Publish '{entry title}'"` / `aria-label="Unpublish '{entry title}'"` — not just "Publish" — so screen readers identify which entry is affected.

#### Admin grid responsive behavior

| Breakpoint | Layout change |
|------------|--------------|
| >768px | Sidebar visible; full table layout |
| ≤768px | Sidebar collapses to `<details>/<summary>` disclosure (existing Phase 18 pattern); both tables switch to `.admin-table--card` card-stack (existing `admin-mobile.css` rule) |
| 375px | Single-column card-stack; "Publish All" + "Hide All" in Actions cell use `flex-wrap: wrap` (existing `td[data-label="Actions"]` rule in `admin-mobile.css`); all buttons ≥44px (existing `admin-common.css` touch-target rule) |

## Accessibility Contract

Applies to all three surfaces.

| Element | ARIA requirement |
