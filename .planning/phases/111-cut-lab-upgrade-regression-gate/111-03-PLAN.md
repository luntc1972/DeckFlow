<objective>
Deliver CLUP-19: a dedicated Cut Lab theme-readability regression check covering ALL
supported themes and the named element set (Lock All role pills, role/card chips, package
chips, sticky status, warning/finding panels, selects, inputs, primary buttons). Today
theme assertions are ad-hoc per spec (e.g. hard-coded rgb() in cut-lab-pill-interactions
for one theme). This plan adds a shared WCAG contrast helper and one spec that loops every
theme, so a future theme fork cannot silently ship an unreadable Cut Lab element.

Purpose: Guild themes are standalone CSS forks; a token regression in any one fork can make
a chip/pill/panel unreadable. A single looped, contrast-asserting spec is the durable guard.

Output: e2e/support/contrast.ts (helper) + e2e/cut-lab-theme-readability.spec.ts (looped spec).
</objective>

Focus-visible check (WIG audit fold-in — CLUP-19): for the interactive named elements
(selects, inputs, primary buttons, Lock All role pill, a role/card chip), drive focus via
keyboard (element.focus() then assert `:focus-visible` matches, or Tab) and read the focus
indicator's colour — outline-color when outline is used, else the border/box-shadow ring
colour, else the background delta for background-only focus styles (autocomplete-option /
df-select). Assert that indicator clears AA contrast (>= 3.0) against the element's own
background for EVERY theme. This is the durable guard for the 4 untuned themes
(gruul/izzet/orzhov/temur), which define no theme-specific :focus-visible and inherit the
base ring, and for the background-only focus cases flagged in the Cycle-19 WIG audit.
