Design (illustrative — final naming/shape is the executor's call, but the behaviors below are
NON-NEGOTIABLE):
- ResolveBatchAsync(requests, fallbackStrategy delegate, normalizeForScryfall=false, cancellationToken)
  → ScryfallBatchResolution
- ScryfallBatchResolution exposes, in ORIGINAL request order, each resolved reference as
  (RequestName [original], ScryfallCard, bool FromFallback), plus an OracleNameMap keyed by
  RequestName → ScryfallCard.Name. Each consuming service maps this to its own shape (Analysis:
  CardReference + displayName + mechanic extraction; Comparison: ScryfallCard list + oracleNameMap;
  MetaGap: oracleNameMap only).
</interfaces>

<load_bearing_behaviors>
Grounded in DeckAnalysisPacketService.cs:1950-2043 (and the analogous Comparison/MetaGap loops):
1. KEY BY ORIGINAL REQUEST NAME. oracleNameMap and the resolved map are keyed by the caller's
   original request name (matchingRequest.Name), NOT the normalized submission and NOT the returned
   card.Name.
2. COLLECTION MATCH-BACK: for each returned card, find the chunk request whose ORIGINAL name equals
   the RETURNED card.Name (Ordinal-IgnoreCase). Submit identifiers = NormalizeForScryfall(name) when
   the opt-in is ON, else the raw name — but the match compares ORIGINAL vs returned card.Name.
   Consequence (must be preserved): a single-slash `"A / B"` name normalizes to `"A // B"` on
   submission; Scryfall returns `"A // B"`; original `"A / B"` ≠ `"A // B"` → NO collection match →
   the request is treated as unresolved and dispatched to the fallback strategy. Do NOT "fix" this.
3. FALLBACK: for each still-unresolved ORIGINAL request name, invoke the supplied fallbackStrategy
   delegate; key the result by the original name; mark FromFallback=true.
4. ORDER: the returned resolved references follow the original request order (Analysis does
   cardRequests.Where(resolved).Select(...)).
5. STATUS VALIDATION: preserve the exact non-2xx / null-Data throw (HttpRequestException with the
   upstream status) — do NOT relax it.
</load_bearing_behaviors>

<do_not_unify>
- The fallback-method CHOICE is load-bearing: Analysis MUST keep SearchPrintingFallbackCardAsync;
  Comparison/MetaGap MUST keep SearchFallbackCardAsync. The collaborator takes this as a delegate —
  it does NOT hardcode one.
- NormalizeForScryfall pre-submission normalization is Analysis-only today → opt-in parameter,
  default OFF; it affects ONLY the submitted identifier, never the key or the match.
- Do NOT add mechanic-name extraction, CardReference construction, the Analysis displayName
  (`submitted_name: ... | resolved_card: ...`) logic, or stat-input mapping here — those stay in each
  consuming service. The collaborator ends at "resolved references (original name + card + fallback
  flag) + oracle name map".
</do_not_unify>
