<objective>
Add the runtime side of the commander role-floor snapshot: a fail-open provider mirroring
`CedhLandBaselineProvider`, plus a shared commander-key helper so both baselines match commander names
through exactly one implementation.

Purpose: D-10 requires the new lookup to use `CedhLandBaselineProvider.CandidateKeys`' shape. Extracting
that shape into one shared helper — rather than duplicating ten lines — is what makes "byte-identical
matching semantics" true permanently instead of true on the day it was written. The fail-open load is what
makes RFLR-06's byte-identical guarantee hold for free when the file is missing or corrupt.
Output: the provider, its DI registration, and its tests. No floor value changes yet — plan 03-04 wires
the provider into `ResolveDefaults`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bundled JSON file -> web process | The only new runtime I/O surface in the phase. A git-committed, offline-generated artifact read from the content root at startup and on cache expiry. Not user-controlled; no request data reaches this read. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Denial of Service | Corrupt or missing `latest.json` throwing at startup or first request | mitigate | Task 2 catches exactly `IOException`, `UnauthorizedAccessException`, `JsonException` and degrades to "no commander data"; Task 3 tests 6 and 7 assert no exception escapes. |
| T-03-11 | Denial of Service | A corrupt file re-read on every request | mitigate | The failed load is cached as a `CacheEntry(null)` for 24 hours; Task 3 test 8 pins it. |
| T-03-12 | Spoofing | A commander name crafted to match the wrong snapshot row | accept | Lookup is exact-string dictionary matching over `CommanderBaselineKeys.Candidates`, with no normalization, wildcarding, or fuzzy matching. The worst outcome of a mismatch is a floor default the user can already edit by hand. |
| T-03-13 | Elevation of Privilege | — | accept | No authn/authz boundary is added or crossed; the provider is a singleton read of a static file with no per-user state. |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs. Both `.csproj` files must show zero diff; adding any dependency requires explicit user approval per CLAUDE.md. |
</threat_model>
