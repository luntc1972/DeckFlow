<objective>
Surface the Phase 81 opening-hand / mulligan evaluation into the `/manabase` PASTE ARTIFACT (the paste-ready
`ManabaseReportTextBuilder` report used by `/manabase/download`): gate it behind the new `analysis.mulligan-eval`
flag (seeded OFF in both dialects with a catalog description), thread the already-computed
`ManabaseMulliganEvaluation` as a trailing optional builder arg, and append a hedged opening-hand block ONLY when
the flag is on — byte-identical when off.

This is the TAP-01/02 recipe (Phase 75): the manabase paste artifact is a SINGLE report builder (there are NO
three decoupled ChatGpt/Claude/Gemini prompt variants here, unlike /deck-analysis — so there is NO 3-variant
parity test; mirror TAP's single-artifact `AppendTapAnalysisBlock` + null-guard byte-identity exactly). The flag
reads fail-safe OFF via `IsFlagOn` and gates SURFACING only; the evaluation itself is always computed in Core
(Plan 81-01).

Purpose: MULLIGAN-06 requires the flag + seed + byte-identical-when-off; MULLIGAN-01 requires the keepable metric
+ color/curve read in the artifact; MULLIGAN-04 requires the has-a-plan read framed as opening-hand EVALUATION,
not keep/mull advice. The block prose (Success Criterion 4) frames every figure as DeckFlow's automated first-pass
consistency signal the AI re-checks, surfaces a BAND not a false-precision %, states the keep criterion narrowly,
and — because the sim runs PER SPELL — the per-opener on-curve read NAMES the tracked early play it belongs to
(TrackedSpellName + TrackedOnCurveTurn from Plan 81-01), never a generic "castable on curve."
Output: catalog + seed rows (both dialects), a builder param + `AppendMulliganEvaluationBlock`, the service flag
gate + `ShowMulliganEval`, the download call-site gating, a Core artifact presence + null-byte-identity test, and
the seed/catalog consistency entries.
</objective>
