# Phase 04-03 — BUG-01 v2: oldest-first printing iteration

## Root Cause

Live UAT against deckflow.gg (2026-05-01) revealed the iterate-printings fix from Plan 04-02 still returns empty for cEDH staples like Sol Ring and Counterspell. Root cause: Scryfall's default `unique=prints` ordering surfaces *newest* commander/eternal/Secret-Lair printings first. For Sol Ring, the first 5 printings are SOC (2026-04), TMC (2026-03), ECC (2026-01), EOC (2025-08), TDC (2025-04) — all 2024-2026 commander/eternal sets, none indexed by Scryfall Tagger. Probing first 5 → all 404 → empty.

Plan 04-02's research correction "no `order=` parameter" was directionally wrong: default ordering empirically yields too-new sets first.

## Fix

Sort `data` array by `released_at` ASC immediately after deserialization, before the probe loop. Old expansion/core printings (e.g., LEA Sol Ring, ICE, mainline Magic sets) ARE Scryfall-Tagger-indexed. With sort, first-5-probed are the oldest 5 printings.
