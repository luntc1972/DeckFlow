# Plan 109-02 — Both Controllers Adopt CommitSwapAsync and Migrate Duplicate Tests

<objective>
Flip both what-if commit paths onto the shared `ICutLabWhatifService.CommitSwapAsync` (built in 109-01), delete the two duplicated restore-then-accept blocks and their divergent validation helpers (`ValidateWhatifPair`, `IsValidWhatifPair`), and preserve each transport's downstream projection and error behavior exactly. Then migrate the duplicated controller-level business-rule tests into the shared service tests (already added in 109-01), leaving only thin delegation/HTTP-shape tests at the controller level. This is a behavior-preserving refactor: no new user-facing behavior, and every existing endpoint protection and error path stays observable.

Purpose: CLUP-04/CLUP-05 — both transports route commit through the one service so the rules cannot drift, and the tests stop duplicating those rules per controller.
Output: Two consolidated controller commit paths and de-duplicated test files.
</objective>

<execution_context>
Delegation: per project rules Codex writes the implementation; this plan is executor-agnostic but implementation-ready. Any dispatch editing existing `.cs` files MUST carry the standard per-file line-ending instruction: preserve each touched file's existing endings exactly (`.gitattributes` enforces LF on changed C# lines; some files are mixed) — do NOT normalize or reflow surrounding method bodies; change only the lines being extracted/replaced. This plan deletes code from long controller methods — remove exactly the duplicated block and helper, leaving the rest of each file byte-for-byte identical.
</execution_context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → JSON API `/api/cut-lab/whatif/commit` | Untrusted swap request; same-origin + antiforgery + state re-validation stay in the controller |
| client → no-JS `/cut-lab/whatif` | Untrusted form POST; antiforgery + state re-validation stay in the controller |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-04 | Information hiding / masked failure | API `PostWhatifCommitAsync` try/catch scope | mitigate | Since `CommitSwapAsync` no longer throws for expected-invalid pairs, narrow the API controller's `try/catch (InvalidOperationException or ArgumentException)` to wrap ONLY the post-commit projection (`_patchBuilder.BuildAsync` + `commanderNames`/`floorByRole` derivation), NOT the `CommitSwapAsync` call. A genuine downstream `BuildAsync` failure must not be swallowed into the generic `NoChangeMessage` (research Pitfall 1). Add a negative test that a throwing patch builder does not produce the generic no-change 400. |
| T-109-05 | Masked failure | no-JS `Whatif` three catch clauses | mitigate | Keep all three catch clauses (`InvalidOperationException` surfacing the real message, `OperationCanceledException` timeout copy, catch-all logging + `NoChangeMessage`). They remain reachable via `Deserialize` and `_pageService.ProcessAsync`; do NOT delete them thinking they are now dead (research Pitfall 2). |
| T-109-06 | Tampering | Same-origin / antiforgery / empty-state guards | mitigate | Preserve every existing early-return guard (API: same-origin 403, null/required 400, deserialize, `Pool.Count==0` 400; no-JS: required-field/intent check, deserialize) BEFORE the `CommitSwapAsync` call — these are HTTP-shape concerns that stay in the controller. |

No package-manager installs occur in this phase — no supply-chain (`T-109-SC`) checkpoint required.
</threat_model>

<must_haves>

CutLabMessages.NoChangeMessage })`; on `Applied=true` calls `_patchBuilder.BuildAsync(result.State, ...)` and returns the existing `CutLabWhatifApiResponse` shape unchanged.

- `ValidateWhatifPair` (API) and `IsValidWhatifPair` (no-JS) are removed; no duplicated restore-then-accept block remains in either controller.
- The API try/catch is narrowed to the projection only; the no-JS three catch clauses remain.
