# Phase 111.1 Plan 03: Batch match-key asymmetry ADR + additive punctuation second pass Summary

Closes SC-4 and SC-5. The H2 DFC lock test
(`ResolveBatchAsync_SingleSlashNameWithNormalizeOn_FallsThroughToFallbackKeyedByOriginalName`)
passed **unmodified, byte-for-byte, both before and after** the Task 3 implementation, and both
`submitted_name:` golden assertions (`AnalysisGoldens.cs:1798` via
`DeckAnalysisByteIdentityTests`, and `DeckAnalysisPacketServiceTests.cs:1460`) passed
**unmodified** in the post-implementation run.

## What Was Built

**Task 1 — ADR 0004** (`docs/decisions/0004-scryfall-batch-match-key-asymmetry.md`): records the
measured live-probe evidence from `111.1-REVIEWS.md` §0 (`/cards/collection` is
punctuation-tolerant but rejects both slash forms of a combined DFC name), traces the phantom-miss
mechanism to the raw `OrdinalIgnoreCase` match-back at `ScryfallReferenceResolver.cs:136`,
evaluates all four options from the plan (decline / `not_found`-driven detection / adopt
`CardNormalizer` / additive second pass), and adopts the additive second pass. States the exact
key definition, the ambiguity rule, and the Deck Analysis prompt-artifact consequence
(a punctuation-drifted name that used to be annotated `submitted_name: X | resolved_card: Y` now
emits the bare resolved name, since it is now `FromFallback: false`).

**Task 2 — RED/GREEN lock tests** (`DeckFlow.Web.Tests/ScryfallReferenceResolverTests.cs`, additions
only, verified via `git diff -U0`):
- `ResolveBatchAsync_PunctuationDriftedCollectionHit_MatchesFromTheBatchResponseWithoutFallback` —
  RED before Task 3 (fallback delegate dispatched and threw, as designed); GREEN after.
- `ResolveBatchAsync_SlashFormsDoNotCollideUnderTheSecondPass` — GREEN both before and after; a
  permanent guard that a future "simplify to `CardNormalizer.Normalize`" change cannot land
  silently, since that key would collide `"a / b"` and `"a // b"` to `"a"`.
- The existing H2 lock test's body, fixture, and assertions were not touched.

**Task 3 — the second pass + SC-5 xmldoc fix**:
- `ScryfallReferenceResolver.cs`: class made `partial`; a private static `BatchMatchKey(string)`
  helper (trim, lowercase, delete `[^\p{L}\p{N}\s/]` via `[GeneratedRegex]`, collapse whitespace)
  is inserted between the raw match-back loop and the fallback loop. It groups still-unmatched
  request names and still-unclaimed returned cards by this key within the same chunk, and commits
  a match only when a key maps to exactly one name AND exactly one card on both sides; any
  ambiguity is left for the fallback loop untouched. A match writes into `oracleNameMap`/`resolved`
  exactly as the raw pass does (`FromFallback: false`, keyed by the ORIGINAL request name). The
  `<remarks>` LOAD-BEARING list gained one new numbered item describing the second pass without
  altering the four existing items.
- `ScryfallCardResolver.cs`: `NormalizeForScryfall`'s xmldoc summary had its false clause deleted
  and replaced with the measured truth (normalization affects only the submitted identifier, never
  the match key; the live probe shows neither slash form resolves at `cards/collection`). A new
  `<remarks>` cross-references ADR 0004. `git diff -U0` on this file shows only `///` comment lines
  changed — no behavior touched. Grepped all `NormalizeForScryfall` call sites first; confirmed
  only the two known ones (`ResolveBatchAsync`'s submission and `SearchPrintingFallbackCardAsync`'s
  query construction) exist.

## Zero-Additional-HTTP-Calls Proof

The inserted second-pass block (`ScryfallReferenceResolver.cs:152-177`) contains no `await` and no
call to `_scryfallCardResolver` or `fallbackStrategy` anywhere in its body — it reads only
`response.Data.Data` (already fetched by the single `ExecuteCollectionAsync` call at line 132,
which existed before this plan) and the in-memory `chunk`/`resolved`/`oracleNameMap` state, and
calls only the pure static `BatchMatchKey` regex helper. There is no code path in the added block
capable of issuing a network request; this was confirmed by direct code inspection, not by
observed absence of a mock invocation.

## Next Phase Readiness

- **Plan 111.1-04/05 (pacing measurement) must know:** this plan changes per-flow Scryfall call
  counts for any punctuation-drifted name (missing/extra apostrophe, curly vs. straight quote,
  etc.) that `cards/collection` already resolves — such a name now costs ONE call (the batch
  `cards/collection` hit) instead of TWO (batch miss + per-name search fallback). DFC-shaped names
  (both single- and double-slash) are UNCHANGED: they still cost the batch call plus one fallback
  call each, because `cards/collection` genuinely cannot resolve either slash form (measured, ADR
  0004). Any pacing measurement that assumes the pre-plan miss/hit ratio for punctuation-drifted
  names is now stale for real-world decks containing apostrophes (`Smuggler's Copter`, `Urza's
  Saga`, etc.) — those will show fewer fallback calls than before this plan.
