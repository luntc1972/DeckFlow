<objective>
Deliver D-14: creator profiles + deck-cache rows reach Render (where content-kb.db never ships) via git-shipped JSON seed files hydrated at startup, plus a manual CLI export command that generates those files.

Purpose: The engine (Phase 99) reads `ICreatorStyleProfileStore` (local-only content-kb.db) and `ICreatorDeckCacheStore` (creator-deck-cache.db). This plan mirrors the proven `ContentKbSeedLoader` startup-hydration pattern (D-100-03) and the `content-index-export` CLI pattern (D-100-04), forked for TWO stores/files.
Output: A two-file seed loader wired into startup, two tracked (empty-array placeholder) seed JSON files, a CLI export command, and tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git repo (public) → prod store | Seed JSON is committed to a PUBLIC repo and hydrated into the prod-local store at startup. It must contain only public deck data + numeric profiles, never secrets or local-only KB content. |
| dev machine CLI → seed files | The operator runs the export locally against local stores and commits the output; a bug that pulls in category-knowledge.db or transcripts would leak local-only content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-100-06 | Information Disclosure | Seed export scope | mitigate | Export reads ONLY `ICreatorStyleProfileStore` + `ICreatorDeckCacheStore` (D-100-02); it never reads category-knowledge.db or transcript bodies. Two-file scoping keeps the surface auditable in diffs. |
| T-100-07 | Tampering | Startup seed hydration | mitigate | Loader is idempotent (plain UpsertAsync), independently present-checks each file, and no-ops cleanly when files are absent — a malformed/absent seed cannot crash startup beyond a logged skip. |
| T-100-SC | Tampering | npm/pip/cargo installs | accept | No package installs; all frameworks (System.Text.Json, System.CommandLine) pre-existing. |
</threat_model>
