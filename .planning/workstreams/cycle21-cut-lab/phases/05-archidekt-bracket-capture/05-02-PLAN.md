**Step A — extract the mapping first, as its own type.** Create `DeckFlow.Core/Knowledge/ArchidektDeckMetadataParameters.cs` holding a pure, dependency-free `ArchidektDeckMetadataParameters.From(ArchidektDeckMetadata metadata)` that returns the six SQL parameter values. Conversions are **mandatory and explicit in C#, never in SQL and never dialect-branched**: bind `metadata.Theorycrafted is null ? (int?)null : (metadata.Theorycrafted.Value ? 1 : 0)`, and bind every timestamp as a pre-formatted `"O"` string (`metadata.CreatedUtc?.ToUniversalTime().ToString("O")` and likewise for `UpdatedUtc` and the non-null `CapturedUtc`). Every emitted value must therefore be `int?` or `string?`. Two concrete Postgres failures this prevents, both invisible under SQLite: binding a `bool?` to `archidekt_theorycrafted INTEGER` makes `BoolTypeHandler.SetValue` bind a native `boolean`, and Postgres has no assignment cast boolean→integer (`42804`); and `COALESCE(timestamptz, text)` cannot be unified, because `DateTimeTypeHandler.SetValue` passes a raw `DateTime` for non-SQLite. `DeckQueueRepository` must build its metadata parameters **only** through this type — no ad-hoc inline conversion at the call site, or the Task 1 Test 7 gate stops proving anything about what the repository actually binds.

Extend `DeckQueueRepository.MarkDeckProcessedAsync` and `MarkUrlDeckProcessedAsync` with `ArchidektDeckMetadata? metadata = null` while keeping `CancellationToken` last. Add `using DeckFlow.Core.Integration;`. When metadata is non-null, set all six columns from `ArchidektDeckMetadataParameters.From(metadata)`. When metadata is null, **leave all six Archidekt metadata columns unchanged** — on the processed-row `UPDATE` simply omit them from the `SET` list, so an already-captured row that later gets re-harvested and skipped cannot revert to "not captured". Skip/failure rows must never gain a capture timestamp per D-06; a fresh never-captured row naturally stays null because the columns were never written.

This is safe on Postgres **only because Step A binds timestamps as `"O"` strings** — `COALESCE(text, text)` unifies trivially, whereas `COALESCE(timestamptz, text)` does not. Do not apply this instruction without Step A.
