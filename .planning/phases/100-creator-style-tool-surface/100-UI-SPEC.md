# Phase 100 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This phase ships one new sibling tool page inside an existing, mature server-rendered design system (ASP.NET Razor + hand-authored CSS, 15 guild-theme forks).** There is no component framework (no React/shadcn/Tailwind) — `components.json` absent, confirmed by filesystem scan. This contract therefore documents **deltas from the closest sibling tool pages**, not a from-scratch design. Do not introduce new CSS primitives where an existing class already does the job.

**Primary visual anchor:** the `.run-button` primary CTA ("Build Critique Packet") is this page's single focal point — accent-colored per the Color contract below, positioned at the bottom of the form exactly as sibling tools place it. Every other element on the page (picker, deck-input columns, summary strip, banners) is visually subordinate to it; nothing else on the page should carry accent color or higher visual weight.

**Closest sibling templates** (Claude's Discretion, resolved):
- **Page/form shape:** `DeckFlow.Web/Views/Deck/Manabase.cshtml` — single `<form>` → result panel below, no `_WorkflowStepTabs` multi-step strip (matches D-100-11).
- **Deck-input columns:** `DeckFlow.Web/Views/Deck/DeckComparison.cshtml` (`.sync-columns` / `.sync-column` / `data-sync-panel` toggle pattern) — matches D-100-10's "standardized import component (site dropdown + URL/paste toggle)".
- **Controller/service orchestration shape:** `DeckAnalysisPacketService.cs` (`PromptMutatingAnalysisFlags` / `ShouldBypassPacketCache()` cache-bypass latch, lines ~156–394) — mirror exactly per D-100-06 and canonical_refs.

## Spacing Scale

This codebase does not use a raw px 8-point scale directly in markup; it uses **rem-based utility spacing already baked into existing shared classes**. New markup for this phase must reuse these existing classes rather than hand-rolling new padding/margin values.

| Token (existing usage) | Value | rem→px | Usage |
|-------|-------|--------|-------|
| xs | 0.25rem–0.35rem | 4–5.6px | icon gaps, chip inline padding |
| sm | 0.5rem | 8px | compact element spacing (`.field` gaps, `.sync-column__hint` margins) |
| md | 0.75rem–1rem | 12–16px | default element spacing (`.field` block spacing, `.result-panel` padding) — 1rem is the single most common value in `site-common.css` (59 occurrences) |
| lg | 1.5rem | 24px | section padding (`.hero`, `.result-panel` top-level sections) |
| xl | 2rem | 32px | layout gaps between major page sections |

**Legacy Spacing System note:** `xs` (0.25rem–0.35rem → 4–5.6px) and `md` (0.75rem–1rem → 12–16px) include values that sit off a strict 4/8/16/24/32/48/64 px grid (5.6px, 12px). These are **not new deviations introduced by this phase** — they are inherited verbatim from the existing sitewide rem-based scale already baked into shared classes this phase reuses. `0.35rem` specifically recurs throughout `site-common.css` (e.g. lines 183, 363, 705) as an established legacy value, predating this phase and out of scope to normalize here.

This inheritance does **not** license new off-grid values. Any genuinely **new page-specific CSS this phase authors** — the creator-picker chip, the summary-strip chips/pills — must restrict itself to standard multiples-of-4 (4px/8px/16px/24px/32px etc., expressed in rem as 0.25rem/0.5rem/1rem/1.5rem/2rem). Off-grid legacy values (0.35rem, 0.75rem, etc.) are reserved exclusively for verbatim-reused existing classes (`.field`, `.sync-columns`/`.sync-column`, `.result-panel`, `.toolbar`, `.hero`) — do not carry them into new selectors. The summary-strip chips (rubric verdict, exemplar names) should otherwise reuse the existing small "chip" pattern already present in this file (see `.manabase-chip`, `.manabase-lens-pill` for the visual precedent — pill/chip = `padding: sm` (0.5rem, on-grid), `border-radius` per existing chip radius, `font-size: var(--fs-xs)`).

## Typography

Reuse the existing token set declared in every theme file's `:root` (verified in `site-azorius.css`; identical variable names across all 15 theme forks, values only differ per theme):

| Role | Token | Size (theme-typical) | Weight | Line Height |
|------|-------|------|--------|-------------|
| Body / hint text | `var(--fs-sm)` / `var(--fs-base)` | 0.85rem / 0.95rem | 400 (default, unset) | 1.4–1.6 (match `.sync-column__hint`, `.manabase-help` precedent) |
| Label (form field labels, small caps status text) | `var(--fs-xs)` or `var(--fs-sm)` | 0.85rem | 600 | 1.2 |
| Heading (`h2`/`h3` section headings, e.g. "Result", "Your Deck") | `var(--fs-xl)` | 1.5rem | 700 | 1.2 |
| Display (`h1` page title, "Creator-Style Critique") | `var(--fs-2xl)` | 1.9rem | 700 | 1.2 |

**The contract is genuinely 3 weights: 400 (body), 600 (labels), 700 (headings/display).** The 700 weight is **not new CSS this phase authors** — it is the sitewide default `h1`–`h3` browser/stylesheet heading weight already applied globally across every existing tool page (see the 700-weight heading rules already present in `site-common.css`, e.g. lines 163–164, 710–711). This page inherits that default by using plain `<h1>`/`<h2>`/`<h3>` tags exactly as every sibling tool page does; it does not declare a page-specific `font-weight: 700` rule anywhere. The 4 declared sizes stay exact — do not introduce a 5th size. Do not hardcode px/rem literals in new CSS — always reference the `--fs-*` custom properties so every guild theme stays in sync.

## Color

Reuse the existing semantic token set — do not introduce new raw hex values in this phase's CSS. Every guild theme file supplies its own values for the same variable names, so the page automatically re-skins per theme with zero page-specific overrides.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--theme-surface)` in light themes / `var(--panel)` in dark themes per existing project rule (see reference: `--theme-surface light in dark themes` pitfall — **use `--panel` for this page's panel backgrounds, never `--theme-surface` directly**, per the standing project reference note) | page background, form panel background |
| Secondary (30%) | `var(--panel-soft-bg)`, `var(--panel)` | `.sync-column` cards, nested result panels, creator-picker dropdown chrome |
| Accent (10%) | `var(--accent)` / `var(--accent-strong)` | reserved for: the primary submit button (`.run-button` — the page's primary visual anchor, see above), the creator-picker's selected-state border, the copy-button, focus rings (`var(--focus)`) — nothing else. Do not tint body text, borders on non-interactive containers, or decorative elements with accent. |
| Destructive | `var(--danger)` | reserved for: the "Start Over" / clear-cache affordance if present (matches sibling `.clear-cache-button` styling), and any inline validation error text. This phase has no true destructive/delete action (no data loss risk on submit) — `--danger` is NOT needed for a confirmation dialog in this phase. |

Accent reserved for: primary CTA button (the page's focal point), selected creator-picker option, copy-button, focus-visible outlines. Never apply accent to informational banners, chips, or body copy.

**Degraded-grounding warning banner (D-100-15):** reuse the existing `.warning-banner` class verbatim (already defined in `site-common.css` with per-theme `.warning-banner` background overrides in every theme file) — do not invent a new banner style. `.info-banner` and `.error-banner` are the sibling classes for the other two banner states this page needs (see Copywriting Contract below).

## Interaction & State Contract (delta notes beyond the standard 6 dimensions)

These are project-specific interaction contracts the checker/executor need beyond generic copy/color/spacing, extracted from locked CONTEXT.md decisions:

- **Page structure:** single `<form>` → result panel appended below on POST, matching `Manabase.cshtml` exactly. No `_WorkflowStepTabs` partial, no multi-step state machine (D-100-11).
- **Deck input:** reuse `.sync-columns`/`.sync-column` two-column layout with `data-sync-panel` URL/paste toggle exactly as `DeckComparison.cshtml` implements it (D-100-10). Do not fix the known deck-input-store restore desync bug in this phase — it is explicitly deferred backlog, inherited as-is.
- **Creator picker:** native `<select>` with `data-df-select` (matches every sibling `<select>` in this codebase — e.g. `Mode`, `SortBy` in `CedhMetaGap.cshtml`), populated server-side only from creators actually present in `ICreatorStyleProfileStore`. No free-text entry, no client-side autocomplete/datalist (unlike the commander-name field in `CedhMetaGap.cshtml`, which does use a `<datalist>` — that pattern is NOT appropriate here since D-100-09 requires the picker itself to be the source of truth).
- **Result content:** copy-ready packet block (`<textarea readonly>` + `.copy-button` targeting it, matching `#cedh-meta-gap-prompt-output` pattern exactly) plus a small summary strip above it (rubric verdict chips + exemplar deck names) — never a full rendered report duplicating the ChatGPT response (D-100-13).
- **Mobile re-download:** reuse the existing fetch-intercept download pattern (see project memory: mobile-refresh re-download fix) if this page offers a "Download packet" affordance mirroring `.manabase-download` / `.prompt-sticky-download` sibling patterns.
- **Flag-off state:** tile hidden from Home, route 404s, and the route is absent from the sitemap (SeoPaths/`SitemapController` gated on `tool.creator-style.enabled`) — mirrors D-100-07/D-100-05. This is a behavioral contract, not a visual one, but the checker should verify no orphan nav link or sitemap entry exists while the flag is OFF.
- **Themes/viewports:** this page must render correctly across all 15 guild theme forks and at desktop + the existing mobile breakpoints (`site-mobile.css`: 900px / 768px / 600px / 480px). No page-specific media queries beyond what sibling tools already use — reuse `.sync-columns` responsive collapse behavior verbatim.
