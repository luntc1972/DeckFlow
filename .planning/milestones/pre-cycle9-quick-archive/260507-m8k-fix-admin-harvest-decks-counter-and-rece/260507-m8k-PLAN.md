<objective>
Fix two production bugs on /Admin/Harvest:

  - **B1** — The decks-imported counter is stuck at 0 for the duration of every running job because `HarvestRunStore.UpdateStateAsync` is only called at terminal state transitions; the initial Running write hardcodes 0 and nothing advances `decks_processed` until the job ends.
  - **B2** — The Recent Runs / Run Log grid does not refresh while the page is open. The `admin-harvest.ts` poller early-exits when initial state is not active, and even when it is running it never updates the recent-runs table; only the live-status banner is touched.

Purpose: restore real-time visibility into harvest progress for the operator without forcing manual page reloads. Both bugs harm operator confidence — the page LOOKS broken even when the harvest is healthy.

Output: incremental mid-run progress writes throttled to roughly every 2 seconds OR every 10 decks (whichever first); an additive `recentRunsRevision` token surfaced from `/Admin/Harvest/status`; an always-on TypeScript poller that reloads the page when the revision changes; no dialect divergence; no breaking interface changes.
</objective>
