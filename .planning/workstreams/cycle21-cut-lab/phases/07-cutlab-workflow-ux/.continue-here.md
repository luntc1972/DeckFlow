## Critical Anti-Patterns

| # | Anti-pattern | severity |
|---|---|---|
| 1 | Trusting a Codex-reported "clean run" instead of the process exit code | blocking |
| 2 | Reading a build warning baseline from a non-rebuild `dotnet build` | blocking |
| 3 | Running the gate spec as one batched invocation instead of `-g` per gate | blocking |
| 4 | Calling `gsd-tools query state.begin-phase` on this STATE.md | blocking |

**1 — Exit codes, not footers.** During 07-02 Codex reported the migrated e2e specs
"rerun cleanly"; the actual exit code was 1 with a failing test. Its own caveat
("Playwright's final footer was suppressed by the runner environment") was the tell.
*Mechanism:* every verification command must be judged by `$?`. Never accept a prose
claim of a pass without re-running it.

**2 — MSBuild only prints warnings for projects it RECOMPILES.** A plain
`dotnet build DeckFlow.sln` on an up-to-date tree prints `0 Warning(s)` while warnings
still exist. The TRUE baseline is **0 errors / 9 pre-existing CS8629** in
`DeckFlow.Core.Tests/Manabase/ManabaseBaselineWeightingTests.cs`, visible only under
`-t:Rebuild`. A fabricated "0 warnings" baseline was handed to Codex once and it correctly
refused to proceed, costing a round. *Mechanism:* state the 0-errors/9-CS8629 baseline
verbatim in every dispatch; never re-derive it from an incremental build.

**3 — The gate spec is `mode: 'serial'`.** One batched run halts after the first failure
and reports the rest as "did not run", which skims as a pass. *Mechanism:* run each gate as
its own process with `-g "G-1"` … `-g "G-4"` and record four independent exit codes.

**4 — `state.begin-phase` corrupts this STATE.md.** It rewrote counters wrongly
(total_phases 10→9 because Phase 01.2 is roadmap-only with no directory; completed_phases
5→2; deleted `percent:`) AND replaced the first line of multi-line prose sentences, leaving
orphaned fragments. It still parses, so nothing complains. *Mechanism:* edit STATE.md
frontmatter by hand. `percent = ((completed_phases/total_phases) + (completed_plans/total_plans)) / 2`.
