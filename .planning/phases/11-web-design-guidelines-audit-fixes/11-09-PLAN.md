<objective>
Land Sweep 9 of the WDG audit: server-render `aria-selected` and `tabindex` on each step tab in `_WorkflowStepTabs.cshtml` based on the current-step predicate, so keyboard users have a valid entry point into the tablist even when JS fails.

Purpose: ARIA tablist pattern requires exactly one tab with `aria-selected="true"` `tabindex="0"`. The current partial renders all tabs with `aria-selected="false" tabindex="-1"` server-side, meaning keyboard users have no tab in focus order until JS runs. WDG-03 fix is to pre-select the current step server-side based on the existing model property (per CONTEXT.md the partial already accepts `currentStep` via `WorkflowStepTabsModel`).

Output: Updated `_WorkflowStepTabs.cshtml` with conditional aria-selected/tabindex; one partial, three consumer pages benefit (ChatGptPackets, ChatGptDeckComparison, ChatGptCedhMetaGap).
