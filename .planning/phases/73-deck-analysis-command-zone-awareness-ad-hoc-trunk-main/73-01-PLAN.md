<objective>
Lay the contract-first foundation for command-zone awareness without changing any rendered output:
register the new default-OFF feature flag, widen the prompt-variant interface to carry a companion
name, and add the companion designator property to the request model. Nothing renders the new data
yet — every change is additive and byte-identical when the flag is OFF (which it is by seed).

**Flag decision (recorded here):** use a NEW flag `analysis.command-zone-awareness`, seeded OFF —
NOT a reuse of `manabase.commander-castability`. Rationale: the existing byte-identity test at
`DeckAnalysisPacketServiceTests.cs:879` toggles `manabase.commander-castability` and asserts
deck-analysis is unchanged; a separate flag keeps that test valid unchanged, gives the operator
independent control, and lives in the correct `analysis.*` namespace (research §RQ6, Option B).

**Designator decision (recorded here):** YES — add `CompanionName` to `DeckAnalysisRequest` for
parity with `ManabaseRequest.CompanionName`. Without it, companion awareness would only work for
Moxfield-direct imports (Archidekt and pasted text never emit `DetectedCompanionName`). The model
field lands in this plan so Plan 02 can read it; the Step-1 UI input lands in Plan 04.

Purpose: downstream plans implement against a settled flag key, interface signature, and request
shape — no scavenger hunt.
Output: flag registered (5 touch points), interface + registry + 3 variant signatures carry
`string? companionName = null`, `BuildAnalysisPrompt` forwards it, request model has `CompanionName`.
</objective>
