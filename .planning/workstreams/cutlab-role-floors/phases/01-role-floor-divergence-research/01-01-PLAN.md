<objective>
Build and run a throwaway `DeckFlow.CLI` research command that re-derives per-commander role-floor
divergence for Cut Lab's five role floors (interaction, protection, engines, payoffs, win
conditions) using the REAL production classifiers (`DeckStatClassifier`, `PlanRoleClassifier`,
`CutLabRoleAssigner`) and the REAL production Scryfall resolver against the Postgres
category-knowledge corpus, applies one explicit, uniformly-applied statistical bar, and publishes a
committed findings document ending in a named go/no-go recommendation for Phase 2.

Purpose: the prior ad hoc session's 4-commander Python reimplementation cannot be trusted to
predict what the shipped C# classifiers would say, and its sample was too small to separate
signal from corpus noise. This phase replaces both problems: real classifiers, in-process, on a
defensible sample, judged by a bar that is written down before the data is read.

Output: `DeckFlow.Core/Research/RoleFloorDivergenceStats.cs` (pure, unit-tested statistical bar),
an additive, backward-compatible board filter on
`CategoryKnowledgeRepository.GetCategoryDeckMembershipForCommanderAsync`,
`DeckFlow.CLI/RoleFloorResearchCommandRunner.cs` (the `role-floor-research` CLI command wired
into `Program.cs`), and the committed `RESEARCH-FINDINGS.md` with its go/no-go line. Nothing
under `DeckFlow.Web`'s shipped controllers/views/services is touched.
</objective>

    - ComputeRatio(commanderMean: 3.0, corpusMean: 6.0) -> 0.5

    - ClearsBar(n: 200, commanderMean: 7.2, corpusMean: 6.0, corpusStdDev: 3.0, minDeckCount: 40, ratioLow: 0.667, ratioHigh: 1.5, zThreshold: 2.0) -> false (ratio 1.2 sits inside [0.667, 1.5] -- not a real divergence even though N is huge and z may clear 2.0; ratio and z are both required, not either/or)
    - ClearsBar(n: 200, commanderMean: 6.0, corpusMean: 0.0, corpusStdDev: 0.0, minDeckCount: 40, ratioLow: 0.667, ratioHigh: 1.5, zThreshold: 2.0) -> false (zero corpus baseline means the role never appears in the corpus at all; nothing to diverge from)
    - ComputePercentile(values: [1,2,3,4,5], percentile: 0.25) -> 2.0 (linear-interpolation rank index = 0.25*(5-1) = 1.0 exactly -> sorted value at index 1)
    - ComputePercentile(values: [1,2,3,4], percentile: 0.25) -> 1.75 (rank index = 0.25*3 = 0.75 -> interpolate between sorted[0]=1 and sorted[1]=2: 1 + 0.75*(2-1))
    - ComputePercentile(values: [7], percentile: 0.25) -> 7.0 (a single-value sample returns that value for any percentile)
    - ComputePercentile(values: [], percentile: 0.25) -> throws ArgumentException (a role-count sample with zero decks has nothing to report a percentile over)
    - ComputeCohensD(commanderMean: 9.0, corpusMean: 6.0, corpusStdDev: 3.0) -> 1.0 (raw effect size, NOT scaled by sqrt(n) the way ComputeZScore is -- reports the same "how many corpus standard deviations apart" regardless of sample size)

    statistical bar Cycle 21 Phase 1 applies uniformly to every commander/role pair -- no other file
    may re-derive or fork this threshold logic. Expose five pure static methods:
      - `public static double ComputeRatio(double commanderMean, double corpusMean)` -- returns
        `commanderMean / corpusMean`; returns 0.0 when corpusMean is exactly 0 (guard, xmldoc'd:
        "no baseline signal to compare against").
      - `public static double ComputeZScore(double commanderMean, double corpusMean, double

        corpusStdDev, int minDeckCount, double ratioLow, double ratioHigh, double zThreshold)` --
        returns true only when ALL THREE hold: `n >= minDeckCount`; `corpusMean > 0` AND
        (`ComputeRatio(commanderMean, corpusMean) >= ratioHigh` OR `ComputeRatio(...) <=
