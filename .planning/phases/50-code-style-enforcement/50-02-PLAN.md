<objective>
Build the single shared changed-lines formatting gate (D-04): `scripts/format-check-changed.sh` holds the diff-intersect logic; `.githooks/pre-commit` runs it on staged hunks (FMT-04); a new parallel `format-gate` job in `ci.yml` runs it on the correctly-selected base-ref diff (FMT-03).

Purpose: Enforce the reconciled `.editorconfig` on NEW/CHANGED lines only — a mis-formatted added line fails, a one-line edit in a quirky legacy file passes. One script, two contexts, zero local-vs-CI drift. The gate must be CORRECT: it must not (a) false-fail legacy edits because the formatter exits non-zero on off-hunk violations, (b) silently pass a mis-formatted ADDED line because absolute report paths never match repo-relative diff paths, or (c) silently pass on a direct push to main because the base ref resolved to HEAD.

Output: The shared script, the versioned hook, and the CI job. The report path lives under `artifacts/` which is ALREADY gitignored (line 4) — NO `.gitignore` edit is needed.

ALWAYS `echo` the selected base ref AND how it was chosen (`before` / `merge-base origin/<ref-name>` / `merge-base origin/main`) to the log before diffing. If no usable base can be resolved at all, fail CLOSED (distinct exit code, clear "could not resolve CI base ref" message) rather than diffing against nothing.

Before intersecting, normalize every report `FilePath` to a repo-relative, forward-slash path: resolve the repo root once via `ROOT=$(git rev-parse --show-toplevel)`, convert backslashes to forward slashes, and strip the `$ROOT/` prefix to get the repo-relative path; likewise strip the leading `a/`/`b/` from git diff paths. Compare ONLY normalized repo-relative paths. If a report `FilePath` cannot be mapped under `$ROOT` after normalization, fail CLOSED (distinct exit, "report path outside repo root: <path>" message) — never silently drop it (an unmapped path yields an empty intersection and a mis-formatted ADDED line would silently PASS).
    Step C-fname — filename-policy / quoted-path guard (FIX LOW 1): git renders paths containing special bytes as C-quoted `+++ "b/..."` headers (and control-char filenames). The parser MUST DETECT a quoted diff path (leading `"` after the `+++ `/`--- ` prefix) or any report/diff path that cannot be mapped under `$ROOT`, and fail CLOSED with a clear "unsupported/quoted filename — gate cannot safely parse" message, rather than mis-parsing.     Step E — verdict: if any intersection exists, print each offending `file:line` plus a one-line "run `dotnet format <file>` and re-stage only the changed lines" hint, then exit 1. Otherwise exit 0.
    Security: quote every `"$file"` expansion; pass changed files to `--include` as separate quoted args, never a joined eval'd string; never `eval` diff/report content (filenames are untrusted — Tampering/EoP mitigation). The `set +e/set -e` window is SCOPED to the formatter run only (Step C); the rest of the script keeps `set -euo pipefail`.
    Filter scope: only ever `*.cs` in the diff and `--include`; never run a global `git add` or any EOL normalization (Pitfall 5 — protects `.ps1/.bat/.cmd` CRLF carve-out files).
    Make the script executable (`chmod +x`). The report lives at `./artifacts/format-report.json`, and `artifacts/` is ALREADY gitignored (verified line 4) — make NO `.gitignore` change. ONLY if you deliberately choose a report path OUTSIDE `artifacts/` (do not) would a new `.gitignore` entry be warranted; keep the report under `artifacts/` to avoid touching `.gitignore` (minimal-diff discipline).
