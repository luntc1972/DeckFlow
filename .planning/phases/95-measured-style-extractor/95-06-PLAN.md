<objective>
Build the Web-host crawler: `ArchidektOwnerClient` behind an `IArchidektOwnerClient` seam (the two NET-NEW Archidekt endpoints — `GET /api/users/?username=` to resolve the creator and `GET /api/decks/v3/?ownerUsername=&pageSize=&page=` to enumerate public decks — live-verified 2026-07-11: top-level `count`/`next`/`results[]` with `id`/`name`/`size`/`parentFolderId`, `parentFolderName` may be null) and `CreatorProfileDeckCrawler`. The crawler applies a **creator-level crawl-freshness short-circuit FIRST** (D-02): if `creator_profile_source.last_crawled_utc` is set, within a configurable freshness window (default 24h), and no force-refresh, it rebuilds the full `CreatorDeckSample[]` from `creator_deck_cache` entries_json and makes ZERO Archidekt calls of any kind (no owner-resolve, no owner-list, no per-deck import). Only when the window has expired (or force-refresh) does it resolve → paginate under a hard cap → per-deck `ArchidektApiDeckImporter.ImportAsync` on cache-miss (or rebuild from the cache's entries_json on an unchanged-hash hit) → drop >105-card decks → capture parentFolder + confidence marker → read-through the creator deck cache → stamp `last_crawled_utc`. Includes the D-01 manual-URL fallback constrained to archidekt.com by host match (SSRF guard), a bounded response-byte cap + `JsonException` handling on the two endpoints (MED-1), and a strict host-match SSRF guard (MED-2).

Purpose: CS-04a/b/c/d — the crawl half. This is net-new HTTP code (NOT `ArchidektRecentDecksImporter`, which is a different endpoint — Pitfall 1). Closes HIGH-2: a warm cache re-hitting Archidekt (even the owner-list endpoint) is the failure this short-circuit eliminates.
Output: Owner client (interface + impl) + crawler + host-match guard + DI wiring + fixtured tests incl. a zero-Archidekt-HTTP-total warm-cache test.
