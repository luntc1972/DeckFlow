<objective>
Add the deck-only staleness PRIMITIVES and the feature flag to `DeckPrimerPacketService`, with golden tests that lock the multiset-hash equivalence relation (PRIMER-02) and the changed-card count semantics (PRIMER-04).

The primitives are deliberately PURE / network-free so the real activation path in 78-02 (resume-without-rebuild) can compute staleness with NO upstream re-fetch and NO `BuildAsync` (PRIMER-03). Three pieces ship here: (1) the deck-only canonical hash reused verbatim from the cache key's deck component; (2) a pure `EvaluateStaleness(hash, currentEntries, savedEntries)` that returns the stale boolean + changed-card count; (3) a network-free `TryParseDeckTextLocal` that turns in-hand paste text into entries without ever importing a URL. Plus the generation-time deck hash is exposed on `BuildAsync`'s result so the controller can re-arm the hidden field and persist the hash into the download zip.

Purpose: Establish the single, testable source of truth for "did the deck change since the primer was generated" before any UI or controller wiring consumes it. The hash MUST canonicalize identically to the primer cache key's deck component so fresh/stale never disagrees with cache behavior.

Output: `DeckPrimerPacketService.StaleFlag` const, `BuildCanonicalDeckSourceText` exposed `internal static`, `DeckMultisetHash` added to `DeckPrimerPacketResult`, the pure `EvaluateStaleness` returning a `PrimerStaleness` record, the network-free `TryParseDeckTextLocal`, the `tool.primer.stale-flag` row in the catalog + both seed blocks, and golden tests.
