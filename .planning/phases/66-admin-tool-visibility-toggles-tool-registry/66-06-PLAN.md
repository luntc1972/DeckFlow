    SECONDARY (a POST sibling) — FILTER-ORDERING CAVEAT: the gate is an IAsyncActionFilter, and ASP.NET
    antiforgery validation runs BEFORE action filters. A token-LESS POST therefore returns 400 (antiforgery)
    and never reaches the gate, which would prove the wrong thing. To exercise the 404 GATE path on a POST you
    MUST submit a VALID antiforgery token: (a) while Deck Analysis is still ON, navigate to `/deck-analysis` so
    the antiforgery cookie is set in the browser context and read the hidden `__RequestVerificationToken` input
    value from the rendered download form; (b) toggle Deck Analysis OFF via /Admin/Tools; (c) `page.request.post(
    '/deck-analysis/download', { form: { __RequestVerificationToken: token, ...minimal required fields } })` using
    `page.request` so the antiforgery COOKIE rides along with the captured token; (d) assert the response is 404 —
    proving the feature gate (not antiforgery) blocks it. Do NOT reorder the gate vs antiforgery pipeline. If
    capturing a usable token/required-field set proves brittle, the PRIMARY GET sibling proof stands alone as the
    required sibling assertion and the POST proof may be marked test.fixme with the reason — but attempt the
    token'd POST first.
    (3) Show flow — toggle card-lookup back ON; assert tile, nav link, help entry reappear and /card-lookup
    returns 200.
    (4) Section collapse — toggle BOTH Categories tools OFF; assert the Categories nav trigger/header is absent
    on / and the Categories hub-group is absent from the home grid; toggle both back ON and assert the section
    returns.
    (5) Core warning — toggle Deck Analysis (core) OFF; assert /Admin/Tools shows the inline warning banner
