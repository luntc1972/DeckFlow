<objective>
Bug B — replace the three hardcoded Jeskai-blue literals with an accent-derived tint so every theme renders its own accent.

Three non-token `rgba(43, 108, 176, …)` values leak a fixed blue into all 24 themes:
1. `site-common.css:792/797` — `.prompt-layout-segment:hover/:focus-visible` and `.is-active` (global, zero theme overrides — the widest leak).
2. `site.css:308` — `.prompt-layout-picker [data-prompt-ui-mode-button].is-active` background.
3. `site.css:623` — `.clear-cache-button:hover` background.

Purpose: closes the Pillar-3 (Color) accent-leak that is the lowest-scoring UI pillar (requirement UIAUDIT-02, "enumerated gaps fixed"). This is the foundation plan — it establishes the inline `color-mix(in srgb, var(--accent) N%, transparent)` accent-tint approach (the SAME pattern already used in-repo at `site-mobile.css:357`) that plan 86-04 reuses, and it is the smallest surface, so it lands first.

Design note (per reviewer): the fix INLINES an accent-derived `color-mix` value at each call site — it does NOT introduce a named `--accent-tint-*` token. "Accent-derived color-mix," not "tokenize."

Output: three literal families replaced by an inline `color-mix` on `var(--accent)`; grep-clean of the literal outside `site-jeskai.css`.
</objective>
