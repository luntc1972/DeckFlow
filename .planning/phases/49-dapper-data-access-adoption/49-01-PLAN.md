<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application code → SQL execution | Store methods pass user-derived values (feedback message/email/page URL/user agent) into queries |
| DB reader → CLR object (type handlers) | Stored DB values (possibly legacy/malformed) are deserialized by the handlers' Parse() |
| process init → SqlMapper global state | Handler registration mutates global Dapper state; both providers run in one test process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-01 | Tampering | FeedbackStore Dapper params (SQL injection regression) | mitigate | All SQL kept verbatim and parameterized via Dapper anonymous objects; no string interpolation introduced; grep confirms no interpolated SQL in converted methods |
| T-49-02 | Tampering | Type-handler Parse() on malformed DB values (data-integrity / D-05 parity) | mitigate | Handlers use explicit `switch` cases with `Convert.*`/`Guid.Parse` fallback that throws InvalidCastException (fail-closed); REQ-2 round-trip test proves exact parity vs pre-Dapper values |
| T-49-03 | Denial of Service | EnsureRegistered() race / both providers in one process (D-04) | mitigate | Interlocked.Exchange idempotent guard registers exactly once; self-detecting handlers branch on runtime value/param type rather than an ambient provider flag, so concurrent SQLite+PG use is safe |
| T-49-SC | Tampering | Dapper package install (supply chain) | accept | Dapper 2.1.79 audited [OK] in RESEARCH §Package Legitimacy (DapperLib official org, ~13yr, 500M+ downloads); user-approved; single approved package |
</threat_model>
