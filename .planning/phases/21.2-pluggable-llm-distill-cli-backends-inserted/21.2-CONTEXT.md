# Phase 21.2: Pluggable LLM Distill CLI Backends - Context

**Gathered:** 2026-06-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Make the local Content KB distill step able to drive its 3 LLM extractions (summary, timestamped clips, controlled-vocab tags) through the **Claude Code (`claude`) CLI** instead of the OpenAI API, selected by an env var, runnable from **WSL or Windows** shells. OpenAI API stays the **default** backend with byte-identical current behavior (no regression). This removes the OpenAI-API-billing dependency that blocked the Phase 21.1 live-UAT gate (it hit `HTTP 429 insufficient_quota` on 2026-06-01).

**SCOPE CHANGE 2026-06-01 (Codex round-2 review):** the `codex` backend is split out to **Phase 21.3** (KB-12). codex `exec` is an agent whose read-boundary under untrusted transcript input can't be cleanly proven (`--sandbox read-only` blocks writes, not reads); claude's `--allowedTools ""` truly disables tools, so claude ships first. The provider factory is built **extensible** — a `codex` value throws a clear NotSupportedException pointing to Phase 21.3.

**In scope:** provider abstraction + factory (openai|claude), one CLI-backed `ILlmDistillationService` (claude), cross-platform process launch + env config, best-effort-JSON parse/repair, spend-ledger bypass for subscription backends, unit tests, docs.
**Out of scope:** the `codex` backend (Phase 21.3 / KB-12); changing the distill prompts/schemas themselves (reuse Phase 21's); the site/index (Phase 22); Whisper transcription backend (stays OpenAI/captions per Phase 20); any Render/server change.
</domain>

<decisions>
## Implementation Decisions

### Seam placement (D-01)
- **D-01:** Add a NEW `CliLlmDistillationService` that implements `ILlmDistillationService` **directly** (SummarizeAsync / clip / tag → SummaryResult / ClipsResult / TagsResult). Do NOT refactor Phase 21's OpenAI-typed `ExtractJsonAsync` (it returns OpenAI `ChatCompletion` — not reusable). Shipped Phase 21 code stays untouched → minimal regression surface.
- **D-01a:** Extract the 3 system prompts + the 3 JSON schema strings (currently constants inside `LlmDistillationService`: `SummarySystemPrompt`, clips/tags prompts, `DistillationSchemas.*`) into a **shared static** so both the OpenAI impl and the CLI impl use **byte-identical** instructions (preserve raw-string literals exactly — invariant #9). Planner decides exact shared-type name/location; OpenAI impl must keep emitting identical bytes after extraction.

### CLI I/O contract + cross-platform launch (D-02) — claude-only; CORRECTED round-2 per Codex H1/H2 + M3/M4 + new-HIGH-A + MED-deadlock
- **D-02:** Instruction + injected schema = the CLI **argument** (verified contract); the **transcript = stdin**. JSON read from **stdout**. `System.Diagnostics.Process`, `UseShellExecute=false`, `RedirectStandardInput/Output/Error=true`.
  - RESEARCH-verified claude shape: `claude -p "<instruction+schema>" --output-format json --allowedTools ""` with transcript piped to stdin → parse stdout JSON, read `.result`, then parse inner JSON (`is_error:true`=fail).
- **D-02a (ArgumentList, not space-split; Codex M3):** Build the command as a **`CliCommandSpec`** = { FileName, ArgumentList (incl. the instruction arg), EnvelopeKind (claude-json | raw), WorkingDirectory }. Use `ProcessStartInfo.ArgumentList` (NOT `Arguments` string) so the instruction arg, `--allowedTools ""`, and paths-with-spaces pass without shell-quoting hazards.
- **D-02a-override (NEW-HIGH-A + round-3 HIGH-1 — structured JSON-array override):** `DECKFLOW_LLM_CLI_COMMAND` is a **JSON array of args** (NOT a space-split string — space-split can't reliably express the empty `--allowedTools ""` arg, and can't position the instruction). Example: `["wsl.exe","claude","-p","{instruction}","--output-format","json","--allowedTools",""]`. Parse with `JsonSerializer`; element[0] = FileName, the rest = ArgumentList **verbatim** (empty strings preserved exactly — so `""` becomes `string.Empty`, NOT a literal quote). Exactly one element MUST equal the `{instruction}` placeholder token → substituted with the actual instruction arg. **Validate the override ONCE up front (fail-fast BEFORE the retry loop)** — missing/duplicate `{instruction}`, empty array, or non-JSON → throw a clear error immediately, do NOT retry (round-3 MED). A test MUST assert the ArgumentList entry immediately after `--allowedTools` is exactly `string.Empty`.
- **D-02b (timeout/kill — Codex H2 + round-3 HIGH-2):** Each extraction enforces a per-call timeout via a linked `CancellationTokenSource` (default ~10 min, env `DECKFLOW_LLM_CLI_TIMEOUT_SECONDS`) created in `ExtractWithRetryAsync` and **passed into the `_runProcess` runner-seam** (so the fake runner exercises it; `CancellationToken.None` from the caller cannot hang). Inside the real `RunProcessAsync`: immediately after `Process.Start`, `linkedToken.Register(() => process.Kill(entireProcessTree: true))` so cancellation kills the tree even if blocked elsewhere; AND make the stdin write cancellation-aware — `process.StandardInput.BaseStream.WriteAsync(bytes.AsMemory(), linkedToken)` (NOT a token-less write) so a child that never drains stdin can't hang past the timeout. Fake-runner timeout test + a real-path "child never reads stdin" reasoning encoded in acceptance criteria.
- **D-02c (deadlock-safe pipes — Codex round-2 MED):** Start the stdout AND stderr `ReadToEndAsync` tasks **immediately after `Process.Start`, BEFORE writing stdin**; then write the transcript to stdin and close it; then await reads + exit. (Round-1's "write+close stdin before starting reads" can deadlock on a large transcript when the child writes enough stderr.)
- **D-02d:** Cross-platform: **auto-detect** Linux/WSL (linux `claude` bin name) vs Windows (throw a clear error telling the operator to set `DECKFLOW_LLM_CLI_COMMAND`, e.g. `wsl.exe claude -p {instruction} --output-format json --allowedTools ""` or `cmd.exe /c claude.cmd ...` — claude verified NOT on Windows PATH). Explicit env wins. Document BOTH a WSL and a Windows invocation with EXACT commands (Codex M4), incl. the hard case: Windows `dotnet.exe` host launched from WSL — show which process owns PATH/env (see canonical ref [[reference_wsl_dotnet_env_secret]]).
- **D-02e (codex deferred):** codex backend + its tool/read-isolation problem move to Phase 21.3 (KB-12). 21.2 factory throws NotSupportedException for `codex` pointing there.

### JSON-repair / retry (D-03)
- **D-03:** Inject the JSON schema text into the prompt as explicit instructions (CLIs have NO Structured-Outputs guarantee). On each response: fence-strip (```json fences) → unwrap result-envelope (claude only) → **balanced-object scan** (quote/escape-aware — NOT naive first-`{`/last-`}`, which breaks on multiple objects or prose braces; Codex M2) → deserialize → **shape-validate** with null/missing-field checks.
  - **Tag validation (Codex H4 — was a gap):** the tags extraction MUST run a `ValidateTags` that requires non-null arrays AND every value within `ContentTagVocabulary` (no duplicates), and a vocab-invalid result MUST trigger the retry — do NOT rely on the downstream post-hoc `FilterTags` (silent-drop would mark a video `distilled` with empty/weak tags). Summary uses `ValidateSummary` (≤200 words); reuse Phase 21 validators where they exist, add `ValidateTags` for the CLI path.
- **D-03a:** Retry **×2** on parse-or-shape failure (3 attempts total per extraction). Final failure → mark the video `failed` (re-attemptable, non-terminal — matches Phase 21 staged-pipeline so a re-run retries only failed videos). Do NOT abort the whole run on a single video failure.
- **D-03b (L1 — automated byte-identical guard):** A unit test must assert the extracted shared statics equal the original Phase-21 values **for both the system-prompt text AND the schema bytes** the OpenAI path emits (i.e. capture the `ChatCompletionOptions.ResponseFormat` schema bytes + system messages `LlmDistillationService` passes), not just the prompt strings. Pure byte-equality, no live call.
- **D-03c (L2 — log/secret hygiene):** bounded `Tail(stderr)` only; NEVER log stdout, prompts, transcripts, or full command lines. The claude `is_error:true` path must throw a **bounded, sanitized** message — do NOT echo the raw `.result` envelope text (it can contain prompt/transcript snippets); include only a short status, not the body.

### Ledger / cost handling (D-04)
- **D-04:** When `provider != openai`: **bypass** the `LlmSpendLedger.WouldExceedCapAsync` cap-gate and token-pricing entirely (subscription = no per-token cost). `DECKFLOW_LLM_MONTHLY_CAP_USD` governs the **openai** backend only. **(Codex M1):** the bypass must also skip `ComputeProjectedVideoCostUsd` (pricing math) for subscription providers — make that call conditional too, not just the `WouldExceedCapAsync` gate.
- **D-04a:** Still write the run record with `spend_usd=0` and the LLM **call-count** for observability. NOTE: Phase 21's run record already overloads `whisper_calls` = LLM calls (`content_harvest_runs`, see CommandRunners.cs ~L641 comment) — reuse that overloaded field, **no schema change** needed.
- **D-04b:** `--dry-run` for a CLI backend reports `N videos would distill ($0, subscription)` — no cap math.

### Provider switch (carried, locked)
- Env var `DECKFLOW_LLM_PROVIDER` = `openai` (default/unset) | `claude` | `codex`. Factory mirrors `TranscriptProviderFactory` exactly: `public static class LlmDistillationProviderFactory` with `Resolve(string? envValue, HttpClient httpClient)`, default branch = OpenAI, unsupported value → `NotSupportedException` listing supported values. Wire into `CommandRunners.RunDistillAsync` where `new LlmDistillationService(llmHttpClient)` is constructed (CommandRunners.cs ~L483).

### Claude's Discretion
- Exact shared-prompts type name + namespace (Core/Integration).
- Process timeout per CLI call (suggest generous — CLI sessions are slow; align with the existing 15-min HttpClient timeout intent).
- `CliCommandSpec` field naming + the `{instruction}` placeholder token spelling (verify at impl per D-02a-override).
</decisions>
