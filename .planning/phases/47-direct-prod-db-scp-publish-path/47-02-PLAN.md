<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Studio → Render SSH endpoint | Untrusted network; private key + host are secrets; failures may echo secrets in messages |
| Local file system → remote /data | Artifact relative paths joined onto a remote root; traversal risk |
| Config store (user-secrets) → logs/UI | Secret values must never cross into observable output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-02a | Information disclosure | `SftpArtifactUploader` SshException handling | mitigate | Catch `SshException`/`IOException`; surface ONLY the sanitized literal "SSH upload failed — check SCP configuration and Render SSH access." Never put `ex.Message` (may contain host/remote path) into `FailureReason` or logs (D-07/Pitfall 3). |
| T-47-02b | Information disclosure | Program.cs SCP detection + startup log | mitigate | Presence-only boolean; `Log.Information("Studio SCP: {Status}", ...)` logs "configured/not configured" only; no Studio:Scp value logged (SC5/D-07). |
| T-47-02c | Tampering | `BuildRemotePath` join | mitigate | Remote path built only from `RemoteArtifactRoot` + the upstream-validated relative ArtifactPath; resolved path confirmed to start with `RemoteArtifactRoot` before upload; reject otherwise (V5 path-traversal). |
| T-47-02d | Tampering | Concurrent SftpClient reuse | accept (guarded) | Phase 47 uploads sequentially; one client per `UploadArtifactsAsync` call documented (Pitfall 5). No parallel uploads introduced. |
| T-47-02e | Tampering | Prod conn string in DI | mitigate | Program.cs does NOT register a prod store/connection singleton; on-demand construction via IProdStoreFactory only (D-03). |
</threat_model>
