<locked_decisions>
**D-3 (F-7 direction) — locked: declare nullable on both sides. Do NOT make the builder always
emit a marker.**
Always-emit-a-marker changes the wire payload and what the client renders on a live contract, to
settle a LOW-severity declaration mismatch. It would need its own regression surface and its own
UAT. Declaring nullable makes the declaration honest with **zero** runtime behaviour change, and
two existing tests already assert the null explicitly — `CutLabUiPatchBuilderTests.cs:620` and
`:774` both call `Assert.Null(patch.NextProposal)`. Those two assertions are the strongest single
piece of evidence for this direction: the suite already encodes the runtime truth the declaration
denies.
Reversibility: **reversible** — the JSON on the wire does not move, so no client or stored payload
depends on this change; reverting is a type-declaration revert.

**Carve-out that must survive:** `.editorconfig` forbids converting `{ get; init; }` to
`{ get; }` — System.Text.Json silently skips get-only properties in .NET 9+, and that has broken
deserialization in this repo before. The accessor pair stays on every property this plan touches.
</locked_decisions>
