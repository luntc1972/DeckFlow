# Quick Task 260612-kb1: Admin KB per-entry Delete

## Context / scope decision (locked)

User wants to remove noise from `/Admin/ContentKb`. Architecture reality (verified):
the web admin only curates `content-site-index.db` (`content_site_index` table) via
`IContentSiteIndexStore`. The CLI block + hard-delete (Phase 37.6) operate on a
DIFFERENT db (`content-kb.db`: content_videos/clips/blocked_videos) that the
deployed web never sees. So a web "block (never re-harvest)" is NOT reachable.

DECISION (user, this session): ship **delete-the-index-row only**. It removes the
entry from the admin grid + browse immediately. Permanent re-harvest suppression
stays a CLI concern (`block-video`). Do NOT add any blocked-key table or seed-loader
change in this task — out of scope.

`IContentSiteIndexStore.DeleteByIdAsync(long id, ct)` already exists and is the
exact primitive (the CLI block path already calls it). The admin grid row id is
`entry.Id` — the same surrogate id already passed to SetVisibility/SetEvergreen.
