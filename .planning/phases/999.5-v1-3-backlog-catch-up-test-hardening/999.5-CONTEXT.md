<decisions>
## Implementation Decisions

### P01-a FeedbackStoreTests SQLite file-lock race

- **D-01:** Fix root cause via `SqliteConnection.ClearAllPools(); GC.Collect(); GC.WaitForPendingFinalizers();` before `File.Delete(_dbPath)` in `FeedbackStoreTests.Dispose()`. Rationale: Microsoft.Data.Sqlite enables connection pooling by default; the per-test `await using` disposal releases the connection logically but the pool retains the OS file handle. The canonical .NET pattern is `ClearAllPools`. 3-line change, no `[Collection]` serialization overhead, no Polly retry on `File.Delete`, no leaked `%TEMP%` files.
- **D-02:** Test name stays `Dispose`; no method rename. Only the body changes.
- **D-03:** Apply identically to `CategoryKnowledgeStoreTests` and any other test class with the same `IDisposable` + `File.Delete` SQLite pattern. Sweep with `grep -rn "File.Delete(_dbPath)" DeckFlow.Web.Tests/` before commit.

### P01-b ScryfallThrottleTests 429-no-Retry-After

- **D-04:** Test is stale, not production behavior. `ScryfallThrottle.cs:117-122` deliberately retries 429-without-Retry-After using `FallbackRetryDelay` for Cloudflare BIC/burst recovery (intentional, comment-documented). Production retry-loop runs `MaxRetryAttempts` (= 2) → total calls 3.
- **D-05:** Rename both test methods (`ExecuteAsync_NonGeneric_DoesNotRetryFor429WithoutRetryAfter` and `ExecuteAsync_Generic_DoesNotRetryFor429WithoutRetryAfter`) to `ExecuteAsync_<NonGeneric|Generic>_RetriesFor429WithFallbackDelay_WhenRetryAfterMissing`. Update assertions to `Assert.Equal(MaxRetryAttempts + 1, calls)` (= 3). Other 429 facts (`AboveRetryAfterCap`, `WithZeroRetryAfter`, `Returns200ResponseAsIs`) stay byte-identical — their contracts are still valid.
- **D-06:** Use the literal `ScryfallThrottle.MaxRetryAttempts` constant reference if visible to tests via `[InternalsVisibleTo]`, otherwise hardcode `3` and add a one-line comment cross-referencing `ScryfallThrottle.cs:30`.

### P01-c DeckAnalysisPacketServiceTests:360 message rot

- **D-07:** Mechanical update. Change the test's expected string from `"The submitted ChatGPT response did not contain a valid deck_profile payload."` to `"The submitted AI response did not contain a valid deck_profile payload."`. This catches the test up to Phase 999.1 shipped behavior. Single-line edit, single commit.

### P01-d DeckComparisonServiceTests:286 CRLF assertion

- **D-08:** Normalize the expected string in the assertion via `\r?\n` matching, or call `.Replace("\r\n", "\n")` on the actual string before compare. Decision: prefer `actual.Replace("\r\n", "\n")` over `Assert.StartsWith(...)` with a regex-shaped expected — keeps the expected literal readable. The service emits platform line endings on purpose (`StringBuilder.AppendLine`); changing the service to force LF would be a different decision and is out of scope.

### P02 D-07 Semantic-Completeness Guards

- **D-09:** Strict mirror of the `ResponseParsers.cs` OR-pattern. `HasMeaningfulComparisonContent(DeckComparisonResponse)` returns true if at least one of: `DeckAName` non-empty, `DeckBName` non-empty, `DeckACommander` non-empty, `DeckBCommander` non-empty, `DeckAGameplan` non-empty, `DeckBGameplan` non-empty, `SharedThemes` count > 0, `MajorDifferences` count > 0, all four strength/weakness lists count > 0, verdict non-empty, recommendation buckets count > 0. Mirror exact OR-chain shape from `HasMeaningfulDeckProfileContent` at `ResponseParsers.cs:124-136`.
- **D-10:** `HasMeaningfulMetaGapContent(MetaGapResponse)` returns true if at least one of: `MetaGap.Commander` non-empty, `MetaGap.ColorId` non-empty, `MetaGap.ReadinessScore > 0`, `MetaGap.ReadinessJustification` non-empty, `MetaGap.WinLines` not null, `MetaGap.Interaction` not null, `MetaGap.Speed` not null, `MetaGap.ManaEfficiency` not null, `MetaGap.CoreConvergence` count > 0, `MetaGap.MissingStaples` count > 0, top-add and top-cut lists count > 0.
- **D-11:** Reuse existing thrown messages verbatim. `DeckComparisonService` already throws `"The submitted AI response did not contain a valid deck_comparison payload."` on wrong-shape; the new semantic-empty branch ORs into the same `if (result is null)` guard and reuses the same message. Same for `MetaGapService` ("did not contain a valid meta_gap payload"). No new `internal const`, no new locked-string infrastructure — over-engineered for two sites. If a third service ever needs it, promote to a const then.
- **D-12:** Test scope: 1 sync xUnit fact per service. `ParseComparisonResponse_SemanticallyEmptyInput_ThrowsValidationError` in `DeckComparisonServiceTests.cs` and `ParseResponse_SemanticallyEmptyInput_ThrowsValidationError` in `MetaGapServiceTests.cs`. Assert `Assert.Throws<InvalidOperationException>(() => Service.Parse*(fixture))` and `Assert.Equal(<existing wrong-shape message>, exception.Message)`.
- **D-13:** Naming inherits the 999.4 D-04 convention (`MethodName_Condition_ExpectedOutcome`). Sync (not async) — both parse methods are static. No service-construction, no DI fakes.
