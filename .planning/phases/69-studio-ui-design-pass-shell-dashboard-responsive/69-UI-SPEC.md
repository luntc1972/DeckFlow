without per-component duplication.

## Spacing Scale

8-point scale (multiples of 4). Map to Bootstrap spacers where one exists so existing utility
classes keep working (Bootstrap base = 16px ⇒ `1` = 4px, `2` = 8px, `3` = 16px, `4` = 24px, `5` = 48px).

| Token | Value | Bootstrap equiv | Usage |
|-------|-------|-----------------|-------|
| `--sp-1` | 4px  | `.p-1` | Icon gaps, badge inline padding, tight stacks |
| `--sp-2` | 8px  | `.p-2` | Compact element spacing, button label gaps |
| `--sp-3` | 16px | `.p-3` | Default element / card inner padding |
| `--sp-4` | 24px | `.p-4` | Section padding, content container gutter |
| `--sp-5` | 32px | — | Layout gaps between dashboard regions |
| `--sp-6` | 48px | `.p-5` | Major section breaks |
| `--sp-7` | 64px | — | Page-level top/bottom rhythm |

**Exceptions:**
- **44px** minimum interactive touch-target floor (nav links, buttons, selects) — ported from
  `admin-common.css` (WCAG 2.5.5). Not a spacing step; a min-size floor.
- **250px** sidebar width and **3.5rem (56px)** top-row height are existing shell constants — keep.
- Content container gutter stays the existing `2rem / 1.5rem` (≈32/24px) left/right padding.

## Typography

Aligned to the public type scale. Exactly 4 sizes, 2 weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Meta / label / small | 14px (0.875rem) | 400 | 1.4 |
| Body | 16px (1rem) | 400 | 1.5 |
| Section heading / page title | 20px (1.25rem) | 600 | 1.25 |
| Display (dashboard H1 + big count numbers) | 28px (1.75rem) | 600 | 1.2 |

**Weights:** `400` (regular) and `600` (semibold) only.
**Exception:** the brand wordmark "DeckFlow Studio" in the shell header may use `700` (single
documented exception, mirrors the public `.page-brand` weight). No other 700/500/etc. usage.

**Notes for executor:**
- Existing page titles use `h1 class="h4 fw-semibold"` (≈24px). Re-target page-title to the
  20px/600 "section heading" role via the shared `.studio-page-title` class so all pages match.
  Bootstrap `fw-semibold` already = 600.
- Dashboard count numbers use the 28px/600 "Display" role; their labels use 14px/400 meta.

## Color

Studio is a single-brand operator tool (not the public site's 22-theme system). Declare ONE
brand palette with a light default and a dark counterpart. Drive dark mode with
`color-scheme: light dark` + a `@media (prefers-color-scheme: dark)` token override (Recommended
default) so Bootstrap's native controls and badges follow without per-component work.

### 60 / 30 / 10 split

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#e9edf3` | `#0f172a` | App background / body / shell canvas |
| Secondary (30%) | `#fafafa` (cards) / `#ffffff` (inputs) | `#1e293b` | Sidebar, cards, panels, table surfaces, nav |
| Accent (10%) | `#2b6cb0` | `#3b82f6` | **see reserved-for list — nothing else** |
| Destructive | `#c53030` | `#dc2626` | Destructive actions only (reject / block / delete) |

Light accent `#2b6cb0` is the public Jeskai brand blue (`site.css --accent`); the dark accent
`#3b82f6` matches the admin console dark palette for contrast on `#0f172a`.

**Accent (10%) reserved for — explicit list:**
1. The single primary action button per view (e.g. the dashboard's primary "Open Harvest"
   quick link; a page's main CTA).
2. Active nav item indicator (left-border + tint, admin pattern) in the sidebar.
3. Keyboard focus ring (`outline: 2px solid` accent) on all interactive elements.
4. Text hyperlinks within content.
5. Emphasis on the dashboard's headline pipeline counts (number color only).

Accent is **never** applied to all buttons, all badges, table chrome, or large fills.

### Status / publish badge palette (separate functional set — NOT part of 60/30/10)

Pipeline state badges are a distinct semantic palette keyed to `VideoStatus` / `PublishState`.
They are **locked to the existing `StatusBadge.razor` vocabulary** (Bootstrap contextual classes)
and must be identical on every page (Home/Review/Publish/Harvest/Blocked/Skipped). This closes the
STATE pitfall "per-page badge colors are defined ad-hoc today."

| State | Class (existing — keep byte-stable) | Reads as |
|-------|--------------------------------------|----------|
| Not harvested | `badge bg-secondary` | neutral gray |
| Harvested | `badge bg-info text-dark` | cyan |
| Distilled | `badge bg-success` | green |
| Approved | `badge bg-primary` | blue |
| Published | `badge bg-success text-white` (+ check) | green/check |
| Blocked | `badge bg-danger` | red |
| Duplicate / Already in DB | `badge bg-warning text-dark` | amber |
| Publish: Never published | `badge bg-secondary` | gray |
| Publish: Pushed-hidden | `badge bg-warning text-dark` | amber |
| Publish: Published | `badge bg-success text-white` | green |
| Publish: Local-newer | `badge bg-info text-dark` | cyan |

**Dark-mode requirement (STUI-03):** verify each badge keeps AA contrast on the `#1e293b` table
surface. `text-dark` badges (`bg-info`, `bg-warning`) already pin dark text on light fills, so they
stay legible; no class changes — just confirm under dark tokens. Do not introduce new badge colors.

## Home Dashboard Contract (STUI-02)

Presentation-only composition over **already-reachable** data — no new store methods, no new query.

**Data source (all existing, already used by `Review.razor`):**
- `IContentSiteIndexStore.GetAllRowsAsync(ct)` → all `ContentSiteIndexRow`.
- `VideoStatusResolver.FromContentRow(approvalStatus, pushedToProdUtc, isVisible)` → `VideoStatus`.
- `PublishStateDeriver.Derive(pushedToProdUtc, isVisible, indexedUtc)` → `PublishState`.
- `StudioConfig.IsProdConfigured` (already on Home) → keep the prod-connection indicator.

**Load discipline (match Review.razor — do not regress behavior):** wrap store calls in
`Task.Run`, `EnsureSchemaAsync` then `GetAllRowsAsync`, guard `OperationCanceledException`, swallow
store errors to the generic error copy above, `IDisposable` CTS cancel on circuit drop.

**Composition (cards on the dashboard):**
1. **Pipeline-state count cards** — one card per meaningful `VideoStatus` bucket
   (Harvested / Distilled / Approved / Published) showing the count (28px/600 number) + label
   (14px/400). Reuse the public `hub-card`/`admin-hub-card` visual pattern (bordered card, 16px
   padding, 10px radius, hover lift).
2. **Publish-state summary** — counts by `PublishState`
   (Never published / Pushed-hidden / Published / Local-newer) rendered with the locked badge palette.
3. **Quick links** — `Open Harvest` (primary/accent), `Review Queue`, `Publish` (outline). These
   are navigation only (`href` to existing routes); no behavior.
4. **Prod connection indicator** — keep the existing "configured / not configured" line, restyled
   into the dashboard (small/meta).

Counts that are zero still render (show `0`), so the operator sees the whole pipeline shape.

## Responsive & Dark-Mode Contract (STUI-03)

Port the public/admin patterns; do not reinvent.

**Table overflow (every data table):**
- Wrap each table in Bootstrap `.table-responsive` (already used by `Review.razor`) OR the admin
  `overflow-x:auto` scroll container. Mandate one wrapper on Harvest/Review/Publish/Blocked/Skipped
  grids so no table forces horizontal page scroll.
- Long title cells truncate (`text-truncate` + `max-width`, already in Review) — keep/standardize.
- `min-width:0` on the content container so the flex/grid child may shrink below content size
  (prevents the classic blowout).

**Breakpoint:** single existing breakpoint at **640.98px** (template value) — sidebar collapses to a
top navbar with the `navbar-toggler` (already wired in `NavMenu.razor`). Keep; restyle to brand.

**Dark mode (Recommended default — operator may override the trigger):**
- `studio-theme.css :root` declares light tokens + `color-scheme: light dark`.
- `@media (prefers-color-scheme: dark)` overrides the token values to the dark column above.
- Because Bootstrap contextual badge classes and `color-scheme` native controls follow the tokens,
  no per-page dark rules should be needed. Verify badge + input + table contrast under dark.
- Alternative trigger (if operator wants a manual switch instead of OS-driven): a
  `[data-theme="dark"]` attribute on `<html>` selecting the same dark token block. Pick one;
  OS-driven `prefers-color-scheme` is the default recommendation (zero new controls, presentation-only).

**Reduced motion:** include the `@media (prefers-reduced-motion: reduce)` guard for the hover-lift
transitions (mirrors `site.css` / `admin-common.css`).
