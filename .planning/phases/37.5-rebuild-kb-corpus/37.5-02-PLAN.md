<verified_findings>
RESOLVED — Open Question 4 (CHECK-constraint migration for `'filtered'`):
content_distill_status.status CHECK (status IN ('distilled','skipped_over_cap','failed')) is set
at CREATE TABLE time (ContentVideoStore.cs Postgres line 633, SQLite line 687). `CREATE TABLE IF
NOT EXISTS` will NOT update an existing constraint, so a DDL-string edit alone is insufficient on a
pre-existing DB. SQLite cannot ALTER a CHECK constraint in place.

CONCRETE STRATEGY (specified, not left open): content_distill_status is a CHILD of content_videos
(`video_id ... ON DELETE CASCADE`) and this phase resets the corpus to empty BEFORE distilling, so
the table holds no rows the operator needs. Use an idempotent table-rebuild migration inside
ContentVideoStore.EnsureSchemaAsync, guarded so it runs at most once:
  - Detect whether the current content_distill_status CHECK already allows 'filtered'. SQLite:
    query `SELECT sql FROM sqlite_master WHERE type='table' AND name='content_distill_status'` and
    test the sql text for the literal `'filtered'`. Postgres: query the check-constraint definition
    via `information_schema`/`pg_constraint` (or the check_constraints view) and test for `'filtered'`.
  - If absent: SQLite → `DROP TABLE content_distill_status;` then recreate with the new CHECK
    (data loss is acceptable — corpus is reset). Postgres → `ALTER TABLE content_distill_status
    DROP CONSTRAINT <name>; ALTER TABLE ... ADD CONSTRAINT ... CHECK (status IN
    ('distilled','skipped_over_cap','failed','filtered'));` (look up the constraint name from
    pg_constraint at runtime — do not hard-code a name). Also update both inline CREATE-TABLE DDL
    strings so fresh DBs include 'filtered' from the start.
This mirrors the idempotent, double-checked EnsureSchemaAsync migration shape used in
ContentSiteIndexStore (PATTERNS.md lines 426-454).

Cost: the classifier call is $0 with the claude CLI subscription backend
(`isSubscriptionProvider` bypass) — no spend-ledger record needed (RESEARCH §Spend Ledger Note).
</verified_findings>
