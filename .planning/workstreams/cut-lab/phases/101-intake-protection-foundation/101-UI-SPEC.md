# Phase 101 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Mode:** AUTO — no user questions were asked. Every decision below is derived from an existing, shipped DeckFlow pattern (cited by file:line) or, where no precedent exists, from the closest shipped analog (Deck History `2026.07.6`, Manabase pill/radio pattern, Bracket tier system). Novel decisions are called out explicitly in **Assumptions Log (Auto Mode)** at the bottom.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — DeckFlow has no component registry (no shadcn, no React). It is server-rendered ASP.NET MVC Razor + a hand-authored CSS component system (`site-common.css` + 22 guild-theme forks). |
| Preset | not applicable |
| Component library | none — custom classes only (`.field`, `.result-panel`, `.hero`, `.hub-*`, `.kb-chip`, `.manabase-pill`, checkbox/radio overrides in `site-theme-overrides.css`). Phase 101 reuses these; it does not introduce a new library. |
| Icon library | none — hand-authored inline SVG, 20×20 `viewBox`, `stroke="currentColor"` `stroke-width="1.5"`, `aria-hidden="true"`, per `DeckFlow.Web/Views/Shared/_ToolTileIcon.cshtml:1-49`. Cut Lab's new `ToolRegistry` tile needs one new glyph in this exact style (a simple padlock outline is recommended — see Assumptions Log). |
| Font | `"Segoe UI", Tahoma, Geneva, Verdana, sans-serif` — sitewide, set once on `body` (`DeckFlow.Web/wwwroot/css/site.css:72`). Not a per-phase choice; every guild theme inherits it via `@import url('site.css')`. |

**Theme constraint (binding):** All 22 guild themes are standalone CSS forks that each redefine the same token names in their own `:root` (e.g. `DeckFlow.Web/wwwroot/css/site-azorius.css:4-39`, `site-jeskai.css` base `site.css:1-59`). Any new Cut Lab layout CSS goes in `site-common.css` ONLY. Any new Cut Lab-specific *token* (e.g. a lock-state color, if one is ever needed beyond the tokens below) must be added to the `:root` of **every** theme file, never to `site.css` alone. Phase 101 is scoped to reuse only tokens that already exist in every theme (`--bg`, `--panel`, `--accent`, `--accent-strong`, `--line`, `--muted`, `--ink`, `--danger`, `--on-accent`, `--focus`, `--fs-*`), so **no new token additions are required for this phase.**

## Spacing Scale

DeckFlow's root font-size is **15px**, not 16px (`site.css:66`), and the existing 4,100-line `site-common.css` uses an organic rem-based scale, not a strict 4px-multiple grid. Per **Assumption A1** below, Phase 101 targets the closest already-in-use rem tokens rather than introducing a parallel 16px-rooted grid that would visually clash with the rest of the product.

| Token | Value | ~px (at 15px root) | Usage |
|-------|-------|---------------------|-------|
| xs | 0.25rem | ~4px | Checkmark/glyph micro-gaps inside a lock chip (matches `.kb-chip` `gap: 0.25rem`, `site-common.css:572`) |
| sm | 0.5rem | ~8px | Compact spacing: checkbox-to-label gap, chip-to-chip gap in a package group (matches `.kb-chip-area__chips` `gap: 0.5rem`, `site-common.css:549`) |
| md | 1rem | ~15px | Default field/section rhythm — every `.field` and `.result-panel` uses this (`site-common.css:485-486`) |
| lg | 1.5rem | ~23px | Section padding, hero spacing (matches `.hub-card`/hero vertical rhythm) |
| xl | 2rem | ~30px | Layout gaps between major page sections (e.g. between the intake form and the lock-list results section) |
| 2xl | 3rem | ~45px | Major section breaks (matches `.page-shell` bottom padding, `site-common.css:149`) |
| 3xl | not used | — | No page in DeckFlow spaces beyond 3rem; omit for this phase |

Exceptions:
- **44×44px minimum touch target** on every lock toggle (per-card checkbox, package-level checkbox, bulk role-group lock control). This is an existing, codified WIG accessibility convention already applied to comparable checkbox-in-a-list UI (`table[data-prompt-cedh-reference-table] td[data-label="Select"] input[type="checkbox"]` sized to `1.35rem` inside a `≥44px` row, `site-common.css:1204-1210`; `.kb-card-actions button { min-width: 44px; min-height: 44px; }`, `site-common.css:479-482`). Cut Lab's lock rows must hit this floor even though the native checkbox itself renders at `1.05rem` (`site-theme-overrides.css:57-58`) — pad the row/label hit area, not the checkbox glyph.
- **0.4rem tight internal gaps** inside pill/chip components (`.manabase-pill` padding `0.3rem 0.85rem`, `site-common.css:2500`) — reused verbatim for the bracket-pill and play-experience-pill controls, no new value introduced.

---

**Visual focal point (checker recommendation):** On the intake screen, the primary visual anchor is the **"Import pool" CTA** at the bottom of the deck-input panel — the hero `<h1>` orients, but the accent-colored CTA is what draws the eye first and is the only accent-filled element above the fold before a pool is loaded. After a pool loads, the focal point shifts to the running card-count badge in the lock panel header.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 0.95rem (`--fs-base`) | 400 | 1.5 |
| Label | 0.85rem (`--fs-sm`) | 600 | 1.3 |
| Heading | 1.05rem (`--fs-lg`) | 600 | 1.2 |
| Display | 1.5rem (`--fs-xl`) | 700 (inherited, see note) | 1.15 |

- **Body** — paragraph copy, help text (`.manabase-help`-equivalent), lock-list row text.
- **Label** — field labels (`.field > span`, `site-common.css:2256-2262`, already 600), lock/package chip text, bulk-lock control captions.
- **Heading** — in-page `h2` section titles: "Import your pool", "Declare your intent", "Lock your pool", "Packages".
- **Display** — the page `<h1>` inside the standard `<section class="hero">` block every tool page uses (`DeckHistory.cshtml:42-45`). Weight 700 here is **inherited global chrome** from `.hero h1 { font-weight: 700; }` (`site-common.css:2241-2244`) — Phase 101 introduces **zero new instances** of weight 700. All net-new Cut Lab component styling (lock rows, package chips, intent form, validation banners) uses only the two declared weights: **400 regular** and **600 semibold**.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` | Page background — every guild theme fork |
| Secondary (30%) | `var(--panel)` | `.result-panel` cards, lock-row containers, package group boxes. **Do NOT use `--theme-surface`** — it renders light even inside dark themes (project memory `reference_theme_surface_light_in_dark.md`); use `--panel`. |
| Accent (10%) | `var(--accent)` | Reserved for: (1) primary CTA fill (`.run-button`), (2) checked lock-checkbox fill + checkmark (existing `input[type="checkbox"]:checked`, `site-theme-overrides.css:83-98` — no new CSS needed), (3) active/selected bracket- and play-experience-pill fill (existing `.manabase-pill:has(> input:checked)`, `site-common.css:2528-2534`), (4) package-container left-accent border when fully locked, (5) focus ring fallback (`var(--focus, var(--accent))`). |
| Destructive | `var(--danger)` | Reserved for: the ≤100-card / >150-card INTAKE-03 rejection banner's accent border, and the inline "can't unlock" message if a user attempts to unlock the commander. `--danger` is never re-aliased per theme (Phase 84 D1 convention, `site.css:44`) — same fixed semantic across all 22 themes. |

Accent reserved for: primary "Import pool" / "Save intent" buttons, the checked state of any lock checkbox, the selected state of a bracket/play-experience pill, the fully-locked package's left border, and focus rings. **Never** apply accent to plain body copy, card names, or non-interactive chrome.

**Third, non-counted semantic token (existing, reused, not new):** `var(--commander-gold, #d4af37)` — the codebase's established "commander identity" marker (`.manabase-cmd-glyph`, `site-common.css:2554-2559`). Phase 101 reuses it exclusively for the commander's auto-lock badge so the commander's permanent lock reads as a distinct, non-negotiable state rather than "just another checked accent checkbox." This is not a new token — no `:root` edits required, only a new class consuming the same `var()` fallback chain already in use.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Import pool"** — the button that submits the URL/paste form and triggers parse → validate → resolve → legality-check (mirrors "Update history" verb+noun pattern, `DeckHistory.cshtml:109`) |
| Empty state heading | **"No pool imported yet"** |
| Empty state body | **"Paste a Moxfield or Archidekt URL, or paste your decklist text, then choose Import pool. Cut Lab is for an oversized pool — 101 to 150 cards plus your commander."** |
| Error state | Three distinct messages, one per INTAKE-03 branch (tone matches the existing `ManabaseAnalysisService.cs:694` style — state the fact, state the limit, no blame language): |
| — parse failure | *"That deck link or paste couldn't be read. Double-check the URL or text and try again."* |
| — ≤100 cards | *"This pool already has 100 cards or fewer — Cut Lab is for trimming an oversized pool down to 100. Try Deck Sync or Deck Analysis instead."* |
| — >150 cards | *"This pool has too many cards for Cut Lab (limit 150 plus commander). Trim it closer to 150 before importing."* |
| Destructive confirmation | Two distinct flows — see **Lock UI Component Contract** below for the full state model: |
| — Unlock a bulk-locked role group | No confirmation — purely a reversible protection toggle, not data loss. |
| — Attempt to unlock the commander | Blocked outright (checkbox stays `disabled`); inline copy: *"Your commander is always locked and can't be cut."* — prevention, not a confirm-after-the-fact dialog. |
| — Delete a named package | `window.confirm()` guard (the one existing public-tool precedent, `moxfield-extension-bridge.ts:135`; no shared modal component exists outside `/Admin`): *"Delete package '{name}'? Cards return to the unlocked pool — this doesn't discard them."* |

## Component Contract: Lock UI (LOCK-01/02/03 — the phase's one genuinely new interaction surface)

All states below reuse the existing themed checkbox/radio rendering in `site-theme-overrides.css:53-142` — **zero new checkbox CSS is required.** Only two small additive classes are needed (see "New CSS" callouts).

| State | Visual | Mechanism |
|-------|--------|-----------|
| **Unlocked** (default) | Empty box, `--line` border, `--panel` background | Native unchecked `input[type="checkbox"]` — existing rule (`site-theme-overrides.css:53-73`) |
| **Locked** (user-locked card) | `--accent` fill + white checkmark | Native `:checked` — existing rule (`site-theme-overrides.css:83-98`) |
| **Auto-locked (commander)** | `:checked` **and** `:disabled` (existing rule fades to `opacity: 0.5`, `site-theme-overrides.css:138-142`), **paired with** a small non-fading badge chip so the state doesn't read as "uncertain." **New CSS:** `.cutlab-lock-badge--commander` — reuse the `.kb-chip` shape (`site-common.css:569-581`) with `border-left: 3px solid var(--commander-gold, #d4af37)`, text "Commander · Always locked". The checkbox itself stays disabled (for correct AT semantics) even though its 50% opacity alone would under-communicate permanence — the badge is what carries the "non-negotiable" signal. |
| **Package — some members locked** | Package-level "select all" checkbox shows the dash-fill indeterminate state | Native `:indeterminate` — existing rule (`site-theme-overrides.css:100-118`), set via a few lines of `cut-lab.ts` on render/toggle |
| **Package — fully locked** | Package-level checkbox `:checked`; **New CSS:** package container gets `border-left: 3px solid var(--accent)` (same left-accent idiom as `.manabase-row--weakest`, `site-common.css:2598-2604`, but with `--accent` instead of `--danger` since this is a positive/protective state, not a warning) |
| **Role-group bulk-lock control** (e.g. "Lock all lands") | A single always-visible pill/button above the card list — reuse `.manabase-pill` exactly (`site-common.css:2492-2534`): `--panel-soft-bg` when not all locked, `--accent` fill when the whole group is locked. Not a per-card action. Minimum 44×44px hit area per the Spacing exception above. |

**List layout:** table-based, not a card grid. DeckFlow's existing per-card-list-with-checkbox convention is `table[data-prompt-cedh-reference-table]` (`site-common.css:1204-1230`), which already has a mobile `data-label` stacked-row fallback proven under the `page-frame: 1120px` / no-horizontal-overflow constraint. Cut Lab's lock list should follow this exact responsive-table pattern (columns: lock checkbox · card name · type/role · package assignment) rather than inventing a card-grid component.

**Package assignment affordance:** a per-row `<select data-df-select>` listing existing package names plus a trailing "+ New package…" option — reuses the `df-select` component already used everywhere (`data-df-select`, e.g. `Manabase.cshtml:98`) instead of a new picker widget. Selecting "+ New package…" reveals an inline text `<input>` (matches the `.card-picker__row` inline-add pattern, `site-common.css:812-862`) — no modal.

**Running card-count display:** a small pinned summary chip at the top of the lock section, reusing the `.manabase-summary-chip`/`.prompt-size-note` idiom (`site-common.css:864-868`, `2888`): copy pattern **"{poolCount} cards in pool · {lockedCount} locked (protected from any future cut)."** This is distinct from Phase 103's "cards remaining to 100" counter (CUT-03) — Phase 101 has not started cutting yet, so the counter here communicates protection state, not progress-to-100.

**Ambiguous-commander fallback:** reuse the `Manabase.cshtml:87-123` `CommanderSelectionRequired` panel pattern verbatim (a `.result-panel.nested-panel` with a `data-df-select` "Commander from this deck" dropdown plus a text-search backstop) — same markup, Cut Lab-specific copy: *"We couldn't identify your commander automatically. Choose it below — it will be locked automatically once selected."*

**Intent-declaration fields (INTAKE-02):** reuse `fieldset.manabase-segmented[role="radiogroup"] > .manabase-pills > label.manabase-pill` verbatim (`Manabase.cshtml:160-219`) for two of the four fields:
- **Target bracket** — 5-way pill (1–5), reusing the Manabase bracket-pill pattern (`Manabase.cshtml:186-202`) plus the official tier names from `Bracket.cshtml:16-20` (Exhibition/Core/Upgraded/Optimized/cEDH) as the pill sub-label, so Cut Lab's bracket language matches the dedicated Bracket Check tool exactly rather than inventing new tier names.
- **Desired play experience** — reuse the exact Casual/Focused/cEDH pill set and copy from `Manabase.cshtml:160-179`, since it is the closest shipped "how strong do you want this to be" control in the product and Cut Lab's audience overlaps directly with Manabase's.
- **Primary plan** (required) and **secondary plan** (optional) — free-text `<textarea rows="2">` inside a standard `.field`, matching the `deck-history-notes` textarea pattern (`DeckHistory.cshtml:101-104`); secondary plan's `<label>` gets the existing `.field` "(optional)" copy convention already used in `DeckHistory.cshtml:63` ("History file (optional)").
