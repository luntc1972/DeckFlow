# Quick 260817-k2d — Fix Scryfall search cache-key collision

## Problem

Two singleton services share the one process-wide `IMemoryCache` (`DeckFlow.Web/Program.cs:71`) and
both wrote results under an **unprefixed** key `query.Trim().ToLowerInvariant()`, both storing
`IReadOnlyList<string>`:

| Service | Method | Scryfall query | Old key |
|---|---|---|---|
| `ScryfallCardSearchService` | `SearchAsync` | `name:{query}` — all cards | `atraxa` |
| `ScryfallCommanderSearchService` | `SearchAsync` | `is:commander type:legendary (creature\|vehicle) name:{query}` | `atraxa` |

Same key, same value type, so there is **no cast exception** — whichever service ran first inside the
10-minute TTL silently poisoned the other's results. Typing a commander name into the general card
typeahead made the commander typeahead return non-commander cards, and vice versa.

Found while researching an upstream cache layer (`/mnt/d/claude_doc/deckflow/spike/2026-08-17-upstream-cache-layer-research.md`, finding D-1).

## Why three namespaces, not two

A third method already used a prefixed key and must **not** be merged with the second one above:

`ScryfallCardSearchService.SearchCommandersAsync` keys on `commander:{...}` and queries
`is:commander name:{query}` — which is *different* from `ScryfallCommanderSearchService.SearchAsync`
(that one additionally restricts to `type:legendary` and creature-or-vehicle).

So assigning `commander:` to `ScryfallCommanderSearchService.SearchAsync` would have relocated the
identical bug onto a new pair rather than fixing it. Three distinct prefixes are required.
