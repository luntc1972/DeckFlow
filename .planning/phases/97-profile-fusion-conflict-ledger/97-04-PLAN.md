  <action>
    Create static class `ConflictCalculator`. Entry point evaluates ONE (stated rule, measured value,
    coverage signal) pair and returns a small result: `{ string Verdict, string? VerdictReason,
    FusedConflict? Conflict, string Winner }` (or equivalent) — Verdict in {agree, conflict,
    insufficient-measured}; VerdictReason is null except when Verdict=="insufficient-measured". Logic:
    (1) coverage gate first — if the profile-level EffectiveSampleSize/NumDecks < MinDeckFloor ->
    "insufficient-measured" with VerdictReason="low-sample", no conflict (document interpretation-1
    global-floor in a `// Why:` comment per RESEARCH Pitfall 2). Note: the OTHER insufficient-measured
    reason, "no-condition-breakdown" (a condition-scoped rule with no matching measured segment), is
    set by the engine (97-05), NOT here — ConflictCalculator only sees a (rule, measured value) pair
    that already matched, so its only insufficient reason is low-sample. (2) Determine the effective band from comparator: `range` -> [min,max];
    `lte`/max -> (-inf, value]; `gte` -> [value, +inf); `eq` -> point with tolerance. (3) If measured
    is inside the effective band -> "agree". (4) Else compute band-relative-% = distance beyond the
    nearest violated edge as a fraction of that edge value (scale-free per D-04); conflict fires only
    if that % exceeds the calibrated threshold X. Pick X (planner discretion, D-04) so the goldens
    above pass — a value around 8-12% of the edge works for these; lock it as a named const with a
    comment citing the prototype. Populate FusedConflict (StatedValue = nearest edge, MeasuredValue,
    Delta, BandRelativePercent, Winner="measured" for observable conflicts). `ArgumentNullException
    .ThrowIfNull`. NO Web/HTTP references. LF endings.
