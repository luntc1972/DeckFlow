**Parsing rules — derive directly from the writer at `ChatGptDeckPacketService.cs:1651-1695`:**

1. Normalize line endings: `text.Replace("\r\n", "\n").Replace("\r", "\n")`. Split on `\n` into a `string[]` (do NOT use `RemoveEmptyEntries`; blank lines are significant inside multi-line blocks).
2. Iterate with an index `i`. Determine line kind by these rules **in order**:
   - **Top-level key line:** matches regex `^([a-z_][a-z_0-9]*):\s?(.*)$` AND has zero leading whitespace. The capture groups give `key` and inline-value (inline-value may be empty).
   - **Inline list item:** preceded (in current state) by a key line with empty inline-value, AND current line matches `^- (.*)$` (single leading hyphen + space). Loop consuming `- ` lines into the list until a non-`-` line is hit.
   - **Multi-line block content:** any other line while we are inside a block scalar (see below).
3. Multi-line block detection: the writer always emits multi-line blocks via `AppendOptionalContextBlock` which writes `\n{label}:\n{value.Trim()}\n`. So a key line with empty inline-value followed by content that is NOT `- item` (and where the key is one of the known multi-line keys: `strategy_notes`, `meta_notes`, `deck_source`) opens a block. Read every subsequent line into a `StringBuilder` until the next top-level key line (regex above, zero leading whitespace) OR EOF. Trim trailing blank lines from the captured block but preserve internal blank lines and structure verbatim. Set the corresponding result property to the captured string.
   - **Critical disambiguation:** `card_specific_question_card_names`, `selected_analysis_questions`, `selected_set_codes` are also "key with empty inline-value" but their bodies are `- ` items. Detect intent by peeking the next non-blank line: if it starts with `- ` it is an inline list, otherwise (or it is a known multi-line key with non-`- ` content) it is a block. The known-multi-line-key allowlist is `strategy_notes`, `meta_notes`, `deck_source` — any other key with empty value and no `- ` items resolves to "empty value" (null/empty string for scalars, empty list for list keys).
4. Scalar mapping (inline-value present): assign trimmed inline-value to the matching property. For `target_commander_bracket`, `format`, `deck_name`, `commander`, `budget_upgrade_amount` — assign string as-is (empty inline-value → leave property null). For `workflow_step` — ignore (LoadFromZip controls this). For `commander` — capture but treat as informational.
5. Boolean parser helper: `private static bool? ParseBool(string raw)` accepting `True`/`False`/`true`/`false`/`1`/`0`; anything else returns `null`. Apply to `include_sideboard_in_analysis` and `include_maybeboard_in_analysis`.
6. List parser: collect each `- (.*)` capture, trim whitespace, drop empty strings. Return `IReadOnlyList<string>` (a `List<string>` materialized once).
7. Defensive: unknown keys are silently ignored (forward-compat for future writer additions). Malformed lines inside an open multi-line block are kept verbatim. Malformed top-level lines (no colon) are skipped.
8. The method MUST return a fully-populated `ParsedRequestContext` even if `text` is null/empty/whitespace — return one with all defaults. NEVER throw.
