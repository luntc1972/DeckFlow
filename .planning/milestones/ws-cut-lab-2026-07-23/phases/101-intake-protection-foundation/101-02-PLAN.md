<objective>
Build the pure, HTTP-free domain layer for Cut Lab: the form request model, the serializable
working-session state envelope, the 101–150 pool-size validator, and the lock-state mutation rules
(individual card lock, named-package lock, bulk role-group lock, and the non-negotiable commander
auto-lock invariant). All logic here is unit-testable without a controller, Scryfall, or a browser.

Purpose: These are the contracts every later Cut Lab plan consumes. Plan 03 (page service + serializer
+ controller) and plan 04 (view + e2e) both build against the types and rules defined here. Defining
them first prevents downstream scavenger hunts and lets the protection logic (LOCK-01/02/03) and the
intake range guard (INTAKE-03) be proven by fast xUnit tests before any wiring exists.
Output: CutLabRequest, CutLabState (+ nested CutLabPoolCard/CutLabPackage/CutLabIntent), CutLabPoolValidator,
CutLabLockRules, and three xUnit test files covering the six behaviors above.

DECISION (state-carry mechanism, RESEARCH.md Open Question 1): the working session is a single
serializable CutLabState envelope carried as a hidden-field JSON round-trip (no ASP.NET Session, no DB
this phase). DB-backed saved scenarios are deferred to Phase 104 (GOAL-02). This plan defines the
envelope shape; plan 03 owns serialization + the tamper re-lock.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client-submitted CutLabState JSON → server | Untrusted; a client could edit the DOM/hidden field to unlock the commander before submit |
| paste textarea → server | Untrusted free text; unbounded length is a memory-pressure vector on the 512 MB tier |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-101-02-01 | Tampering | Commander unlock via edited lock state | mitigate | CutLabLockRules.EnforceCommanderLock forces every IsCommander card locked, idempotently; UnlockCard/UnlockPackage refuse to release the commander. Plan 03's serializer re-applies this after every deserialize — the server never trusts client lock state for the commander |
| T-101-02-02 | Denial of Service | Oversized paste body | mitigate | CutLabPoolValidator rejects deckSourceLength > 100,000 chars (mirrors ManabaseAnalysisService.MaxDeckSourceChars) before any resolution work |

| T-101-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase — zero new dependencies |
</threat_model>
