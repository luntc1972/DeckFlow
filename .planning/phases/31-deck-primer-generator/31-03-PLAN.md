The orchestration core: the `IPrimerPromptVariant` contract + `PrimerPromptVariantRegistry` dispatch type, plus `DeckPrimerPacketService` (mirror of `DeckAnalysisPacketService`). BuildAsync loads the deck, resolves the commander, and assembles the four grounding inputs the variants format: (1) the D-2 two-block combo grounding from Commander Spellbook with null disclosure and the PRM-08 ranking branch selected by the 31-SPIKE.md verdict; (2) the PRM-07 category-distribution block (ramp/draw/tutor/interaction) with graceful omit on 0 rows; (3) bracket-5-only matchup data per the OQ-2 verdict — named archetypes via the NEW `EdhTop16Client.GetTopArchetypesAsync` when `meta-query-available`, generic buckets when `per-commander-only` (PRM-06/HIGH-1); (4) the selected-section list. It then builds the platform-AGNOSTIC grounded payload ONCE and renders EVERY ENABLED platform variant from it into `DeckPrimerPacketResult.PromptTextsByPlatform` (HIGH-2). "Enabled" = exactly the `_AiSelector` set: ChatGPT + Claude always, Gemini only when `DECKFLOW_GEMINI_ENABLED` (HIGH-3). Includes a cache key + replay guard and the internal test-seam ctor.

Purpose: This service owns all I/O. The 3 decoupled variant files (31-04) only FORMAT the blocks this service produces — they re-fetch nothing (ADR 0001 decoupling stays prose-only; data assembly is shared via internal helpers). The interface + registry TYPES live here so the service compiles standalone; 31-04 adds the three variant implementations + the DI registrations (including AddScoped of this service).

Output: `IPrimerPromptVariant` (+ `CategoryDistributionSummary`), `PrimerPromptVariantRegistry`, `IDeckPrimerPacketService` + `DeckPrimerPacketResult` (with `PromptTextsByPlatform`), `DeckPrimerPacketService` (combo grounding, category distribution, bracket routing, ranking branches, build-once render-each-enabled, cache key, internal helpers), the CONDITIONAL `EdhTop16Client.GetTopArchetypesAsync` extension, and service + client unit tests via the internal seam.
