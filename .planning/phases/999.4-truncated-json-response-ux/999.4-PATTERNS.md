**Current state — `ParseSetUpgradeResponse` (lines 47-76):** identical shape, parse at line 55.

**Const declaration (D-02 locked verbatim message):** add at top of class, immediately after `DeserializerOptions` (line 14). Note em-dash U+2014 — match `JsonTextFormatterService` convention:
```csharp
internal const string TruncatedResponseMessage =
    "The pasted response appears truncated — wait for the AI to finish generating before copying, then re-submit.";
```

Visibility `internal` (not `private`) because `DeckComparisonService` and `MetaGapService` will reference it as `ResponseParsers.TruncatedResponseMessage` (D-02 Option A preferred). All three callers live in `DeckFlow.Web.Services` namespace; `internal` is sufficient. Tests also reference it as `ResponseParsers.TruncatedResponseMessage` for the assertion.

**Catch-wrapper refactor (D-05 carve-out: two valid shapes).** Both preserve `JsonDocument` dispose semantics. **Recommendation: Shape A** (local + `using` block), because:
- Existing file already uses `using var document = ...;` 2×; Shape A is the minimum-touch local refactor (move one declaration above try, add 3-line try/catch, replace `using var` with bare local, wrap rest in `using (document)`).
- Shape B (helper extraction) duplicates the dispose responsibility split across two methods, which is less idiomatic in this pure-helper file.
- Identical shape across both parse sites (and across the two service-class sites below) gives a single grep target for future audits: `catch (JsonException)` × 4.

**Shape A — recommended pattern to apply at both `ResponseParsers.cs:24` and `:55`:**
```csharp
var json = JsonTextFormatterService.ExtractJsonPayload(input);

JsonDocument document;
try
{
    document = JsonDocument.Parse(json);
}
catch (JsonException)
{
    throw new InvalidOperationException(TruncatedResponseMessage);
}

using (document)
{
    var payload = document.RootElement;
    if (payload.ValueKind == JsonValueKind.Object
        && payload.TryGetProperty("deck_profile", out var profileElement))
    {
        payload = profileElement;
    }
    // ... rest of existing method body unchanged, including the existing
    //     throw new InvalidOperationException(...) for wrong-shape payload
    //     and the final `return result;`
}
```

**Shape B (alternative — only if reviewer prefers helper extraction):**
```csharp
private static JsonDocument ParseOrThrowTruncated(string json)
{
    try
    {
        return JsonDocument.Parse(json);
    }
    catch (JsonException)
    {
        throw new InvalidOperationException(TruncatedResponseMessage);
    }
}

// Call site:
using var document = ParseOrThrowTruncated(json);
```

Shape B is more compact at call sites but adds an extra private helper. Plan author may pick either; both pass D-04 xUnit gate. **Shape A is recommended for symmetry across all 4 sites.**

**Integration notes:**
- Re-throw type is `InvalidOperationException` (D-01) — the controller catch filter at `DeckController.cs:485, 691, 975` already covers this.
- Message must be byte-identical at all 4 sites — declared once as `TruncatedResponseMessage` const and referenced. **Plan author confirms em-dash bytes** via `grep` per CONTEXT.md (canonical convention: U+2014, three bytes `e2 80 94` in UTF-8).
- Logger / telemetry: D-05 wrap-up gate declined logging on the catch. No `_logger.LogWarning(ex, ...)`. The catch silently re-throws.
- File-level state: the existing `DeserializerOptions` static readonly stays where it is. The new const lives above or below it (plan author choice).
