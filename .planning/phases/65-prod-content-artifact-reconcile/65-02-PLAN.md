Reconcile decision tree (verbatim source: 65-RESEARCH.md "Three Reconcile Paths" → "Decision tree"):
  published-orphan count > 0:
    local .md artifacts available?  YES → Option A (Studio DirectPush re-upload)
                                    NO  → Option B (unpublish/delete published orphans, reclassify rest)
  published-orphan count = 0 (all orphans hidden/unpublished):
    want to restore content eventually?  YES → Option B (unpublish, note for future re-upload)
                                         NO  → Option B (delete) or Option C (formally accept cosmetic)

Operator-run write tools (AI never writes prod):
  - Option A re-upload: DeckFlow.Studio Pages/DirectPush.razor — Stage 2 SCP upload of `.md` files to
    Render `/data/content-kb/...`; Stage 3 UpsertContentColumnsOnlyAsync is idempotent for known rows.
    Requires operator-local `content-kb.db` + `content-kb/` artifacts for the orphan rows + SCP secrets.
  - Option B unpublish/delete: admin console `/Admin/ContentKb` visibility/delete controls.
  - Option C accept: no DB/file action; record-only.

Post-reconcile confirmation tools (READ-ONLY):
  - Prod probe Query B (RESEARCH "Prod Probe Specification") re-run via Render MCP
    `mcp__render__query_render_postgres` postgresId `dpg-d7oj8iugvqtc73fso0g0-a`.
  - content-kb-check CLI (delivered by Plan 65-03): run against the post-reconcile local state pulled
    via Studio Pull-from-Prod; exit 0 == no published orphans.

Pitfall (RESEARCH Pitfall 3): Pull-from-Prod CANNOT reconstitute a missing artifact — if prod is
missing the `.md`, the local pull will also be missing it. Option A's re-upload source is the
operator's ORIGINAL distill output, not a prod pull.
