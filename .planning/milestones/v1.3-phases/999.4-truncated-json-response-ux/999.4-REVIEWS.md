# Cross-AI Plan Review — Phase 999.4

## Codex Review

## Summary

The plan is technically sound for the core bug: malformed/truncated JSON pasted into the normal workflow postbacks should stop escaping as raw `JsonReaderException` and should render through the existing `InvalidOperationException` → `ErrorMessage` path. I verified the key assumptions in the repo. The main gaps are not in the basic catch strategy; they are around adjacent surfaces that reuse the same parsers, semantically incomplete JSON that still parses, and a couple of stale closure instructions.

## Strengths

- The four direct AI-response `JsonDocument.Parse` sites are correctly identified: [ResponseParsers.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Services/ResponseParsers.cs:24), [ResponseParsers.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Services/ResponseParsers.cs:55), [DeckComparisonService.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Services/DeckComparisonService.cs:915), [MetaGapService.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Services/MetaGapService.cs:946).
- Reusing the existing controller `InvalidOperationException` handling is the right minimal change. The normal postback actions preserve `Request = request` at [DeckController.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Controllers/DeckController.cs:485), [DeckController.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Controllers/DeckController.cs:691), and [DeckController.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Controllers/DeckController.cs:975).
- Keeping `JsonTextFormatterService` untouched respects the Phase 999.2 invariant and avoids widening the blast radius.
- The xUnit plan is right-sized: direct parser facts with exact message equality are high-signal and cheap.
- The carve-outs for EDH Top16 override, Scryfall upstream parsing, and fetched-entry zip parsing are explicit.

## Concerns

- **MEDIUM**: The same parsers are also used by zip upload restore paths. `DeckComparisonUpload` calls `ParseComparisonResponse` at [DeckController.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Controllers/DeckController.cs:891), and `CedhMetaGapUpload` calls `ParseResponse` at [DeckController.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Web/Controllers/DeckController.cs:1149). After this change, a corrupted zip with truncated embedded response JSON will show “The pasted response appears truncated...” even though the user uploaded a file. Those upload catches also reset `Request` to a new request, so textarea preservation does not hold there.

- **MEDIUM**: Valid but semantically incomplete JSON is not covered. `DeckComparisonService.ParseComparisonResponse` and `MetaGapService.ParseResponse` only check `result is null`; inputs like `{"deck_comparison":{"deck_a_name":"Atraxa"}}` or `{"meta_gap":{"commander":"Tymna / Kraum"}}` can parse into mostly-empty objects. This is not the raw-stack bug, but it is a real “partial AI response” edge case.

- **MEDIUM**: The plan requires creating `.planning/phases/999.4-truncated-json-response-ux/999.4-01-SUMMARY.md`, but no task creates it, it is not in `files_modified`, and Task 5 acceptance does not check it.

- **LOW**: Task 5’s ROADMAP edit instructions are stale. The actual roadmap says `**Plans:** 1 plan` at line 321, not `0/0 plans`. The progress table still says `0/0`, so the closure task needs exact-current-text instructions.

- **LOW**: Manual UAT says to use Gemini, but Gemini is hidden unless `DECKFLOW_GEMINI_ENABLED=true`. The plan should either start the app with that env var for the Gemini pass or make Gemini optional under the existing “2 of 3 AI selections” requirement.

- **LOW**: Catching all `JsonException` from `JsonDocument.Parse` is intentionally broad. It will label any syntactically malformed JSON as “appears truncated.” That is acceptable because the copy says “appears,” but it should be treated as a deliberate UX tradeoff, not precise classification.

## Suggestions

- Add an explicit note to Task 5: zip upload restore paths may surface the same truncation message for malformed embedded response JSON, or add a small controller-side mapping for upload actions to a corrupted-zip message if you want to keep D-03 clean.

- Either add semantic completeness guards for comparison/meta-gap responses now, or record a follow-up backlog item. If added now, mirror the existing `HasMeaningful*Content` pattern from `ResponseParsers`.

- Add `999.4-01-SUMMARY.md` to Task 5 `files_modified`, acceptance criteria, and commit 5.

- Fix the ROADMAP closure instructions to match the actual file: change `**Plans:** 1 plan` to `**Plans:** 1/1 plans complete`, check the listed plan, and change the progress row `0/0 | Planned | —` to `1/1 | Complete | 2026-05-21`.

- Adjust UAT wording: “For Gemini, run with `DECKFLOW_GEMINI_ENABLED=true`, otherwise satisfy the required spot-check with ChatGPT + Claude.”

## Risk Assessment

**Overall risk: MEDIUM as written, LOW after the plan tweaks above.** The core implementation is small and likely correct. The medium risk comes from unacknowledged adjacent behavior: upload restore paths reuse the same parsers, and syntactically valid but incomplete AI output can still bypass the new UX. Those are not blockers for the stated truncated-JSON stack-trace fix, but they should be explicit before execution.
