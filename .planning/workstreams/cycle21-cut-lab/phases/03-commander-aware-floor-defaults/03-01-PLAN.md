Create `DeckFlow.Core/Research/RoleFloorBaselineDriftCheck.cs` in namespace `DeckFlow.Core.Research`,
LF line endings, mirroring `CedhBaselineDriftCheck`'s structure exactly: an all-`required` thresholds
record with a `FromJson`, a finding record, a verdict record, and a static `Evaluate` that accumulates
findings through one private `Add*` method per rule.

`RoleFloorDriftThresholds` — every property `required` (a missing field must throw, because a typo in
the config would otherwise disable the guard silently — carry that rationale into the xmldoc):
- `int MinEstablishedN` — prior sample size at or above which a commander's disappearance is a failure.
- `int MinPopulousN` — prior sample size at or above which a commander is checked for sample collapse.
- `double MaxSampleDropPct` — maximum tolerated percentage drop in a populous commander's sample.
- `int MoverThresholdFloors` — minimum absolute change in an adopted floor for a pair to count as a mover.
- `int MinMoversForDirectionTest` — minimum movers before the one-sidedness test is meaningful.
- `double MaxOneSidedPct` — percentage at or above which same-direction movers fail.
- `double MaxAdoptedPairDropPct` — maximum tolerated percentage drop in the snapshot's total `adoptedPairs`.
`FromJson(string json)` deserializes with `new JsonSerializerOptions { PropertyNamingPolicy = JsonNamingPolicy.CamelCase }`
and throws `JsonException` when the result is null.

`RoleFloorDriftFinding` : `required string Rule`, `string? Commander`, `string? Role`, `required string Detail`.
`RoleFloorDriftVerdict` : `required bool Passed`, `required IReadOnlyList<RoleFloorDriftFinding> Findings`.

`public static RoleFloorDriftVerdict Evaluate(RoleFloorBaselineSnapshot previous, RoleFloorBaselineSnapshot candidate, RoleFloorDriftThresholds thresholds)`:
- Null-guard all three.
- Short-circuit: when `previous.Commanders.Count == 0`, return a failed verdict carrying a single
  `EmptyPreviousSnapshot` finding whose `Detail` names `previous.Generated` and states the committed
  snapshot is treated as corrupt.
- Otherwise run, in this order: `AddDroppedEstablishedCommanders`, `AddDroppedEstablishedRoles`,
  `AddSampleCollapses`, `AddAdoptedPairCollapse`, `AddOneSidedDrift`.
- `Passed` is `findings.Count == 0`.

Rules:
- `DroppedEstablishedCommander` — prior `N >= MinEstablishedN` and the key is absent from `candidate.Commanders`.
- `DroppedEstablishedRole` — this is the rule the lands guard has no analog for, because lands has no
  sub-role dimension; add a `// Why:` comment saying so. For a commander present in both with prior
  `N >= MinEstablishedN`, any role key present in the prior `Floors` but absent from the candidate's
  `Floors` is a finding. Set `Role` on the finding.
- `SampleCollapse` — prior `N >= MinPopulousN`, commander present in both, and
  `(prior.N - current.N) / (double)prior.N * 100.0 > MaxSampleDropPct`.
- `AdoptedPairCollapse` — `previous.AdoptedPairs > 0` and
  `(previous.AdoptedPairs - candidate.AdoptedPairs) / (double)previous.AdoptedPairs * 100.0 > MaxAdoptedPairDropPct`.
- `OneSidedDrift` — over every (commander, role) pair present in BOTH snapshots, a delta with
  `Math.Abs(delta) >= MoverThresholdFloors` counts as a mover in its direction. When
  `movers >= MinMoversForDirectionTest` and `Math.Max(up, down) / (double)movers * 100.0 >= MaxOneSidedPct`,
  emit one finding whose `Detail` records movers, up, down, the observed percentage, and the limit, plus
  the sentence that genuine drift scatters while a one-sided shift indicates systematic input corruption.

Every `Detail` string states the observed value and the limit breached, matching the lands guard's style.
`Evaluate` never throws on a breach — it reports.

Preserve LF line endings on this new file.
