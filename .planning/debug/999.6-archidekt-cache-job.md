## Root Cause

`IHarvestRunStore` lacks a `GetByIdAsync(Guid id, CancellationToken)` method. `ArchidektCacheJobService.GetJob(Guid)` (`DeckFlow.Web/Services/ArchidektCacheJobService.cs:208-222`) is implemented as `_runStore.GetActiveAsync()` plus an id-filter — so it can only return rows whose state is in `('Queued','Running','Stopping')`. Once a job transitions to a terminal state (`Succeeded`/`Failed`/`Cancelled`), `GetActiveAsync` no longer returns it, and `GetJob(completedJobId)` returns null.

The SUT comment at lines 210-215 explicitly acknowledges the gap: **"We don't have a GetByIdAsync on IHarvestRunStore yet — Plan 04 will add one when it needs per-run history."** This is the author's own forward-reference to the missing contract — exactly the gap that needs to land HERE in Phase 999.6 P03 per D-15.

The contract under test is: "Completed jobs remain queryable by id even after they're no longer the active job." That contract is **correct** and **broken** — the test is right; the production code is wrong.

### 2. `DeckFlow.Web/Services/Harvest/HarvestRunStore.cs` — add the production implementation

Insert after `GetActiveAsync` (after line 232). Mirror the shape of `GetActiveAsync` EXACTLY: `EnsureSchemaAsync`, open connection, parameterized SQL, map row via the existing `ReadHarvestRunRow` helper. **CRITICAL — D-23 provider-specific Guid binding:**

```csharp
/// <inheritdoc />
public async Task<HarvestRunRow?> GetByIdAsync(Guid id, CancellationToken cancellationToken = default)
{
    await EnsureSchemaAsync(cancellationToken).ConfigureAwait(false);

    await using var connection = await OpenConnectionAsync(cancellationToken).ConfigureAwait(false);
    await using var command = connection.CreateCommand();
    command.CommandText = """
        SELECT id, kind, state, requested_utc, started_utc, completed_utc,
               duration_seconds, decks_processed, additional_decks_found, error_message, url
          FROM harvest_runs
         WHERE id = @id
         LIMIT 1;
        """;

    // SQLite stores Guid as TEXT; Npgsql accepts Guid directly. Mirrors the
    // existing provider-specific bind pattern at HarvestRunStore.cs lines
    // 118-119 (InsertQueuedAsync), 165-166 (UpdateStateAsync), and
    // 201-202 (UpdateProgressAsync).
    RelationalDatabaseConnection.AddParameter(
        command, "@id",
        _connectionInfo.IsPostgres ? (object)id : id.ToString());

    await using var reader = await command.ExecuteReaderAsync(cancellationToken).ConfigureAwait(false);
    if (!await reader.ReadAsync(cancellationToken).ConfigureAwait(false))
    {
        return null;
    }
    return ReadHarvestRunRow(reader);
}
```

**Provider-specific binding precedents** confirmed during this investigation (D-23 critical):
- `HarvestRunStore.cs:117-119` (`InsertQueuedAsync` `@id`): `_connectionInfo.IsPostgres ? (object)id : id.ToString()`
- `HarvestRunStore.cs:164-166` (`UpdateStateAsync` `@id`): `_connectionInfo.IsPostgres ? (object)id : id.ToString()`
- `HarvestRunStore.cs:200-202` (`UpdateProgressAsync` `@id`): `_connectionInfo.IsPostgres ? (object)id : id.ToString()`

The new `GetByIdAsync` MUST mirror this pattern at the `@id` parameter site. Raw `(object)id` (Npgsql-native Guid) would fail under SQLite which stores the column as TEXT. The schema fork at `HarvestRunStore.cs:80` + `:86` (Postgres `UUID PRIMARY KEY` vs SQLite `TEXT PRIMARY KEY`) is what forces the binding fork.

SQL text itself is identical across providers — `WHERE id = @id` works on both (SQLite compares TEXT, Postgres compares UUID — the bind layer above guarantees the parameter type matches the column type). No schema/SQL fork needed for the SELECT; only the parameter binding forks.

No `_stats?.Invalidate()` call (this is a read, not a write — matches `GetActiveAsync` pattern at line 211-232).
