<locked_decisions>
**D-6 (test matrix) — locked: delete the separate `workflowComponentThemes` list and iterate the
existing 24-entry `themes` const.**
Adding the three failing themes to the short list would close F-6 and leave the drift mechanism
intact — two lists that can diverge again is the defect, not the three missing entries. One list
cannot drift from itself.
Reversibility: **reversible** — restoring a narrower list is a one-line edit.

**D-7 (runtime) — locked: measure, then set an explicit per-test timeout. Do not discover it as a
flake.**
`playwright.config.ts` declares no global `timeout`, so Playwright's 30s per-test default applies.
The widened workflow-component test performs one full `importPool` per theme per viewport —
24 x 2 = 48 imports where it previously did 6. The executor measures the wall time and sets
`test.setTimeout()` on that test to the measured value with headroom, recording both numbers in a
comment next to the call. Splitting the test per theme is explicitly NOT chosen: `test.beforeEach`
acquires an admin lock (`:398-401`), so 24 separate tests would acquire and release it 24 times and
add contention this plan has no reason to introduce.
Reversibility: **reversible**.

**Not re-theming.** F-6 raises tokens to clear the floor. It does not restyle
`.cutlab-intake-summary`, does not change which token that element uses, and does not touch a
theme the census shows passing. Layout CSS goes in `site-common.css` and never in `site.css`; this
plan adds no layout CSS anywhere — only `:root` token values in individual theme files.
</locked_decisions>
