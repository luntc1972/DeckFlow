<objective>
Package `DeckFlow.Studio` (Blazor Server, .NET 10) as a self-contained, single-file `win-x64`
executable the operator can run on a clean Windows box with NO .NET runtime installed — produced by a
repeatable, documented publish step. This closes DIST-01. ONLY `DeckFlow.Studio` is in scope; no
behavior change to the app itself — this is build/packaging + docs only.

Purpose: Lets the operator run Studio without installing the .NET SDK/runtime, removing the biggest
friction in the local harvest→publish workflow.

Output:
- A publish profile (`win-x64-selfcontained.pubxml`) that, when explicitly selected, yields
  `DeckFlow.Studio.exe` (~116 MB) with the only native dep (`e_sqlite3.dll`) embedded and `wwwroot/`
  beside it.
- A re-runnable PowerShell publish script (primary) + a thin bash wrapper for WSL, both invoking the
  Windows `dotnet.exe`, stripping non-distribution files, zipping, and printing artifact path + size.
- `appsettings.json` pins Kestrel to `http://localhost:5271` so the packaged exe serves at the
  documented port without operator action.
- Docs: a "Run the standalone Windows executable" section in `STUDIO-SETUP.md` + a README pointer.
</objective>

LOCKED publish shape (63-CONTEXT.md, trial-publish-verified in 63-RESEARCH.md):
  SelfContained=true, RuntimeIdentifier=win-x64, PublishSingleFile=true,
  IncludeNativeLibrariesForSelfExtract=true, PublishTrimmed=false. ReadyToRun OFF (document as
  optional toggle only; do not enable).

WHERE publish config lives (D — do NOT change the default build):
  All publish properties go in the NEW profile
  DeckFlow.Studio/Properties/PublishProfiles/win-x64-selfcontained.pubxml — NOT unconditionally in
  the .csproj. Unconditional <PublishSingleFile>/<SelfContained>/<RuntimeIdentifier> in the csproj
  would alter every `dotnet build`/`dotnet run`/CI/Docker invocation. The .csproj is on the project
  "Do Not Modify beyond strictly needed" list — leave it untouched; the profile carries everything.

Build invocation (WSL → Windows): the repo builds Windows-side. Scripts MUST invoke the Windows
  dotnet at "/mnt/c/Program Files/dotnet/dotnet.exe" (bash) / "C:\Program Files\dotnet\dotnet.exe"
  (ps1). Verified present: .NET 10.0.301 SDK. The .sh wrapper does NOT use the Linux `dotnet`.

The one native dep: e_sqlite3.dll (Microsoft.Data.Sqlite → SQLitePCLRaw). With
  IncludeNativeLibrariesForSelfExtract=true it is embedded and extracted to %TEMP% at first launch;
  WITHOUT it, it lands as a loose DLL beside the exe and breaks the single-file story. All other
  deps (SSH.NET, BouncyCastle, Npgsql) are managed-only.

wwwroot is NOT embeddable: Blazor Server's UseStaticFiles() reads wwwroot/ from the exe directory
  on disk. The deliverable is therefore exe + wwwroot/ (+ appsettings.json +
  DeckFlow.Studio.staticwebassets.endpoints.json), optionally zipped — NOT a literal single file.
  Document this honestly; do NOT claim a one-file drop.

Files to EXCLUDE from the distribution zip: *.pdb, *.xml, web.config, appsettings.Development.json.

Secrets on a clean machine = environment variables (config `:` → `__`):
  Studio__ProdConnectionString, Studio__Scp__Host, Studio__Scp__Username, Studio__Scp__KeyFile,
  Studio__Scp__RemoteArtifactRoot, Studio__Scp__Port (opt), Studio__Scp__KeyPassphrase (opt),
  DECKFLOW_LLM_PROVIDER, OPENAI_API_KEY. The basic harvest → distill → review → approve flow works
  with NO secrets; only DirectPush (SCP + prod Postgres) and the git commit-publish path need extra
  config (prod conn string / SSH creds / git.exe on PATH). Program.cs already calls
  AddUserSecrets<Program>() — harmless when absent; do NOT remove it.

Project rules (./CLAUDE.md):
  - NO new NuGet packages (pure SDK publish properties only).
  - Public repo — NEVER commit secrets; the _launch-studio.bat env-var wrapper is documented but NOT
    committed/distributed (it holds secrets).
  - LF/CRLF enforced by .gitattributes on commit: *.ps1 → CRLF, *.sh → LF, *.pubxml falls through to
    `* text=auto eol=lf` (LF, consistent with .csproj/.props). Write new files to match; the
    .gitattributes filter normalizes on commit regardless.
  - Do NOT edit Dockerfile / render.yaml (infra "Do Not Modify" list, out of scope).
  - README updated when behavior/workflow changes (a new publish/run path is a workflow change).
