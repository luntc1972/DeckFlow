New static class to create (one public type per file, sealed-equivalent static, file-scoped namespace):

namespace DeckFlow.Web.Services;
public static [partial] class ContentKbClipSanitizer
{
    // Returns clip text with instruction-like patterns neutralized for safe prompt injection.
    public static string Sanitize(string clipText);
}

Pattern families to neutralize (extendable; cover at least these per 34-CONTEXT + PITFALLS P7):
  - Role markers at line start: ^(System|Assistant|User|AI)\s*: (case-insensitive)
  - Override phrases: (ignore|disregard|forget|override)\s+(all\s+)?(the\s+)?(previous|prior|above|earlier|preceding)\s+(instructions|guidelines|rules|prompts)
  - Prompt-structure markdown inside clip text: fenced code blocks (```), and ATX headers (^#{1,6}\s)
    that would mimic the prompt's own section structure.
Neutralize by stripping/escaping (e.g. drop role-marker prefixes, replace ``` fences with a plain
token, demote/escape leading # so it is not read as a header). Do NOT silently empty the clip — keep
the human-readable content; only defang the structural/instruction tokens. Use Regex.Escape for any
caller-supplied value compared as literal (none expected here — patterns are static).
</interfaces>

## Trust Boundaries

|----------|-------------|
| harvested transcript clip text -> analysis prompt -> user's downstream LLM | The attacker controls harvested third-party YouTube transcript content. It crosses from KB artifact into the rendered `## Expert Context` block and is pasted by the user into ChatGPT/Claude/Gemini. This is THE boundary KBR-03 defends. |
| clip Source/Title attribution fields | Also harvested; rendered in the attribution line; same injection surface as Excerpt. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-10 | Elevation of Privilege / Tampering | Injection: transcript text acting as instructions to the downstream LLM (instruction-override, role-confusion: "ignore previous instructions", "System:") | mitigate | Regex sanitizer (ContentKbClipSanitizer.Sanitize) neutralizes role markers + override phrases + prompt-structure markdown BEFORE injection (Task 1+2); structural data fence + boundary instruction wrap the block so the model treats it as quoted data (Task 2); existing evidence-not-instructions preamble preserved. ASVS L1: untrusted input neutralized at the trust boundary. |
| T-34-11 | Spoofing | Clip text forging a fake prompt section (e.g. embedding `## Output Format` to redirect output) | mitigate | ATX-header demotion in the sanitizer + the structural fence make embedded headers non-authoritative; the fence delimiter is a non-markdown token the model is told to treat as a data boundary. |
| T-34-12 | Information Disclosure | Fence delimiter or boundary instruction leaking internal structure | accept | The fence is intentionally visible to the downstream LLM (that is the mitigation); no internal IDs are exposed (Excerpt/Source/Title/Timestamp only — no DB row ids per PITFALLS security note). Residual risk negligible. |
| T-34-13 | Tampering | Sanitizer over-stripping benign deckbuilding text (false positive harming KB value) | mitigate | Tests assert benign passthrough (e.g. "#5" survives; only true ATX `^#{1,6}\s` demoted); neutralize-not-blank policy keeps human-readable content. |
| T-34-SC | Tampering | npm/pip/cargo installs | mitigate | NONE expected. Zero-dep mitigation (regex + string ops). If any package install is proposed, STOP — scope violation per CLAUDE.md + 34-CONTEXT. No package-manager command runs in this plan. |

Residual risk after mitigation: regex sanitization is not a complete defense against all adversarial
