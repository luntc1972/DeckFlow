<objective>
Bug A — redesign the active step-tab as a filled-accent pill and fix the active-text WCAG fails.

Today `.prompt-step-tab.is-active` (site.css:320) reuses the SAME `background: var(--panel-soft-bg)` as an inactive tab; only border/text-tint/weight differ — a low-salience active state, and several themes fail active-text contrast.

The locked fix (CONTEXT Bug A) is a filled-accent pill: `background: var(--accent)` + `color: var(--accent-contrast, #fff)` + `border-color: var(--accent)`, reusing the template already proven at `site-mobile.css:353`. Because the 13 standalone forks each duplicate the base rule, the fill must be MIRRORED into 12 of them (the 11 @import themes inherit the base for free; `site-rakdos.css:168` already renders an acceptable filled pill and is left as-is).

TWO reviewer-flagged hazards drive this plan:
1. **Empirical contrast, not a static list.** The rule is per-theme: for EVERY theme, if white (#fff) on that theme's `--accent` is < 4.5:1, the theme MUST define `--accent-contrast` set to a color that clears >=4.5:1 against its accent, and the active-tab text MUST resolve `var(--accent-contrast, #fff)`. Codex's verified sweep (starting matrix below) is a checklist, not the source of truth — the executor re-measures each theme and the Playwright WCAG gate in 86-05 is the empirical enforcement.
2. **Duplicate late overrides win.** `site-abzan.css` (:323 and :1268), `site-jund.css` (:323 and :1214), and `site-sultai.css` (:323 and :1214) each declare `.prompt-step-tab.is-active` TWICE; the LATER block wins the cascade. Editing only the first leaves them broken. Edit EVERY occurrence (grep all, fix each), and the verify asserts the TERMINAL (last) block resolves the filled pill.

Purpose: raises Pillar-2 (Visuals) active-state salience and clears the WCAG fails (requirement UIAUDIT-02).
Output: filled-pill active tab in base + 12 forks (all occurrences); per-theme `--accent-contrast` tokens wherever white-on-accent < 4.5:1.
</objective>
