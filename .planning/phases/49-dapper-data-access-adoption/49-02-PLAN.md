DateTimeOffsetTypeHandler (NEW, 5th handler) shares logic with DateTimeTypeHandler.
LOCKED semantics per CONTEXT D-06 (read the D-06 wording before implementing):
  - SetValue (write path):
      SqliteParameter  => p.Value = value.UtcDateTime.ToString("O", CultureInfo.InvariantCulture);
      else (NpgsqlParameter) => p.Value = value.UtcDateTime; // PG TIMESTAMPTZ native
  - Parse (read path):
      DateTimeOffset dto => dto.ToUniversalTime();
      DateTime dt        => new DateTimeOffset(DateTime.SpecifyKind(dt, DateTimeKind.Utc), TimeSpan.Zero);
      string text        => ParseOffsetString(text);   // TWO-STEP parse, see below
      _                  => new DateTimeOffset(Convert.ToDateTime(value, CultureInfo.InvariantCulture), TimeSpan.Zero);

  ⚠ MEDIUM-1 FIX — the parse flags `RoundtripKind | AssumeUniversal | AdjustToUniversal`
     are MUTUALLY INCOMPATIBLE (Microsoft docs: RoundtripKind cannot be combined with
     AssumeUniversal/AdjustToUniversal). Do NOT OR them together. Use a TWO-STEP parse helper:
        step 1 — strings written by "O" / containing an explicit offset or "Z":
                 DateTimeOffset.TryParse(text, CultureInfo.InvariantCulture,
                     DateTimeStyles.RoundtripKind, out var dto)  → dto.ToUniversalTime()
        step 2 — fallback for offset-less legacy strings (BlockedVideoStore's prior
                 AssumeUniversal read, Pitfall 5):
                 DateTimeOffset.Parse(text, CultureInfo.InvariantCulture,
                     DateTimeStyles.AssumeUniversal | DateTimeStyles.AdjustToUniversal)
                     .ToUniversalTime()       // NO RoundtripKind in this branch

  WRITE-PATH REGISTRATION (per locked CONTEXT D-07 — UNCONDITIONAL, same as the original four):
     Register it inside EnsureRegistered() with the other handlers using the SAME unconditional
     RemoveTypeMap-before-AddTypeHandler default that 49-01 established for DateTime/decimal/bool/Guid.
     That means ALWAYS, for DateTimeOffset:
        SqlMapper.RemoveTypeMap(typeof(DateTimeOffset));
        SqlMapper.RemoveTypeMap(typeof(DateTimeOffset?));
        SqlMapper.AddTypeHandler(new DateTimeOffsetTypeHandler());
     in that order. This is NOT a fallback applied only on failure — RemoveTypeMap(T)+RemoveTypeMap(T?)
     before AddTypeHandler is the required default path per D-07 (both nullable and non-nullable
     forms must be removed because stores bind DateTimeOffset? — e.g. HarvestRunStore.UpdateStateAsync),
     so the handler is the resolved write-path binder and SetValue fires.

Connection-open per store (preserve, do NOT change — PATTERNS.md finding #2):
  - These six stores use _connectionInfo.OpenConnectionAsync() (FK PRAGMA applied)
    in most cases — verify each at its call site before converting and keep it.
