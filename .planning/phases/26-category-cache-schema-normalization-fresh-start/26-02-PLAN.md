<objective>
Port the `CategoryKnowledgeRepository` write and read paths onto the normalized integer-keyed schema created in 26-01, proving byte-identical lookup results (parity) and removing the non-sargable `o.source = 'archidekt_live:' || q.deck_id` string-concat join in favor of an integer join through the `sources` dimension. Then add a resolve-once-per-deck batch boundary so dimension id resolution does not repeat per category/card (MEDIUM-4), update the full-reset runbook's table list, and update the Postgres integration test.

Purpose: Parity is the central requirement of this phase. The REVISED design (HIGH-1) interns the generic `source` string into its OWN `sources` dimension — `deck_queue` is NOT the universal source dimension. The three source kinds behave exactly as today:
- `archidekt_live:{deckId}` -> sources row whose `deck_queue_id` points at the matching `deck_queue.id` (resolved by stripping the `archidekt_live:` prefix to the bare deckId and looking up deck_queue). This is the ONLY source kind in the commander aggregate.
- `archidekt_url:{url}` and `edhrec` -> sources rows with `deck_queue_id = NULL`; they contribute to card lookups but NOT the commander aggregate, and never enter the harvest queue.

HIGH-2 is resolved by carrying the display `card_name` on the observation/totals fact rows (set in 26-01 DDL), so the read methods that `GROUP BY ... card_name` keep identical row shapes — display spellings are NOT collapsed.

The `ICategoryKnowledgeStore` interface signature stays UNCHANGED (A6). `DeckCategoryCacheWriter` (internal) gains a resolve-once batch path but its public-facing entry points keep their shapes.

Output: Re-pointed read/write SQL with intern-on-write (get-or-insert dimension id via `INSERT ... ON CONFLICT ... RETURNING id`), a per-deck-write batch API resolving deck_id + card_ids once, GREEN parity tests, updated PG integration test, updated runbook.
