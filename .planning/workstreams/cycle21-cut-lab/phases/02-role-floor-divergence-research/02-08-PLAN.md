# Phase 2 Plan 08 — Run it for real, behind an operator checkpoint

## Release Posture

**This phase ships NO user-visible change and is NOT a release.** The ROADMAP release-posture table
is explicit: *"2. Research — No — harness is additive and does not ship to the web app — Not a
release. Commit findings; no version bump."*

**Do NOT run `scripts/release.sh` or `scripts/release.ps1`. Do NOT bump `<Version>` in any csproj.
Do NOT create a git tag.** Commit the findings and stop.

## Why This Plan Exists

Plans `02-01` through `02-07` repaired the harness. Nothing has run. Both
`role-floor-research-run.log` and `role-floor-research-run.exit` were 0 bytes — the plainest possible
evidence that the previously-committed findings were fixture output — and plan `02-01` deleted them
along with the fixtures.

This plan produces the run, and it is the only plan in the phase that touches a live database.

**It does NOT fetch from EDHREC.** The EDHREC bracket corpus was acquired in full on 2026-07-27
(1,525/1,525 cells, 0 failed, 0 404, 0 unresolved slugs) and is verified in place here — see D-03.
No task in this plan may issue a request to `json.edhrec.com`. The only outbound calls this plan may
make are Scryfall card resolution on behalf of 02-09's grid arm (D-09) and the Postgres connection
itself.

## The operator checkpoint is the whole point

The run needs a **live Postgres connection string**. That string is a secret. CLAUDE.md is explicit:
connection strings are secrets; never echo them into chat output, code comments, commits, logs, or
error messages, and never hardcode them.

At the time this phase was first planned, `RoleFloorResearchCommandRunner` read the string only from
the required `--connection-string` argument (`:82-91`, via
`PostgresConnectionStringNormalizer.Normalize`), with no environment fallback. **Plan `02-04` D-07
changed that**, precisely so this plan would not have to put a live credential on a command line:
command-line arguments are visible in the process list to any other user on the machine for the
entire duration of a run measured in hours. The harness now reads
`DECKFLOW_ROLE_FLOOR_CONNECTION_STRING` directly when `--connection-string` is absent, and
`--connection-string` remains supported for backward compatibility.

So the string reaches the process without an agent handling it AND without appearing in argv:

1. The **operator** exports `DECKFLOW_ROLE_FLOOR_CONNECTION_STRING` in their own shell.
2. The committed wrapper script invokes the harness **without** a `--connection-string` argument; the
   variable is inherited by the child process and read there.
3. The agent runs the wrapper. It never sees, logs, or stores the value, and `ps` never shows it.

**The wrapper must NOT pass `--connection-string`.** If plan `02-04`'s change is missing when this
plan runs — the harness still rejecting an absent flag — STOP and report rather than falling back to
argv. Passing the secret on the command line is a decision for the developer at the Task 2
checkpoint, not something the agent takes silently to make the run start.

**The agent must never attempt to obtain the connection string itself** — not from
`~/claude/connections/`, not from Render MCP, not from `render.yaml`, not from `appsettings*.json`,
not by guessing. If the variable is unset, the wrapper fails closed with a message telling the
operator what to export, and the agent returns to the checkpoint.

This mirrors the blocking checkpoint plan `01.1-02` used for its downstream delta: an agent-blocking
stop where a human decision or a human-held secret is genuinely required.

## The run is long — plan for it

Cost drivers, from the harness's own structure:

| Stage | Cost |
|---|---|
| `LoadCommanderRowsAsync` (`:309-331`) | Pages 200 commanders at a time until exhausted. |
| Membership load (`:102-155`) | One `GetCategoryDeckMembershipForCommanderAsync` per commander at `MaxDegreeOfParallelism = 8`, progress logged every 200 commanders. **The dominant Postgres cost.** |
| `ResolveCardsAsync` (`:360-472`) | Scryfall `cards/collection` in batches of 75, plus a per-miss fallback search at a 350 ms pace with up to four 429 retries at 5/8/12/15 s. **Heavily mitigated by the existing 8.2 MB `_role-floor-research/cards_full.json` cache — do not delete it.** |
| Classification | In-process, fast. |

The membership progress line already prints elapsed time and running counts every 200 commanders, so
the log gives a live sense of progress. Expect hours, not minutes. Run in the background with output
tee'd to the log so the agent is not blocked on a foreground process.

## Design Decisions

### D-01 — a committed wrapper script, not an ad-hoc command line

An ad-hoc invocation is unreproducible and invites the connection string landing in shell history or
a chat message. A committed script fixes the flags, does the logging and exit-code capture, and is
the artifact a future re-run uses.

It must **fail closed**: if `DECKFLOW_ROLE_FLOOR_CONNECTION_STRING` is unset or empty, print the
export instruction and exit non-zero **before invoking anything**.

It must never echo the variable — no `set -x`, no echoing of the value, and no inclusion of it in the
logged command line.

### D-02 — exit code 2 is accepted, never retried around

Plan `02-04` made exit code 2 mean "ran successfully, zero commanders cleared the minimum". Under
criterion 10 that is a legitimate outcome.

**If the run exits 2, do NOT lower `--min-decks` and re-run.** Record the exit code, capture the
diagnostic threshold table the harness printed to stderr, and take it to the checkpoint. Lowering a
threshold after seeing that nothing passed is the exact failure mode plan `02-07`'s
`NO-GO-TEMPLATE.md` section 10 names.

The developer may authorize a different threshold at the checkpoint. The agent may not choose one.

Note the harness already prints how many commanders qualify at 15/20/25/30/40/50/75/100
(`:257-259`), so a first run at 40 tells the developer what any other threshold would have yielded
**without a second run**.

### D-03 — the EDHREC fetch is ALREADY DONE; verify it, never re-run it

**Changed 2026-07-27.** An earlier draft of this plan opened with "run the fetcher". The fetch already
happened: `scripts/edhrec-brackets/fetch.py` ran to completion on 2026-07-27 and wrote **1,525 cells**
(305 commanders x 5 brackets, 0 failed, 0 404, 0 unresolved slugs, 33 minutes) into
`_edhrec-brackets/`. Plan `02-02` committed the tooling and pinned the on-disk contract; plan `02-06`
ingests it.

So this plan's EDHREC work is **verification, not acquisition**:

1. Confirm `_edhrec-brackets/manifest.json` exists and reports `cells_written: 1525`,
   `cells_failed: 0`, `cells_404: 0`.
2. Confirm `_edhrec-brackets/cells/` holds 1,525 files.
3. Confirm the directory is still untracked and unmodified.

**Make NO request to `json.edhrec.com`.** Not to top up, not to refresh, not to "make sure". If the
corpus is damaged or absent, STOP and take it to the Task 2 checkpoint — re-acquiring 1,525 cells from
a third party is a developer decision, not an agent's.

At the >=400-decks-per-cell floor the corpus yields **805 qualifying cells** (versus the 2026-07-16
study's 148), with **B1/exhibition unusable at one qualifying cell** and **B5/cedh thin at 40**. Plan
`02-06` labels both by computation; nothing here needs to decide it.

`--edhrec-data` remains optional, and declining to use the corpus remains a legitimate — if now much
harder to justify — operator choice, with the D-07 consequences unchanged.

### D-04 — grep for credentials before staging anything

The findings artifacts are committed to a **public repository**. Plan `02-04` D-03 made the harness
emit only the host, but a defence-in-depth check costs nothing and the failure mode is a live secret
leak.

Before `git add`, grep both artifacts and the run log for credential shapes. If **anything** matches,
STOP, do not stage, and report immediately — per CLAUDE.md, an exposed secret must be flagged to the
user with a rotation recommendation.

### D-05 — the run log is committed; the caches are not; `.gitignore` is NOT edited by any plan

`role-floor-research-run.log` is evidence the run happened and is small. Commit it.

`_role-floor-research/` (8.2 MB Scryfall cache) and `_edhrec-brackets/` (the fetched grid) are
local caches. **Do not commit either.**

**`.gitignore` is not edited by any plan in this phase, under any authorization obtained at a
checkpoint.** An earlier draft of this plan allowed the agent to make the edit "if authorized" at the
Task 4 checkpoint. That was wrong: `.gitignore` is on CLAUDE.md's "Do Not Modify Without Explicit
Permission" list, the permission that list requires is one the user gives for a specific task, and no
such permission exists for Phase 2. A checkpoint answer inside a plan is not a substitute for it.

The underlying question stays alive, demoted: **"should `_role-floor-research/` and
`_edhrec-brackets/` be gitignored?"** is recorded as a **FOLLOW-UP RECOMMENDATION in the phase's
closing output** (`02-08-SUMMARY.md`), explicitly outside these execution plans, for the developer to
decide and act on separately. Note the precedent in the recommendation — the sibling cEDH pipeline
gitignores its `_calib/` cache — but do not act on it.

Relatedly: **no task in this phase may "clean" untracked directories.** Both caches must still be
present and untracked when the phase ends, and `_role-floor-research/cards_full.json` in particular
costs hours of rate-limited Scryfall calls to rebuild.

### D-06 — a deliberate exit-2 smoke run, because nothing else can prove criterion 3

ROADMAP criterion 3 — zero qualifying commanders exits non-zero and writes NO artifact — is the
phase's central anti-fixture guarantee. It is also the criterion with the weakest proof: **there is
no `DeckFlow.CLI` test project** (the solution has `DeckFlow.Core.Tests`, `DeckFlow.Web.Tests` and
`DeckFlow.Studio.Tests` only). Plan `02-04` D-06 moved the *predicate* into `DeckFlow.Core` where a
unit test covers it, but nothing in the repo can test that the predicate is CALLED in the right
place. A guard placed one statement too late would write the artifact and then return 2 — producing
exactly the empty-artifact-with-a-verdict failure this phase exists to kill — and would still pass
every static acceptance criterion in plans `02-04` through `02-07`.

So this plan runs the harness **twice**:

1. **Smoke run first**, with `--min-decks 999999`. No commander can qualify at that threshold, so a
   correct harness exits **2** and writes **no** findings artifact. This also exercises, end to end
   and before the real run commits hours: the connection path, the taxonomy drift guard, the
   membership load, the card resolution, and the provenance capture.
2. **The real run**, at the developer's chosen `--min-decks`.

**Cost, stated honestly rather than discovered later.** The exit-2 guard sits after
`qualifyingCommanders` is populated, which is after `LoadCommanderRowsAsync`, the membership load and
`ResolveCardsAsync`. So the smoke run pays the FULL Postgres membership cost — the dominant cost —
a second time. Its Scryfall cost is near zero because `_role-floor-research/cards_full.json` is
already populated and the smoke run warms anything missing for the real run. Running the smoke first
also means a connection, allowlist or taxonomy failure surfaces before the developer commits to the
long run.

This doubling is a real cost and is therefore an explicit item at the Task 2 checkpoint, not an agent
decision. If the developer declines the smoke run, criterion 3 remains proven only by code-reading —
record that in `02-08-SUMMARY.md` as an open verification gap rather than claiming the criterion met.

### D-07 — a Postgres-only run is LABELLED, and records criterion 8 and D-A as unmet

The Task 2 checkpoint lets the developer decline the EDHREC bracket corpus and run Postgres-only. That is a
legitimate operational choice — `--edhrec-data` is optional and the Postgres half is what feeds the
go/no-go — but it is **not** a free one, and an earlier draft understated it as merely "not
recommended".

Taking the skip means:

- **Decision D-A (hybrid corpus) is UNSATISFIED for that run.**
- **ROADMAP criterion 8 — "both corpora are used and distinguishable in the output" — is UNMET.** Half
  of it, distinguishability, still holds; the "both are used" half does not.
- The lands calibration control loses its closest comparison: the 2026-07-16 prior was EDHREC
  average-decks, so an EDHREC-sourced per-bracket lands mean measures the same thing the prior did.

Rule: a Postgres-only run must be **visibly labelled as such in the output**, never silently
indistinguishable from a hybrid run. Plan `02-06` D-05 already requires the artifacts to print
`_No EDHREC cells were supplied for this run (--edhrec-data not provided)._` — that is the mechanism.
This plan adds the accounting: the findings artifact's provenance/coverage section, and
`02-08-SUMMARY.md`, must state explicitly that criterion 8 and decision D-A are UNMET for this run
and why. The artifacts must not render as if the phase completed its corpus scope.

### D-08 — gate the GENERATED markdown for per-row source attribution

Plan `02-05` D-06 declares every figure table's columns in `RoleFloorFigureTable` and asserts at
build time that each declaration carries a `Source` column. That covers the emitter. It does not
cover the artifact: a table could still be emitted by hand-written markdown elsewhere in
`BuildMarkdownReport`, or a column could be dropped in formatting.

So before staging, this plan checks the **artifact the run actually produced**: every markdown table
in `RESEARCH-FINDINGS.md` that carries figures must have a `Source` header column, and every data row
under such a table must carry a non-empty source value. A failure is a harness bug and goes to the
Task 4 checkpoint — it is **never** fixed by hand-editing the generated artifact.

### D-09 — plan 02-09's grid arm runs here too, or is declined on the record

Plan `02-09` implements `edhrec-role-grid` but deliberately does not run it: its first pass needs
roughly **17,600 Scryfall cache misses** (31,788 distinct card names in `edhrec.csv` against 14,167
cached entries), which is a live third-party call at scale and belongs behind the same operator
checkpoint as everything else in this phase.

So this plan runs it, with three properties worth stating:

- **It needs no database credential.** The grid reads two local CSVs and Scryfall. It can run before,
  after, or concurrently with the Postgres work; run it FIRST, because every card it resolves warms
  `_role-floor-research/cards_full.json` for the harness run that follows.
- **Its inputs are in the MAIN worktree.** `--edhrec-csv` and `--averages` must be absolute paths into
  `/mnt/c/users/chrislunt/source/personal/deckflow/artifacts/edhrec/`; `artifacts/edhrec/` does not
  exist in `deckflow-role-floors`.
- **Declining is allowed and must be recorded.** The grid feeds no verdict (plan `02-09` D-07), so
  skipping it costs the findings a breadth instrument and nothing else. But a silent skip would leave
  a committed command with no evidence it ever ran — the same failure mode the 0-byte
  `role-floor-research-run.log` represented. If declined, `02-08-SUMMARY.md` says so explicitly.

Its exit code 2 (zero commanders survived the denominator gate) is a legitimate outcome and is **not**
retried around, on the same D-02 reasoning.
