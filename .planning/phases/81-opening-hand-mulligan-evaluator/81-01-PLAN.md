<objective>
Add the pure-Core opening-hand / mulligan reads that Phase 81 surfaces on `/manabase`: a keepable-hand
probability BAND, the London mulligan keep-size distribution, representative openers with keep / mull-to-6 /
bottom decisions plus a SPELL-ATTRIBUTED on-curve-castability + "has a plan" read, and a color/curve read — ALL
derived from the single existing Monte-Carlo castability pass (the per-spell `CastabilitySimulator.Simulate` calls
the manabase tool already runs), with NO second `Simulate`, NO upstream re-fetch, and NO change to the cast %.

This is the TAP-02 recipe (Phase 75): TAP added `Turn1UntappedTrials` as a pure-observation counter on the
existing trials and averaged it across non-commander rows in `ComputeTapAnalysis`. Phase 81 does the same for
the mulligan process — instrument the trials the sim already runs, surface additive fields on
`CardCastability`, and aggregate a deck-level `ManabaseMulliganEvaluation` in the analyzer. Reuse the sim's own
`LondonMulligan` + `ColorKeepCap` as the SINGLE definition of "keepable", and bucket each trial by the keep
value `LondonMulligan` ALREADY RETURNS (7/6/5) — never by the raw depth index.

CRITICAL correctness constraint (Simulate is PER SPELL): `BuildCastability` runs one `Simulate` per tracked spell
row, and `firstCastableTurn` is that ROW'S result, not a deck-wide fact. So the keepable %/keep-size distribution
(which depend only on `LondonMulligan`, ignoring the spell) are legitimately averaged across rows, but a
representative opener's on-curve read is SPELL-SPECIFIC: each sample is attributed to the tracked spell that
produced it (TrackedSpellName + TrackedOnCurveTurn), and the aggregator selects openers from the EARLY (low-MV)
rows so the surfaced read is about a genuine early play the deck must make on curve — never a generic "castable on
curve." `HasPlan` ("workable line") requires that tracked early play to actually be castable on-curve, satisfying
MULLIGAN-04's "early play + payoff/path" — not merely "a non-land is in hand."

Purpose: MULLIGAN-01/02/03/04 need the keepable %, the keep-size process, per-opener SPELL-ATTRIBUTED on-curve
castability, and the has-a-plan flag; MULLIGAN-05 forbids a second sim / re-fetch and forbids contradicting the
tool's numbers. All of it is pure CPU derivation over the sim's own state, lives in `DeckFlow.Core`, and every new
member is a Core output DTO (no sim-internal leak to Web).
Output: the two-stage trial instrumentation + the OpeningHandSample record (with tracked-spell fields), two new
Core records, an analyzer aggregator, and Core tests (GREEN on CI) — including the sim-layer byte-identity proof
that cast % is unchanged, the singleton free-mulligan bucketing test, and the tracked-spell attribution test.
