<objective>
Improve readability of the Content KB entries list so a long, fully-rendered grid is comfortable
to scan: zebra row shading, a clear hover/focus row highlight, a sticky table header inside the
existing scroll container, and clean tag-chip wrapping. This is the second of the two Phase 33
capabilities (the first, 33-01, added the filter/search box).

Purpose: Even with filtering, the operator scans and clicks publish/unpublish per row in a list
that has grown long. Visual scannability (which row am I on? which header does this column map to?)
reduces mis-clicks and fatigue.

Output: `.admin-shell #kb-entries-table`-scoped CSS in admin-common.css, mobile-safe overrides in
admin-mobile.css, and (only if needed) minimal markup hooks in Index.cshtml.

Note on file ordering: this plan edits Index.cshtml and admin-common.css, which 33-01 also edits.
It therefore runs in WAVE 2, after 33-01 is complete, to avoid file-ownership conflicts.
</objective>
