## Ticket A — `ManabaseClassifier.cs` (two tasks, one file)

### A1: Table-driven `ClassifySpecialLand`
Replace the ~8-branch if-chain with an ordered rule table, mirroring the existing `ConditionalTypeTemplates` array pattern.

- Rule shape (private nested type): applicability gate (`RequiresCheckLandUntapped` / `RequiresRestrictedLands`), a `Regex`, and a builder delegate receiving the successful `Match` plus a small context (card, allCards, produces, defaultUntapped, creatureComposition, stripped text).
- **First-match-wins in the exact current order:** FastLand, SlowLand, EldThreshold, Verge, TrainingCompound, VividCharge, then (restrictedLands-gated) SpendOnlyCreature, NykthosDevotion.
- **Fall-through semantics preserved:** the Verge branch only produces a result when `produces.Count >= 2`; today a successful Verge match with <2 produced colors falls through to later branches. Model this by letting a builder return `null` = "rule declined, keep scanning".
- The empty-text early return and the final default classification stay as-is.
- Behavior byte-identical: same `LandSourceClassification` values (Produces order, Weight, CountCondition/Threshold/TypeFilter, ConditionalAnyColorSource construction incl. `Name + " (vivid)"` / `" (devotion)"`, IsRestrictedSourceApproximation) for every input.

### A2: `AddLandCopies` context record
`AddLandCopies` currently takes 11 params. Introduce a `readonly record struct LandClassificationContext` bundling the shared deck-level inputs (deckColorCount, fetchTypeColors, fetchBasicColors, payLifeUntapped, checkLandUntapped, restrictedLands, allCards, creatureComposition). The mutated collections (`sources`, `restrictedSourceLandNames`, `restrictedSourceLandNameSet`) stay explicit parameters (they are outputs, not context). Build the context once in the caller loop (it is loop-invariant) and pass `(sources, card, context, restrictedSourceLandNames, restrictedSourceLandNameSet)` or equivalent ≤5-param shape.

### A3: Pin tests FIRST (plan-review MED findings)
Codex plan review (gpt-5.5, PASS_WITH_NOTES) found two unpinned semantics. Before touching `ClassifySpecialLand`, add two tests to `DeckFlow.Core.Tests/Manabase/ManabaseClassifierTests.cs` that pass against CURRENT code, then keep them green through the refactor:
1. **restrictedLands-only gating:** a fastland-oracle-text land classified with `restrictedLands: true, checkLandUntapped: false` gets NO `CountCondition` (check-land rules must not fire when only the restricted gate opened the classifier).
2. **Verge decline fall-through:** a Verge-matching land with only 1 produced color does not take the Verge branch (falls through to default classification).

**Verify:** `dotnet build` clean; full `DeckFlow.Core.Tests` + `DeckFlow.Web.Tests` pass; the two A3 pin tests pass both pre- and post-refactor.
