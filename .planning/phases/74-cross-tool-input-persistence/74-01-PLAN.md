<objective>
Ship cross-tool deck-input persistence: a new shared client-side TypeScript module
(`deck-input-store.ts`) that stores the canonical last deck source
`{inputSource, deckUrl, deckText}` in `sessionStorage` and, on each in-scope tool page,
silently prefills empty deck-source fields on load and writes the current deck source on
change. Wire the 5 in-scope views to load the compiled module before `deck-sync.js`.

Purpose: Users currently re-paste their deck when moving between tools — every GET builds a
fresh empty request and no shared "last deck" store exists. This restores the deck input
automatically (LOCKED scope: deck-analysis, manabase, cedh-meta-gap, convert, deck-primer
ONLY; 2-deck tools deferred).

Output:
- `DeckFlow.Web/wwwroot/ts/deck-input-store.ts` (new module; compiled to `wwwroot/js/` by MSBuild — NEVER commit the `.js`).
- Script reference added to 5 in-scope views.
</objective>

<design_decisions>
Two planner decisions that override loose guidance in CONTEXT/PATTERNS — implement as stated:

1. ALL wiring lives in `deck-input-store.ts`; `deck-sync.ts` is NOT modified.
   Rationale: `deck-sync.js` is loaded on MANY pages including the DEFERRED 2-deck tools
   (`Views/Deck/DeckComparison.cshtml:718`, `Views/Deck/DeckSync.cshtml:236`) and several
   out-of-scope tools (CommanderCategories, MechanicLookup, JudgeQuestions, CardLookup,
   SuggestCategories). Putting wiring in `deck-sync.ts` would wire those pages too,
   violating the LOCKED single-deck-only scope. The new `deck-input-store.js` is added
   ONLY to the 5 in-scope views, so it scopes itself correctly.

2. Field-shape reality (verified against the actual DOM — PATTERNS field map is correct;
   the CONTEXT line calling DeckPrimer "combined DeckSource" is WRONG):
   - SPLIT-field tools (inputSource select + `input[name="DeckUrl"]` + `textarea[name="DeckText"]`):
     DeckAnalysis, Manabase, DeckConvert, DeckPrimer.
   - DeckConvert's select is `select[name="InputSource"]` (NOT `DeckInputSource`); the other
     three split tools use `select[name="DeckInputSource"]`.
   - COMBINED-field tool (single `textarea[name="DeckSource"]`, NO inputSource select):
     CedhMetaGap ONLY.
   Detect by field presence (one shape per page), not by route.
</design_decisions>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-74-01 | Information Disclosure | deck source persisted in sessionStorage | accept | No secrets/PII — only a public deck URL or deck list the user already typed; same-origin only; per-tab; auto-cleared on tab close. Matches existing precedent (card-lookup.ts, content-kb.ts already store form state in sessionStorage). |
| T-74-02 | Denial of Service | sessionStorage quota exceeded on large paste | mitigate | deckText capped at DECK_TEXT_MAX_BYTES (100KB) and every storage call wrapped in try/catch — quota/disabled-storage degrades silently, never throws. |
| T-74-03 | Tampering | corrupt/forged JSON in sessionStorage | mitigate | getLastDeck validates shape (object + inputSource is string) and returns null on parse failure; restore is fill-if-empty only, so a bad value cannot clobber a server-rendered field. |
| T-74-SC | Tampering | npm/NuGet installs | mitigate | No new packages added (no install tasks). If any install is attempted, stop — not authorized by this plan. |
</threat_model>
