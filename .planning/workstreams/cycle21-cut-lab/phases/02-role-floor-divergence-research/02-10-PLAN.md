# Phase 2 Plan 10 — DFC names never reach Scryfall's collection endpoint

## Why this plan exists

Plan `02-08`'s D-06 smoke run **failed with exit 1**, not the required exit 2, so ROADMAP criterion 3
is still unproven. The proximate error was:

```
Scryfall card lookup (cards/collection) returned HTTP 429 during role-floor research.
```

The cause is not load. It is that **every double-faced card misses the batch lookup**, cascades into
an individual `cards/search` fallback, and the accumulated retry traffic exhausts the rate limit until
the batch endpoint itself 429s.

In the smoke run: 13 distinct cards needed fallback, **all 13 double-faced**, producing 34
rate-limited requests and 7 abandoned cards before the run died.

## The empirical rule — measured live, 2026-07-28, not assumed

`cards/collection` with a `name` identifier matches a **single face name, front or back**. It does
**not** match the combined name. Verified against the live API:

| Identifier sent | Layout | Result |
|---|---|---|
| `Delver of Secrets` | transform | FOUND |
| `Insectile Aberration` (back face) | transform | FOUND |
| `Delver of Secrets // Insectile Aberration` | transform | **not_found** |
| `Agadeem's Awakening` | modal_dfc | FOUND |
| `Agadeem's Awakening // Agadeem, the Undercrypt` | modal_dfc | **not_found** |
| `Bonecrusher Giant` / `Stomp` | adventure | FOUND |
| `Bonecrusher Giant // Stomp` | adventure | **not_found** |
| `Fire` / `Wear` / `Life` / `Alive` | split | FOUND |
| `Fire // Ice`, `Fire / Ice`, `Fire//Ice` | split | **not_found** (all three spacings) |

The other endpoints behave the OPPOSITE way and must not be touched:

| Endpoint | `Fire // Ice` |
|---|---|
| `cards/named?exact=` | FOUND |
| `cards/search?q=name:"…"` | FOUND (total_cards 1) |

**Known exception, accepted.** `Who // What // When // Where // Why` is found by its combined name
while bare `Who` is not — presumably ambiguity on a very short face name. Cards like this fall through
to the existing per-card fallback, which is what the fallback is for. This plan reduces fallback
volume from "every DFC in the corpus" to "a handful of oddities"; it does not claim to eliminate it.

## The four defective call sites

All four build collection identifiers from an unsplit name:

| Site | Current form | Note |
|---|---|---|
| `DeckFlow.CLI/RoleFloorResearchCommandRunner.cs:722` | raw `A // B` | killed the 02-08 smoke run |
| `DeckFlow.CLI/EdhrecRoleGridCommandRunner.cs:375` | raw `A // B` | same defect; masked because the grid ran before we were throttled, so DFCs resolved expensively rather than failing |
| `DeckFlow.Web/Services/Scryfall/ScryfallCardResolver.cs:110` | raw `cardName` | production |
| `DeckFlow.Web/Services/Packets/ScryfallReferenceResolver.cs` (collection identifiers) | `NormalizeForScryfall(name)` | production; **actively converts `" / "` into `" // "`**, turning one failing form into another |

`NormalizeForScryfall` is `cardName.Replace(" / ", " // ")`. Its doc comment asserts the conversion
makes "DFC cards resolve on the first /cards/collection attempt instead of cascading into per-card
fallbacks" — the exact opposite of measured behavior. The method is still CORRECT at its
`cards/search` (:170) and `cards/named` (:196) call sites, which do accept the combined form. Only
the comment and the collection usage are wrong.

## Design Decisions

### D-01 — a new Core helper, not a change to CardNormalizer.Normalize

`CardNormalizer.Normalize` already truncates to the front face, but it also lowercases and strips
punctuation, and it is used for MATCHING in many places. Do not repurpose or modify it — a change
there has a large blast radius and would alter match keys across the codebase.

Add a separate, single-purpose helper that preserves case and punctuation, because the identifier is
sent to a third-party API rather than used as an internal key.

### D-02 — it lives in DeckFlow.Core so CLI and Web can both use it

`DeckFlow.CLI` cannot reference `DeckFlow.Web`. The existing `NormalizeForScryfall` sits in
`DeckFlow.Web`, which is why the CLI runners each hand-rolled the identifier and both got it wrong.
Putting the helper in `DeckFlow.Core/Normalization/` — beside `CardNormalizer` — makes one
implementation reachable from every call site, and testable in `DeckFlow.Core.Tests`.

### D-03 — de-duplicate identifiers within a batch

Front-face collapse can map two distinct corpus names onto the same identifier. The batch cap is 75
identifiers, so duplicates waste slots. De-duplicate before building the request. Match-back is
unaffected (see D-04), so this is purely a request-side concern.

### D-04 — match-back needs NO change, and must be left alone

The response is matched by `CardNormalizer.Normalize(card.Name)` against
`CardNormalizer.Normalize(cardName)`. Scryfall returns the COMBINED name, and `Normalize` truncates
both the combined response name and the combined corpus name to the same front face. The keys already
align. **Do not touch the match-back loop** — changing it is how the sibling cEDH-baseline DFC bug
discarded results through a key mismatch.
