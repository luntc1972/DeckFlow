# Plan 108-01 — Server Cut Lab UI Patch Projection

<objective>
Create a shared server-side Cut Lab live-patch projection that converts authoritative C# state into the fields the live UI needs after JSON mutations.
</objective>

<threat_model>
T-108-01: Invalid or malicious serialized Cut Lab state could cause the patch builder to bypass existing API validation. Mitigation: the builder only accepts an already-deserialized `CutLabState`; controllers keep existing state parse, empty-pool, feature-flag, same-origin, and request-size gates.

T-108-02: Patch DTOs could leak unnecessary internal state or raw request payloads. Mitigation: expose only display fields required by live mutation rendering: serialized state, counts, export eligibility, proposal, floor warnings, cuts made, structural findings, data availability flags, and what-if options.
</threat_model>

<must_haves>
- The server patch derives working-list state through `CutLabWorkingList.Derive`.
- The server patch derives proposal state through `CutLabCutRoundEngine.BuildFindingsAndRoundPlan`.
- The server patch derives structural finding rows through `CutLabFindingPresenter`.
- The server patch owns `CurrentCount`, `CardsRemaining`, and `CanBuildExport`.
- The server patch owns what-if card-out/card-in option lists.
- No JavaScript helper is treated as source of truth for quantity legality, accepted cuts, or export readiness.
</must_haves>

Use server helpers equivalent to `CutLabViewModel.BuildWhatifCardOutOptions` and `BuildWhatifCardInOptions`: card-out is derived working-list cards that are not locked and not commanders, distinct case-insensitive ordered by name; card-in is accepted pool cards, distinct case-insensitive ordered by name.
