<objective>
Re-plumb `DirectPushCoordinator` to the expand→verify→contract ordering (SYNC-09 / D-06) and confirmed-stamp timing (SYNC-10 / D-07). Split `WritePublishAsync` so the content upsert no longer stamps `pushed_to_prod_utc` or flips `is_visible`; add a confirm step that issues a Studio HTTPS GET of the public Content-KB detail URL and treats HTTP 200 as "body reachable at `/app`" (D-09); only then run the stamp + visibility flip (prod-first-then-local). Set the Plan 90-03 durable awaiting-confirm marker at content-upsert time and clear it on confirm so a mid-flight push is recoverable (D-10).

Purpose: Today Stage 3 stamps + flips-visible before git even runs — the textbook contract-before-expand bug (M3/M6a). This plan moves the contract (stamp + visible) to AFTER a real deploy is confirmed reachable, using the shared body hash's render-guard for corruption and a simple 200 for reachability per D-09 (no new authenticated web endpoint).
Output: the split coordinator methods, the confirm-GET, marker set/clear wiring, HttpClient DI, and ordering tests using a stub confirm.
</objective>
