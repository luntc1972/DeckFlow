<objective>
Create the dedicated in-memory packet session cache that fronts BuildAsync for all three workflow services, AND capture the pre-phase build-warning baseline that all subsequent build gates compare against. This plan delivers ONLY the cache wrapper (the LOW-LEVEL hashing + storage primitive), the size-estimation helpers, its DI registration, and the baseline file.

Purpose: D-06 requires a DEDICATED MemoryCache instance with SizeLimit (the shared IMemoryCache singleton has no SizeLimit per CardLookupCache.cs:10's comment, so packet results would grow unbounded on Render Starter's 512MB tier).

**The architectural pivot (Codex reviews H1-H4):** Cache-key composition has been MOVED OUT OF the cache wrapper. The wrapper exposes `ComputeKey(object fieldBag)` as the low-level hashing primitive only; the per-service field-bag composition (including the same private deck-load path BuildAsync uses for D-02 normalization and the same commander-extraction logic) lives on the THREE SERVICES as `TryComputeCacheKeyAsync(...)` async helpers introduced in Plan 02. Plan 01 does NOT attempt to solve cache-key parity — it only provides the storage + hashing infrastructure.

**Codex review fixes addressed in Plan 01:**
- **M1:** Eviction PostEvictionCallback uses the EXACT D-13 contract template `"Packet cache {Outcome} for {KeyPrefix} ({SizeBytes} bytes)"`. The `reason=` suffix is REMOVED (was a template drift in iter 1).
- **M2:** Helper shape locked to ONE form: `internal static class PacketSizeEstimator` with three `EstimateSizeBytes` overloads. The "three public static methods on the cache class" alternative is REMOVED.

Output: One baseline file, one new code file (`PacketSessionCache.cs`), and one new DI registration line in `Program.cs`. Build must remain clean.
</objective>
