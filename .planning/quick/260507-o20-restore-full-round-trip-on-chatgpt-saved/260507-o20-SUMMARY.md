# Summary

## What Was Done

Added round-trip restoration of user-controlled form fields when importing a saved ChatGPT packet zip.

**New file:** `DeckFlow.Web/Services/ChatGptRequestContextParser.cs`
- `internal static partial class ChatGptRequestContextParser` with `Parse(string?)` method
- Parses the YAML-like `01-request-context.txt` export format (unindented scalars, `- item` lists, raw multi-line blocks for `strategy_notes`/`meta_notes`/`deck_source`)
- Returns `ParsedRequestContext` record with all user-controlled fields; returns `Empty` on null/whitespace input, never throws

**Modified:** `DeckFlow.Web/Services/ChatGptPacketArtifactStore.cs`
- `01-request-context.txt` added to `PacketAllowedNames` allowlist
- `LoadFromZip` now reads `requestContextText` from the entry and calls `ChatGptRequestContextParser.Parse`
- Restores: `Format`, `DeckName`, `TargetCommanderBracket`, `IncludeSideboardInAnalysis`, `IncludeMaybeboardInAnalysis`, `CardSpecificQuestionCardNames`, `BudgetUpgradeAmount`, `SelectedAnalysisQuestions`, `SelectedSetCodes`, `StrategyNotes`, `MetaNotes`, `DeckSource`
- Backwards-compatible: older zips without `01-request-context.txt` silently skip context hydration

**New test:** `DeckFlow.Web.Tests/ChatGptPacketArtifactStoreRoundTripTests.cs`
- xUnit fixture test against real Arna Kennerüd packet zip at `/tmp/arna-test/`
- Asserts all restored fields including deck text, analysis questions, set codes, bracket, booleans, strategy notes

## QA Results

- `dotnet build DeckFlow.sln`: 0 errors
- No DeckText/DeckUrl blanking lines in `LoadFromZip`
- Parser wired at line 161 of `ChatGptPacketArtifactStore.cs`
- `01-request-context.txt` in allowlist (line 19) and read (line 148)

## Decisions

- Parser returns `null` (not empty string) for absent/empty multi-line blocks so `LoadFromZip` can guard with `is not null` instead of length checks
- `DeckSource` setter routes to `DeckText` or `DeckUrl` based on `DeckInputSource` — default `PasteText` means deck content lands in `request.DeckText` as expected
- Fixture test uses hardcoded `/tmp/arna-test/` path; Dockerfile has no `dotnet test` step so CI is unaffected
