<objective>
Build the data + service layer for the Phase 25 paged harvested-decks grid AND land the cold-cache perf fix (ROADMAP Success Criteria 2 + 5). This plan adds a server-side LIMIT/OFFSET paged query with a stable two-key sort, the three missing `deck_queue` indexes (including one that covers the paged sort), parallelizes the stat queries, removes the now-orphaned top-10 grouped query from the cold path, and converts the largest-table COUNT to a schema-qualified Postgres `reltuples` estimate with a SQLite fallback. No UI changes here — those land in 25-02, which depends on the interface member created here.

Purpose: AHD-01 requires showing ALL harvested decks with server-side paging that never loads the full table into memory, and the ROADMAP perf note requires the stats payload to stop relying on serial unindexed full scans.
Output: New `HarvestedDeckRow` DTO, new `ICategoryKnowledgeStore.GetPagedProcessedDecksAsync` member + impl on ALL four implementors, the Core-side repository `GetPagedProcessedDeckRowsAsync` tuple method (defensively clamped, stably sorted), 3 indexes in `EnsureSchemaAsync`, parallelized `BuildAsync` with the orphaned top-10 query removed, schema-qualified `reltuples` fast-path for observation count, updated test fakes, and repository tests.

## Naming contract (internally consistent across 25-01 + 25-02)
- **Store interface method** (DeckFlow.Web): `GetPagedProcessedDecksAsync(int page, int pageSize, CancellationToken)` → returns `IReadOnlyList<HarvestedDeckRow>` (Web type).
- **Repository method** (DeckFlow.Core): `GetPagedProcessedDeckRowsAsync(int page, int pageSize, CancellationToken)` → returns `IReadOnlyList<(string DeckId, string? CommanderName, string InsertedUtc, string? LastCheckedUtc)>` tuples (Core-visible, no Web dependency).
- The Web store wrapper maps repository tuples → `HarvestedDeckRow`. This is the only place the two names meet.
