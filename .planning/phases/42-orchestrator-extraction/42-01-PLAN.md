Define the `DeckFlow.Core/Orchestration/` contract skeleton: the `IContentKbOrchestrator` facade composed of focused sub-interfaces (D-01), one structured result record per operation (D-02), a SYNCHRONOUS progress-sink abstraction (D-03), and an options record carrying the host-resolved artifactRoot (so the Wave 2/3 orchestrator ctor is cleanly DI-resolvable — see DI note below). DI note (closes round-2 MEDIUM "artifactRoot string ctor param is not cleanly DI-resolvable"): the artifactRoot is NOT a bare `string` ctor parameter. It is carried by a small options record `ContentKbOrchestratorOptions { required string ArtifactRoot }`. The Wave 2 orchestrator ctor will take `ContentKbOrchestratorOptions options` (instead of `string artifactRoot`), and `AddContentKbOrchestrator()` (Plan 42-03) resolves the options from DI. This avoids registering a bare global `string` in the container. Defining the options record here (contract-first) lets Plan 42-02 build against it and Plans 42-03/42-04 register/construct it.

Existing internal counts aggregators to FOLD into result records (D-02):
- DistillCounts: SourcesProcessed, VideosDistilled, VideosFiltered, DistillFailed,
  LlmCalls, LlmSpendUsd, WouldRun, ProjectedSpendUsd, FailedVideoIds (List<string>)
- HarvestCounts: Captions, Whisper, SkippedNoCaptions, WhisperFallbackRatio (double)

Core dependency note: DeckFlow.Core references Microsoft.Extensions.Logging.Abstractions
(NOT Serilog). Any optional logger parameter must be ILogger<T> defaulting to
NullLogger<T>.Instance. Live progress lines (today logger.Information / Console.WriteLine)
are surfaced via the D-03 progress sink, NOT via Serilog.

Progress-sink decision (closes review MEDIUM "Progress parity is fragile"): the abstraction
is a SYNCHRONOUS custom interface `IOrchestratorProgress { void Report(string message); }`,
NOT System.Threading.IProgress<string> (whose Progress<T> impl posts asynchronously to a
captured SynchronizationContext and would reorder the interleaved per-video CLI lines). The
CLI sink writes directly to Console.WriteLine synchronously; Studio supplies its own. This
preserves today's real-time output interleaving (parity).

artifactRoot binding (closes round-2 MEDIUM): today the CLI passes a resolved `string artifactRoot`
into the distill/harvest paths. To keep that DI-clean, the orchestrator ctor (Wave 2) consumes a
`ContentKbOrchestratorOptions { required string ArtifactRoot }` options record instead of a bare
string. Path RESOLUTION still happens host-side (CLI via ContentKbCliPaths, Studio via its data dir)
per D-06 — the options record is only the transport for the already-resolved value. Define the
record here so downstream plans (02 build against it, 03 register it, 04 construct it) share one shape.
