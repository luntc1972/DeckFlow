> Visual and interaction contract for Cut Lab navigation, pool filtering/search, section collapse,
> package help copy, and text-first card disclosures. Generated by gsd-ui-researcher, verified by

> component library, no Tailwind, no shadcn. All styling is hand-written CSS with custom properties,

## Spacing Scale

DeckFlow does not enforce a strict 8-point scale; existing Cut Lab CSS mixes `rem` values on an
approximately-4px rhythm (`0.4rem` ≈ 6.4px steps alongside `0.75rem`/`1rem`/`1.5rem`). Phase 110 new
CSS must stay inside the **existing** rhythm already used by `.manabase-anchor-nav` and
`.cutlab-sticky-bar` rather than inventing a new scale:

| Token (existing usage) | Value | Usage in this phase |
|-------|-------|-------|
| xs | `0.4rem` (6.4px) | Gap between pill nav items on narrow screens (`.manabase-anchor-nav-list` gap) |
| sm | `0.75rem`–`0.85rem` (12–13.6px) | Nav padding, chip padding, help-block padding |
| md | `1rem` (16px) | Panel-heading gaps, disclosure padding, section vertical rhythm |
| lg | `1.5rem` | Section-to-section spacing (existing `.cutlab-proposal` padding) |

Exceptions:
- The sticky jump-nav is capped at **≤4rem (64px) total height** including padding and border (D-05) —
  this is a hard ceiling, not a spacing token, driven by the existing global rule
  `h1,h2,h3,[id] { scroll-margin-top: 4rem; }` (`site-common.css:104-111`). Do not exceed it.
- Touch targets for filter/search controls and collapse triggers follow the existing 44×44px minimum
  already used on Cut Lab (`input[data-cut-lab-goal]` `min-height: 44px`, `.cutlab-sticky-bar`
  `min-height: 44px`) — not a spacing token but a hit-target floor that must be preserved on any new
  interactive control (filter buttons, search input, collapse summaries).

## Typography

Existing DeckFlow type scale (`site.css:34-39`, inherited by all themes) — reuse these tokens verbatim,
do not introduce new sizes:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / nav links / chip text | `var(--fs-sm)` = 0.85rem (13.6px) | 400 (inherit) | 1.4 (inherit body default) |
| Label (nav label, "Showing N of M", filter/search labels) | `var(--fs-xs)` = 0.85rem (13.6px), uppercase, `letter-spacing: 0.06em` | 600 semibold | 1.3 |
| Section heading (`<h2>`, `.cutlab-collapsible__summary`) | `1.2rem` (existing `.cutlab-collapsible__summary`) / `var(--fs-xl)` = 1.5rem for `<h2>` | 600 semibold | 1.2 |
| Disclosure body (oracle text, type line, mana cost) | `var(--fs-base)` = 0.95rem (15.2px) | 400 (inherit) | 1.5 |

Only **two weights** are used anywhere in this phase's new markup: 400 (body/disclosure text) and 600
(nav label, section headings, "no cards match" empty-state emphasis). Do not introduce a third weight.

## Color

DeckFlow is a themed app: 11 standalone guild-theme CSS forks each redefine these custom properties in
their own `:root`. The values below are the **Jeskai (default) theme** (`site.css:1-53`) as the
reference point — every new rule in this phase MUST reference the **token name**, never a literal hex,
so each fork resolves its own values.

| Role | Token / Jeskai value | Usage |
|------|-------|-------|
| Dominant (60%) | `--panel` (`#fafafa`) | Page background, disclosure `<details>` body |
| Secondary (30%) | `--panel-soft-bg` (`#edf3fa`) | Sticky nav background, help-block background, filter-control panel-heading area (all inherit the existing `.manabase-anchor-nav` / `panel-heading` treatment) |
| Accent (10%) | `--accent-strong` (`#1e4f82`) | Nav link text/hover-underline only, "jump to section" active affordance, filter/search focus ring (via `--focus`) |
| Destructive | `--danger` (`#c53030`) | Not used by this phase — no destructive actions exist in nav/filter/collapse/disclosure/help-copy work |

Accent reserved for (explicit list, per project's existing accent-reservation convention referenced in
the approved card-text spec §Invariants):
- Anchor-nav link text and its hover/focus underline (mirrors `.manabase-anchor-nav-list a`)
- The live match-count text is **not** accent — it is `--muted`, since it is informational, not
  actionable
- Filter/search input `:focus-visible` ring uses `--focus` (already aliased to `--accent-strong`,
  `site.css:46`) — no new focus treatment
- **Do not** apply accent to: collapse `<summary>` triggers (stay `--ink`, matching
  `.cutlab-collapsible__summary` today), disclosure `<summary>` text (stay `--ink`/`--muted`), the
  package help-block body text (stay `--muted`/`--ink`, it is static copy not a call to action)

`--theme-surface` warning: per project constraint, `--theme-surface` reads **light** in dark guild
forks — do not use it for the sticky nav or disclosure backgrounds. Use `--panel` / `--panel-soft-bg`
with the `var(--panel-soft-bg, var(--panel))` fallback chain already established by
`.manabase-anchor-nav` and `.manabase-mode-chip` (`site-common.css:2964-2976`). This sidesteps the
known dark-theme trap.

## Layout & Responsive Contract

- **Breakpoint:** reuse the existing **640px** single-column threshold already used by
  `.manabase-anchor-nav` (implied by "collapses to a single column under 640px" per CONTEXT.md D-02)
  and the existing `@media (max-width: 600px)` rules in `site-common.css`. Do not invent a new
  breakpoint for this phase; align to the nearest existing one (640px matches Manabase's anchor nav;
  600px matches the card-picker/back-to-top rules) — use **640px** for anchor-nav sticky activation
  since that is the pattern being mirrored (D-01/D-02).
- **Sticky nav placement:** top of viewport (D-06), clear of the fixed back-to-top button's
  reserved right-edge space (`site-common.css:1065-1070`, `@media (max-width: 1152px)` adds
  `padding-right: 5rem` to `.page-footer` — the anchor nav is a different fixed-position layer so this
  specific rule does not directly collide, but the executor must visually verify the stuck nav does not
  sit under/behind the back-to-top button at the same viewport width during Phase 111 screenshot review).
- **Sticky nav rendering when stuck:** horizontally scrollable single row of pills (D-07) — `overflow-x:
  auto`, `white-space: nowrap` on the list, matching chip/pill affordances already themed across all 11
  forks (reuse `kb-chip` sizing conventions, not a new pill shape).
- **Desktop:** anchor nav renders as today's `.manabase-anchor-nav`-style static wrapped list, not
  sticky (D-02).
- **Filter/search controls:** live inside the existing `panel-heading` above the "Lock your pool" table
  (D-19) — no separate sticky row, no competing with the 4rem sticky-nav budget.
- **44×44px minimum touch targets** apply to: filter option buttons/radios, search input, collapse
  `<summary>` elements, and disclosure `<summary>` triggers — consistent with the WIG convention already
  applied in Phase 101/102 and referenced by the approved card-text spec §4.

## Interaction Contract (behavioral — for planner/executor, not just visual)

These are not typical UI-SPEC "copy/color" items but are load-bearing interaction rules already locked
in CONTEXT.md; restated here because the gsd-ui-checker and gsd-ui-auditor validate against this file,
and several of Phase 110's success criteria are behavioral, not purely visual.

1. **Never detach pool rows.** Filtering/search hide via `[hidden]`/CSS class only. `getPoolRows()`
   (`cut-lab.ts:490`) and `buildSnapshotFromDom()` must keep seeing every row regardless of filter state
   (D-13).
2. **No-JS parity.** Filter/search controls are `hidden` until JS reveals them (D-14); anchor nav still
   renders and works as plain in-page `#hash` links with no-JS (native browser jump, no auto-expand,
   no focus-move — those are JS enhancements per D-04/D-12); collapsible `<details>` are natively
   functional without JS.
3. **Server-authored "safe to scroll."** Use the existing `SubmitFormId` seam from
   `_WorkflowStepTabs.cshtml:24` (`type="button"` vs `type="submit"`) — never re-derive this in
   TypeScript by probing the DOM (D-04).
4. **No filter/collapse persistence across the trust boundary that matters:** filter/search state resets
   every page load (D-15); collapse state persists in `localStorage['deckflow.cutlab.sections']`
   (D-21), scoped to the page, not to a specific deck.
5. **Status counts never reflect the filtered view** — only the new match-count text is filter-aware
   (D-18).
6. **Jump to a collapsed section auto-expands it first, then scrolls** (D-24).
7. **Fail-open on missing oracle text** — absent data renders as simply absent text, never an error,
   never a blank required field (D-31).
