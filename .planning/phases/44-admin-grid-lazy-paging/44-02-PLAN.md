## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /Admin/Harvest/commanders | Untrusted cross-origin requests may target the AJAX-only partial endpoint |
| client → page parameter | `page` query value is attacker-controllable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-csrf | Spoofing / Information Disclosure | GET /Admin/Harvest/commanders | mitigate | `SameOriginRequestValidator.IsValid(Request)` at the top of `Commanders`; cross-origin Origin/Referer → `StatusCode(403, {Message})`. Verified by `Commanders_CrossOrigin_Returns403` (SC4). NOTE: the validator returns TRUE (allow) when BOTH Origin and Referer are absent — so the realized SC4 behavior is "a CROSS-ORIGIN request (Origin: https://evil.test) returns 403", NOT "a bare direct-nav GET with no headers returns 403". The test asserts the cross-origin case, mirroring AdminContentKbControllerTests.cs:299. Do not write a no-header → 403 test; it would falsely fail. The endpoint is also behind BasicAuthMiddleware (V2). |
| T-44-page | Tampering | `page` parameter on Commanders | mitigate | `Math.Max(page, 1)` + `Math.Min(page, deckTotalPages)` clamp before any DB read (same pattern as the former Index). Prevents negative/overflow OFFSET. |
| T-44-xss | Information Disclosure (XSS) | innerHTML swap of partial HTML | accept | Response is server-rendered Razor; `HarvestedCommanderRow` fields are Razor-HTML-encoded by default; no user-controlled content is concatenated into the markup. |
| T-44-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs; RESEARCH.md Package Legitimacy Audit = N/A (zero new packages). |
</threat_model>
