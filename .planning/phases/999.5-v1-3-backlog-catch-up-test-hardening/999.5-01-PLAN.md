<design_notes>
## Deliberate Design Trade-offs

These follow CONTEXT.md decisions exactly. Document them so Codex does not second-guess the choices mid-edit.

### D-01 chooses `ClearAllPools` over `[Collection(DisableParallelization=true)]`

`Microsoft.Data.Sqlite` enables connection pooling by default; `await using` releases the connection logically but the pool retains the OS file handle until either (a) the pool drains by idle timeout, or (b) `SqliteConnection.ClearAllPools()` is called. xUnit's per-class parallelism makes (a) hit `File.Delete` before the pool drains, producing `IOException: The process cannot access the file ... because it is being used by another process`. `ClearAllPools` is the canonical .NET pattern for this exact race and is a 3-line change in `Dispose()`. `[Collection]` serialization would also fix the race but at the cost of ~10s of serialized test execution. Discretion clause (CONTEXT.md §Claude's Discretion): if `ClearAllPools` alone still flakes after Task 1 lands, fall back to `[Collection("FeedbackStoreSerial")]` — judgment per executor when running Task 1's verify gate.

### D-04 reverses the assertion direction — test was wrong, not production

`ScryfallThrottle.cs:117-122` deliberately retries 429-without-Retry-After using `FallbackRetryDelay` for Cloudflare BIC/burst recovery (intentional, comment-documented as `Returns FallbackRetryDelay when the header is missing/unparseable`). The retry loop runs `MaxRetryAttempts = 2`, so total calls = 1 initial + 2 retries = 3. The old test asserted `Assert.Equal(1, calls)` claiming the throttle should NOT retry — but production has always retried, and that behavior is the intended Cloudflare recovery contract. Renaming the test method makes the contract self-documenting; flipping the assertion encodes ground truth.

### D-06 hardcodes `3` instead of importing `ScryfallThrottle.MaxRetryAttempts`

Verified at line 33: `private const int MaxRetryAttempts = 2;` — visibility is `private`, not `internal`, so `[assembly: InternalsVisibleTo("DeckFlow.Web.Tests")]` does NOT expose it. Promoting to `internal` would be a production-source edit outside this plan's scope (P01 is test-only). Per D-06 fallback clause, hardcode `3` with a one-line comment cross-referencing `ScryfallThrottle.cs:33`. If a future plan promotes the constant to `internal`, the literal `3` can be replaced with `ScryfallThrottle.MaxRetryAttempts + 1` then.

### D-08 normalizes actual, not expected

Two options exist: (a) keep the expected literal `"Commander\n1 ..."` and call `.Replace("\r\n", "\n")` on `result.DeckAListText` before the compare, or (b) change the expected to a regex `\r?\n` pattern. Per CONTEXT.md D-08, option (a) wins — keeps the expected literal readable and matches the existing test style (no regex-shaped assertions elsewhere in this file). The service emits platform line endings on purpose via `StringBuilder.AppendLine`; changing the service to force LF is explicitly out of scope.
</design_notes>
