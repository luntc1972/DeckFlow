## Component Contract 1: Slot-Competition Groups (SLOT-01)

**Resolution of 102-RESEARCH Open Question 3 (grouped sections vs duplicated pool table):** the Phase 101 pool table **remains the single canonical lock surface**; role groups are **display-only** `<details>` sections. Rationale: multi-membership means one card can appear in several groups — duplicating lock checkboxes across groups multiplies the Pitfall 8 desync surface, whereas display-only groups have zero lock state of their own. The only interactive control per group is a bulk-lock pill that drives the canonical table checkboxes through the existing `cut-lab.ts` state path (the same mechanism "Lock all lands" already uses).

| Element | Contract |
|---------|----------|
| Container | One `<section class="result-panel">` holding eight `<details class="cutlab-role-group">` blocks, one per role, in fixed order: Lands, Ramp, Card draw, Interaction, Protection, Engines, Payoffs, Win conditions. **New CSS** (`site-common.css`): `.cutlab-role-group` — `--panel` background, `--line` border, follows `.kb-expert-accordion` summary idiom (`site-common.css:501-509`). |
| Summary row | `<summary>` shows: role display label · member count · locked-in-role count. Pattern: **"Interaction · 14 cards · 3 locked"**. Collapsed by default on ALL viewports (a 150-card pool across 8 groups is too tall open); the summary line carries the headline data so collapsed is informative. 44px min hit area. |
| Group body | `.kb-chip-area__chips` flow of `.kb-chip` per member card. Locked members get **new CSS** `.cutlab-role-chip--locked`: `border-left: 3px solid var(--accent)` (same idiom as the locked package container from 101). Commander chip additionally keeps its commander badge treatment. Chips are display-only — locking happens in the pool table above. |
| Bulk lock per group (LOCK-03 continuity) | Each group body starts with one `.manabase-pill` button: **"Lock all {role}"** — same visual/behavior contract as the shipped "Lock all lands" pill (`CutLab.cshtml:172-175`): `--panel-soft-bg` idle, `--accent` fill when every non-disabled member is locked. Clicking toggles the underlying pool-table checkboxes via `cut-lab.ts` and re-renders chips from that single source. The existing standalone "Lock all lands" toolbar pill is **superseded by** the Lands group's pill — remove the old one to avoid two controls for one action. |
| Multi-membership display | A card appearing in >1 group renders a chip in each. No "primary role" is invented — overlap is honest per Assumption A2 (payoffs/win-cons may overlap and the UI says so via the section sub-line copy). |
| Pool-table amendment | The "Type / role" column's crude `Land` text (`CutLab.cshtml:214-219`) is replaced by the card's role memberships as compact plain-text list (e.g. "Ramp · Engine"), Body size, `--muted`. The `data-cut-lab-role` attribute is upgraded from the single `land` value to a space-separated role-key list (`data-cut-lab-role="land ramp"`) — the existing `isLandRole` TS check must be updated to token matching, keeping the bulk-land-lock e2e green. |
| Role keys (stable, serialized) | `lands`, `ramp`, `draw`, `interaction`, `protection`, `engines`, `payoffs`, `wincons` — display labels map from these; keys never change (Assumption A5). |

## Component Contract 2: Structural Findings (SLOT-02)

| Element | Contract |
|---------|----------|
| Container | `<section class="result-panel">`, heading "Structural findings". Focal point of the results view is the findings summary chip in this panel's heading: `.prompt-size-note` pattern, copy **"{n} structural findings"** (or the all-clear empty-state copy). This supersedes the 101 focal point (lock count chip) once findings exist — one focal point per screen state. |
| Finding block | One block per triggered finding: **new CSS** `.cutlab-finding` — `border-left: 3px solid var(--gold-warning, var(--warning, #c8a040))`, `background: color-mix(in srgb, var(--gold-warning, var(--warning, #c8a040)) 10%, var(--panel-soft-bg, var(--panel)))` — the exact shipped advisory idiom at `site-common.css:2850-2851`. Heading at Label size/weight, lead sentence at Body, then evidence. |
| Evidence | The card list backing the finding, rendered as `.kb-chip` flow (same chips as role groups; locked members show the accent left border). Curve-congestion evidence chips append MV: "Card Name · MV 3". |
| Non-judgmental rule (binding) | No finding may rank, score, or recommend cutting a specific card. Findings state counts, shares, and floors only. Words banned from finding copy: "bad", "worse", "should cut", "weak card". ("Weak floor case" names the *floor situation*, not a card.) |
| Untriggered findings | Not rendered at all — no "passed" checklist rows. The all-clear empty state covers the zero-findings case. |
| Degraded sources | When Spellbook/category data failed open, the affected finding types render a single muted degradation line (Copywriting Contract) instead of their normal content — never a silent absence, never an error banner. |

## Component Contract 3: Role Floor Editor (FLOOR-01/02)

| Element | Contract |
|---------|----------|
| Container | `<section class="result-panel">`, heading "Role floors", followed by the responsive table below and the "Recalculate analysis" button in a `.toolbar`. |
| Layout | Reuse `table[data-prompt-cedh-reference-table]` responsive pattern (same as the lock table — proven mobile `data-label` stacked fallback, `site-common.css:1204-1230`). Columns: **Role · In pool · Floor · Source**. Eight rows in the same fixed role order as the groups. |
| "In pool" cell | Current pool count for the role with state marker per Copywriting Contract ("at floor" marker uses a **new CSS** class `.cutlab-floor-state--at` colored with the gold-warning chain; comfortable counts are plain `--muted`). Updated live by `cut-lab.ts` when locks change nothing (counts are role-fixed per POST) but floor edits change the at-floor comparison — the comparison math runs client-side, the counts themselves are server-rendered only. |
| "Floor" cell | Native `<input type="number" min="0" max="{poolCount}" step="1">`, styled by the existing `.field input` rules, 44px min hit area (admin precedent `AdminYoutubeExport/Index.cshtml:26`; no custom stepper component exists and none is introduced). Each input carries `data-cut-lab-floor="{roleKey}"`. On change, `cut-lab.ts` marks the row adjusted, updates the at-floor marker, and re-serializes `RoleFloors` into `CutLabStateJson` (extending `buildCutLabStateJson` — camelCase contract, `cut-lab-lock-interactions.test.ts` convention). Server re-clamps on POST (tamper defense — values here are UI convenience, never trusted). |
| "Source" cell | Default state: sub-label *"Default for B{bracket}: {value}"* (`--muted`, Body). User-set state: a `.kb-chip` badge **"Adjusted"** with `border-left: 3px solid var(--accent)` plus a plain text button **"Reset to default"** (44px hit area, no confirmation) that restores the derived default and clears the user-set flag. |
| Persistence semantics | Floor edits live-update the display and the hidden state JSON immediately; findings that depend on floors recompute server-side on the next POST. The "Recalculate analysis" button exists precisely to make that round-trip one tap from the floor editor. Interim staleness is acceptable and visible (the at-floor markers update live; finding blocks carry the server-rendered values). |
| Floor-break warning contract (Phase 103 handoff) | The warning *presentation* is fixed now so Phase 103 inherits it: gold-warning left-border inline block using the FLOOR-02 warning copy pattern (Copywriting Contract), rendered adjacent to whatever cut proposal triggers it. Phase 102's own "weak floor case" finding uses the same visual family, proving the idiom before 103 consumes it. |
