<objective>
Build the pure LLM distillation service: three isolated OpenAI `gpt-4o-mini` strict-`json_schema` calls per transcript (summary, clips, tags), mirroring the existing `WhisperTranscriptionService` OpenAI-client construction seam. This is greenfield over the Phase 19/20 foundation — the service writes NO database rows (Phase 20 D-11: services pure, orchestrator owns persistence). It is the first piece of the Phase 21 vertical slice that later distills one video end-to-end.

Each result carries the EXACT token usage (`InputTokens`/`OutputTokens`) read from `completion.Usage` so Plan 04 can compute real USD cost and feed `LlmSpendLedger.RecordCallAsync` — no estimation at ledger time (HIGH-1 / AI-SPEC §4 Cost Budget). The exact 2.10 SDK property path for token usage is VERIFIED against the installed package in Task 1 before the cost path is coded, so a hallucinated API fails the build (not production).

Purpose: Provide the reliable structured-extraction primitive (D-01/D-02) that the orchestrator (Plan 04) composes. Strict schema buys the <0.1% parse-failure target (PITFALLS P4 / eval E1).
Output: `ILlmDistillationService` + `LlmDistillationService` + `DistillationSchemas` + `DistillationResults` records (incl. `TokenUsage`) + a unit test exercising parse/refusal/truncation/garbage classification AND the token-usage read path.

NO new NuGet package: `OpenAI` 2.10.0 is ALREADY a `DeckFlow.Core` dependency (it powers Whisper via `AudioClient`). This plan only adds a NEW NAMESPACE USAGE `using OpenAI.Chat;` from the same assembly. Do NOT run any `dotnet add package`.
</objective>
