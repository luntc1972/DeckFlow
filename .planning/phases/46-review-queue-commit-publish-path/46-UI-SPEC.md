# Phase 46 — UI Design Contract: Review Queue + Commit-Publish Path

> Visual and interaction contract for the Review Queue and Commit-Publish pages in DeckFlow.Studio.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

This contract covers **DeckFlow.Studio** only — the standalone local Blazor Server operator tool.
It does NOT apply to the public deckflow.gg site or DeckFlow.Web.

**Audience:** single operator running Studio locally. Clarity and action-safety affordances
take priority over visual polish.

**New pages this phase:**
- `DeckFlow.Studio/Pages/Review.razor` — review queue (REVQ-02, REVQ-03)
- `DeckFlow.Studio/Pages/Publish.razor` — commit-publish path (PUB-03)

Both are added to `NavMenu.razor` below the existing "Harvest" link.

## Color

Bootstrap 5 semantic color variables. No custom hex values. Pre-populated from `45-UI-SPEC.md`
and extended with phase-specific accent reservations.

| Role | Bootstrap Var / Class | Hex Reference | Usage |
|------|----------------------|---------------|-------|
| Dominant (60%) | `--bs-body-bg` | #ffffff (light) | Page background, content area |
| Secondary (30%) | `--bs-gray-100` / `bg-light` | #f8f9fa | Cards, sidebar, diff background, table-striped rows |
| Accent (10%) | `--bs-primary` / `btn-primary` | #1b6ec2 | Approve CTA, active tab underline, diff-box border, progress spinner |
| Destructive | `--bs-danger` / `text-danger` `btn-danger` | #dc3545 | Reject button, "artifact missing" warning badge |
| Warning | `--bs-warning` / `text-warning` `bg-warning` | #ffc107 / #fff3cd | Artifact missing inline alert, re-distill warning (carried from Phase 45) |

Accent (`--bs-primary`) is reserved for:
- "Approve" per-row CTA button (`btn-outline-primary`)
- "Approve Selected" bulk action button (`btn-primary`)
- Active/selected filter tab highlight (`nav-link active`)
- Diff preview card border (`card border-primary`)
- Progress spinner during export + commit operations (`spinner-border text-primary`)

Destructive (`--bs-danger`) is reserved for:
- "Reject" per-row CTA button (`btn-outline-danger`)
- "Reject Selected" bulk action button (`btn-outline-danger`)
- "Artifact missing — cannot approve" inline badge
- Any git command failure alert (`alert alert-danger`)

## Interaction Contracts

### Review Page — Section: Filter Tabs

Four tabs rendered as Bootstrap `nav nav-tabs`:

| Tab | Filter | Default |
|-----|--------|---------|
| Pending | `approval_status = 'pending'` | Active on page load |
| Approved | `approval_status = 'approved'` | |
| Rejected | `approval_status = 'rejected'` | |
| All | No filter | |

Each tab label includes a count badge (updated on load and after any status change):
`Pending (12)` — `<span class="badge bg-secondary ms-1">12</span>` (secondary for pending count;
approved tab uses `bg-success`; rejected tab uses `bg-danger`; all tab uses `bg-secondary`).

Switching tabs clears all checkbox selections and dismisses the batch action bar.

---

### Review Page — Section: Queue Table

**Columns:** Checkbox | Title + video link | Tags | Approval badge | Actions

**Checkbox column:** Standard `<input type="checkbox">` per row. Header row has a
select-all checkbox for the current filtered view. `aria-label="Select {title}"` on each.

**Title column:** Entry title as text + external link to YouTube video
(`<a href="{url}" target="_blank" rel="noopener noreferrer">`). Max 60 chars, truncated with
CSS `text-truncate` at `max-width: 300px`.

**Tags column:** A compact summary: archetype tags + bracket tag displayed as small badges.
Use `badge bg-light text-dark border me-1` for each tag. Max 3 tags shown inline; remainder
suppressed with `+N more` label if count exceeds 3. Full tags visible in expanded row only.

**Approval badge column:** One badge per row per the Approval Status Badge Vocabulary above.
If artifact is missing, show both badges side-by-side (approval badge + `badge bg-warning text-dark` "Artifact missing").

**Actions column:** Two icon+label buttons per row:

| Button | Label | Style | Disabled When |
|--------|-------|-------|---------------|
| Approve | Approve | `btn btn-sm btn-outline-primary` | Row already `approved`; artifact missing (D-10) |
| Reject | Reject | `btn btn-sm btn-outline-danger` | Row already `rejected` |

Both buttons call `SetApprovalStatusAsync` immediately on click (D-05 — optimistic, no separate Save).
After click: badge updates in place, row tint reflects new state, button re-evaluates disabled state.

**Row tinting:**
- `approved` rows: `table-success` (light green tint)
- `rejected` rows: `table-danger` (light red tint)
- `pending` rows: no tint

**Expand column:** A toggle button at the far right: `btn btn-sm btn-link` with icon
`oi oi-chevron-bottom` (collapsed) / `oi oi-chevron-top` (expanded).
`aria-label="Expand entry for {title}"` / `aria-label="Collapse entry for {title}"`.
`aria-expanded="true|false"`.

---

### Review Page — Inline Expand Row (D-09)

When a row is expanded, a full-width `<tr>` is inserted immediately below the parent row.
It spans all columns (`colspan="8"` or column count). Background: `bg-light`.

**Expanded content sections (vertical stack, `p-3`):**

1. **Artifact content** — the full markdown artifact file at `artifact_path` rendered as
   plain text in a `<pre>` block. Style: `bg-white border rounded p-2` with
   `max-height: 400px; overflow-y: auto; font-size: 0.8125rem; font-family: monospace`.
   Label above: `<h3 class="h6 fw-semibold mb-1">Content Preview</h3>`.

2. **Full tag sets** — displayed as a definition list `<dl class="row mb-0">` with three rows:
   - Archetype tags
   - Bracket tag
   - Card-category tags
   Each `<dt>` at `col-sm-3`, `<dd>` at `col-sm-9`. Tag values rendered as individual
   `badge bg-light text-dark border me-1` badges within the `<dd>`.

3. **Missing artifact warning** (D-10) — shown instead of the artifact content block when
   `artifact_path` is missing or unreadable:
   `<div class="alert alert-warning py-2">` with icon `oi oi-warning` and copy:
   "Artifact file not found — cannot display content preview. Reject is still allowed;
   approve is disabled until the artifact is restored."

---

### Review Page — Batch Action Bar

Visible only when ≥1 checkbox is checked. Rendered as a `d-flex gap-2 align-items-center mb-3`
bar, positioned between the filter tabs and the queue table:

```
[Approve Selected (N)]  [Reject Selected (N)]  [N entries selected]
```

| Button | Style | Behavior |
|--------|-------|---------|
| Approve Selected | `btn btn-primary btn-sm` | Calls batch `SetApprovalStatusAsync` with all checked rows; disabled if all checked rows are already approved or have missing artifacts |
| Reject Selected | `btn btn-outline-danger btn-sm` | Calls batch `SetApprovalStatusAsync` with all checked rows; disabled if all checked rows are already rejected |

`(N)` in button label is the count of eligible checked rows (rows where the action would change state).

After batch operation completes: deselect all checkboxes, refresh tab counts, re-render table.

### Publish Page — Section 1: Export + Diff (D-11, D-12)

**Pre-trigger state:**

Display approved entry count above the trigger:
`<p>N entries approved and ready to commit.</p>` (loaded from `GetApprovedRowsAsync` count on page init).

If N = 0: disable the export button and show:
`<p class="text-muted">No approved entries to commit. Approve entries in the Review queue first.</p>`

**Export trigger:**

"Export & Preview Diff" (`btn btn-outline-primary`). Disabled during export/commit.
On click: runs `ExportIndexAsync` (writes seed with LF, D-13) then runs `git diff` shell-out
and in-memory key comparison (D-11).

**Loading state:** spinner + "Exporting seed and computing diff..." replaces button label.

**Diff result card** (shown after export, hidden before) — `card border-primary`:

```
card-header: "Diff Preview"
card-body:
  [Summary row]     Added: N  |  Updated: N  |  Removed: N
  [Branch display]  Committing onto branch: v1.7   ← resolved at export time
  [Seed path]       Seed: content-kb/seed/index-seed.json
  [Raw diff box]    <pre> scrollable, max-height 300px
```

Summary row uses inline `badge` per count: `badge bg-success` for Added,
`badge bg-primary` for Updated, `badge bg-danger` for Removed. Label + count always shown
even if zero (e.g., "Added: 0").

Raw diff box: `<pre class="bg-light border rounded p-2" style="max-height:300px; overflow-y:auto; font-size:0.8125rem; font-family:monospace">`. If `git diff` produces no output (no changes vs HEAD): show `<p class="text-muted">No changes vs HEAD — seed is already up to date.</p>` and disable Commit button.

**Git diff error:** `<div class="alert alert-danger py-2">` with copy:
"Could not compute git diff — {reason}. Check that Studio is running from the repo root."

### Publish Page — Section 2: Commit (D-04)

Visible only after export succeeds and diff result card is shown (rendered conditionally).

**Commit message field:**

```html
<label for="commitMsg" class="form-label fw-semibold small">Commit message</label>
<input id="commitMsg" type="text" class="form-control"
       value="content: publish approved KB seed ({N} entries)" readonly />
```

The field is pre-filled with the default and marked `readonly` — operator cannot edit it
(Claude's discretion: operator-editable message is optional; this phase uses read-only default
to keep the phase scope minimal; see 46-CONTEXT.md "Claude's Discretion").
If editability is wanted, switch to `@bind` and remove `readonly` — no other contract changes needed.

**Reviewed-diff checkbox (D-04 — required gate):**

```html
<div class="form-check mt-3">
    <input class="form-check-input" type="checkbox" id="diffReviewed" @bind="_diffReviewed" />
    <label class="form-check-label" for="diffReviewed">
        I have reviewed the diff above and want to commit these changes.
    </label>
</div>
```

Unchecked by default. Must be checked to enable the Commit button.
Re-check is reset to unchecked whenever a new export+diff is triggered.

**Commit button:**

"Commit to Branch" (`btn btn-primary`). Disabled until `_diffReviewed = true` and no operation
in flight. On click: runs `git add {seed_path} {artifact_paths...}` then `git commit -m "{message}"`.

Spinner label during commit: "Committing..." with `spinner-border spinner-border-sm text-primary`.

**Commit result:**

- Success: `<div class="alert alert-success py-2 mt-3">` with icon `oi oi-check` and copy:
  "Committed: {commit_sha_short} — {N} entries on branch {branch_name}."
  Immediately below, the post-commit push reminder (see below).
- Failure: `<div class="alert alert-danger py-2 mt-3">` with icon `oi oi-warning` and copy:
  "Commit failed — {reason}. No files were changed."

**Post-commit push reminder (D-01 — shown only on success, never auto-runs):**

```html
<div class="alert alert-info mt-3">
    <strong>Next step:</strong> push from your terminal to deploy.
    <code class="ms-2">git push origin {branch_name}</code>
    <br>
    <small class="text-muted">Render auto-deploys when push reaches main. Studio never pushes.</small>
</div>
```

### Dirty Working-Tree Handling (Claude's Discretion)

If there are staged changes in the repo that do NOT include the seed or artifact paths, the commit
scopes itself to the known paths only (`git add {seed} {artifacts...}` — no `git add -A`). This
means unrelated staged hunks are never swept in. No blocking error for dirty-but-unrelated working
tree state. If `git add` of the seed/artifact paths fails (e.g., path not found), surface the
failure as an `alert alert-danger` before attempting the commit.

## State Machine Summary

### Review.razor

```
Idle
  → [tab switch]           → FilterChanged  → Idle (table re-rendered, selections cleared)
  → [Approve row]          → ApprovingRow   → Idle (badge updated optimistically)
  → [Reject row]           → RejectingRow   → Idle (badge updated optimistically)
  → [Approve Selected]     → BatchApproving → Idle (badges updated, selections cleared)
  → [Reject Selected]      → BatchRejecting → Idle (badges updated, selections cleared)
  → [Expand row]           → Expanding      → Idle (artifact loaded once, cached in _expandCache)
  → [Collapse row]         → Idle
```

One shared `_operationInFlight` bool for batch operations only (per-row approve/reject are
fast DB writes that do not need a spinner; batch operations show a spinner on the button).

Artifact file reads are cached in a `Dictionary<string, string?>` (`_expandCache`) keyed by
natural key. Null value = file missing/unreadable (D-08: "cache the file read per expand").

### Publish.razor

```
Idle
  → [Export & Preview Diff]  → Exporting  → DiffReady (diff card shown, commit section visible)
  → [Commit to Branch]       → Committing → CommitDone (success) | CommitFailed (error shown)
```

One `_operationInFlight` bool. Export and commit cannot run simultaneously.
`_diffReviewed` is reset to false whenever a new export is triggered.
After a successful commit: disable the Commit button; require a new Export cycle to re-enable.

| Action | Risk | Confirmation |
|--------|------|-------------|

## Accessibility Notes

- All form inputs have explicit `<label for="...">` associations.
- Tab navigation via keyboard is available (Bootstrap nav-tabs are standard `<a>` elements).
- Expand/collapse toggle carries `aria-expanded` and `aria-label` reflecting current state.
- Diff `<pre>` carries `role="log" aria-live="polite"` so screen readers announce content on export.
- Spinner has `aria-label="Operation in progress"` + `role="status"`.
- Disabled buttons retain their label text (do not clear to blank when disabled).
- Badge color is never the sole differentiator — label text always accompanies color.
- Approve button's `aria-label` is overridden when disabled due to missing artifact, per
  copywriting contract ("Approve disabled — artifact file missing").
