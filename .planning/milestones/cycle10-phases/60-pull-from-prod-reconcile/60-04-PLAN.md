    0. (Read-only safety baseline — BEFORE) Using only the sanctioned read-only path (Render MCP

       b. The prod `content_site_index` SCHEMA — the FULL column definition for every column

          FROM information_schema.columns WHERE table_name = 'content_site_index'
          ORDER BY ordinal_position;`). This is the R5 schema baseline.
       c. A FULL-TABLE snapshot of every mutable column for ALL rows, keyed by id + natural key —
          NOT a sample (a 3-row sample would miss a table-wide admin rewrite, which is exactly what
          EnsureSchemaAsync's mutation surface could do). Capture for every row:
          `SELECT id, natural_key_type, natural_key_value, is_visible, is_hidden, is_evergreen,
          approval_status, pushed_to_prod_utc FROM content_site_index ORDER BY id;` (save the whole
          result set, e.g. hash it or store it, so the AFTER comparison is row-for-row).
    1. Start Studio headless: `DECKFLOW_DISABLE_AUTO_BROWSER=true`, open the "Pull from Prod" page
       from the nav.
    2. Confirm the page shows prod + SCP as "configured" (no warning banners) and the Pull button
       is enabled.
    3. Click "Pull & classify". Confirm: prod rows load, artifacts download into
       `<studio data dir>/pull-staging/` (verify the directory now holds the pulled `.md` files),

       applicable. If any entry shows "artifact not downloaded", confirm adopt-prod is still
       selectable for it (R4).
    5. Pick adopt-prod on one MissingLocally (or ProdNewer) entry and keep-local on another, then
       click "Resolve". Confirm: the adopted entry's local row now exists/updated with the prod
       content + prod approval_status, and its artifact was promoted from staging into
       `content-kb/`; the keep-local entry's local store is unchanged.
    6. (Read-only invariant — SC4 / R5, AFTER) Re-capture the SAME three measurements from step 0
       using the read-only path:
       a. ROW COUNT — confirm IDENTICAL to step-0a (no rows inserted/deleted on prod).
       b. FULL SCHEMA definition — confirm IDENTICAL to step-0b for every column (NO column/table
          added or altered; no DDL ran against prod). With R1 there is no DDL code path, so this
          must hold exactly.
       c. FULL-TABLE mutable-column snapshot — confirm IDENTICAL to step-0c row-for-row across ALL
          rows (no admin column rewritten anywhere, e.g. no table-wide approval_status/visibility
          change). This is the strong proof, not a sample.
       The pull + resolve must have written NOTHING to prod — no rows, no schema, no admin-column
       mutation on any row.
    7. Confirm no error banner exposed any host / connection string / SSH path / raw exception
