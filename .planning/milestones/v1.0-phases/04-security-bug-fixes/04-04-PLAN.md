# Phase 04-04 — BUG-02 v2: trust Render proxy network

## Root Cause

Live UAT 11-burst against deckflow.gg returned mixed pattern (6×429 + 5×401, Retry-After ascending 251→252) — proves multiple distinct partition keys for the same client. Per Render docs research: Render Starter (with persistent disk) is guaranteed single-instance, but Render's edge load balancer fronts that single instance with **multiple proxy IPs**. Each proxy IP becomes a different `Connection.RemoteIpAddress` → different bucket → fragmented throttle (~50% effective).

Phase 03 TD-04's "Path B-rawpeer" assumption that Render proxy = stable peer IP was empirically wrong. Feedback rate-limit (TD-04) is also fragmented on prod, just never load-tested past one bucket.

## Fix

Trust Render's proxy network in `ForwardedHeadersOptions.KnownNetworks`. With RFC1918 networks trusted and `ForwardLimit=1`, ASP.NET peels exactly one X-Forwarded-For hop (the entry Render's proxy appended = real client IP). Spoofed X-FF from external attacker is NOT consumed because ForwardLimit only trusts the rightmost entry, which is always written by Render's proxy.
