## Top 3 Priority Fixes

1. **Clarify the flag-off maintenance copy** — users may think all category features are offline even though Category Reference remains available — change the title/message to "AI category suggestions temporarily unavailable" and mention Category Reference remains available.
2. **Add an alternate action to the maintenance page or route-specific copy** — direct visitors to `/suggest-categories` hit a dead-end 503 — include a link to `/commander-categories` or Help in the maintenance view/model path for this gate.
3. **Improve the one-card Categories section when suggestions are hidden** — the landing page can show a sparse one-card row — either promote Category Reference to `hub-card--primary`, add short explanatory helper copy, or collapse the Categories section into a tighter single-link treatment when the flag is OFF.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

**WARNING:** The route gate copy is accurate but too broad. Both gated actions use title `Category suggestions temporarily unavailable` and message `The Categories tool is offline for maintenance. Please try again shortly.` in `DeckFlow.Web/Controllers/DeckController.cs:89` and `DeckFlow.Web/Controllers/DeckController.cs:746`. Because `Category Reference` remains intentionally visible in `DeckFlow.Web/Views/Shared/_DeckToolTabs.cshtml:51` and `DeckFlow.Web/Views/Deck/Home.cshtml:77`, "The Categories tool" can read as if the whole category area is offline. Prefer "AI category suggestions are offline for maintenance. Category Reference is still available."

**PASS:** The visible navigation/card labels are concrete and task-oriented: `AI Category Suggestions` and `Category Reference` in `DeckFlow.Web/Views/Shared/_DeckToolTabs.cshtml:49` and `:51`, mirrored on the landing page in `DeckFlow.Web/Views/Deck/Home.cshtml:73` and `:78`.

### Pillar 2: Visuals (3/4)

**WARNING:** The gated UI removes the broken entry cleanly, but the normal page offers no visible explanation when the feature is disabled. `_DeckToolTabs.cshtml:47` omits the AI suggestions link entirely and `Home.cshtml:70` omits the hub card entirely. That prevents a broken click, but users who previously used the tool get no in-context signal about why it disappeared.

**PASS:** The feature uses established hierarchy instead of inventing new visual language. Navigation entries use `.tool-nav__link` and the landing card uses `.hub-card`; these styles define clear hover/focus states and hierarchy in `DeckFlow.Web/wwwroot/css/site.css:796` and `DeckFlow.Web/wwwroot/css/site-common.css:161`.

### Pillar 3: Color (3/4)

**WARNING:** No screenshot pass was available, so theme-specific visual verification across all guild themes could not be completed. The implementation relies on existing tokenized classes, which is good, but the audit cannot prove contrast and accent balance under each theme.

**PASS:** The phase introduced no new hardcoded UI colors. The gated surfaces reuse `.tool-nav__link` and `.hub-card`, which resolve color through theme variables such as `var(--ink)`, `var(--accent)`, `var(--panel)`, and `var(--line)` in `DeckFlow.Web/wwwroot/css/site.css:799`, `:810`, and `DeckFlow.Web/wwwroot/css/site-common.css:166`.

### Pillar 4: Typography (4/4)

**PASS:** New text sits inside existing typography roles. The dropdown link uses `.tool-nav__link` with `font-size: var(--fs-base)` in `DeckFlow.Web/wwwroot/css/site.css:801`; the landing card title and description use `.hub-card__title` and `.hub-card__description` with existing `var(--fs-base)` and `var(--fs-sm)` in `DeckFlow.Web/wwwroot/css/site-common.css:181` and `:187`.

**PASS:** The maintenance state uses the shared maintenance view rather than ad hoc text styling: `DeckFlow.Web/Views/Shared/_MaintenancePage.cshtml:5`.

### Pillar 5: Spacing (3/4)

**WARNING:** When `feature.categories.enabled` is OFF, `Home.cshtml:70` removes the AI suggestions card but leaves the Categories section and grid intact with only `Category Reference`. The grid definition `repeat(auto-fill, minmax(16rem, 1fr))` in `DeckFlow.Web/wwwroot/css/site-common.css:155` is good for multiple cards, but a single remaining card may look visually underfilled on wide screens.

**PASS:** The implementation did not introduce arbitrary spacing. Dropdown spacing stays on the established `0.55rem 1rem` link padding in `DeckFlow.Web/wwwroot/css/site.css:796`, and cards keep the established `1rem 1.1rem` padding in `DeckFlow.Web/wwwroot/css/site-common.css:161`.

### Pillar 6: Experience Design (2/4)

**WARNING:** The kill-switch protects users from a broken flow but creates a dead-end for direct traffic. A user visiting `/suggest-categories` while the flag is OFF gets a generic maintenance page via `FeatureFlagGateAttribute` and `_MaintenancePage` (`DeckFlow.Web/Infrastructure/FeatureFlagGateAttribute.cs:57`, `DeckFlow.Web/Views/Shared/_MaintenancePage.cshtml:5`) with no action to browse Category Reference, go back home, or understand that only AI suggestions are disabled.

**WARNING:** The flag-off state is operationally correct but not discoverable. The nav entry and landing card are removed (`_DeckToolTabs.cshtml:47`, `Home.cshtml:70`), but no visible disabled state or explanatory copy tells returning users that this is intentional maintenance rather than a missing feature.

**PASS:** The route gate is applied to both GET and POST actions (`DeckFlow.Web/Controllers/DeckController.cs:88` and `:745`), so stale forms cannot continue into the broken backend after the visible entry points disappear.
