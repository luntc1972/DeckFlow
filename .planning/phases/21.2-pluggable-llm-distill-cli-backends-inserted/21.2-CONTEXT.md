# Phase 21.2: Pluggable LLM Distill CLI Backends - Context

**Gathered:** 2026-06-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Make the local Content KB distill step able to drive its 3 LLM extractions (summary, timestamped clips, controlled-vocab tags) through a **local AI CLI** — Claude Code (`claude`) or Codex (`codex`) — instead of the OpenAI API, selected by an env var, runnable from **WSL or Windows** shells. OpenAI API stays the **default** backend with byte-identical current behavior (no regression). This removes the OpenAI-API-billing dependency that blocked the Phase 21.1 live-UAT gate (it hit `HTTP 429 insufficient_quota` on 2026-06-01).

**In scope:** provider abstraction + factory, one CLI-backed `ILlmDistillationService` impl, cross-platform process launch + env config, best-effort-JSON parse/repair, spend-ledger bypass for subscription backends, unit tests, docs.
**Out of scope:** changing the distill prompts/schemas themselves (reuse Phase 21's), the site/index (Phase 22), Whisper transcription backend (stays OpenAI/captions per Phase 20), any Render/server change.
</domain>

<decisions>
## Implementation Decisions

### Seam placement (D-01)
- **D-01:** Add a NEW `CliLlmDistillationService` that implements `ILlmDistillationService` **directly** (SummarizeAsync / clip / tag → SummaryResult / ClipsResult / TagsResult). Do NOT refactor Phase 21's OpenAI-typed `ExtractJsonAsync` (it returns OpenAI `ChatCompletion` — not reusable). Shipped Phase 21 code stays untouched → minimal regression surface.
- **D-01a:** Extract the 3 system prompts + the 3 JSON schema strings (currently constants inside `LlmDistillationService`: `SummarySystemPrompt`, clips/tags prompts, `DistillationSchemas.*`) into a **shared static** so both the OpenAI impl and the CLI impl use **byte-identical** instructions (preserve raw-string literals exactly — invariant #9). Planner decides exact shared-type name/location; OpenAI impl must keep emitting identical bytes after extraction.

### CLI I/O contract + cross-platform launch (D-02)
- **D-02:** Prompt piped to the CLI via **stdin**; JSON read from **stdout**. `System.Diagnostics.Process` with `UseShellExecute=false`, `RedirectStandardInput/Output/Error=true`.
- **D-02a:** Per-provider **default** command, **overridable** via env: `claude` → `claude -p --output-format json` then unwrap the `.result` field (Claude Code wraps the completion text in a JSON envelope); `codex` → `codex exec` (researcher MUST confirm the exact flag for clean machine-readable output — codex emits agent chatter; check `codex exec --json`/equivalent).
- **D-02b:** Cross-platform: **auto-detect** WSL (linux `claude`/`codex` on PATH) vs Windows (`claude.cmd`/`.exe`); **explicit env wins** when set. Env surface: `DECKFLOW_LLM_CLI_COMMAND` (+ args template) overrides the resolved default. Document BOTH a WSL invocation and a Windows invocation.
- **D-02c:** WSL→Windows env note (learned this session, see canonical ref): when the .NET distill host is itself launched via Windows `dotnet.exe` from WSL, the `claude`/`codex` it should spawn must be reachable from that process. The CLI child inherits the .NET host's env/PATH — document which `claude` (linux vs Windows) the operator's chosen launch resolves to.

### JSON-repair / retry (D-03)
- **D-03:** Inject the JSON schema text into the prompt as explicit instructions (CLIs have NO Structured-Outputs guarantee). On each response: fence-strip (```json fences) → unwrap result-envelope → brace-match (first `{` … last `}`) → deserialize → **shape-validate** (required fields present; tags within `ContentTagVocabulary`; summary ≤200 words — reuse Phase 21 validators).
- **D-03a:** Retry **×2** on parse-or-shape failure (3 attempts total per extraction). Final failure → mark the video `failed` (re-attemptable, non-terminal — matches Phase 21 staged-pipeline so a re-run retries only failed videos). Do NOT abort the whole run on a single video failure.

### Ledger / cost handling (D-04)
- **D-04:** When `provider != openai`: **bypass** the `LlmSpendLedger.WouldExceedCapAsync` cap-gate and token-pricing entirely (subscription = no per-token cost). `DECKFLOW_LLM_MONTHLY_CAP_USD` governs the **openai** backend only.
- **D-04a:** Still write the run record with `spend_usd=0` and the LLM **call-count** for observability. NOTE: Phase 21's run record already overloads `whisper_calls` = LLM calls (`content_harvest_runs`, see CommandRunners.cs ~L641 comment) — reuse that overloaded field, **no schema change** needed.
- **D-04b:** `--dry-run` for a CLI backend reports `N videos would distill ($0, subscription)` — no cap math.

### Provider switch (carried, locked)
- Env var `DECKFLOW_LLM_PROVIDER` = `openai` (default/unset) | `claude` | `codex`. Factory mirrors `TranscriptProviderFactory` exactly: `public static class LlmDistillationProviderFactory` with `Resolve(string? envValue, HttpClient httpClient)`, default branch = OpenAI, unsupported value → `NotSupportedException` listing supported values. Wire into `CommandRunners.RunDistillAsync` where `new LlmDistillationService(llmHttpClient)` is constructed (CommandRunners.cs ~L483).

### Claude's Discretion
- Exact shared-prompts type name + namespace (Core/Integration).
- Process timeout per CLI call (suggest generous — CLI sessions are slow; align with the existing 15-min HttpClient timeout intent).
- Whether the args template uses a placeholder token or stdin-only (stdin preferred per D-02).
</decisions>

## Existing Code Insights

### Reusable Assets
- `ILlmDistillationService` interface — the seam; CLI impl implements it directly (D-01).
- Phase 21 prompts + `DistillationSchemas` + `ContentTagVocabulary` + `ValidateSummary` — reused verbatim (shared static + validation in D-01a/D-03).
- `TranscriptProviderFactory` — copy-paste shape for `LlmDistillationProviderFactory`.
- Run-record `whisper_calls` overload = LLM calls (no new column for call-count).

### Established Patterns
- Env-var provider switch with default + `NotSupportedException` (Core, no DI container in CLI path — `CommandRunners` news up services directly).
- Test seam: services expose an `internal` ctor taking a delegate so tests bypass real I/O (mirror for CLI: inject a `Func<...>` process-runner so tests feed canned stdout — D-06 below). `[InternalsVisibleTo]` already grants Core.Tests/Web.Tests.
- Core has NO AspNet/HttpClient-new; CLI backend uses `System.Diagnostics.Process` (allowed — not HTTP).

### Integration Points
- `CommandRunners.RunDistillAsync` construction site (swap `new LlmDistillationService(...)` for `LlmDistillationProviderFactory.Resolve(...)`).
- Ledger cap-gate call inside the distill loop (guard with provider check).
</code_context>

## Specific Ideas

- Default behavior MUST be byte-identical to shipped Phase 21 when `DECKFLOW_LLM_PROVIDER` is unset (regression guard via existing distill tests).
- The CLI-backed live distill over `artifacts/uat-content-kb.db` (10 videos) is the acceptance run that ALSO clears the Phase 21.1 gate (SC5) — E5/E6 human sample (archetype/bracket plausibility, thesis coherence).
- Tests use a fake process-runner seam (canned stdout: clean JSON, fenced JSON, enveloped JSON, garbage→retry, persistent-fail→mark-failed) — NO real `claude`/`codex` spawned in tests (D-06).
