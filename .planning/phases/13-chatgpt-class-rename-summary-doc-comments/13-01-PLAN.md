Tone rules (extracted from analogs):
- ONE sentence per `<summary>`. Active voice. Verb-first or noun-phrase first.
- View-model class summary: "Represents the results of ..."
- Request DTO class summary: "Form-bound request DTO for the ... page" or "Request payload for ..."
- Response class summary: "Top-level JSON shape returned by the ... prompt"
- Nested response shape class summary: "A single ... from ..." or "Pair of ... for a single ..."
- Property summaries on view models start with "Gets" (init-only setters).
- Property summaries on request DTOs describe the field's effect ("Chooses ...", "Describes ...", "Holds ...").
- "ChatGPT" as a narrative word inside `<summary>` is PERMITTED per D-07 #5 (e.g., "Parses the ChatGPT-returned JSON payload into ...").
- NEVER write "TODO add summary" or vague generic placeholders.
