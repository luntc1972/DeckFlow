# 70-02 — MQ-02: Model per-source mana QUANTITY

**Finding:** Audit #1 (High, broad — biggest accuracy win). Verified in code.
**Risk:** **HIGH.** **Blast radius:** every deck's cast% (shifts UP); deficits/verdict can move.
**Prereq note:** CONTEXT lists 70-03 (MQ-03) as sharing the "modeled mana path"; this plan ships
the amount model first because MQ-03's ritual/Treasure credit reuses the same `ManaAmount` field.

## Problem
Every mana source is modeled as exactly **1 mana**. Sol Ring / Mana Vault = +1 (should be +2),
Ancient Tomb = 1 (should be 2 — and it is a **land** source), Gilded Lotus = 1 (should be 3). The
affordability is `availableNow = onlineLandMasks.Count + onlineRamp.Count` (`CastabilitySimulator.cs:442`)
and the color-coverage list `availableColors` (`:464-466`) holds exactly **one mask per source**.
Output is systematically **pessimistic** on burst-mana decks — the decks where quantity matters most.

## Payment model (REPLACES the naive "duplicate the mask N times" — Codex BLOCKER)
Duplicating a multi-color mask N times is **wrong**: `ColorsCoverable` (`CastabilitySimulator.cs:636`)
treats each mask copy as independently flexible, so a 3-mana 5-color Gilded Lotus could illegally pay
`{U}{B}{R}`. Real rule: a multi-mana source produces N mana **of a single decision**, not N
independent any-color units. Model each source as `(mask, ManaAmount)` where one source pays **up to
`ManaAmount` pips, but all of the SAME color choice** (or generic/colorless). Implement the color
check as a small bounded assignment/flow: each online source has capacity `ManaAmount`, an edge to a
pip-color only if its mask includes that color, and one source may fill multiple pips **only of one
color it actually produces**. For the *count* check, `availableNow` sums `ManaAmount` over online
sources. Colorless/generic sources (Sol Ring=2, Ancient Tomb=2, Mana Vault=2) carry an empty/colorless
mask and only pay generic. A negative test MUST prove Lotus cannot pay mixed-color pips.

## Locked decision (from CONTEXT + Codex review)
- **Color-SOURCE counting stays Karsten-correct: a 2-mana rock is still ONE source of its color.**
  `ManaAmount` feeds ONLY the sim's quantity/affordability/curve side. It MUST NOT touch
  `EffectiveSources`, `SimRequiredSources`, per-color deficit, or `ColorFindings`. (Codex rejected
  re-basing the verdict on mana-weighted color counts.)
- **Ship behind a flag.** New flag `manabase.source-mana-quantity` (FeatureFlagStore seed). Default
  decided AFTER the baseline diff: ON if the verdict shift is small/justified, OFF (opt-in) if large.
  **Read the flag ONCE in the caller (`ManabaseAnalyzer`) and pass an explicit `bool useManaQuantity`
  into `CastabilitySimulator.Simulate`/`BuildLibrary`** — do NOT read an ambient flag inside the
  simulator. `Simulate` stays pure from its arguments (`CastabilitySimulator.cs:112`), so the
  flag-OFF byte-identical proof and the ON-vs-OFF A/B tests stay clean. (Codex MED.)

## Side-Effects Report
**Files (direct):**
- `DeckFlow.Core/Manabase/ManabaseModels.cs` — `ManaSource` gains `int ManaAmount { get; init; } = 1`;
  `LibraryCard` gains an amount field (currently `(CardKind, mask, deployCost, isPartial)`-shaped).
- `DeckFlow.Core/Manabase/CastabilitySimulator.cs` — `AddSourcesAsCards`/`AddWeighted` thread amount
  onto `LibraryCard`; `SimulateGame` accounting (`onlineRamp`, `onlineLandMasks`, `availableColors`)
  contributes `amount` per source instead of 1.
- `DeckFlow.Core/Manabase/ManabaseClassifier.cs` — set `ManaAmount` on **both** paths: non-land
  sources (`:342`, `AddPartialSources`/`AddGrantedSources`) AND the **land** path
  (`AddLandCopies` ~`:204`) — Ancient Tomb / Sanctum of Eternity etc. are lands that make 2 (Codex
  HIGH; "lands = 1" was wrong). Conditional/granted sources (`IsConditional`, the 0.25 Bernoulli
  any-color sources) are **forced to `ManaAmount = 1`** — the Bernoulli roll gates a single unit and
  bundle semantics are out of scope (Codex MED). Assert this with a test.
- Amount capture chain: `CardFact` (add amount field), `ScryfallCardData`, `ScryfallCardFactMapper`
  (parse `Add {C}{C}` / "Add three mana" / `{R}{R}{R}` from oracle; default 1 when unparseable).

**Files (transitive):** `ManabaseAnalyzer.cs` (passes `deck.Sources` through — no logic change, verify
no double-count); display/views unchanged (composition breakdown reads color counts, not amount).

**Shared state:** none. **External surfaces:** none (Scryfall oracle already fetched; parse only).
**Contract:** `ManaSource`/`LibraryCard`/`CardFact` gain optional fields, default 1 → additive, no
serialization break (respects `{ get; init; }` carve-out). **Perf:** online sources stay one entry
each, now carrying a `(mask, amount)` capacity record (NOT duplicated masks); the color check is a
small bounded assignment over ≤ deck-size sources — negligible; prefix-shuffle/loops unchanged.

**Backward-compat risk:** flag-OFF path MUST be byte-identical to today (amount forced to 1). The
flag is the rollback switch.

## Steps (layered)
1. **Capture amount.** Add `int ManaAmount { get; init; } = 1` to `CardFact` (mana-source cards).
   In `ScryfallCardFactMapper`, parse the produced amount from oracle text: count repeated mana
   symbols (`{C}{C}`, `{R}{R}{R}`), "Add two/three mana", "{2}", etc.; **default 1** on no match.
   Scaling sources (Coffers/Nykthos/Cradle) stay 1 in this plan — note as deferred, do not guess.
2. **Carry through the model.** `ManabaseClassifier` sets `ManaAmount = card.ManaAmount` on **both**
   the non-land source paths AND the land path (`AddLandCopies`) so Ancient Tomb = 2.
   Conditional/granted sources forced to 1. `BuildLibrary`/`AddWeighted` put the amount on `LibraryCard`.
3. **Sim accounting (the hard part).** `BuildLibrary`/`Simulate` take an explicit `bool
   useManaQuantity` (snapshotted by the caller). When ON, each online source carries
   `(mask, ManaAmount)`: `availableNow` sums `ManaAmount`; the color check becomes the bounded
   single-color assignment from the Payment model above (one source fills up to `ManaAmount` pips of
   **one** color it produces, or generic). When OFF, every source is amount 1 → **byte-identical to
   today**. `TryDeployRamp`'s "stop once we can make the cost" stays — it just reaches cost faster.
4. **Karsten basis guard.** Add an assertion/test that `EffectiveSources`, `SimRequiredSources`, and
   per-color deficit are identical flag-ON vs flag-OFF (amount must not leak into color counts).

## Tests (Core, xUnit — `ManabaseAnalyzerTests` / new `ManaQuantityTests`)
- `SolRing_PaysTwoColorless_TwoDropCastableTurnOne`: turn-0 Sol Ring → a 2-drop castable turn 1.
- `AncientTomb_LandCountsTwoColorless`: 4-drop turn-2 off Ancient Tomb (a **land**) + 2 lands —
  proves the land path carries amount (Codex HIGH).
- `GildedLotus_PaysThreeOfOneChosenColor`: a 3-mana source covers three pips of a SINGLE color.
- **`GildedLotus_CannotPayThreeDifferentColoredPips`** (negative): Lotus must NOT satisfy `{U}{B}{R}`
  — locks the Payment model against the duplicate-mask BLOCKER (Codex BLOCKER).
- **`AnyColorTwoManaSource_CannotSplitAcrossTwoColors`** (negative) unless the oracle truly allows it.
- `MultiManaRock_AffordabilityScales`: cast% rises flag-ON vs OFF for a burst-mana deck.
- `Flag_Off_IsByteIdenticalToBaseline`: cast% + verdict identical to pre-MQ-02 for a normal 2-color deck.
- `ColorCounts_Invariant_ToManaAmount`: `EffectiveSources`/`SimRequiredSources`/deficit unchanged ON vs OFF.
- `ConditionalGrantedSource_StaysAmountOne`: an `IsConditional` source keeps amount 1 (Codex MED).
- Regression: existing manabase suite stays green.
