<objective>
Wire the staleness evaluator into the Deck Primer request DTO, view model, controller, and zip round-trip — with the **resume-without-rebuild** flow as the real, reachable activation path. All behind `tool.primer.stale-flag`, byte-identical when OFF (pages AND zips).

Purpose: Make a user actually able to SEE the banner. Every rebuilding render path (generate, today's upload) produces a fresh hash by construction, so the banner can only surface when an OLD primer and a CHANGED current deck coexist in one render. That render is the upload/resume path rewritten to NOT call `BuildAsync`: it restores the generation-time hash + deck snapshot + the old primer text from the zip, renders the old primer verbatim, and compares the restored hash against the deck the user currently has in Step 1 — with NO upstream re-fetch (PRIMER-03, locked decision #1). The in-session hidden `GeneratedPrimerHash` field is retained as mechanism plumbing (re-arms on generate, mirrors phase-77 `ScoreJson`) but is honestly NOT the live trigger.

Output: `GeneratedPrimerHash` on the request; `IsStale` / `ChangedCardCount` / `GeneratedPrimerHash` / `StaleDetectionEnabled` on the view model; a `PrimerZipRestore` record returned by `LoadPrimerFromZip`; `02-primer-deck-hash.txt` persisted by `BuildPrimerZip`; controller wiring (re-arm on generate, persist on download, resume-without-rebuild on upload); a controller-level test suite that drives a REAL generate→download→upload sequence to `IsStale=true`.
</objective>
