### Phase 87: Creator-Source Model Hardening
**Goal**: Link the two Studio content-KB creator tables (`creator_sources` curated list ↔ `content_sources` KB source) that currently drift — so adding a creator and harvesting it yields one consistent, slug-owning, linked record, and removing a creator disables its KB source without orphaning artifacts.
**Depends on**: Nothing structurally — Studio-local `content-kb.db` + harvest pipeline only, disjoint from the web/theme surface of Phases 84-86; sequenced last so it never blocks the visual work.
**Requirements**: CREATOR-01, CREATOR-02, CREATOR-03, CREATOR-04
**Success Criteria** (what must be TRUE):
  1. Adding a creator on `/creators` and later harvesting it links `creator_sources`↔`content_sources` by a persisted `content_source_id` (single idempotent update keyed by creator id), with provenance carried on the browsed videos and a browse-time match guard preventing edit-after-select mislinks.
  2. An existing-but-disabled same-URL content source is detected and re-enabled on both the `AddSourceAsync` unique-violation path and `EnsureYoutubeSourceAsync`, returning the persisted canonical slug.
  3. `/creators` shows each creator's slug + existence-aware link status; Remove disables the linked content source (never deletes KB artifacts) and notes remaining on-disk files.
  4. `creator_sources` migrates additively/idempotently; an existing `content-kb.db` upgrades cleanly; build stays clean and `DeckFlow.Core.Tests` + `DeckFlow.Studio.Tests` (incl. the four provenance/dedupe failure-mode cases) pass.
**Plans**: TBD (converged v3 design already Codex-cleared across 4 plan-review rounds — see `project_creator_model_hardening_plan` memory + session `scratchpad/PLAN-creator-hardening.md`)
**Cross-cutting gate**: trivially held — no paste artifact or theme surface touched (Studio operator tool only).
