# Phase 56 — UI Design Contract

> Visual and interaction contract for Studio Surfaces. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>
> **Important scope note:** DeckFlow.Studio is a standalone Blazor Server app that uses
> Bootstrap 5 utility classes only. There is no shadcn, no Tailwind, no custom token
> system, and no shared CSS with DeckFlow.Web. All design decisions are expressed as
> Bootstrap class names. The design system here is the LOCKED EXISTING baseline read from
> source — not a proposal.

## Spacing Scale

Bootstrap 5's built-in spacing scale (`0`–`5`, maps to 0/4/8/16/24/48 px at default rem).
Phase 56 must use only Bootstrap spacing utilities — no hand-rolled `style="margin:..."` values.

| Bootstrap class | Value | Usage in Studio |
|-----------------|-------|-----------------|
| `gap-1` / `me-1` / `ms-1` | 4px | Badge gap in multi-badge cells, icon-to-label inline gap |
| `py-2` / `mb-2` | 8px | Alert padding, small element spacing |
| `mt-3` / `mb-3` / `px-3` | 16px | Section spacing, card-body padding, nav item padding |
| `mt-4` | 24px | Card-to-card spacing (e.g. Harvest page sections) |
| `px-4` | 24px | `<article class="content px-4">` — established page horizontal padding |
| `p-3` | 16px | Expand rows, inline detail panels |

Exceptions: touch-target minimum for icon-only buttons is `btn btn-sm` (Bootstrap default
36px height) — no additional padding override needed for this phase.

## Typography

All sizes are Bootstrap defaults on Helvetica Neue / Helvetica / Arial.

| Role | Bootstrap class | Approx size | Weight | Line Height | Usage |
|------|----------------|-------------|--------|-------------|-------|
| Page heading | `h1` + `h4 fw-semibold` | ~21px | 600 | 1.2 | Every page title (e.g. "Harvest + Distill") |
| Section heading | `h2` + `h5 fw-semibold mb-0` | ~18px | 600 | 1.2 | Card header titles (e.g. "Browse Channel or Playlist") |
| Sub-heading | `h3` + `h6 fw-semibold` | ~16px | 600 | 1.2 | Expand-row detail header (e.g. "Content Preview") |
| Body / table cell | implicit (`p`, `td`) | 16px | 400 | 1.5 | General prose and table data |
| Small / muted | `text-muted small` | ~14px | 400 | 1.5 | Hints, empty states, secondary labels |
| Code / monospace | `font-family:monospace` (inline style) | `0.875rem` (~14px) | 400 | 1.5 | Diff preview, artifact preview `<pre>` |

| Form label | `form-label fw-semibold small` | ~14px | 600 | 1.5 | Input labels above `<input>`/`<textarea>` |

**Rule:** Phase 56 uses the same heading + body pattern as every existing page. No new font
sizes or weights are introduced.

## Status Badge Vocabulary

### VideoStatus Badge (channel-browse, BROWSE-02)

Used in `Harvest.razor`'s channel table and paste-queue table. Extended in Phase 56 with
two new states. All six states MUST include a text label (color is never the sole differentiator).

| VideoStatus | Bootstrap classes | Label text | Visual meaning |
|-------------|-------------------|------------|----------------|
| `NotHarvested` | `badge bg-secondary` | `Not harvested` | Neutral — no action taken |
| `Harvested` | `badge bg-info text-dark` | `Harvested` | Info — transcript captured, not yet distilled |
| `Distilled` | `badge bg-success` | `Distilled` | In KB, pending review |
| **`Approved`** (NEW) | `badge bg-primary` | `Approved` | In KB, approved, not yet pushed to prod |
| **`Published`** (NEW) | `badge bg-success text-white` + `oi oi-check` prefix | `Published` | Pushed to prod AND visible — highest-value state |
| `Blocked` | `badge bg-danger` | `Blocked` | Suppressed — will not be re-harvested |
| `Duplicate` (queue only) | `badge bg-warning text-dark` | `Already in DB` | Already exists in local KB |

**`Published` vs `Distilled` differentiation:** Both use `bg-success`. `Published` MUST include
a leading checkmark icon (`<span class="oi oi-check me-1" aria-hidden="true"></span>`) and the
explicit `text-white` class to visually distinguish it from `Distilled`. The text label "Published"
(not "Distilled") is always present.

**Semantics for pushed-but-hidden entries (open question resolved):**
A video with `pushed_to_prod_utc != null` but `is_visible = false` maps to `VideoStatus.Approved`
in the channel-browse badge (the operator considers it "still in limbo" until the admin makes it
visible). This mirrors the `PublishState.PushedHidden` logic in the Review/Publish pages and keeps
the two enums consistent in intent. Document this accepted semantic in the plan.

**Row highlight for new states:** Rows with `Approved` or `Published` status get NO additional
row-level `table-*` class (only the badge differentiates them). This keeps the channel-browse
table visually clean and consistent with the existing pattern where only `Harvested`/`Distilled`
get `table-secondary` highlighting.

### PublishState Display (Review + Publish pages, PUB-03)

Used as an additional column on Review.razor and Publish.razor. Rendered as a `<span class="badge ...">`.
The column header is `Publish State`. Placed immediately after the existing `Status` column.

| PublishState | Bootstrap classes | Label text |
|--------------|-------------------|------------|
| `NeverPublished` | `badge bg-secondary` | `Never published` |
| `PushedHidden` | `badge bg-warning text-dark` | `Pushed-hidden` |
| `Published` | `badge bg-success text-white` + `oi oi-check` prefix | `Published` |
| `LocalNewer` | `badge bg-info text-dark` | `Local-newer` |

**Source:** `PublishState.ToDisplayString()` already returns these exact strings (Phase 55).
The Razor badge rendering wraps the display string in the appropriate classes above.

## Surface Contracts

### 1. Channel Browse Status Badge (BROWSE-02)

**Location:** `Harvest.razor` — channel-browse table column "Status" (existing `<th>Status</th>`).

**Current behavior:** `RenderBadge(vm.Status)` switch in `Harvest.razor:1450` handles 5 states.

**Change:** Add two new `switch` arms to `RenderBadge`:
```
VideoStatus.Approved  => <span class="badge bg-primary">Approved</span>
VideoStatus.Published => <span class="badge bg-success text-white"><span class="oi oi-check me-1" aria-hidden="true"></span>Published</span>
```

Remove the `_` default arm and replace with an exhaustive `VideoStatus.Duplicate` + named fallback
pattern to catch future missing cases at compile time (Pitfall 5 from RESEARCH.md).

**Accessibility:** Both new badge labels are always visible text. No tooltip or additional ARIA
needed beyond the existing `aria-label` on the row checkbox.

### 2. Multi-select + Selective Harvest (BROWSE-01/03)

**Existing interaction (document, do not change):**

- Channel-browse table has a "select all" header checkbox (`ToggleAllChannelSelections`) and
  per-row checkboxes (`vm.Selected = !vm.Selected`). Both lists (channel + paste queue) feed
  `GetAllSelectedVideos()` → `HarvestSelectedAsync`.
- "Harvest Selected" button triggers `HarvestSelectedAsync`; disabled when `_operationInFlight`.
- Badge refreshes post-harvest via `RefreshBadgesAsync(harvestedIds)`.

**No layout change required.** The only addition is the two new badge states above.

### 3. Block Action per Row (REM-01)

**Location:** `Harvest.razor` — channel-browse table row, new action cell.

**Placement:** Add a new `<th scope="col" style="width:80px">Actions</th>` column to the
channel-browse table (rightmost, after "Status"). Per-row: a single `btn btn-sm btn-outline-danger`
labeled "Block Video".

**Button spec:**
```html
<button class="btn btn-sm btn-outline-danger"
        @onclick="() => PromptBlockAsync(vm.VideoId, vm.Title)"
        disabled="@(_operationInFlight || vm.Status == VideoStatus.Blocked)"
        aria-label="Block @vm.Title">
    Block Video
</button>
```

Disabled when `vm.Status == VideoStatus.Blocked` (already blocked — idempotent guard) or when
an operation is in flight.

**Confirmation interaction (destructive action):**

Block hard-deletes KB artifacts. A confirmation step is required.

Pattern: **inline confirmation within the row** (not a modal, to stay consistent with the
existing Studio pattern of inline state rather than overlays). On first click:
1. Row enters a "pending confirmation" UI state (`vm.PendingBlock = true`).
2. The Block Video button is replaced by two inline buttons:
   - `btn btn-sm btn-danger` labeled "Confirm Block" (executes `BlockVideoAsync`)
   - `btn btn-sm btn-outline-secondary ms-1` labeled "Keep Video" (resets `vm.PendingBlock = false`)
3. A `<span class="text-danger small ms-2">This will delete KB artifacts.</span>` warning appears inline.

This avoids focus-trap modal complexity, matches the page's existing no-modal pattern, and
keeps the confirmation in visual proximity to the data being acted on.

**Post-block behavior:** `RefreshBadgesAsync(new[] { videoId })` is called on success; the row
badge updates to `Blocked` and the Block Video button disables. No page reload required.

**Accessibility:** Confirm button is `btn-danger` (explicit destructive styling). The warning text
is always visible (not tooltip-only). Keyboard tab order: Block Video → [confirm flow] → Keep Video.

### 4. Blocked Videos List Page (REM-02)

**Route:** `/blocked`

**File:** `DeckFlow.Studio/Pages/Blocked.razor`

**Visuals:** The `<h1 class="h4 fw-semibold">Blocked Videos</h1>` heading is the page's primary
visual anchor and the first element the operator reads on arrival.

**Page title / heading:**
- `<PageTitle>Blocked Videos</PageTitle>`
- `<h1 class="h4 fw-semibold">Blocked Videos</h1>`
- `<p class="text-muted">Videos blocked from harvest. Unblock to allow re-harvest.</p>`

**Layout structure:** Matches `Review.razor` exactly — `<article class="content px-4">` wrapper,
`table-responsive` → `table table-sm table-hover align-middle`, `thead class="table-light"`.

**Table columns:**

| Column | Width | Content |
|--------|-------|---------|
| Video ID | auto | `<a href="https://youtu.be/{id}" target="_blank" rel="noopener noreferrer">@video.YoutubeVideoId</a>` |
| Blocked at | 140px | `@video.BlockedUtc.ToString("yyyy-MM-dd HH:mm")` UTC |
| Reason | auto | `@(video.Reason ?? "—")` |
| Actions | 90px | Unblock Video button (see below) |

**Unblock Video button spec (NOT destructive — no confirmation required):**
```html
<button class="btn btn-sm btn-outline-secondary"
        @onclick="() => UnblockAsync(video.YoutubeVideoId)"
        disabled="@_operationInFlight"
        aria-label="Unblock @video.YoutubeVideoId">
    Unblock Video
</button>
```

`btn-outline-secondary` (not `btn-outline-danger`) — unblocking is a recovery action, not a
destructive one.

**Empty state:**
- Heading: none (no h2 for empty state — just inline paragraph)
- Copy: `<p class="text-muted mt-3">No blocked videos. Block videos from the Harvest page to prevent re-harvest.</p>`

**Loading state:** Same spinner pattern as Review.razor:
```html
<div class="d-flex align-items-center gap-2 mt-3">
    <span class="spinner-border spinner-border-sm text-primary" role="status" aria-label="Operation in progress">
        <span class="visually-hidden">Loading...</span>
    </span>
    <span class="text-muted">Loading blocked videos...</span>
</div>
```

**Error state:** `<div class="alert alert-danger py-2 mt-3">Could not load blocked videos — @_loadError</div>`

**Post-unblock behavior:** remove the row from `_blocked` list in-memory and call `StateHasChanged()`.
No full page reload required.

**NavMenu entry:** Add to `Shared/NavMenu.razor` after "Direct Push":
```html
<div class="nav-item px-3">
    <NavLink class="nav-link" href="blocked">
        <span class="oi oi-ban" aria-hidden="true"></span> Blocked
    </NavLink>
</div>
```

Icon: `oi-ban` (prohibition/block symbol from Open Iconic, already in the icon set).

### 5. Add Single Video by URL/ID (ADD-01)

**Existing interaction (fully functional — confirm only):**

The "URL / ID Paste Queue" section in `Harvest.razor` (Section 2) already handles single
YouTube URLs. One URL pasted into the textarea → `AddToQueueAsync` → `GetByIdsAsync([id])` →
video appears in the queue with its badge → operator checks the box → "Harvest Selected".

**Gap found in RESEARCH.md (section 9):** When `GetByIdsAsync` fails for a private/unlisted
video, the queue table stays empty with no explicit "not found" message. The operator sees a
silent non-response.

**Polish required:** Add an inline "0 videos resolved" feedback message after `AddToQueueAsync`
completes when the input was non-empty but `_queueVideos` gained zero new entries:

```html
@if (_addToQueueDone && _lastAddCount == 0 && !string.IsNullOrWhiteSpace(_pasteQueueText))
{
    <div class="alert alert-warning py-2 mt-2">
        No videos found for the pasted input. The video may be private, unlisted, or the URL may be invalid.
    </div>
}
```

`_addToQueueDone` and `_lastAddCount` are new private state fields (bool + int).

**No other UI change.** Single-URL + multi-URL paste already both work. No new section or
control is needed.

### 6. Publish-State Column (PUB-03)

**Surfaces:** `Review.razor` and `Publish.razor`. Both get an identical new `Publish State` column.

**Review.razor change:**

Add to `thead`:
```html
<th scope="col">Publish State</th>
```
Placed after the existing `Status` column, before the `Actions` column.

Add to each `<tbody>` row:
```html
<td>@RenderPublishStateBadge(Deriver.Derive(vm.PushedToProdUtc, vm.IsVisible, vm.IndexedUtc))</td>
```

`ReviewViewModel` needs three new properties populated from `ContentSiteIndexRow`:
- `DateTimeOffset? PushedToProdUtc` (from `row.PushedToProdUtc`)
- `bool IsVisible` (from `row.IsVisible`)
- `DateTimeOffset IndexedUtc` (from `row.IndexedUtc`)

New `RenderPublishStateBadge` static method (same file):
```csharp
private static RenderFragment RenderPublishStateBadge(PublishState state) => state switch
{
    PublishState.NeverPublished => @<span class="badge bg-secondary">Never published</span>,
    PublishState.PushedHidden   => @<span class="badge bg-warning text-dark">Pushed-hidden</span>,
    PublishState.Published      => @<span class="badge bg-success text-white"><span class="oi oi-check me-1" aria-hidden="true"></span>Published</span>,
    PublishState.LocalNewer     => @<span class="badge bg-info text-dark">Local-newer</span>,
    _                           => @<span class="badge bg-secondary">Unknown</span>,
};
```

**Publish.razor change:**

The Publish page shows a summary count (`_approvedCount`) and a two-stage export/commit flow
with no per-entry table in the current markup. The PUB-03 contract for Publish.razor is to
add a summary indicator showing how many approved entries are in each publish state, displayed
after the `_approvedCount` paragraph:

```html
@if (_publishStateSummary.Count > 0)
{
    <div class="d-flex gap-2 flex-wrap mb-2">
        @foreach (var (state, count) in _publishStateSummary)
        {
            <span>@RenderPublishStateBadge(state) <span class="text-muted small">@count</span></span>
        }
    </div>
}
```

`_publishStateSummary` is a `List<(PublishState, int)>` computed during `OnInitializedAsync`
from `GetApprovedRowsAsync()` rows + `PublishStateDeriver.Derive(...)`.

This approach avoids adding a full table to `Publish.razor` (which currently has no per-entry
listing) while still satisfying the PUB-03 requirement that the operator can see publish-state
on the Publish page.

**`PublishStateDeriver` DI registration:** Add `builder.Services.AddSingleton<PublishStateDeriver>()`
to `DeckFlow.Studio/Program.cs` before the page registrations. Both pages inject via
`[Inject] private PublishStateDeriver Deriver { get; set; } = default!;`.

## Interaction States

### Block Action Flow (per-row, Harvest.razor)

```
Default state:
  [Block Video]  ← btn btn-sm btn-outline-danger

→ operator clicks Block Video:
  [Confirm Block] [Keep Video]  This will delete KB artifacts.
  (btn-danger)    (btn-outline-secondary)

→ operator clicks Confirm Block:
  row shows spinner (operation in flight)
  → on success: badge updates to "Blocked", Block Video button disabled
  → on error:   alert-danger inline: "Block failed — {reason}"

→ operator clicks Keep Video:
  returns to Default state (no change)
```

### Unblock Flow (per-row, Blocked.razor)

```
Default state:
  [Unblock Video]  ← btn btn-sm btn-outline-secondary

→ operator clicks Unblock Video:
  button shows spinner (operation in flight)
  → on success: row is removed from list; StateHasChanged()
  → on error:   alert-danger inline: "Unblock failed — {reason}"
```

No confirmation needed for Unblock — it is a non-destructive recovery action.

## Accessibility Contract

Per WCAG AA compliance for this phase:

1. **Color is never the sole state differentiator.** Every badge includes a text label.
   `Published` uses both `bg-success` + checkmark icon + text label "Published" to distinguish
   it from `Distilled`'s `bg-success` + text label "Distilled".
2. **Destructive Block confirm button** is `btn-danger` (red) AND labeled "Confirm Block"
   (not just a checkmark icon).
3. **Disabled controls** use the `disabled` attribute (Bootstrap visually dims and removes
   pointer events; screen readers read "dimmed"). No custom CSS needed.
4. **Keyboard navigation:** all buttons are native `<button>` elements, tab-reachable by
   default. The inline confirm flow (Block Video → Confirm/Keep Video) uses two sequential
   buttons — focus moves to "Confirm Block" on appearance via `@ref` + `ElementReference.FocusAsync()`
   (implementation detail for the executor; the contract is that focus lands on the confirm
   button, not the triggering Block Video button).
5. **Spinner** uses `role="status"` + `<span class="visually-hidden">Loading...</span>`
   (existing pattern from all pages, mirrored exactly for Blocked.razor).
6. **External links** (video ID links in Blocked.razor, title links in Harvest.razor) use
   `target="_blank" rel="noopener noreferrer"` (existing pattern).
7. **`aria-label` on row checkboxes** already present in Harvest.razor and Review.razor;
   Blocked.razor does not need checkboxes (no bulk-select is in scope for Phase 56).
