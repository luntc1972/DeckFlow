## Summary

Phase 37.5 is a CLI-only corpus rehabilitation with five concrete sub-problems. All five can be resolved with targeted changes to `CommandRunners.cs` and `DistillationSchemas.cs` in `DeckFlow.Core/Integration/` and `DeckFlow.Core/Knowledge/` — no controller, view, or web-layer changes are required.

**Sub-problem 1 (REBUILD-01 — corpus reset):** There is no existing CLI reset command. The planner must add one. The full table inventory is confirmed from live DDL in `ContentVideoStore.cs` and `ContentSiteIndexStore.cs`: six `content_*` tables (`content_sources`, `content_videos`, `content_distill_status`, `content_transcripts`, `content_summaries`, `content_clips`, `content_tags`, `content_site_index`) plus two spend-ledger tables (`llm_spend_ledger`, `whisper_spend_ledger`) and one run-history table (`content_harvest_runs`). The reset MUST NOT touch `blocked_videos` (Phase 37.6 carve-out — its DDL explicitly documents this). The prod Postgres reset requires the operator to either run SQL directly or use a new CLI command pointing at the Postgres connection string; the CLI stores resolve both providers through the dialect-pluggable `RelationalDatabaseConnection`.

**Sub-problem 2 (REBUILD-03 — clip timestamp defect):** The defect has two independent causes. (a) `YouTubeTranscriptFetcher.cs` line 76 joins only `caption.Text`, discarding `caption.Offset` (the per-caption timestamp from YoutubeExplode's `ClosedCaption`). The stored transcript body is plain text with no time markers. (b) The clips system prompt in `DistillationSchemas.ClipsSystemPrompt` says "Use timestamp_seconds only when the transcript provides a defensible time; otherwise use null" — so the LLM rationally returns null because no timestamps are in the transcript. `CommandRunners.cs` lines 1427-1432 then store `clip.TimestampSeconds ?? 0`. Fix requires: change the transcript fetcher to embed timestamps in the stored body (e.g., `[mm:ss] caption text` prefix per caption), update the clips system prompt to require a non-null per-clip timestamp pointing at the advice moment, add a validation that rejects any distill result where all clips have `TimestampSeconds == 0`.

**Sub-problem 3 (REBUILD-02 — LLM quality classifier):** No classifier exists today. The distill flow in `DistillVideoAsync` (CommandRunners.cs ~line 1292) calls summary → clips → tags in sequence, all against the transcript. A classifier step is best inserted as a new first LLM call inside `DistillVideoAsync`, before `ClearDistillOutputAsync`. If the classifier returns "drop", the distiller should mark the video with a new distill status (e.g., `filtered`) and skip indexing — it must NOT call `indexStore.UpsertRowAsync`. The classifier can reuse the existing `ILlmDistillationService` / `CliLlmDistillationService` pattern with a new `ClassifyAsync` method or be wired as a separate pre-flight call using the same infrastructure.

**Sub-problem 4 (REBUILD-04 — admin curation hybrid gate):** The full Phase 33 admin curation UX already exists. `AdminContentKbController.cs` has `SetVisibility`, `BulkSetVisibility`, `SetEvergreen`, and `ReloadSeed`. `ContentSiteIndexStore.GetPublishedRowsAsync` returns only rows where `is_visible = true`. The browse controller `ContentKbController.Index` calls `GetPublishedRowsAsync` and is gated by `[FeatureFlagGate("content.kb.enabled")]`. Nothing in this phase needs to touch the admin curation layer or the browse controller.

**Sub-problem 5 (REBUILD-05 — browse site + Copy artifact):** The browse site, detail page, and "Copy artifact" button are all present from Phase 22 + Phase 37 un-dark. `ContentKbController` renders the detail page with `Markdig.DisableHtml()` XSS protection (Phase 37 addition). The `CleanBodyText` property on `ContentKbDetailViewModel` feeds the copy button. Nothing new is required; re-distilled artifacts surface automatically once the operator publishes them via the admin grid.

**Primary recommendation:** (1) Add a new `corpus-reset` CLI command that DELETEs all `content_*` content rows (preserving `blocked_videos`, the three sources rows, and the two spend-ledger/run-history tables). (2) Fix transcript fetch to embed `[mm:ss]` timestamps. (3) Add a `ClassifyAsync` step to the distill pipeline gating on deck-advice/philosophy before summary/clips/tags. (4) Add all-zero-timestamp rejection to `DistillationValidation.ValidateClips`. (5) Run the full pipeline for Salubrious Snail only, operator publishes survivors.

## Sub-problem 2: Clip-Extraction Defect (REBUILD-03)

### Root Cause Trace (two independent sites)

**Site 1 — Transcript fetcher strips timestamps [VERIFIED: YouTubeTranscriptFetcher.cs line 76]:**

```csharp
var body = string.Join(" ", track.Captions.Select(caption => caption.Text));
```

YoutubeExplode's `ClosedCaption` carries an `Offset` property (the per-caption `TimeSpan` start position). This line discards it, producing a flat plain-text transcript with no time markers. Every transcript in the DB is timestamp-free.

**Site 2 — System prompt explicitly allows null [VERIFIED: DistillationSchemas.cs lines 51-56]:**

```csharp
public static string ClipsSystemPrompt { get; } = """
    You extract 3 to 8 useful key clips from Magic: The Gathering video transcripts.
    Output only JSON matching the supplied schema.
    Use timestamp_seconds only when the transcript provides a defensible time; otherwise use null.
    Excerpts must be grounded only in the transcript.
    """;
```

Since the transcript contains no timestamps (Site 1), the LLM cannot infer them and returns `null` for every clip — which is the correct behavior given the instruction.

**Site 3 — Storage converts null to 0 [VERIFIED: CommandRunners.cs lines 1427-1432]:**

```csharp
await videoStore.InsertClipAsync(
    video.Id,
    clip.TimestampSeconds ?? 0,   // <-- the ?? 0 sentinel
    clip.Excerpt,
    sortOrder++,
    ct).ConfigureAwait(false);
```

The `content_clips.timestamp_s` column is `NOT NULL INT`, so null cannot be stored; 0 is used as the "unknown" sentinel.

**Site 4 — Artifact writer renders 0 as `[00:00]` [VERIFIED: ContentArtifactWriter.cs lines 68-74]:**

```csharp
if (clip.TimestampSeconds is { } timestampSeconds)
{
    builder.Append("- **[")
        .Append(FormatClipTimestamp(timestampSeconds))   // 0 -> "00:00"
        .Append("]** ")
        .AppendLine(clip.Excerpt);
}
```

`FormatClipTimestamp(0)` = `"00:00"`. Every clip renders `[00:00]`.

### Fix Plan

Three coordinated changes are required:

**Change A — `YouTubeTranscriptFetcher.cs` line 76:** Embed per-caption offsets in the stored body. Format each caption as `[mm:ss] text` to produce a timestamped transcript the LLM can cite:

```csharp
var body = string.Join(" ", track.Captions.Select(caption =>
    $"[{(int)caption.Offset.TotalMinutes:00}:{caption.Offset.Seconds:00}] {caption.Text}"));
```

This changes the `ContentTranscript.Body` format for all future harvests. Existing corpus rows (being reset anyway) are unaffected. The summary and tags prompts receive this enriched text, which is neutral — they ignore the `[mm:ss]` prefixes.

**Change B — `DistillationSchemas.ClipsSystemPrompt`:** Update to require a real per-clip timestamp. The "otherwise use null" escape hatch must be removed. New prompt should state: "Each clip must include a `timestamp_seconds` (integer) citing the actual time in the transcript where the advice is given. Select mid-video advice moments, not the opening. Return only clips with a defensible non-zero timestamp."

**Change C — `DistillationValidation.ValidateClips`:** Add a new guard that rejects a distill result where ALL clips have `TimestampSeconds == 0` (or null):

```csharp
if (clips.All(clip => (clip.TimestampSeconds ?? 0) == 0))
{
    throw new InvalidOperationException(
        "All clips have timestamp 0 — the distiller failed to extract real timestamps. " +
        "Ensure the transcript contains embedded [mm:ss] markers.");
}
```

This makes the all-zero defect a hard failure rather than silent corruption.

### Schema Note

`ContentVideoStore.InsertClipAsync` takes `int timestampS` (not nullable). The schema column `timestamp_s INT NOT NULL` is correct for non-zero timestamps. The storage layer does not need to change; only the upstream logic (fetcher + prompt + validation) changes.

### Note on `ClipItem` Model

`ClipItem` is defined in `DistillationResults.cs` as `record ClipItem(int? TimestampSeconds, string Excerpt)`. The nullable `int?` is the in-memory shape; storage converts to non-null. After the fix, the in-memory model stays the same (nullable is fine) but the all-zero guard fires before storage.

## Sub-problem 3: LLM Quality Classifier (REBUILD-02)

### Distill Pipeline Entry Point

**Finding [VERIFIED: CommandRunners.cs lines 1292-1493]:**

`DistillVideoAsync` is the per-video distillation method. Its current pipeline:
1. Fetch transcript from store (`GetLatestTranscriptAsync`)
2. Check spend cap
3. `ClearDistillOutputAsync` (delete prior summary/clips/tags rows)
4. `distiller.SummarizeAsync(transcript.Body)`
5. Record spend
6. `distiller.ExtractClipsAsync(transcript.Body)`
7. Record spend
8. `distiller.InferTagsAsync(transcript.Body)`
9. Record spend
10. Validate + insert summary, clips, tags
11. Write artifact file
12. `indexStore.UpsertRowAsync` (adds to site index)
13. `videoStore.SetDistillStatusAsync(... "distilled")`

**Classifier gate insertion point:** The classifier should be step 1.5 — AFTER fetching the transcript (so it can read the content), BEFORE `ClearDistillOutputAsync` (so a dropped video leaves its prior distill-status row untouched). A dropped video should:
- NOT call `ClearDistillOutputAsync`
- NOT call summary/clips/tags
- NOT call `indexStore.UpsertRowAsync`
- Call `videoStore.SetDistillStatusAsync(video.Id, "filtered", ct)` with a new status value

### New Distill Status

`ContentVideoStore.IsValidDistillStatus` currently accepts `"distilled"`, `"skipped_over_cap"`, `"failed"`. A new `"filtered"` status must be added to the `CHECK` constraint in the DDL and the `IsValidDistillStatus` guard. This is a schema migration for both SQLite (local) and Postgres (prod).

**Alternatively (simpler):** Use the existing `"failed"` status for classifier-dropped videos and log a distinguishing message. This avoids a schema migration. The planner should choose; research recommends adding `"filtered"` as a distinct status so the operator can distinguish "pipeline error" from "intentionally dropped by quality gate."

### `ILlmDistillationService` Extension

`ILlmDistillationService` currently defines `SummarizeAsync`, `ExtractClipsAsync`, `InferTagsAsync` (verified in `ILlmDistillationService.cs`). Adding a `ClassifyAsync` method is the cleanest approach. It would return a new `ClassificationResult` record (e.g., `record ClassificationResult(string Verdict, string Reason)` where `Verdict` is `"keep"` or `"drop"`).

`CliLlmDistillationService` would implement `ClassifyAsync` using the same `ExtractWithRetryAsync<T>` pattern with a new `ClassificationSchema` and `ClassificationSystemPrompt` in `DistillationSchemas`.

The JSON schema for the classifier response is simple:

```json
{"type":"object","additionalProperties":false,
 "properties":{
    "verdict":{"type":"string","enum":["keep","drop"]},
    "reason":{"type":"string"}},
 "required":["verdict","reason"]}
```

### Classifier Prompt (Claude's Discretion — calibrate at impl)

The CONTEXT.md defines the taxonomy. Research observation: the prompt must explicitly list the drop classes and the keep classes, and include a "when in doubt, keep" tiebreaker to avoid false negatives. Example structure:

- **Keep:** videos about deckbuilding decisions (card selection, synergy, slot philosophy, cuts), deckbuilding philosophy (principles, heuristics, meta-positioning within a deck's context)
- **Drop:** trivia/quiz ("is X a draw spell?"), news/set-commentary with no deckbuilding application, meta-format philosophy with no actionable deckbuilding content ("cEDH is a format where..."), intro/announcement/promotional, "$X budget deck pool reveal"

The CONTEXT.md notes specific drop-class examples from the value gate: "is X a draw spell", "Tall Commander" meta, "$25 deck pool".

### Spend Ledger Note

The classifier call incurs $0 cost with the claude CLI backend (subscription provider, `isSubscriptionProvider = true`). The existing spend-ledger bypass for subscription providers (`isSubscriptionProvider ? 0m : ...`) handles this correctly — no spend-ledger recording needed for the classifier call.

## Sub-problem 5: Browse Site + Copy Artifact (REBUILD-05)

### Existing Implementation Confirmed [VERIFIED: source files]

**Browse page:** `ContentKbController.Index` at `GET /content-kb` — calls `GetPublishedRowsAsync`, renders `ContentKbBrowseViewModel`. Client-side filter over tags.

**XSS protection:** The Markdig pipeline includes `.DisableHtml()` (Phase 37.2 addition) and the controller uses `new HtmlString(Markdown.ToHtml(body, Pipeline))` where `Pipeline` is the `.DisableHtml()` pipeline. Any harvested text is HTML-encoded before rendering.

**Artifact path security:** The controller validates `row.ArtifactPath.StartsWith("content-kb/", ...)` and checks the resolved path is under `allowedRoot + Path.DirectorySeparatorChar`.

**Note on artifact files:** The `DistillVideoAsync` call to `ContentArtifactWriter.WriteFile` writes artifacts to `artifactRoot` (passed through `RunDistillAsync`). The public entry point `RunDistillAsync(FileInfo? db, ...)` wires `artifactRoot` as:

```csharp
var artifactRoot = Path.Combine(Directory.GetCurrentDirectory(), "artifacts");
```

(Verified at CommandRunners.cs ~line 457.) The artifact files are local `.md` files. The web app reads them from `MTG_DATA_DIR`. For the browse site to serve rebuilt artifacts in prod, the `content-index-export` command must be run after distillation + publish to update the committed `index-seed.json`, which the web app loads via `ContentKbSeedLoader`.

## Common Pitfalls

### Pitfall 1: Cascade assumption — `content_site_index` is NOT a child of `content_videos`
**What goes wrong:** Developer truncates `content_videos` and assumes all corpus data is gone. `content_site_index` has no FK to `content_videos`. Its rows persist, causing the browse site to show stale entries pointing at deleted artifacts.
**How to avoid:** Reset must explicitly `DELETE FROM content_site_index` as a separate step after `DELETE FROM content_videos`.
**Warning signs:** After reset, `content_site_index` has rows but `content_videos` is empty.

### Pitfall 2: `content_sources` is accidentally reset
**What goes wrong:** Developer deletes all rows including `content_sources`. The harvest command finds no enabled sources and silently harvests nothing.
**How to avoid:** The reset command must scope its DELETE to `content_videos` and `content_site_index`, NOT `content_sources`.

### Pitfall 3: Distill pipeline resets `content_distill_status` for existing rows
**What goes wrong:** `DistillVideoAsync` calls `ClearDistillOutputAsync` (line 1329) which deletes summaries/clips/tags for the video, then re-distills. If the corpus reset left the `content_videos` rows intact (only clearing child rows), re-distill could corrupt videos that were intentionally in "filtered" status.
**How to avoid:** The corpus reset deletes `content_videos` rows entirely. Cascade handles children. Fresh harvest creates new `content_videos` rows with new IDs. No residual distill status exists.

### Pitfall 4: Classifier prompt produces false negatives on deckbuilding content with tangential trivia
**What goes wrong:** The LLM marks a good deckbuilding video as "drop" because it briefly discusses a card's ruling (e.g., "is X a draw spell?") before giving deckbuilding advice.
**How to avoid:** Include a "when in doubt, keep" tiebreaker in the classifier prompt. The hybrid gate (step 2 = operator review) catches false negatives. The LLM gate's job is removing clear junk, not achieving perfection.

### Pitfall 5: All-zero timestamp validation fires on the first video of every re-harvest
**What goes wrong:** If `YouTubeTranscriptFetcher` changes are not deployed (or tested), the new `ValidateClips` all-zero guard throws on every distill run.
**How to avoid:** The fix to the transcript fetcher (embedding `[mm:ss]` markers) and the new prompt are prerequisites for the all-zero guard. Deploy/test the fetcher change first; confirm a sample transcript has embedded timestamps before running distill.

### Pitfall 6: Prod `content_site_index` reset loses operator publish decisions permanently
**What goes wrong:** Operator publishes 20 entries, then a prod reset wipes `is_visible`. All visibility decisions are lost.
**How to avoid:** Export the current visibility state before resetting (SELECT from prod). This is a destructive one-time operation — the CONTEXT.md explicitly accepts this. The corpus being replaced is gate-condemned junk. Documenting the before-state is good practice.

## Open Questions

1. **Spend-ledger FK cascade behavior**
   - What we know: `llm_spend_ledger` has a `video_id` column but the spend-ledger DDL in `LlmSpendLedger.cs` must be verified to determine if `video_id` has `ON DELETE CASCADE`.
   - What's unclear: If the FK is `ON DELETE CASCADE`, spend rows auto-delete. If not, `DELETE FROM content_videos` will fail with FK violation (on Postgres) or leave orphans (on SQLite with FK enforcement disabled).
   - Recommendation: Planner must read `LlmSpendLedger.cs`/`WhisperSpendLedger.cs` DDL lines ~97-120 to confirm cascade behavior before writing the reset command.

2. **`content_sources` reset decision**
   - What we know: Keeping sources avoids re-registration. Deleting sources and re-adding them is a minor inconvenience.
   - What's unclear: Whether the operator wants to reset source slugs/display names as part of the corpus reset.
   - Recommendation: Keep `content_sources` rows. The reset targets only `content_videos` and `content_site_index`.

3. **Classifier step cost accounting**
   - What we know: The claude CLI backend is subscription ($0). No spend-ledger record needed.
   - What's unclear: Whether a "filtered" count should appear in the distill summary log line.
   - Recommendation: Add `counts.Filtered` to `DistillCounts` and include it in the final log. Useful for quality monitoring.

4. **Schema migration for `"filtered"` distill status**
   - What we know: `content_distill_status.status CHECK (status IN ('distilled','skipped_over_cap','failed'))` is enforced. Adding `'filtered'` requires `ALTER TABLE` on both local SQLite and prod Postgres.
   - What's unclear: The planner must decide: alter the constraint or reuse `'failed'` with a log message.
   - Recommendation: Add `'filtered'` as a new value. The `ContentVideoStore.EnsureSchemaAsync` already uses `CREATE TABLE IF NOT EXISTS` so the table DDL update alone won't alter the existing CHECK constraint. The planner must add an `ALTER TABLE` migration in `EnsureSchemaAsync` analogous to how `is_visible` and `is_evergreen` were added to `content_site_index` (lines 57-73 of `ContentSiteIndexStore.cs`).
