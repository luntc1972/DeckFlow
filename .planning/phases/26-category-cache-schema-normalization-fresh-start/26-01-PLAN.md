<objective>
Lay the dual-dialect schema foundation for the normalized category cache: add an `IRelationalDialect.SurrogateIdColumnType` member, reshape `EnsureSchemaAsync` to create the new integer-keyed star schema on a clean DB, and create the failing parity-test scaffold that the write/read port in 26-02 will turn green.

The new schema has THREE dimensions plus two slim facts:
- `cards(id PK, normalized_card_name UNIQUE, display_name)` — interns card identity.
- `sources(id PK, source TEXT UNIQUE, deck_queue_id INT NULL)` — interns the generic `source` string. This is the REVISED design (HIGH-1): the `source` column is NOT always a harvest-queue deck. Writers emit three distinct source kinds — `archidekt_live:{deckId}` (harvest), `archidekt_url:{url}` (admin URL import), and `edhrec` (read-path enrichment write-back). Forcing all of those into `deck_queue` would pollute the harvest queue (`GetNextUnprocessedDeckIdsAsync` would return fake decks) and detach URL/edhrec facts from the live-deck commander linkage. Instead, intern every `source` string ONCE into `sources`; the fact tables reference `source_id INT`. `deck_queue` stays the harvest queue ONLY. `sources.deck_queue_id` is populated (to the integer `deck_queue.id`) ONLY for `archidekt_live:` sources, giving the commander aggregate a clean integer join while non-live sources have NULL linkage — exactly as today.
- `deck_queue` extended with an integer surrogate `id` + reserved `content_hash` (Phase 27).
- `card_category_observations` / `card_deck_totals` slimmed to `source_id INT` + `card_id INT`, but each ALSO carries the display `card_name` at the observation grain (HIGH-2 — see below).

Purpose: This phase is a fresh-start schema reshape (DB wiped + re-harvested, no online migration). The schema + dialect contract must exist and be proven dual-dialect-safe BEFORE the write/read paths are re-pointed at integer keys. The single biggest correctness risk is parity; the single biggest dual-dialect risk is the SQLite AUTOINCREMENT + composite-PK restriction (RESEARCH A1). Both are nailed down here.

Output: New dialect member, new DDL in `EnsureSchemaAsync`, and a RED parity/harness test file. The repository's read/write SQL is NOT yet ported (that is 26-02) — this plan only changes schema-creation DDL and adds tests.

This plan implements DBO-01 (schema half). Codex implements the code AND the tests; Claude reviews. NO new packages. Dual-dialect only via `IRelationalDialect` (never `if (IsSqlite)` string branching in `EnsureSchemaAsync`). Preserve LF, `{ get; init; }`, and raw-string SQL literal indentation — touch only the lines that change. No Format Document / Code Cleanup.
