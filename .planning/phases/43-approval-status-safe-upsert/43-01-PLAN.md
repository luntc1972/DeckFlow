<objective>
Add the data-layer prerequisites for the v1.7 review/publish workflow, all in DeckFlow.Core, with no UI and no publish/commit/SCP logic:

1. An `approval_status` column on `content_site_index` (`pending`/`approved`/`rejected`), added via the established self-healing ALTER pattern, with DDL-level `DEFAULT 'pending'` and a one-time grandfather backfill (REVQ-01).
2. A safe content-only upsert overload, `UpsertContentColumnsOnlyAsync`, that refreshes content/nav columns but never clobbers the four admin fields {`is_visible`, `is_hidden`, `is_evergreen`, `approval_status`} on UPDATE, and inserts new rows as `pending` (PUB-01).
3. `GetApprovedRowsAsync` (approved-only filtered read) plus wiring the orchestrator export to it, and wiring the distill index-write to the safe overload (PUB-02 + D-09).

Purpose: Unblock the review queue (Phase 46) and both publish paths (Phases 46/47). This is the additive data-layer foundation.

Output: Modified store, interface, row model, and orchestrator call sites. No exported JSON shape change. No new packages.
</objective>
