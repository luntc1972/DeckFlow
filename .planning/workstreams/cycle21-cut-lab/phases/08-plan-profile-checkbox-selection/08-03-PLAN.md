<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| EDHREC CDN → `EdhrecCommanderThemeService` | Untrusted third-party JSON crosses into the app. This is the only new external data source in Phase 8. |
| client session profile → theme slug → cache filename | A theme slug can originate from client-supplied session JSON and is used to build a filesystem path |
| app → local disk cache | The service writes files under the artifacts directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03-01 | Tampering | Commander/theme slug interpolated into a cache filename | mitigate | Both slugs are validated against `^[a-z0-9-]+$` before any `Path.Combine`, mirroring `EdhrecCellReader.cs:154,218-224`, and the combined full path is asserted to remain under the resolved cache root. A slug containing `..`, `/`, `\`, or a NUL is rejected before I/O. |
| T-08-03-02 | Tampering | Commander/theme slug interpolated into the request URL | mitigate | The same regex gate runs before the `RestRequest` is built; RestSharp additionally URL-encodes. The base address is a fixed `https://json.edhrec.com/pages/` constant, so a slug cannot redirect the host. |
| T-08-03-03 | Denial of Service | Oversized or deeply nested EDHREC response (deserialization bomb) | mitigate | Body is rejected above `MaxResponseBytes` (4 MiB) before parsing. `System.Text.Json` is used with its default 64-level depth limit, which is not raised. Parsing is streaming-tolerant and wrapped so a malformed document degrades rather than throwing. |
| T-08-03-04 | Denial of Service | Retry storm against a permanently-403 commander page | mitigate | 403 is deliberately excluded from `IsTransientFailure`, and the 403 + `AccessDenied` branch returns before any retry. A test asserts an exact request count of 1. |
| T-08-03-05 | Denial of Service | EDHREC outage stalling the Cut Lab request | mitigate | `AddTimeout(10s)` in the `edhrec` pipeline bounds each attempt, retries are capped at 2, and every failure returns the empty unavailable result so the generic strategy layer renders regardless. |
| T-08-03-06 | Tampering | Cache poisoning by overwriting an unrelated file on disk | mitigate | Filenames are derived solely from validated slugs, the containment check rejects any escape, and the cache root is app-owned (`MTG_DATA_DIR` or the artifacts directory) — never the read-only content root. |
| T-08-03-07 | Information Disclosure | Theme display names and card names taken verbatim from EDHREC | transfer | These strings are stored and returned unencoded; HTML encoding is enforced at the Razor boundary in 08-07, where the plan panel renders them. Recorded here so the downstream plan cannot assume it was handled upstream. |
| T-08-03-08 | Spoofing | Man-in-the-middle on the EDHREC fetch | accept | Transport is HTTPS to a fixed host with the platform certificate store; no credential or user data is sent, and the worst case of a forged response is a wrong theme list on a flag-dark tool. |
| T-08-03-SC | Tampering | npm / NuGet installs | mitigate | No packages added. RestSharp, Polly v8 and `System.Text.Json` are already present. Any new package stops the plan pending explicit user approval. |
</threat_model>
