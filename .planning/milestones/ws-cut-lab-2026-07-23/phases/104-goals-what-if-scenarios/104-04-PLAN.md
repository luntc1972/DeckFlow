<objective>
Deliver named scenarios (GOAL-02): save/list/load/delete of the whole session as browser localStorage slots, reusing the existing `CutLabStateSerializer` JSON as the payload. This is the one Cut Lab feature with NO server tier and NO no-JS fallback (Pitfall 2) — JS-only with `<noscript>` messaging. Modeled on `deck-input-store.ts`'s try/catch silent-degrade pattern, but folded INTO `cut-lab.ts` so the code actually loads (the view references only `cut-lab.js`; tsconfig is `module: "none"` per-file output, so a standalone `cut-lab-scenarios.js` would never run).

Purpose: Let a builder keep multiple configurations (different goals/locks/cut states) and switch between them per browser, with zero backend.
Output: scenario store functions inside `cut-lab.ts`, a Scenarios panel in CutLab.cshtml, and Vitest coverage.
</objective>

DECISION: fold the scenario store functions directly into `cut-lab.ts`, attached to the SAME `api` object before `root.DeckFlowCutLab = api;`, so they load with the existing bundle and cannot be clobbered. localStorage schema (from RESEARCH.md Pattern 4):
  SCENARIO_INDEX_KEY = 'deckflow.cutlab.scenario-index'  (JSON array of {id, name, savedAt})
  SCENARIO_SLOT_PREFIX = 'deckflow.cutlab.scenario.'      (one key per scenario, raw state JSON)
  MAX_SCENARIO_SLOTS = 20
Quota detection: error instanceof DOMException && (error.name === 'QuotaExceededError' || error.code === 22).
ID generation (LOW-7): prefer crypto.randomUUID() when available, else a tiny fallback (e.g. `s-${Date.now()}-${Math.random().toString(36).slice(2)}`) so jsdom / older browsers that lack randomUUID still save.
deck-input-store.ts try/catch silent-degrade convention (lines 35-47 / 49-69) is the template for every read/write.
