## Summary

This is a prose-only brand-neutralization phase (replace user-visible "ChatGPT" with AI-agnostic phrasing per D-01..D-05). The implementation correctly:

- Adds `var aiPlatform = AiPlatform.Normalize(Model.Request.TargetAiPlatform)` at the top of each of the three multi-AI views. `AiPlatform.Normalize` is null-safe and always returns a non-null `AiPlatform` whose `DisplayName` is a hardcoded constant (`"ChatGPT"`, `"Claude"`, `"Gemini"`) — no user-controlled input flows into `DisplayName`, so the `@aiPlatform.DisplayName` Razor interpolations are XSS-safe (HTML-encoding aside).
- Preserves the explicitly-carved-out literal "ChatGPT" in `Home.cshtml` line 62 (Ask-a-Judge hub card) and the corresponding README Ask-a-Judge section (line 493).
- Preserves Phase 10 round-trip fallbacks: the `target_ai_platform: ChatGPT` literal default in `BuildRequestContextText` in all three services (DeckAnalysisPacketService line 1309, MetaGapService line 266, DeckComparisonService line 229). These match the canonical `AiPlatform.ChatGpt.Key = "ChatGPT"` value so re-uploaded zips deserialize back to ChatGPT.
- Preserves Phase 13 D-08 identifier invariants: `chatgpt-packets-form`, `data-chatgpt-*`, `data-cache-key="chatgpt-*"`, `chatgpt-step-eyebrow`, etc. — all intact in the three views.
- Help markdown and README prose are clean. No broken markdown anchors or table structures (28 table rows in README scan correctly, 61 heading lines intact).

Two real issues found in `DeckAnalysis.cshtml`: a typo and a sentence-start capitalization slip. One latent UI inconsistency surfaces when Gemini is disabled at runtime while a stale `TargetAiPlatform=Gemini` value persists. Minor style nits round out the info findings.

### WR-02: Lowercase "your AI" at start of new sentence (capitalization slip)

**File:** `DeckFlow.Web/Views/Deck/DeckAnalysis.cshtml:227`
**Issue:** Inside the Analysis-context expandable section, the closing sentence reads "If you leave these blank, the prompts still work. **your AI will infer more** from the decklist alone." The "your AI" universal noun starts a new sentence after a period and must be capitalized. The phase's universal-noun rule (D-01/D-05) is "your AI" mid-sentence; at sentence start it should be "Your AI". Every other sentence-start occurrence of this noun in the changed files is correctly capitalized — this one was missed.
**Fix:**
```cshtml

```

## Info

### IN-01: `_AiSelector` Gemini-disabled fallback and view-level `aiPlatform` diverge when a stale Gemini value is persisted

**File:** `DeckFlow.Web/Views/Deck/DeckAnalysis.cshtml:4`, `DeckFlow.Web/Views/Deck/DeckComparison.cshtml:5`, `DeckFlow.Web/Views/Deck/CedhMetaGap.cshtml:5`, `DeckFlow.Web/Views/Shared/_AiSelector.cshtml:14-18`
**Issue:** The view-level `var aiPlatform = AiPlatform.Normalize(Model.Request.TargetAiPlatform)` does NOT honor the `DECKFLOW_GEMINI_ENABLED` feature flag, but the `_AiSelector` partial does — it silently rewrites `selected = "ChatGPT"` when the persisted value is `"Gemini"` while Gemini is disabled. If a user submitted with `TargetAiPlatform=Gemini` while the flag was on, then the flag was turned off, the next page render will:
- Show "ChatGPT" as the checked radio (selector's fallback).
- Display "Gemini" everywhere `@aiPlatform.DisplayName` is interpolated (e.g. "Paste this into Gemini" at DeckAnalysis.cshtml:422, DeckComparison.cshtml:481, CedhMetaGap.cshtml:298) because `AiPlatform.Normalize("Gemini")` returns Gemini regardless of the runtime flag.

User sees instructions for Gemini while the form will submit ChatGPT. This is a pre-existing latent inconsistency that this phase made more visible by sprinkling `@aiPlatform.DisplayName` throughout the views. Outside this phase's prose-rename scope to fix, but worth tracking.

**Fix:** In a follow-up, either centralize the Gemini-disabled fallback in `AiPlatform.Normalize` (overload that accepts the options accessor), or have the views inject `IOptions<AiPlatformOptions>` and apply the same fallback before computing `aiPlatform`.

### IN-02: Inconsistent namespace qualification for `AiPlatform.Normalize` between the three views

**File:** `DeckFlow.Web/Views/Deck/DeckAnalysis.cshtml:4` vs `DeckFlow.Web/Views/Deck/DeckComparison.cshtml:5`, `DeckFlow.Web/Views/Deck/CedhMetaGap.cshtml:5`
**Issue:** `DeckAnalysis.cshtml` writes the fully-qualified form `DeckFlow.Web.Models.AiPlatform.Normalize(Model.Request.TargetAiPlatform)`, while the other two views write the bare `AiPlatform.Normalize(...)`. Both compile (the `_ViewImports.cshtml` already does `@using DeckFlow.Web.Models`), so this is purely stylistic. Pick one form so future readers don't wonder if the long form was intentional.
**Fix:** Drop the namespace prefix in DeckAnalysis.cshtml line 4 to match the other two views:
```cshtml
var aiPlatform = AiPlatform.Normalize(Model.Request.TargetAiPlatform);
```
