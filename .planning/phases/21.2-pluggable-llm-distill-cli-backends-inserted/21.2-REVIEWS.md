# Cross-AI Plan Review — Phase 21.2

## Codex Review

**Summary**

The plans are directionally solid and use the right primary seam: keep OpenAI default, add a separate CLI `ILlmDistillationService`, and wire ledger bypass only at the runner layer. I would not execute them as written yet. There are several blockers around real CLI invocation, timeout/kill behavior, Codex tool exposure, and tag validation that directly affect ROADMAP success criteria KB-10/KB-11 and the live UAT gate.

**Strengths**

- Good seam placement: `CliLlmDistillationService` avoids refactoring the OpenAI-specific `ExtractJsonAsync`.
- Factory pattern mirrors the existing `TranscriptProviderFactory`, which fits the codebase.
- Ledger bypass sites are correctly identified in [CommandRunners.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.CLI/CommandRunners.cs:595) and [DistillVideoAsync](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.CLI/CommandRunners.cs:975).
- Fake process seam is the right test strategy. Real `claude`/`codex` must not run in unit tests.
- Plans correctly preserve the OpenAI default as the regression-critical path.
- Process I/O concerns are mostly recognized: stdin close, stdout/stderr concurrent reads, no transcript text in command args.

**Concerns**

- **HIGH: Claude default command is probably invalid or at least unproven.** The plan defaults to `claude -p --output-format json --allowedTools ""` while writing the full prompt to stdin. The research verified `claude -p "<instruction>"` plus stdin context, not `-p` with no prompt argument. This can break the primary `claude` backend before UAT.

- **HIGH: Hung CLI timeout is not actually implemented.** Plan 01 says timeout is deferred to Plan 02, but Plan 02 never wires a per-call timeout. `CommandRunners.RunDistillAsync` receives `CancellationToken.None` from the CLI path, so a stuck child process can hang forever. Also, cancellation should kill the process tree.

- **HIGH: Codex is treated as a pure text model, but it is an agent.** `codex exec --sandbox read-only` may still let a transcript prompt injection, meaning transcript text that instructs the agent to ignore the task, read local files and echo them. Read-only prevents writes, not necessarily reads. Claude disables tools with `--allowedTools ""`; Codex needs an equivalent verified mitigation or an isolated empty working directory with minimal environment.

- **HIGH: Tag validation contradicts D-03.** The plan says tags get “no extra validator beyond shape,” but D-03 requires tags within `ContentTagVocabulary`. Current downstream `FilterTags` only drops bad tags after all three calls, which can produce a “distilled” artifact with empty or weak tags instead of retrying malformed CLI output.

- **MEDIUM: Ledger bypass still computes OpenAI pricing in one subscription path.** Plan 02 guards `WouldExceedCapAsync`, but leaves `var projectedVideoCost = ComputeProjectedVideoCostUsd(...)` before the first guard in [CommandRunners.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.CLI/CommandRunners.cs:974). If “token-pricing bypass” means no pricing math for subscription providers, that must be conditional too.

- **MEDIUM: JSON repair is under-specified.** First `{` to last `}` fails with multiple JSON objects or prose containing braces. Missing fields can deserialize to null and fail later with incidental exceptions. Tests should cover null/missing lists, empty excerpts, invalid tag values, extra wrapper text, and persistent malformed envelopes.

- **MEDIUM: `DECKFLOW_LLM_CLI_COMMAND` parsing is fragile.** Splitting at the first space plus using `ProcessStartInfo.Arguments` makes paths with spaces, nested quoting, and `--allowedTools ""` platform-sensitive. This is especially risky for Windows examples.

- **MEDIUM: Cross-platform instructions need executable exactness.** The plan says WSL and Windows are documented, but the hard case is Windows `dotnet.exe` launched from WSL. The docs and UAT need exact commands proving which process owns `PATH` and env vars.

- **LOW: OpenAI byte-identical regression guard is too manual.** The extraction from [LlmDistillationService.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Core/Integration/LlmDistillationService.cs:236) to [DistillationSchemas.cs](/mnt/c/users/chrislunt/source/personal/deckflow/DeckFlow.Core/Knowledge/DistillationSchemas.cs:11) should have an automated test capturing system messages and schema bytes, not only a diff note.

- **LOW: Error logging may leak sensitive text.** `Tail(stderr)` is useful, but CLI stderr can contain auth details or prompt snippets. Keep it bounded and avoid logging stdout, prompts, transcripts, or full command lines.

**Suggestions**

- Add a pre-implementation spike or first task to verify the exact `claude` default command from `System.Diagnostics.Process`, not a shell. If `claude -p` cannot read the full prompt from stdin, use `ProcessStartInfo.ArgumentList` and pass the instruction as a real `-p` argument while transcript/body stays on stdin.

- Add a `CliCommandSpec` instead of `(fileName, arguments)` string pairs: `FileName`, `ArgumentList`, `EnvelopeKind`, `WorkingDirectory`. Keep the env override if needed, but defaults should avoid shell-style quoting.

- Implement timeout inside `CliLlmDistillationService`: default 10 minutes per extraction, optional env override, linked CTS, and `process.Kill(entireProcessTree: true)` on timeout/cancellation. Add a fake-runner cancellation test.

- Add `ValidateTags` for the CLI backend: required arrays non-null, every value in `ContentTagVocabulary`, preferably no duplicate tags. Invalid tags should trigger retry, not silent filter-only success.

- Harden JSON extraction by scanning for a balanced JSON object with quote/escape awareness, then deserialize and explicitly validate null/missing fields.

- In Plan 02 tests, assert `WouldExceedChecks` is empty for subscription live and dry-run paths, every ledger record has `CostUsd == 0m`, and `CompleteRunAsync(... SpendUsd)` is zero with `WhisperCalls == 3 * distilledVideos`.

- Make UAT deterministic with SQL checks: distilled video count, slim-index row count, artifact file count, `sum(cost_usd)=0` in LLM ledger, latest run `spend_usd=0`, and expected LLM call count.

**Risk Assessment: HIGH**

The architecture is basically right, but the execution plan has blockers in the parts that matter most: actual CLI invocation, hung-process control, untrusted transcript safety, and validation before marking content distilled. Fix those before execution. After those changes, risk drops to medium because the remaining uncertainty is mostly CLI behavior drift and live UAT variability.

## Consensus Summary (single reviewer: Codex)

**Verdict: HIGH risk — block execution until the 4 HIGH findings are resolved.** Architecture/seam placement validated; defects are in CLI invocation mechanics, process control, untrusted-input safety, and output validation.

### Agreed Strengths
- Seam placement (new CliLlmDistillationService, OpenAI ExtractJsonAsync untouched).
- Factory mirrors TranscriptProviderFactory; ledger-bypass sites correctly located; fake-process test seam.
- OpenAI default preserved as regression-critical path.

### HIGH blockers (must fix before execute)
- **H1 — claude/codex command shape**: RESEARCH verified instruction(+schema) as the CLI `-p`/exec ARG + transcript on STDIN; the plan writes the whole prompt to stdin with an empty `-p`. Likely breaks the claude backend. Fix: instruction-as-arg via ProcessStartInfo.ArgumentList, transcript-on-stdin. (Corrects CONTEXT D-02 wording.)
- **H2 — no real timeout/kill**: per-call timeout deferred Plan01→Plan02 but never wired; CLI path gets CancellationToken.None → infinite hang possible. Fix: linked CTS (~10 min default, env-overridable) inside CliLlmDistillationService + process.Kill(entireProcessTree:true) on timeout/cancel + fake-runner cancellation test.
- **H3 — codex agent tool exposure**: `--sandbox read-only` blocks writes, not reads; transcript prompt-injection could read+echo local files. Fix: run codex with tools disabled / isolated empty working dir + minimal env (parallel to claude's `--allowedTools ""`); verify the exact mitigation.
- **H4 — tag validation contradicts D-03**: plan says tags get no validator beyond shape, but vocab-invalid tags must trigger RETRY (not post-hoc FilterTags silent drop). Fix: ValidateTags (non-null arrays, every value in ContentTagVocabulary) in the retry loop.

### MEDIUM
- M1 — ledger bypass still runs ComputeProjectedVideoCostUsd before the first guard for subscription path; make pricing math conditional too.
- M2 — JSON repair under-specified: first-{/last-} fails on multiple objects/prose braces; missing fields → null; add quote/escape-aware balanced-object scan + null/missing-field validation + tests (null lists, empty excerpts, invalid tags, wrapper text, persistent-malformed).
- M3 — DECKFLOW_LLM_CLI_COMMAND first-space split fragile (paths/quoting/`--allowedTools ""`). Prefer a CliCommandSpec {FileName, ArgumentList, EnvelopeKind, WorkingDirectory} over a string split (converges with H1's ArgumentList fix).
- M4 — cross-platform exactness: the hard case is Windows dotnet.exe launched from WSL; docs+UAT need exact commands proving which process owns PATH/env.

### LOW
- L1 — automate the OpenAI byte-identical regression guard (test capturing system-message + schema bytes), not just a diff note.
- L2 — error logging: bound Tail(stderr); never log stdout/prompts/transcripts/full command lines (auth/prompt leak).

### Suggested resolution
Replan via `/gsd-plan-phase 21.2 --reviews` to fold H1-H4 + M1-M4 into the plans (esp. ArgumentList command spec, in-service timeout+kill, codex tool-isolation, ValidateTags-in-retry, conditional pricing). L1/L2 fold in as acceptance criteria.

# Cross-AI Plan RE-REVIEW — Phase 21.2 (Round 2, Codex, 2026-06-01)
Verdict: **BLOCK** — 2 HIGH open after replan. RESOLVED: H4, M1. PARTIAL: H1,H2,M2,M3,M4,L1,L2. NOT-RESOLVED: H3.

**Finding Status**

- **H1 Claude command validity: PARTIAL**  
  Plan 01 Task 2 fixes the Linux/WSL default with `ArgumentList=["-p", instruction, "--output-format", "json", "--allowedTools", ""]`. But the override path appends `instruction` as the final arg, which cannot express `claude -p <instruction> ...`; Plan 02’s Windows examples like `DECKFLOW_LLM_CLI_COMMAND=wsl.exe claude` are therefore not executable for Claude.

- **H2 Hung CLI timeout: PARTIAL**  
  Plan 01 Task 2 requires `CreateLinkedTokenSource`, `CancelAfter`, and `Kill(entireProcessTree: true)`. Production process timeout is covered, but the fake-runner seam is inconsistent: `ExtractWithRetryAsync` passes the caller token to `_runProcess`, while the timeout is described inside `RunProcessAsync`, so the mandatory fake-runner timeout test will hang/fail unless timeout wraps the runner call.

- **H3 Codex agent/tool exposure: NOT-RESOLVED**  
  Plan 01 Task 2 adds empty `WorkingDirectory` + `Environment.Clear`, but still runs `codex exec --sandbox read-only`. That does not prove tools are disabled or prevent absolute-path reads. The acceptance grep only checks `WorkingDirectory` and `Environment.Clear`, not that Codex cannot read local files.

- **H4 Tag validation: RESOLVED**  
  Plan 01 Task 2 requires `ValidateTags` inside the retry loop, checking non-null arrays, allowlist membership via `ContentTagVocabulary`, and duplicates; Task 3 adds vocab-invalid and duplicate/null-array tests.

- **M1 Ledger pricing bypass: RESOLVED**  
  Plan 02 Task 1 explicitly guards `WouldExceedCapAsync`, `ComputeProjectedVideoCostUsd`, `ComputeProjectedCallCostUsd`, and the three `ComputeCostUsd` call sites with `isSubscriptionProvider`, plus tests zero cap checks and zero spend.

- **M2 JSON repair: PARTIAL**  
  Plan 01 Task 2 replaces first/last brace with quote-aware balanced scanning and null/missing validation. However it extracts the first balanced object only, so output with an earlier non-result object plus a later valid result still fails/retries despite the must-have claiming “multiple objects” recovery.

- **M3 CLI command parsing: PARTIAL**  
  Defaults now use `ProcessStartInfo.ArgumentList`, resolving the core shell-quoting issue. But `DECKFLOW_LLM_CLI_COMMAND` still uses space splitting, cannot express empty args reliably, and cannot position the injected instruction for Claude’s `-p <prompt>` shape.

- **M4 Cross-platform exactness: PARTIAL**  
  Plan 02 Task 2 requires WSL, Windows, and `dotnet.exe`-from-WSL docs. The proposed Windows override examples are not exact/executable for Claude because they omit `-p`, JSON output, and tool-disabling flags, and the override appends the instruction in the wrong position.

- **L1 OpenAI byte-identical guard: PARTIAL**  
  Plan 01 Task 1 adds prompt regression tests, but the prior finding asked for system messages and schema bytes. The plan does not assert the actual OpenAI `ChatCompletionOptions.ResponseFormat` schema bytes or capture the messages passed by `LlmDistillationService`.

- **L2 Error logging leakage: PARTIAL**  
  Plan 01 mostly resolves this with bounded `Tail(stderr)` and no stdout/prompt/transcript/full command logging. But `ExtractModelText` for Claude `is_error:true` says the exception uses `.result` error text; that is stdout-envelope content and may contain prompt/transcript snippets.

**New Concerns**

- **HIGH: Windows/override Claude path is structurally broken.**  
  The command override model appends `instruction` at the end, but Claude requires it immediately after `-p`. Add a placeholder-based override, e.g. `{instruction}`, or model provider defaults as prefix/suffix parts so Windows can run `wsl.exe claude -p {instruction} --output-format json --allowedTools ""`.

- **HIGH: Codex isolation is overclaimed.**  
  Empty cwd + minimal env is not equivalent to disabling tools. Either verify a real Codex no-tools mode, run Codex in a stronger sandbox/container with only stdin-visible data, or remove Codex from supported providers until the read boundary is proven.

- **MEDIUM: Process pipe reads start too late.**  
  Plan 01 says write all stdin and close before starting stdout/stderr reads. A child that writes enough stderr while parent writes a large transcript can deadlock until timeout. Start stdout/stderr reads immediately after process start, then write stdin.

- **LOW: Temp working directories may accumulate.**  
  Plan 01 creates isolated Codex temp dirs but does not require cleanup.

**Final Verdict: BLOCK**

Open HIGH items: Codex read/tool isolation is not genuinely resolved, and the Windows/override Claude command path is not executable as planned.
